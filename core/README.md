# core — ядро ИС (Kotlin/JVM, ADR-010)

**Одно имя на всех уровнях.** Требование `TZ-KA-005` описано в `docs/tz/TZ-KA.md`
и реализуется в `core/ka/`. Никаких таблиц соответствия не нужно: префикс
идентификатора — это и имя файла ТЗ, и имя модуля.

| Модуль | ТЗ | Что делает |
| --- | --- | --- |
| `core/com` | `TZ-COM.md` | Общесистемное: HTTP API, валидация на границе, сценарии, происхождение значений |
| `core/mod` | `TZ-MOD.md` | Модель данных: типы из схем, Quantity, граф параметров, хранилище PostgreSQL |
| `core/req` | `TZ-REQ.md` | Нужды, сервисы, требования, трассировка, flow down, V&V |
| `core/bal` | `TZ-BAL.md` | Баллистика на Orekit: предрасчёт геометрии, энергетика витка, KPI |
| `core/ka` | `TZ-KA.md` | Космический аппарат: платформа, ПН, бюджеты линий, зоны обслуживания |
| `core/usr` | `TZ-USR.md` | Потребители: профили терминалов, популяции, карта спроса |
| `core/net` | `TZ-NET.md` | Адаптер сетевого протокола, модель коллизий и ёмкости |
| `core/flw` | `TZ-FLW.md` | Информационные потоки: ядро Монте-Карло, карта потоков |
| `core/ai` | `TZ-AI.md` | ИИ-контур: промпт-пакеты, разбор ответов, акцепт предложений |
| `core/out` | `TZ-OUT.md` | Отчёты, матрицы трассировки и верификации, экспорт |

Зависимости направлены внутрь: `com` → прикладные модули → `mod`.
Прикладные модули обмениваются данными только через типы контрактов
`schemas/contracts/`, не через внутренние структуры друг друга (TZ-COM-007).
