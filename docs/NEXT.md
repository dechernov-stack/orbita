## Открытые вопросы

* **Стейкхолдер с несколькими ролями** (замечание живого прохода ПМИ-3,
  владелец: «не критично, надо поправить потом»). Сейчас `role` — одно
  значение из перечня, а один и тот же участник бывает разом регулятором,
  заказчиком и потребителем: ГКРЧ и Роскомнадзор регулируют и потребляют,
  Минтранс заказывает и регулирует. Правка: `role` → массив ролей с
  сохранением совместимости (одиночное значение читается как список из
  одного), матрица группирует по каждой роли, обобщение в профиль А2 берёт
  главную. Задевает схему стейкхолдера, матрицу покрытия, заведение
  носителей из нужд и профиль полки — поэтому отдельным шипом, не правкой
  на ходу.

* **Дизайн формы карточки объекта** (поставлен инженером на втором заходе,
  2026-08-25). Сделанное по ходу прогона — вкладки «Определение / Готовность /
  История», действия и препятствия сверху, поля-ссылки списками, ужатие
  таблицы при открытой карточке — снимает остроту, но карточка остаётся
  сырой формой по схеме: без группировки полей по смыслу (постановка /
  показатель / верификация), без разумной ширины колонок, подформы событий
  верификации громоздки. Нужен осознанный проход дизайном (пользователь:
  «дизайном займёмся позднее» — по всему приложению разом, эскизы
  docs/ui/reference как основа).

* **Автопростановка происхождения из документа-источника** (ADR-030,
  отложено): материал, порождённый службой из исходного документа SD-NNNN,
  пока не несёт `provenance.import.dataset = SD@версия` автоматически.
