# Приёмка задания «прогон до KDP B» — отчёт

Единственный критерий задания (§5): инженер проводит миссию «Национальная
спутниковая платформа IoT» от создания проекта до решения KDP B, проходя все
шесть точек, целиком через интерфейс.

Прогон выполнен на пустом стенде (ADR-028, `docker compose down -v && up`)
в настоящем браузере (`web/mission-run.mjs`, Playwright, 1440×900). Прогон вёл
агент от лица инженера «Инженер приёмки» — живой инженер, не участвовавший
в разработке, в контуре недоступен, и это честно записано здесь. Роль внешней
LLM канала О2–О4 исполнили заранее подготовленные ответы
(`web/mission-material.json`): они вставлены в экран ИИ ровно тем же путём,
каким инженер вставляет ответ настоящей модели. Материал инструментов
(входы моделирования — из эталонного демо, выгрузка замечаний обзора)
загружен пачками через экран «Загрузка пачкой» — штатный канал ADR-024.

## Что показал прогон (и что было исправлено по его ходу)

Прогон — приёмка путём данных, и он честно ловил дефекты; каждый исправлялся
в изделии, прогон перезапускался от пустой базы:

1. **Глобальная уникальность идентификаторов** (ADR-022): пачка нужд легла бы
   поверх занятых демо-проектом номеров — приёмка ушла на пустой стенд, как
   и задумано §5 («от создания проекта»).
2. **План верификации**: закрывающим событием может быть только
   квалификационное/приёмочное/сертификационное — сгенерированные требования
   получили двухсобытийный план (предварительный анализ Phase A +
   квалификационные испытания Phase C).
3. **Фильтр ИИ-канала** ловил рассогласование «не менее» ↔ оператор `le` —
   12 формулировок переписаны; фильтр показал себя рабочим.
4. **Правка бесстатусных видов** (замечание обзора, риск): рабочий слой
   навешивал `lifecycle` всем подряд — схема отклоняла правку; исправлено
   (`Editing.update` уважает схему вида), закрытие RF-0001 с ответом прошло
   через инспектор.
5. **Реестр наследовал чужой вид** при смене экрана (React state) — исправлено
   `key` экрана; «Оценки стоимости» перестали показывать технологии.
6. **Панель операций скрыта на портфеле** — «Паспорт проекта» переехал в
   раздел «Контроль», иначе статус проекта было не поднять из интерфейса.

## Ход прогона (сжатый)

1. Создание проекта формой портфеля: имя, фаза Pre-Phase A, шесть точек.
2. Канал О2–О4 пачками: 10 целей с MOE → 24 нужды → 12 сервисов с QoS →
   212 требований с MOP и планами верификации; каждый пакет: сборка →
   вставка ответа → разбор и фильтр → «Принять пачкой».
3. Материал Pre-Phase A одной пачкой (40 объектов): состав системы, WBS,
   альтернативы AoA и descope, оценка стоимости ROM, начальная ODA, риски
   по NPR 8000.4, технологии с планами созревания, три сценария ConOps.
4. Выпуск комплекта Д1–Д9 кнопкой «Выпустить» — девять документов;
   **internal_review пройдена**.
5. Выгрузка замечаний MCR пачкой: критическое RF-0001 **заблокировало MCR**;
   закрыто с ответом через инспектор; массовые переводы зрелости
   (цели и нужды Approved, альтернативы/стоимость/технологии/риски
   Preliminary); **MCR пройдена**.
6. Сервисы и элементы Preliminary; **KDP-A пройдена** — проект перешёл
   в Phase A, операции и комплекты сменились.
7. Входы моделирования и сценарий пачкой; **базирование 212 требований
   одним действием** (отказов 0); цели и нужды Baseline; ConOps и сервисы
   Approved; выпуск комплекта Phase A (SEMP, спецификация, архитектура,
   планы, диапазоны, Project Plan); **SRR пройдена**.
8. Элементы Approved, интерфейсы Preliminary, ConOps и сервисы Baseline,
   сценарий Preliminary; **SDR/MDR пройдена**.
9. Паспорт проекта Preliminary, технологии Approved, ODA Preliminary;
   **KDP-B пройдена — вехи исчерпаны**.
