## Сидер полок под учётками

Включённые учётки останавливали сид на 401. Теперь сидер входит сам:
логин и пароль берутся из `ORBITA_LOGIN` / `ORBITA_PASSWORD`, а при запуске
из терминала спрашиваются на месте (пароль в командную строку не идёт — он
попал бы в историю оболочки и в список процессов). Сессия приходит кукой,
дальше сид ходит тем же токеном заголовком `Authorization: Bearer`.

Отказы стали внятными: неверный пароль — «вход отклонён»; нехватка прав —
«вход есть, но роли не хватает: POST /library/objects → 403; полки правят
роли specialist, lead_se или lead». Проверено на чистом стенде с включёнными
учётками: без входа — понятная подсказка, со входом — сессия получена и
запрос доходит до проверки прав.

Запуск владельцем (учётка руководителя проекта имеет нужную роль):

    ORBITA_LOGIN=de ORBITA_PASSWORD=… python3 tools/seed_registries.py http://localhost:8080/api

либо просто `python3 tools/seed_registries.py` из терминала — логин
спросится. Тем же запуском обновится шаблон `DT-9001` с выправленной
семантикой меток источников.
