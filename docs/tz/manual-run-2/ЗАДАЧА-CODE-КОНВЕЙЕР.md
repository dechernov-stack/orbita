# Задача Code: конвейер экранов. №1 — «Создать проект»

Стоп-кран вёрстки снимается **поэкранно**: верстается только то, чей эталон
заморожен конвейером «бриф → эталон → круги → заморозка». Серверные части
волн (`ЗАДАНИЕ-ВОЛНЫ-ПОСЛЕ-ПМИ`) идут как шли — им конвейер не указ.

## Правила конвейера

1. Эталоны v2 живут в `docs/ui/reference2/`; прежний `reference/` — история.
   Экран без эталона в `reference2/` не верстается.
2. «По эталону» = «и не сверх эталона»: элемент без эталонного прообраза —
   прокол, равный вёрстке без эталона. Расхождение или нехватка в эталоне —
   **вопрос владельцу**, не самодеятельность.
3. Приёмка экрана — снимки всех состояний рядом с эталоном; расхождения
   названы поимённо или их нет.
4. Ритм: Code верстает экран N, пока конвейер крутит N+1. Очередь ниже.

## Очередь экранов

1. **Создать проект** — эталон заморожен, задача ниже.
2. Портфель + первая установка.
3. Жизненный цикл.
4. Готовность к точке.
5. Реестр требований + инспектор.
6. Рабочее место узла + дерево состава ← здесь встречаемся с серверной В2
   (определение/вхождение) — к этому моменту она должна быть готова.
7. Документ: просмотр выпуска + печать (встык с серверной В1).
8. Предложения ИИ + загрузка пачкой. Дальше — по ходу.

## Задача №1: «Создать проект» по `reference-create-project.html`

Эталон — стенд из четырёх состояний; в вёрстке это один экран.

**Оболочка (общая правка, не только этот экран):**

- Рейка становится **68 px с подписями под иконками** — как в эталоне:
  Портфель · Постановка · Требования · Модели · Контроль (и остальные
  разделы по той же схеме). Подпись целиком, без обрезки. Это компонент
  общего shell — обновляется везде сразу.
- На экране создания **панели раздела (236 px) нет** — решение эталона:
  фокусный экран, назад ведут «Отмена» и крошка «Портфель / Новый проект».

**Поведение:**

- «Создать проект» неактивна при пустом имени; Enter в поле имени создаёт;
  повторное нажатие во время создания второй проект не создаёт.
- Смена фазы меняет ленту контрольных точек (Pre-Phase A: внутренний обзор →
  MCR → KDP-A; Phase A: SRR → SDR/MDR → KDP-B) и строку «после создания…»
  с первыми операциями фазы.
- Даты вех — в раскрывашке «Задать плановые даты», необязательны; «дата не
  задана» — законное состояние без предупреждений.
- Совпадение имени с существующим проектом — жёлтое предупреждение с
  идентификатором и фазой существующего; создать можно.
- Отказ сервера — красное состояние по эталону; **введённое не теряется**.
- Первая установка (в портфеле нет проектов) — вариант с вводной строкой,
  форма та же.
- Ссылка «или загрузить проект из файла» → существующий экран загрузки.
- После создания — переход в жизненный цикл нового проекта.

**Тексты** — дословно из эталона, включая «ёлочки» и тире. Ни одного нового
текста, которого нет в эталоне.

**Приёмка №1:**

- [ ] снимки четырёх состояний рядом с эталоном, расхождения поимённо или
      их нет;
- [ ] ничего сверх эталона (сверить списком элементов);
- [ ] рейка с подписями — на всех экранах системы, обрезок нет;
- [ ] поведение — все восемь пунктов выше, проверены руками;
- [ ] тексты дословны.

Отчёт по экрану — короткий: снимки, расхождения, вопросы. Следующий эталон
(портфель) придёт, не дожидаясь отчёта.

## Живой стенд: владелец идёт по ПМИ параллельно конвейеру

1. **Каждый замороженный экран выкатывается на стенд сразу** — владелец
   смотрит переделанное на живых данных, не на статике. Версия стенда тегом
   в каждом отчёте.
2. **База не сбрасывается.** Владелец ведёт сквозной проход по ПМИ — стенд
   стартует пустым один раз, дальше только накат: миграции при выкатке —
   поверх, пересоздание запрещено. Проход владельца не должен начинаться
   заново из-за выкатки экрана.
3. **Замечания владельца — два сорта, две судьбы:**
   - по **переделанным** экранам — чинятся в рамках экрана как круг
     вёрстки, отчёт снимком;
   - по **ещё не переделанным** — точечно **не чинятся**: складываются в
     `docs/tz/manual-run-2/замечания.md` и уходят входом в брифы и эталоны
     соответствующих экранов очереди. Красить старое запрещено — конвейер
     заведён ровно для того, чтобы не страдать с отдельными экранами.
4. В приёмку каждого экрана добавляется пункт: **экран виден на стенде** —
   снимок со стенда, не только из локальной сборки.
