# Отчёт · круг 2 стартового потока (даты вех и исходные документы)

Эталоны владельца — обновлённой поставкой в `reference2/` (отказ порядка
дат в create-project S3; карточка исходного документа в project-start Ш2).
Версия стенда: тег `stand-round2-01`.

## 1. Порядок дат вех

- **Одно правило на сервере** (правила паспорта в ReqService): действует
  на создании проекта, в паспорте и в канале правки с основанием —
  StartFlowRound2Test. Живой стенд: обратные даты → 422
  «MCR не может быть раньше внутреннего обзора — даты идут по порядку
  точек», объект не создаётся. Подписи точек — данные
  (gate-labels-ru.json).
- Частично заданные даты законны (КТ-2 без КТ-1 — не ошибка); «дата не
  задана» — законно всегда.
- Форма: календарь ограничен предыдущей заданной вехой (min), нарушение
  красит поле и даёт warn текстом эталона. Ограничение платформы:
  браузерный календарь не умеет «открыться на дате» без значения —
  min-предел даёт то же поведение выбора.

## 2. Исходные документы: файл + карточка + разбор

- Типология вида: записка миссии · норматив · даташит · справка · прочее;
  вид один, живёт в обеих областях (area=library — полки А3/А4/В2).
- POST /sd-files: файл + карточка (тип и наименование обязательны);
  **текст извлекает сервер** (docx — POI, PDF — PDFBox, txt/md); файл
  хранится в томе orbita-files (подключён к api, входит в копию О-18 —
  backup_stand.sh пакует том). GET /sd-files/{id} отдаёт файл обратно.
- Ш2 «Сложить своё»: форма загрузки (файл, тип, наименование, источник);
  строка файла — «карточка заполнена ✓», карточка раскрытием (тип,
  источник, дата, аннотация) с кнопками «Разобрать: профили
  стейкхолдеров» / «типовые риски» — запуск существующих видов службы,
  профиль подбирается по разрешённым видам; «результат придёт на акцепт»
  (область LIB). Вид «Аннотация документа» заведён (document_annotation).
- AP-0001 стенда → в. 4: виды разбора добавлены процедурой с основанием.
