## §1 · решения кругов — применены и на стенде (v+1)

- Состояние модели — агрегатом (счётчики + занятые диапазоны id) плюс
  релевантная выборка операции; перечни релевантного — данные
  (`context_types` реестра видов), не код. Контекст видит и полки LIB
  (стейкхолдеры, типовые риски, нормативы) — §6 структуры библиотеки.
- Роль — в профиль (поле `role`); модельная преамбула из кода умерла,
  в коде — транспортная обвязка формата ответа. Проверено предпросмотром:
  «Ты — инженерная служба…» в промпте отсутствует, роль профиля — есть.
- Стенд: AP-0001 → в. 3, AP-0002 → в. 2 (процедурой с основанием — они
  базированы), заготовки Г1 получили роли.

## §2 · доводка В3 по уточнениям

- **Реестр прав — данные**: `permissions.json` рядом с gates.json
  (метод+путь→роли, первый совпавший, fail-closed); проверка в
  маршрутизаторе читает реестр; `PermissionsCoverageTest` сверяет покрытие
  write-маршрутов и запрещает перечни ролей в коде.
- Первичная настройка: первая учётка — руководитель существующих проектов.
- Карта авторов `author_map` (история неприкосновенна) + маршруты
  POST/GET /auth/author-map; служебные прогоны — отдельной учёткой
  (`ci-runner` заводится при включении, не «Чернов Д.»).
- Акцепт ИИ — роль из профиля (`accept_role`): несовпадение — 403 с
  именами ролей; руководителю можно.
- 409 конфликта несёт ОБЕ версии значений (`their_values` + `your_values`),
  кто и какие поля.
