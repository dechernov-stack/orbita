# Отчёт О-4 · «Профили службы» (круг 2 — по эталону владельца)

Эталон: `docs/ui/reference2/reference-ai-profiles.html` — поставка владельца
(мой черновик круга 1 заменён; по пакету v2 эталоны Code не создаёт).
Версия стенда: тег `stand-queue-02`. Снимки — в сессии.

## Сделано по эталону

- Список профилей: имя, id, версия, **доля акцепта** бейджем (зелёный ≥70 %),
  «вызовов не было» — по-профильная сводка в /ai/journal (`by_profile`:
  вызовы, акцепт-%, стоимость, последний вызов и модель — считает сервер).
- Карточка: id, имя, версия · автор, строка «основание обязательно…»;
  вкладки **Правила · Промпт · Глоссарий · Журнал**.
- «Правила»: виды пилюлями, П-правила по номерам, запреты проекта,
  строка фильтра источника.
- «Промпт»: плашка «только чтение… новой версией профиля», выбор вида,
  легенда **четырёх** источников (профиль vN / состояние модели / вход /
  формат ответа — отдельный цвет), блоки с подписями. Мера позиции: запреты
  Р1–Р7 видны строками в синем блоке (стенд, AP-0001).
- «Журнал»: вызовы профиля; подвал — «Запустить прогон» (в службу),
  «Новая версия» (форма), аудит «Вызовов N · $ · последний — дата, модель».
- Пустое состояние — текст эталона + «Создать профиль»/«Загрузить пачкой».
- Рейка: иконка «Инструменты» — шестерёнка эталона (общесистемно).

## Расхождения поимённо / вопросы владельцу

1. Блок «Из состояния модели» показывает ФАКТИЧЕСКИЙ промпт службы —
   листинг объектов, а не агрегатную сводку эталона («В проекте: 8 целей…
   id заняты до…»). Сводка изменила бы производственный промпт службы —
   самовольно не менял. Сводить? (уменьшит токены вызова).
2. Роль («Ты — инженерная служба…») в фактическом промпте — модельная
   преамбула, в эталоне — «из профиля · роль и правила». Переносить роль
   в профиль?
3. «Запустить прогон» ведёт в службу ИИ (там вход и запуск) — прогона прямо
   из карточки нет.
4. Стоимость в списке/аудите — 0 $ скрывается (циферблат тарифов пуст).
