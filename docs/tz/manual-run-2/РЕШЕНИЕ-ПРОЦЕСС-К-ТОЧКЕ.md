# Решение: процесс к точке. Задание = адресованный разрыв

## 1. Модель (спринт-позиция МВП-П1, после Б-01/Б-02)

1. **Задание** — лёгкий объект: разрыв (или группа разрывов) + исполнитель
   (учётка В3) + срок + комментарий. Статус задания **вычисляется**:
   разрыв закрыт — задание закрыто; ручных «сделано» нет — принцип
   готовности продолжается на процесс.
2. **Назначение** — с экрана готовности и с любого разрыва: «Назначить…»
   (учётка, срок DateInput); по группе — массово с подтверждением числом.
   Назначать может руководитель и ведущий СИ (реестр прав).
3. **«Мои задания»** — личный разрез готовности: вход участника → его
   разрывы со ссылками «к месту», сроки, просроченное первым. Это ответ
   на «как вести процесс»: каждый видит своё, руководитель — всё.
4. **Операции регламента — рамка, не мёртвые ссылки.** Порядок работы по
   точке: операции фазы, у каждой — её проверки-разрывы (счётчиком),
   исполнители по ролям, выход-артефакт ссылкой к месту. Некликабельное
   умирает: строка либо ведёт к месту работы, либо несёт тихую подпись
   «место появится с волной N» — мёртвая ссылка запрещена как класс.
5. Серверно: вид `task` (gap_ref/цель, assignee, due, note); `/views/my-tasks`;
   счётчик «моих» в шапке. Уведомлений и обсуждений нет (В3-граница).

Мера: руководитель с готовности назначает три разрыва двум участникам;
каждый видит свои в «Моих заданиях» и доходит до места одним переходом;
закрытие разрыва закрывает задание без единого клика по заданию.

## 2. Пакет обобщений (владелец подтвердил паттерны)

- **П-А · «раскрытие строки + карточка» — общесистемный паттерн.**
  Переделать: цели, нужды, сервисы, узлы состава, риски, карточки
  документов. Боковые панели умирают по мере переделки. Анатомия — по
  Т-1/Т-2 (раскрытие: суть тремя колонками, Esc/↑↓; карточка: вся область,
  листание по выборке).
- **П-Б · сортировка кликом по заголовку — во всех таблицах.** Один
  компонент заголовка: стрелка, повторный клик — реверс; клиентская по
  загруженным данным.
- **П-В · сохранённые виды — где осмысленно.** `saved_view` получает
  scope=экран; включается там, где есть конфигуратор колонок или
  группировка (постановка, состав, риски, библиотека); в простых таблицах
  (<3 управляемых колонок) не плодить.

## 3. Порядок — чтобы спринт не располз обратно в конвейер

1. Б-01, Б-02 (стоят проход) → **МВП-П1** минимумом §1 → владелец
   продолжает проход, ведя процесс по-настоящему: назначая разрывы.
2. **П-Б (сортировки)** — попутно, дёшево, одним компонентом.
3. **П-А и П-В** — первым пакетом сразу после итога прохода: это
   переделка полудюжины экранов, внутри спринта она съест сам спринт.
   В журнал итога они уже вписаны решением — не потеряются.
