# Отчёт: составное орбитальное построение + тепловая карта + Leaflet (МВП-М1)

Вход: `ЗАДАЧА-CODE-ПОСТРОЕНИЕ2.md` (надмножество первой). Выкат: живой стенд
накатом, тег `mvp-m1-01`. Тесты: `CompositeConstellationTest` (5 кейсов) +
полный прогон зелёные; приёмка — сквозным прогоном на одноразовом стенде из
копии прод-базы (снимки `мвп-м1-*.png`).

## §1–§2 Модель и расчёты — мерами
- **Построение = набор подгрупп** (схема `constellation.subgroups`, kind
  `composite`): walker_delta (RAAN 360°/P), walker_star (веер 180°/P — новый),
  sso (наклонение ВЫЧИСЛЯЕТСЯ из высоты, вводится LTAN; плоскости разнесены
  на 24/P ч). Итог КА — сумма, вычисляется.
- **Пример владельца** (4 пл. 52° + 3 пл. ССО, 600 км): разворачивается в
  14 КА двух подгрупп, id уникальны, кампаний 2; покрытие — по ОБЪЕДИНЕНИЮ
  (зона каждого КА — его высотой: λ на трек, не одна на конфигурацию);
  свёртки и бюджеты — суммой (кампании/срок — прежними прокси по полному
  перечню орбит).
- **ССО из высоты**: 600 км → 97.79°, 800 км → 98.60° — сверка со
  справочными значениями в тесте; руками не вводится (в форме — серым,
  «вычислено: ССО для h=…»).
- **Миграция ×1**: одиночный Walker читается как построение из одной
  подгруппы — перечень орбит побайтно тот же (тест); прежние проекты живут
  без правок. Конфликт пересчёта с базированным показателем — прежняя
  механика, не тронута.

## §5 Тепловая карта: подтвердилась гипотеза №3
Расчёт НЕ был витриной: Orekit-пропагация и интеграл по трассам живы
(гипотезы №1 и №2 отклонены тестами широт). Равномерно зелёное давало
ПРЕДСТАВЛЕНИЕ: (а) метрика была долей времени доступности, не ёмкостью;
(б) заливка тремя классами ok/degraded/gap + прозрачность — почти всё «ok»
одним цветом; (в) легенда без чисел. Починка:
- ёмкостная мера ячейки — **проходо-минуты** (сумма длительностей ВСЕХ
  сервисных пролётов, без слияния окон: два КА над ячейкой — двойная
  ёмкость); ёмкости канала в модели КА нет — при её появлении мера
  умножается на канал (поле в spacecraft сегодня отсутствует);
- шкала непрерывная с ЧИСЛОВОЙ легендой (min/max — от сервера), «вне
  зоны» — честно серым, не зелёным и не нулём шкалы; тултип ячейки —
  число, клик закрепляет подпись.

Меры (тест + живой прогон):
- Walker 52°: ячейка 85° — **0** проходо-минут (вне зоны видимости);
- ССО: полюс(85°)/экватор ≥ **5×** по проходо-минутам (на 80° — 4.6×:
  зона видимости конечна, пик схождения ближе к полюсу);
- баланс: Σ по ячейкам = Σ длительностей пролётов (машинная точность);
- min ≠ max: пример владельца на живой сетке спроса (1208 ячеек) —
  **142.5 … 627.0** мин, Σ=306084; полярная ячейка 77.5° = **387.5 мин**
  (читается тултипом и в таблице); расчёт 1208 ячеек × 14 КА × сутки —
  **0.9 с**.

## §6 Карта — Leaflet, офлайн
- Leaflet 1.9 (канвас-рендер), подложка — контуры стран Natural Earth из
  npm-пакета `world-atlas` (домен общественный): тайлов и интернета нет,
  стенд самодостаточен. Cesium-глобус не тронут (отдельный экран, умрёт
  своим решением).
- Зум/пан свободные; слои независимыми переключателями: **ёмкость**
  (ячейки канвасом по числовой шкале), **маски зон** (круги приёма и
  сброса с радиусами сервера), **станции** (точки), **трассы подгрупп** —
  каждая своим цветом (снимок: красные наклонные до 52°, жёлтые ССО к
  полюсу — «4×52° + 3 ССО» сверяется глазами); разрыв полилиний на
  антимеридиане — без линий через всю карту.

## §3 Форма
Таблица подгрупп в редакторе построения: строка = подгруппа, тип чипами
(ССО скрывает наклонение, показывает LTAN и вычисленное серым), «итого
КА: 14 = 4×2 + 3×2» — СЧИТАЕТ СЕРВЕР (`/calc/constellation-summary`,
ловушка 2), предупреждения (F ≥ T) — оттуда же.
