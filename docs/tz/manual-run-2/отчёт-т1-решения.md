# Отчёт: исполнение РЕШЕНИЯ-Т1 + ОТВЕТЫ-Т1-ДОП

## §1 Пометы — содержательность вместо арифметики версий

`rowMarks` переписан: сравнение содержательных полей (формулировка,
показатель, распределение, уровень, категория) против **якоря**; якорь —
первая утверждённая версия либо последняя после неё версия служебной
учётки (`system`, `ci-runner`). «Пересчитан после базирования» — только
от механизма пересчёта (`mop.provenance.source = recomputed`); механизма
нет — **флаг честно ноль** (было 140 врущих).

Живой реестр: recalc 140 → **0**; changed 144 → **130**. Ручная проверка
трёх помеченных (мера решения) — `RQ-0101`, `RQ-0205`, `RQ-0306`, по
истории в БД:

- все три **базировались с пустым показателем** (mop = null);
- затем инженерский акцепт службы (вызов 5, автор Чернов) **дозаполнил
  показатель** — содержательное изменение после утверждения;
- перебазированы заново.

То есть 130 помет — не шум арифметики, а правда прогона: дозаполнение
144 дыр показателей шло после базирования. Техническая часть (14 помет)
снята якорем. «Разряд исключений» на этом стенде означает «полтора
десятка снятых»: остальное — содержательно, помета честна.

Попутно закрыт дефект канала `/objects/{id}/change`: автор изменения
терялся — все правки писались в историю как «system». Теперь автор — из
учётки/тела, когда назван (без него — прежний контракт).

## §2 Ответы исполнены

1. **Плотность**: тулбары ужаты (36/33/26), чипы разрывов — компактнее и
   в одну строку (моно — только числам). Замер на живых 212:
   **1440×900 — 28 строк реестра** (26 данных + 2 заголовка групп),
   **1920×1080 — 35** (33 + 2); **обрезанных подписей 0**. Мера
   «≥27 / ≥33 / обрезок 0» выполнена; чистыми данными без заголовков —
   26/33.
2. **Порядок конфигуратора** — уже был порядком таблицы; обновлённый
   эталон заморожен заменой.
3. **«Декомпозировать» с автоподстановкой**: создание открывается с
   `derives_from = [текущее]` и унаследованным уровнем (снимок:
   «Уровень: проект» в форме), носитель пуст; отмена создания следов
   не оставляет (документ не пишется до «Создать»).

## Журнал автораспределения (ОТВЕТЫ §2) — хранимо

Вычисляемая подстановка заменена **хранимой**, как решено:

- Появление ЕДИНСТВЕННОГО корня дерева состава (создание CU — руками,
  кнопкой карточки, каркасом Ш2) раздаёт носителя проектным требованиям
  без носителя: правка с `allocated_to.provenance.source = "auto_root"`
  (поле добавлено в схему требования), **автором-человеком**, одной
  сводной записью-основанием: «Распределено на корень: N требований
  уровня проекта — автоматически, по правилу уровня проекта».
- **Отмена симметрична**: revert взятия, гасящего корень, снимает
  auto_root-связи той же сводной записью; ручные распределения на
  корень — 409 с перечнем. Мера — ReqRegistryTest (автораспределение,
  сводная запись, снятие, блокировка ручным).
- Следствие статусной модели (правка = новая версия в Draft): у
  базированного проектного требования автораспределение опустит статус —
  на живом стенде корня нет (5 корней), случай не возникает; если
  захотите сохранение статуса — это отдельное решение по ядру.

## Компонент даты (reference-date-input) — последний нативный закрыт

`ui/DateInput`: моно-ввод дд.мм.гггг равноправен календарю, пустая дата
законна (очистка крестиком), календарь открывается **от опорной даты**
(живой снимок: «Март 2027», опора серым, 14 дней зачёркнуто), дни раньше
опоры недоступны, ручной ввод раньше опоры — отказ **тем же текстом, что
серверный** (живой прогон: «MCR не может быть раньше внутреннего обзора
(15.03.2027) — даты идут по порядку точек.»); ↑↓/PgUp/PgDn/Enter/Esc.
Заменён везде: вехи создания проекта (опора — предыдущая веха), якорные
даты вех жизненного цикла, все date-поля генерируемых форм (ObjectForm).
Нативных date input в клиенте не осталось.

## Имя группы системных сирот (ОТВЕТЫ §3)

Заголовок — короткое **«Без носителя»** (уровень ясен из контекста),
первой среди групп системного уровня, нейтральным стилем; тревога — в
чипе-счётчике и приглашениях «распределить». «Не распределено» не
возвращалось.

## Дозаход: закрытие TBD не помета; статус наследуется (ADR-031)

### §1 Закрытие TBD

`rowMarks`: поле считается изменённым, только если в якоре оно было
**задано** и отличается; переход пусто/TBD → значение помету не поднимает.
Живой реестр: **changed 130 → 0, recalc 0** — каждое изменение прогона
было либо закрытием пустого показателя (штатное закрытие TBD), либо
перебазировано (якорь-последнее-утверждение гасит). Реальных ревизий
заданного на стенде нет — тройки не набрать честно; семантика закрыта
тестом: ревизия заданного (100→90 инженером) горит, служебная волна и
закрытие TBD — нет, повторное базирование гасит. Счётчик «TBD закрыто
после базирования» — заложен решением на будущее, не делался.

### §2 Статус наследуется — ADR-031 (записан в docs/adr/)

1. `ObjectStore.change`: новая версия **в том же статусе**; смена —
   только `transition`. 2. Основание обязательно и на Approved (рабочий
   слой отсылает к процедуре — как для Baseline). 3. Механические правки
   (auto_root) — автоматическое основание, статус не трогают by
   construction. 4. Якорь помет — **последняя** transition-запись в
   Approved/Baseline; подтверждение (переход в тот же утверждённый
   статус) — законно и гасит помету; в закрываемую строку пишется
   основание «повторное утверждение» (требование триггера).

Меры (ReqRegistryTest): базированное проектное после появления корня —
**осталось Baseline** с auto_root-распределением; правка Baseline без
основания — 409; правка с основанием — Baseline + помета; base → правка
→ base — помета гаснет. Следствия закона по кодовой базе: дозаполнение
службой ИИ больше не понижает статус (`demoted` из enrich-apply умер,
EnrichmentTest переписан), фикстуры расчётных правок несут основание.
