# Отчёт конвейера · экран «Мастер-путь „Начало проекта"»

Эталон: `docs/ui/reference2/reference-project-start.html` (круг 1), бриф —
`БРИФ-МАСТЕР-ПУТЬ.md`. Версия стенда: тег `stand-screen-02`.
Снимки состояний — в сессии; сквозной прогон — на одноразовом стенде с
пустой БД (основная база не сбрасывалась; на основной стенд выкачены
api и web).

## Что сделано

- Паспорт проекта: новые поля `mission_class`, `constraints[{code,text}]`,
  `start_path{status,step,source_ref,profile_ref}` — путь сохраняется в
  паспорт процедурой с основанием (работает и для базированного).
- Сервер: `POST /views/start-path/profile` — профиль службы СОБИРАЕТСЯ из
  ограничений паспорта (запреты + «(код)»), виды mission_to_goals +
  mission_to_needs, require_source; повторная сборка обновляет, а не плодит
  дубли (тест StartPathTest).
- Экран `StartPath.tsx`: степпер 3 шагов, «Пропустить — заполню руками»,
  Ш1 (класс миссии, ограничения с добавлением по Enter и «убрать»),
  Ш2 (две панели), Ш3 (собранный профиль, блоки «Из ограничений · Ш1» /
  «Из материалов · Ш2», «показать промпт целиком» — промпт собирает служба,
  запуск генерации целей и нужд, акцепт — в «Предложениях ИИ»).
- Жизненный цикл: строка пути — «шаг N из 3 · Продолжить» / «Начало
  пройдено» / «Начало пропущено · пройти».
- Новый проект открывает путь первым экраном.

## Проверено руками (одноразовый стенд)

создание → путь; Ш1 → Ш2 → Ш3 с сохранением шага; запреты Ш1 дошли до
собранного промпта службы (видны в «показать промпт целиком»); отказ
канала ИИ — честное красное состояние, путь не помечен пройденным;
брошенный путь продолжен с Ш3, профиль пересобран (в. 2, без дубля);
пропуск → строка «Начало пропущено · пройти».

## Расхождения с эталоном (поимённо)

1. Ш1 «Класс миссии» — ввод текстом, не выпадающий выбор: библиотеки
   классов миссии в системе нет; селектор появится с библиотечной волной.
2. Ш1: предзаполнение ограничений «из класса миссии предложено 3 типовых»
   не реализовано (нет библиотеки) — список начинается пустым, добавление
   руками; hint эталона про предложенные не показывается.
3. Ш2 «Взять из библиотеки» — исходные документы других проектов с
   чекбоксами и «Взять выбранное · N» (решение владельца, круг
   2026-08-25); наборов типовых требований и шаблонов компонентов
   по-прежнему нет — их строки не показываются. Текст пустой библиотеки —
   мой (эталона нет).
4. Ш2 «Сложить своё» — файлы (.docx/PDF) система не хранит: материал —
   исходные документы с текстом (реестр «Исходные документы»); вместо
   drop-зоны — «Загрузить документ» → реестр. Строки документов — с
   пометкой «приложена ✓» при непустом тексте.
5. Ш3: подсветка mark внутри промпт-блоков не воспроизводилась; счётчики
   наборов в блоке «Из материалов» отсутствуют (наборов нет).
6. Свёрнутая строка «Начало пройдено»: сабтекст сокращён до факта
   («Профиль AP-XXXX создан, генерация запущена») — счётчиков применённых
   наборов нет.
7. Плановые даты точек упомянуты в брифе для Ш1, но в эталоне Ш1 их нет —
   не делались (задаются при создании проекта и в паспорте).

## Вопросы владельцу (включая метки «⟵ проверить» брифа)

1. Состав основных параметров Ш1 — что добавить к классу миссии и
   ограничениям? (метка брифа)
2. ~~Состав библиотеки на старте?~~ **Решено владельцем: библиотека — это
   исходные документы** (реестр ADR-030, круг 2026-08-25). Ш2 «Взять из
   библиотеки» показывает исходные документы ДРУГИХ проектов; взятие —
   копия в текущий проект с провенансом imported (dataset «библиотека
   исходных документов: SD-XXXX (PJ-YYYY)», версия, дата, условия из
   rights; тест LibraryTest). Взятый документ сразу доступен постановкой
   для Ш3. Открытым остаётся хвост: наборы типовых требований и шаблонов
   компонентов — отдельная волна, когда потребуется.
3. Предлагать ли путь существующим проектам, где он не пройден, строкой на
   жизненном цикле? Сейчас строка появляется только у проектов, где путь
   стартовал (то есть у новых). (метка брифа)
4. Текст пустого состояния библиотеки в Ш2 — принять мой или дать
   эталонный.
