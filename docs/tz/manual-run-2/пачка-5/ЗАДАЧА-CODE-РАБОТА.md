# Задача Code: раздел «Работа» (по КОНЦЕПЦИЯ-РАБОТА-ФАЗЫ и эталону)

Порядок шипов = порядок разделов. Эталон: `reference-phase-work.html`
(два состояния), бриф: `БРИФ-РАБОТА.md`.

## 0. Отчёт-статус по старой процесс-задаче — первым, до кода

`ЗАДАЧА-CODE-ПРОЦЕСС` исполнена частично (RefChip/RefPicker есть;
Tooltip-компонента, «Мои задания», зависимости — под вопросом). Таблица
«пункт → сделано/нет → где» — день. Дальнейшие шипы опираются на неё.

## 1. Фундамент: доделать процесс-задачу

Вид `task` (цель-разрыв · исполнитель · срок), `/views/my-tasks` +
счётчик в шапке, вычисляемое «ожидает: ‹вход›», `ui/Tooltip` + линт
«элемент без подсказки» в сторожах, сортировка заголовком где не дошла.
Меры — из исходной задачи, они не менялись.

## 2. Реестр задач фазы — данными с полки

Полка «задачи фазы» (по фазам Pre-A/Phase A): задача · операции-основания
· вход (виды/условия) · шаги (заголовок, подсказка, целевое место —
маршрут+преднастройка) · выход (артефакт, зрелость к точке). Контент
Pre-A — 9 задач из концепции; тексты «зачем» и подсказок — с полки,
в коде контента нет. Phase A — той же схемой, наполнение после.

## 3. `/views/phase-work` — и окна ленты

**Лента (лёгкий Гант) — вид по умолчанию** (правка владельца). Окна
задач вычисляются без ручных длительностей: старт = готовность входа
(факт) либо прогноз = плановая дата-дедлайн предшественника; конец =
плановая дата точки, к которой зреет выход. Изменение даты вехи
пересчитывает ленту; «окно сжато» (до дедлайна меньше порога при
невыполненном входе/выходе) — вычисляемый разрыв «цепочка не успевает»
в готовности, красным на ленте. Переключатель «Весь проект | Моя
работа» — фильтр по исполнителю заданий. Стрелки зависимостей — от
данных фазы.

Список задач со статусами, **всё вычисляется**: ожидает (вход не готов,
с именем входа) → доступна → в работе (есть объекты/задания шагов) →
выполнена (выход в требуемой зрелости). Разрывы задачи — те же объекты,
что в готовности к точке, **разрезом по операциям задачи** — второй
готовности не заводить. Исполнители — из заданий. Параллельность — из
данных фазы (О2–О12 / цепочка О13+).

## 4. Экран «Работа» по эталону

Список группами статуса (Выполнены свёрнуты); строка: статус-точка,
имя, текущий шаг/причина ожидания именем, люди, чип разрывов, выход.
Карточка задачи: «зачем» с полки, вход-строка, **полоса шагов**
(паттерн проводника: сделанное ✓ вычислением, текущий акцентом, переход
«→» к преднастроенному месту), панели «Разрывы задачи» (назначить… →
задание) и «Выход» (зрелость — от готовности, подпись «ручной отметки
нет»). Раздел «Работа» — первый в рейке проекта; «следующий шаг» в
шапке — из первой активной задачи.

## 5. Вливания (из накопителя, термин «фикс» закрыт)

- Проводник постановки = шаги задачи 1 (отдельного не строить).
- **Стейкхолдеры**: вид в проекте + раздел + **матрица «стейкхолдер ×
  нужды»** с тройным состоянием (заявлена/покрыта/закрыта) и группой
  ролей, включая поставщиков (связь: поставщик ↔ узел состава ↔ его
  анкета); акцепт урожая — в проект, «обобщить в профиль» — отдельное
  действие.
- **Полки видны и наполняются**: экран состава полок; «обобщить на
  полку …» со следом; нитка «взято/брали» в обе стороны.
- **Справочники ведутся**: правка глоссария и единиц из UI (мягкая
  отмена, роль-право, предупреждение об объёме пересчёта отпечатков).
- **Анкеты, путь 3**: предзаполнение из разбора даташита (мера LR1121).

## 6. Приёмка (сквозная)

- [ ] после мастера инженер попадает в «Работу»: 9 задач, статусы
      вычислены; задача 4 ожидает «2 · Концепция» именем;
- [ ] карточка задачи 3: вход готов от принятых целей/нужд; шаг 2 ведёт
      в преднастроенный промпт; после акцепта требований шаг гаснет сам;
- [ ] «назначить…» на разрыве создаёт задание; исполнитель видит его в
      «Моих»; закрытие разрыва закрывает задание и двигает задачу;
- [ ] матрица покрытия: «перевозчики ОГ — покрыто N из M»; поставщик
      платформы связан с узлом и анкетой;
- [ ] полка типовых листается (34), «обобщить в профиль» работает со
      следом; единица «Вт/кг» вводится с экрана и принимается границей;
- [ ] грепом: ручного статуса задачи нет нигде; линт подсказок в CI.

## 7. Ловушки

1. Вторая готовность/чек-листы задач — запрещено: разрывы одни, разрез
   разный. 2. Контент задач в коде — только полкой. 3. Ручные статусы/
   проценты. 4. Ручные длительности и сроки задач — запрещены и на ленте: окна — только производные от дат вех и зависимостей. 5. Джира-
   сущности (комментарии, вотчеры) — граница В3. 6. «Работа» не ломает
   прямые маршруты разделов — это русло, не клетка.
