## Шип 0 · Два отчёта-статуса (день, до кода)

1. **Процесс-задача** пункт-за-пунктом: task / «Мои задания» /
   зависимости «ожидает» / Tooltip + линт подсказок / сортировки —
   сделано・нет・где.
2. **Моделирование** мера-за-мерой по задачам построения (§1–§7) и
   сравнения: что закрыто тегами, что нет. Недоделанное обоих отчётов —
   в шип 5 списком.

## Шип 1 · Фундамент процесса (доделать по старой задаче)

Вид `task`, `/views/my-tasks` + счётчик, вычисляемое «ожидает: ‹вход›»,
`ui/Tooltip` + линт «элемент без подсказки» в CI, сортировка заголовком
где не дошла. Меры — исходные.

## Шип 2 · «Работа» — главный экран фазы

Реестр задач фазы **данными с полки** (9 задач Pre-A из концепции;
Phase A — схемой, наполнение после). `/views/phase-work`: статусы и
**окна ленты вычисляются** (старт = готовность/дедлайн входа, конец =
дата точки выхода; «окно сжато» = разрыв «цепочка не успевает» в
готовности). Экран: **Лента по умолчанию** (стрелки зависимостей,
«сегодня», вехи ◆, переключатель «Весь проект | Моя работа») · Список ·
карточка задачи с полосой шагов и преднастроенными переходами.
«Работа» — первая в рейке; «следующий шаг» шапки — из неё. Разрывы
задач = разрывы готовности разрезом, второй готовности нет.

## Шип 3 · Стейкхолдеры и матрица покрытия (Ф-13)

Вид `stakeholder` в проекте (роли включая **поставщиков**; связь
поставщик ↔ узел состава ↔ его анкета), раздел в Постановке, **матрица
«стейкхолдер × нужды»** с тройным состоянием (заявлена / покрыта /
закрыта верификацией) и видимыми краями; акцепт урожая — **в проект**,
«обобщить в профиль А2» — отдельное действие. Проводник постановки
(Ф-12) не строится отдельно — это шаги задачи 1 из шипа 2.

## Шип 4 · Библиотека живая (Ф-14, Ф-15, Ф-06.3)

Экран состава полок + «обобщить на полку …» со следом и ниткой
«взято/брали» в обе стороны. Справочники **ведутся** из UI (мягкая
отмена, роль-право, предупреждение об объёме пересчёта отпечатков при
правке единицы). Анкеты, путь 3: **предзаполнение из разбора даташита**
(мера LR1121: чувствительность и частоты с якорями).

## Шип 5 · Хвосты моделирования

Состав — из отчёта шипа 0.2. Известное заранее: сверить вставку
«таблица сравнения» в раздел AoA (Д2) и меры §5 карты после фикса

## Сквозная приёмка (поверх мер исходников)

- [ ] после мастера — «Работа»: лента с окнами от вех, задача 4 ждёт
      «2 · Концепция» именем, красное «окно сжато» появляется при
      сдвиге даты MCR ближе (тест);
- [ ] назначение разрыва из карточки задачи → задание в «Моих» у
      исполнителя; закрытие разрыва закрывает задание и двигает задачу;
- [ ] матрица: «перевозчики ОГ — покрыто N из M»; поставщик платформы
      связан с узлом и анкетой;
- [ ] полка листается, «обобщить в профиль» со следом; единица «Вт/кг»
      вводится с экрана и принимается границей пакетов;
- [ ] даташит предзаполняет анкету с якорями;
- [ ] грепы: ручной статус задачи — 0; ручная длительность — 0; линт
      подсказок в CI валит элемент без title.

## Ловушки (свод)

1. Вторая готовность / чек-листы задач. 2. Контент задач и подсказок в
коде (только полкой). 3. Ручные статусы, проценты, длительности, сроки
задач — окна лишь производные от дат вех и зависимостей. 4. Канбан,
комментарии, вотчеры (граница В3). 5. «Работа» — русло, не клетка:
прямые маршруты разделов живут. 6. Урожай стейкхолдеров на полку мимо
проекта — маршрут исправлен, не вернуть.
