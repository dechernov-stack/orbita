# Решение (ранга ADR): разбор документа при загрузке — выжимка-спутник

## Принцип

У каждого исходного документа два слоя: **файл как есть** + **разбор**
(структурированная машиночитаемая выжимка), создаваемый один раз при
загрузке и хранимый рядом. Всё, что потребляет документ — промпты,
извлечения, поиск, цитирование, — читает разбор, не файл. LLM никогда не
получает сырой файл повторно.

## Пайплайн разбора (детерминированный — без LLM)

1. **Извлечение структуры по формату** (стек уже умеет: POI/PDFBox):
   docx → разделы, абзацы, таблицы; xlsx → листы и таблицы с шапками;
   pptx → слайды (заголовок + тезисы); pdf → текст постранично.
2. **MD — полнотекстовый канон** (правка владельца): 100% текста, якоря
   блоков (`{#s2}`, `<!-- b7 -->`), таблицы MD-таблицами, сложные — с
   пометой деградации и приложением-CSV; xlsx → обзор листов + CSV;
   pptx → слайды разделами; страница/слайд — в якоре. **Текст живёт
   только в MD**; человек читает его как документ, промпт берёт разделы
   по якорям.
2а. **JSON-карта — текста не хранит**: структура (оглавление блоков с
   якорями) + урожай сущностей, каждая ссылка — якорь MD. Дублирование
   текста в карте запрещено — иначе слои разъедутся.
3. **Словарная разметка — глоссарий и единицы сразу**:
   - числа с единицами → канонизация по справочнику (30 мин → 1800 с,
     происхождение «переведено из…»; неизвестная единица — в карточку
     разбора вопросом, не тихо);
   - термины глоссария → помечены (связь «упоминает»);
   - обозначения нормативов (ГОСТ…, ПП №…) → кандидаты-ссылки на
     `normative_document` (акцептом).
4. **Индексация**: полнотекст + по термам — поиск по материалам проекта.

Версионирование: разбор привязан к хешу файла и версии разборщика;
новый файл → новый разбор; новый разборщик → фоновая переиндексация с
пометкой.

## Смысловой разбор — LLM, один раз при загрузке (правка владельца)

Поверх детерминированной выжимки — **единый смысловой разбор**: один
вызов на документ, по **всем классам сущностей сразу**, независимо от
типа (тип — подсказка приоритетов, не фильтр). Урожай — кандидаты с
координатами блоков, разложенные по адресам системы, всё через акцепт:

- стейкхолдеры → полка А2 (включая учреждаемых: «центр мониторинга…»);
- нормативные ссылки → кандидаты `normative_document`; без реквизитов —
  помечены «уточнить обозначение» (готовый разрыв);
- сервисы, цели и нужды с числами → постановка (числа — каноном единиц);
- этапы и сроки → вехи программы; суммы → канон денег;
- географические приоритеты → маски карты спроса;
- ограничения-кандидаты → рамки проекта.

Экономика: вызов один, на выжимке (дешевле сырого файла), кэш по хешу —
переиспользование бесплатно. Прежние «виды извлечения по типу» остаются
классами сущностей внутри единого разбора, не единицами вызова.

## Прочие потребители

- **Промпт-сборка**: включение документа = выбор блоков/разделов —
  токены падают кратно, состав точнее.
- **Карточка**: оглавление из разбора; урожай — вкладкой «Найдено в
  документе» со счётчиками по классам и акцептом по месту.
- **Онтология**: термы, канонические числа, нормативы, урожай сущностей —
  готовый семантический слой; В4 придёт не в пустоту.

## Этапность (в большую пачку, режим накопления)

- **Д1**: детерминированный разбор docx/pdf + канонизация чисел +
  оглавление.
- **Д2**: **смысловой разбор одним вызовом** (ядро ценности): урожай
  кандидатов по классам с координатами, вкладка «Найдено в документе»,
  акцепт по адресам. Мера — записка Минтранса: ≥6 стейкхолдеров,
  ≥5 нормативных ссылок с пометой «уточнить», 5 сервисов, цель-2033
  числом, этапы вехами, 7–9 млрд ₽ каноном.
- **Д3**: xlsx/pptx; термы глоссария; индекс и поиск; промпт из блоков.

Мера Д1: записка Минтранса разобрана блоками с координатами; «30 с» из
текста лежит каноном с происхождением; повторный вызов службы по записке
не читает docx.
