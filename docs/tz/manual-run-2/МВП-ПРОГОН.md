# Спринт к MVP: полный проход ПМИ до итога

## Цель и мера

**Один сквозной проход ПМИ на живом стенде: пустой стенд → создание →
начало → постановка → требования → состав → документы → точки → KDP-B —
штатным интерфейсом, без обходных путей и ручных скриптов.**

Итог, который смотрим руками в конце:
1. Комплект документов точки — **печатью** (docx/PDF), как уйдёт людям.
2. Реестр требований с матрицами и честными разрывами.
3. Модель состава со свёртками бюджетов.
4. Журнал ИИ: сколько предложено/акцептовано, почём.

Мера MVP: проход завершён; **блокеров ноль**; всё остальное — записано,
не починено. Продукт оценивается целиком, впервые после переделки.

## Правила спринта — что чинится, что нет

1. **Чинится только то, что блокирует или искажает проход**: падение,
   тупик без штатного выхода, враньё данных (свёртка считает неверно,
   документ теряет текст). Приоритет — багам моделирования.
2. **Всё остальное — в журнал** (`замечания.md`), включая дизайн: некрасиво,
   неудобно, «хочется иначе» — записали и идём дальше. Разбор — после
   итога, пачкой.
3. **Дизайн-конвейер приостановлен**: новых эталонов и кругов нет до конца
   прохода (Т-3, Т-4, дом операций — ждут). Замороженное остаётся законом,
   но не дополняется.
4. Выкатка чинящих правок — накатом на живой стенд, проход не начинается
   заново; версия тегом в каждом отчёте, как заведено.

## Роли

- **Владелец** — идёт по ПМИ сквозняком; блокер — сразу сообщением
  (проход стоит), остальное — в журнал одной строкой.
- **Code** — первым делом: **триаж багов моделирования** — таблица
  «дефект → блокирует проход? → оценка» из журнала и известного ему;
  затем чинит по приоритету «блокирует → искажает → остальное не трогает».
  Никаких новых позиций очереди до конца спринта.
- **Я** — веду реестр блокеров и приоритеты для Code, разбираю пачки
  замечаний без производства эталонов, собираю разбор итога после прохода.

## Порядок

1. Code: триаж моделирования (день) → починка блокеров списком.
2. Владелец: старт сквозного прохода, как только известные блокеры
   моделирования закрыты (не ждать идеала — ждать проходимости).
3. Проход → итог → **разбор итога**: смотрим четыре выхода из меры,
   решаем, что из журнала стоит следующего цикла, и только тогда
   конвейер оживает — с приоритетами, взятыми из прохода, а не из
   очереди по инерции.

## Первый вход, который нужен сейчас

Список известных багов моделирования — от владельца одной строкой каждый
(что делал → что ожидал → что вышло) либо командой Code выгрузить всё
помеченное «Модели» из журнала и дополнить своим. Без этого триаж слеп.
