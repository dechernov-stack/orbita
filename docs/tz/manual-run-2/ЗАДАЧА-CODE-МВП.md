# Задача Code: спринт MVP (правила — МВП-ПРОГОН.md)

Очередь позиций заморожена. До конца прохода — только это.

## 1. Триаж моделирования — первый отчёт, в день получения

Таблица в `docs/tz/manual-run-2/триаж-моделирования.md`:
`дефект · как проявляется · блокирует проход? (да/искажает/нет) · оценка`.
Источники: журнал `замечания.md` (метка «Модели»), список владельца (придёт),
свои известные. Ничего не чинить до таблицы — сначала карта.

## 2. Починка — строго по приоритету

Блокирует → искажает данные (свёртки, пересчёты, показатели) → стоп.
«Нет» из таблицы не трогать даже если чешется. Каждая починка: накатом на
живой стенд, тег, строка отчёта «дефект → починен → чем проверено».
Проход владельца не прерывается и не начинается заново.

## 3. Подготовка прохода (до старта владельца)

- Резервная копия стенда, тег в журнал (механика О-18).
- `ПМИ-2-МВП.md` → `docs/tz/manual-run-2/`; заготовка журнала
  `прогон-мвп.md` (таблицы ПМИ с пустой графой «вышло»).
- Пакеты `packets/` проверить на совместимость с текущими схемами
  (единицы по словарю!); чего не хватает по шагам ПМИ-2 — собрать.
- Сверить шаги ПМИ-2 с фактическими маршрутами стенда: несуществующий
  путь = блокер подготовки, в отчёт немедленно.

## 4. Во время прохода

Владелец сообщает блокер → чинится вне очереди, тег, короткий ответ
«починено, продолжайте с шага N». Замечания из журнала не чинить —
копятся к разбору итога.

## 5. Чего не делать

Новые позиции очереди; вёрстка по незамороженным эталонам; рефакторинги
«раз уж полез»; починка косметики из журнала. Спринт кончается итогом
прохода, не пустой очередью.
