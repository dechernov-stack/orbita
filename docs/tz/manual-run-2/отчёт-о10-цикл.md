# Отчёт О-10: Жизненный цикл (бриф + эталон круга 1)

Вёрстка по `reference-lifecycle.html`; живой снимок —
`снимки-т1/о10-жизненный-цикл.png`.

## Сервер (`/views/gates` дополнен)

- Вехе — русская подпись (`label` из gate-labels); пройденной — решение
  прохождения (`decision_rationale` из Decision «Прохождение точки …»);
  ближайшей — `open_count` (без конфигурации — честно отсутствует).
- `return` — полосе: точка, причина, дата, счётчик открытых замечаний.
- `passport` — руководитель (lead/автор, человеческим именем), класс
  миссии с именем из библиотеки, ограничения, путь начала.

## Клиент (Lifecycle.tsx — переверстан целиком)

- **Лента вех — главная и единственная**: пройденные зелёным ✓ с датой
  факта и решением («комплект рассмотрен без замечаний», «замечания
  устранены»…); ближайшая — акцентом, счётчик «не закрыто · N» кликом
  ведёт в готовность, «Зафиксировать прохождение» с подписью «фиксирует
  DA» (основание — полем, отказ — сервером); будущие — **DateInput с
  опорой одной строкой** (водопад «план/дата/не/задана» умер); горизонт
  следующей фазы — блеклая веха с тихой подписью «проверки появятся с
  регламентом Phase B после KDP-B». 13 вех — лента прокручивается.
- Возврат — полосой между лентой и паспортом: «Возврат ‹точка› · ‹дата›»,
  причина, «замечания · N →» (ведёт в замечания обзора). На живом стенде
  возврата нет — состояние закодировано по эталону S2.
- Паспорт: руководитель · класс миссии · ограничения чипами · путь начала
  строкой («настроить заново»/«продолжить») · «изменить» → паспорт-экран.
- **Чего больше нет на экране** (бриф §5, §8): ленты активности (живёт в
  портфеле), операций О1–О15 (мастер-механика — отдельно; переход к
  следующей операции остался в шапке приложения), правки длительностей и
  кнопки «+ вехи Phase B–F» (настройки состава вех на экране нет).

## Вопросы владельцу

1. Список операций фазы жил на этом экране и был навигацией к рабочим
   местам операций — убран по брифу. До появления «дома операций» переход
   к ним — только «следующий шаг» в шапке. Если нужен временный доступ к
   полному списку — скажите где.
2. Планирование длительностями (duration_days) осталось в данных и в
   расчёте дат сервером (⟲ у вычисленных), но редактирование длительностей
   с экрана ушло вместе с прежней лентой.

## Ответы исполнены

1. **«Операции» — пунктом в «Контроле»**: старый экран операций выделен
   как есть (Operations.tsx — карта 17 операций, «следующий шаг», переходы
   к рабочим местам; не перекрашен); «Жизненный цикл» переехал в панель
   «Контроль» первым пунктом (по вашему перечислению соседей и рейке
   эталонов — там он и подсвечен); маршруты живы (ключи прежние). Живой
   прогон: Контроль → Операции (17 карт) → Жизненный цикл — всё ходит.
   Снимок `о10-операции-контроль.png`.
2. **Длительности умерли насовсем**: сервер дат из duration_days больше
   не выводит (только явные плановые даты вех), `computed`/⟲ умерли,
   интервал `days_from_prev` читается между явными датами; редактирования
   нет нигде. GatesPlanTest переписан под новый закон («длительности дат
   не выводят»); WBS-свёртка сроков не тронута — встреча с датами вех
   придёт в О-20 разрывом.
