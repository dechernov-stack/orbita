# Дизайн-задача: раздел «Требования» целиком

Самая большая позиция конвейера. Это главный рабочий экран системы — в нём
инженер живёт часами, на нём меряется плотность, в него сходятся все
решения последних месяцев: носители, вхождения, статусные пометы, разрывы,
ИИ-предложения. Поэтому не «переверстать реестр», а спроектировать раздел.

Роли — по конвейеру: брифы и эталоны собираю я (поставки владельца в
`reference2/`), владелец даёт доменные правки и снимки кругов, Code не
верстает до заморозки.

## Вход

1. Замечания владельца по разделу из журнала живого прохода — сырьё брифов.
2. `reference-registry.html` (круг-0, «нижняя планка») — пересобирается: в
   нём нет новой рейки, носителей-вхождений, помет и разрывов.
3. Живая выгрузка со стенда — **212 требований** реального прогона: брифы и
   эталоны строятся на ней, не на сокращённой затравке. Крайности из неё же:
   длиннейшая формулировка, требование с пятью детьми, сирота без носителя.

## Состав пакета — четыре части, каждая своим кругом

### Т-1. Реестр + инспектор (ядро)

Бриф обязан решить — и это главные проектные вопросы пакета:

- **Колонки и порядок их смерти.** Что видно всегда (ID, формулировка,
  показатель, статус), что уходит первым при сжатии, что живёт только в
  инспекторе. Показатель — моноширинный, вправо; вид требования —
  колонкой (закладка под Г5, вёрстка включит по готовности сервера).
- **Разрезы: уровни / носители / плоско** — один реестр с переключателем,
  не три экрана. Дерево против групп: когда строки — иерархия, когда —
  группировка с заголовками.
- **Разрывы в строке**: без носителя, без верификации, вид связи не
  указан — маркер в строке + сводка разрывов над таблицей (счётчики-фильтры,
  не пустые ячейки).
- **Пометы**: «изменено после утверждения», «показатель пересчитан после
  базирования» — как выглядят в строке и в инспекторе, чем отличаются от
  статуса.
- **Массовые действия и их безопасность**: промоут выделенного с
  подтверждением числом («Базировать 34 требования?»), массовый акцепт —
  только порождающее (ловушка блока E остаётся).
- **Инспектор**: вкладки определение · трассировка (цепочкой вверх и вниз)
  · распределение (переход «к носителю» — мост в рабочее место узла) ·
  верификация · история с откатом · ИИ (предложения к этому требованию).

### Т-2. Карточка требования в состояниях

Решением круга 2 боковой инспектор для требований умер: раскрытие строки
даёт суть, полная анатомия — **карточка на всю рабочую область** (две
колонки секций, листание по реестру). Отдельный стенд — карточка в
состояниях: Baseline с «Изменить с основанием» и полем основания; конфликт
«пересчитан после базирования» — что было, что стало, что делать; разрыв
трассировки; история с откатом; сирота — приглашение распределить, не
прочерк. Сохранённые виды реестра (Т-1) — серверная часть: вид
`saved_view` (колонки · сортировка · фильтры · разрез; личный/проектный) —
задача Code при вёрстке.

### Т-3. Режим «по носителю»

Реестр в разрезе дерева носителей: группы — узлы (определения с
вхождениями ×N), внутри — требования узла; счётчики на узлах; сирота —
первая группа «Не распределено», а не последняя. Мост к О-13: строка узла
ведёт в его рабочее место.

### Т-4. Матрицы

Трассировка «требование × источник» и верификация «требование × событие»
вкладками; **разрывы — списком сбоку со счётчиком**, не пустой ячейкой
(решение старого разбора «Готовности» применяется и здесь); из ячейки —
в инспектор.

## Что в пакет не входит

Рабочее место узла (О-13, свой пакет — Т-3 даёт только мост); типизация
Г5 и порты В4 — закладываются местами в макете с пометой этапности, вёрстка
включает по готовности сервера; редактор формулировки с множественными
вставками-значениями (Г7) — не сейчас.

## Порядок и круги

Брифы по одному, Т-1 первым; на каждом — доменная правка владельца по
меткам «⟵ проверить», затем эталон, круг снимком, заморозка. Т-2 можно
параллельно Т-1 (общая анатомия инспектора); Т-3 и Т-4 — после заморозки
Т-1: они наследуют его решения по колонкам и маркерам.

## Приёмка дизайн-пакета

- [ ] плотность числом на живой выгрузке: ≥30 строк при 1440×900, длиннейшая
      формулировка не обрезана при свободном месте;
- [ ] пятисекундный тест на каждом эталоне: посторонний называет главное,
      и это совпадает с вопросом №1 брифа;
- [ ] все состояния Т-2 показаны; ни одного серого прочерка на месте
      разрыва;
- [ ] чек-лист переделки чист (плотность · порядок чтения · коды · переносы
      · витрина/форма · иерархия · состояния · типографика · «каждый элемент
      называет работу»);
- [ ] замечания владельца из журнала — каждое либо закрыто эталоном, либо
      отклонено с причиной в разборе круга.
