# Отчёт О-11: Готовность к точке (бриф + эталон круга 1)

Живой снимок (PJ-0002, внутренний обзор) — `снимки-т1/о11-готовность.png`.

## Сервер

- `GET /views/gate-readiness` — структурная готовность вместо телефонной
  книги: те же источники, что блокируют pass (выходы операций точки ·
  зрелость · TBD/трассировка · критические замечания · комплект
  документов) — АГРЕГАТАМИ с числом и местом починки; плюс вычисляемые
  предупреждения (нужды покрыты, верификация назначена, системные
  распределены, предложения службы разобраны, риски заведены, ОДА
  присутствует). Семантика pass не менялась: блокирует то же, что и
  блокировало; предупреждения точку не держат.
- «0 объектов» — разрыв, не зелёный ноль («0 объектов — рисков не
  заведено»).
- **Tailoring**: `POST /views/gate-readiness/na` — проверка неприменима
  к точке; запись в паспорте (`gate_tailoring`: точка · проверка ·
  обоснование ≥10 знаков · автор · дата), правкой с основанием; отмена —
  `remove: true`. Крайность «горизонт пройден» — честное состояние, не
  ошибка (живой PJ-0001 таков).
- Мера — ReqRegistryTest: агрегаты группами, blocking первая, «0
  объектов» разрыв, tailoring с автором, короткое обоснование — отказ,
  отмена возвращает.

## Клиент (GateReadiness.tsx — переверстан целиком)

- Сводка сверху: «не закрыто · N» (зелёная при нуле) · «блокирует
  фиксацию · M» · «план: дата».
- «Блокирует фиксацию» — первая, всегда раскрыта, красной рамкой;
  тематические схлопываемые, закрытые схлопнуты по умолчанию; строка:
  имя человеческим языком · число («9 из 9 не выпущено») · «к месту →» ·
  «неприменимо…» (форма обоснования по месту); неприменимое — серым с
  обоснованием, автором, датой и «вернуть».
- «Готово к фиксации» — зелёная полоса со ссылкой на цикл (фиксации
  здесь нет — она у DA на цикле); ручных галочек нет; перечень
  пересчитывается при возврате фокуса (кнопки «пересчитать» нет).
- Прежний плоский список замечаний и фиксация с экрана ушли.
