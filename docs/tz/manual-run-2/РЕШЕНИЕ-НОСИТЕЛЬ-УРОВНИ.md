# Решение: носитель стратифицирован по уровням

Правка владельца, принята: **требование уровня проекта — нужда, приведённая
к инженерной форме.** Его якорь — трассировка на нужду; распределение на
корень — инженерная механика. Настоящий сирота — системное требование без
элемента/интерфейса. Инвариант «требование без носителя не существует»
не отменяется — стратифицируется.

## Правила

1. **Уровень проекта**: обязательна трассировка вверх на нужду/цель;
   её отсутствие — разрыв «без нужды». Носитель — корень системы,
   назначается **автоматически при появлении корня** (создание руками,
   кнопка на карточке, каркас PBS из Ш2) — с записью в журнал; до корня —
   законная пустота (тихий дефис с подсказкой), не разрыв.
2. **Системный уровень и ниже**: носитель обязателен; отсутствие — разрыв
   «без носителя», приглашение «распределить».
3. **Новый разрыв уровня проекта — «нужда не покрыта»**: нужда без единого
   требования — валидационная дыра. На пилоте счётчик сразу нашёл 4.
4. **Правило пустоты**: прочерк запрещён на месте разрыва; законная
   пустота — тихий дефис. Различие — семантическое, не косметическое.

## Code — правки к Т-1 (серверные флаги)

- Флаг «без носителя» в `/views/requirement-tree` считается только для
  уровней ниже проектного; чипы реестра: «Без носителя (системные)» ·
  «Нужда не покрыта» · «Без нужды (проектные)».
- «Нужда не покрыта» — счёт по нуждам проекта без входящих трассировок от
  требований; клик-фильтр ведёт на перечень нужд (раздел «Постановка»).
- Автораспределение проектных требований при появлении корня: тихо,
  журналируемо, идемпотентно; системные — никогда автоматически.
- Группа «Не распределено» в группировке по носителю умирает; проектные —
  группа «Уровень проекта — на нуждах».

Эталоны обновлены этой поставкой: `reference-req-registry.html` (чипы,
дефисы, группа) и `reference-req-card.html` (состояния 5 и 5б).

## В4 — правка задания графа

Инвариант 1 записки («требование без носителя не существует»)
переформулируется по уровням при исполнении В4; валидационная свёртка
«нужда ← требования» — часть несворачиваемой валидации, счётчик покрытия
нужд — её первый вычислимый кусок, уже живёт в реестре.
