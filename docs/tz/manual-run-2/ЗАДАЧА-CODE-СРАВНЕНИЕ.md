# Задача Code: сравнение построений (по МЕТРИКИ-ПОСТРОЕНИЙ.md)

Зависимость: `ЗАДАЧА-CODE-ПОСТРОЕНИЕ` §1–§5 — метрики группы А считаются
из того же интеграла видимости, вторых расчётных движков не заводить.

## 1. Варианты построений

Построение (§1 задачи построения) существует в проекте **вариантами**:
имя + набор подгрупп. Сравнение — по выбранным 2–5 вариантам. Вариант —
обычный объект (версии, происхождение); «рабочий» вариант помечается —
его считает карта и показатели требований.

## 2. Расчёт метрик — 14 по документу

- **А1–А6**: из интеграла §5 по ячейкам (гэпы дают покрытие, max gap,
  ревизит 75-м перцентилем — квантиль, не среднее; отклик; латентность
  через станции; запас ёмкости минимумом по зонам класса). Взвешивание
  спросом — сеткой, по классам A′/B′/C′ раздельно.
- **Б7–Б8**: партии несовместимости по (наклонение, высота); время
  развёртывания с RAAN-разводом прецессией; прокси-стоимость с
  коэффициентом попутности типа орбиты (коэффициенты — данными в конфиге,
  не константами в коде).
- **В9–В10**: деградация — повторный счёт интеграла без одного КА худшей
  подгруппы (Δ max gap худшей зоны); Δv поддержания и увод — по высоте и
  нормативу.
- **Г11–Г14**: **только прокси** — тень/β прямой астрономией по
  подгруппам; радиация таблицей классов (данные, не код); станции
  перебором каталога площадок до достижения латентности; окно/доплер из
  геометрии. Больших моделей не заводить; в выдаче — признак «прокси».

## 3. Экран сравнения

1. Таблица: строки — варианты, колонки — метрики группами; сортировка
   заголовком; колонки Г — с пометкой «прокси» (тултип: чем посчитано).
2. **Пороги требований — фильтром**: вариант, не прошедший порог
   показателя, — отсеян с перечнем «кто и по какому порогу выбыл»
   (честно, не молча).
3. **Парето-подсветка** недоминируемых по осям (запас ёмкости · max gap ·
   прокси-стоимость); оси — переключаемы.
4. Никакого итогового балла на экране. Веса — после итога прохода,
   явным сохранённым профилем.
5. **Вставка «таблица сравнения» в документ** — механизмом вставок В1:
   раздел AoA (MCReport §2) получает живую матрицу сравнения; выпуск
   фиксирует снимок. Это замыкает сравнение на комплект точки.

## 4. Приёмка

- [ ] мера документа: 52°-Walker против смеси с ССО различимы таблицей
      (полярная ёмкость, латентность севера, энергорежим — против партий);
      без единого балла;
- [ ] ревизит — перцентилем (тест на распределении с хвостом: среднее
      обмануло бы, перцентиль нет);
- [ ] отсеянный порогом вариант — в перечне с именем порога;
- [ ] деградация: Δ max gap при минус-одном КА посчитана и отлична между
      вариантами;
- [ ] коэффициенты Б и таблицы Г — данными (правка без пересборки);
- [ ] вставка таблицы в раздел AoA рендерится и попадает в снимок выпуска;
- [ ] «рабочий» вариант единственный; смена — явным действием.

## 5. Ловушки

1. Скрытый балл или зашитые веса — запрещены; сравнение = таблица.
2. Среднее вместо перцентиля в ревизите — прячет хвост.
3. Большие модели для Г (SPENVIS-класс, энергобаланс) — не сейчас;
   прокси с пометкой честнее точной модели без времени.
4. Второй расчётный движок для метрик — всё из интеграла §5.
5. Коэффициенты и таблицы в коде — только данными.
6. Сравнение «всех со всеми» — выбранные 2–5, экран не каша.
