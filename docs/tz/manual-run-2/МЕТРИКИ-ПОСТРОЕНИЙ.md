# Метрики сравнения орбитальных построений

Принцип — ваш, литература его подтверждает: **метрики раздельно, свёртка
отдельно**. Ключевой вывод оптимизационной литературы: улучшение одной
метрики покрытия не влечёт улучшения других — конфигурации, лучшей во
всех метриках, не существует (AIAA JSR, MILP-формулировки задач
покрытия). Значит сравнение — честная таблица + Парето, а не скрытый
балл «по непонятному сценарию».

## Набор: 10 метрик тремя группами

### А. Обслуживание (канонические FoM + наш спрос)

1. **Покрытие целевых зон, % времени** — взвешено спросом по нашей сетке
   (не «% поверхности Земли»: Тикси и океан не равны), раздельно по
   классам потребителей A′/B′/C′.
2. **Максимальный разрыв (max gap)** — гарантия худшего случая; метрика
   обещаний заказчику.
3. **Ревизит, 75-й перцентиль** — правило квантиля вместо среднего:
   среднее прячет хвост (практика STK: перцентильный ревизит).
4. **Среднее время отклика (mean response time)** — чувствительно к
   распределению разрывов, дополняет 2–3.
5. **Латентность доставки** (store-and-forward: сбор с терминала → сброс
   на станцию → доставка) — против порогов постановки (у нас: «не реже
   30 с» для ОГ) по классам QoS.
6. **Запас ёмкости** — обслуживаемо/спрос по ячейкам (интеграл §5 карты),
   минимум по зонам каждого класса: узкое место, не среднее.

### Б. Стоимость и логистика

7. **Пусковые партии и время развёртывания.** Не «плоскости ≈ пуски»:
   партии несовместимы по наклонению и высоте (смена плоскости —
   запретный Δv), а RAAN внутри одного наклонения разводится прецессией —
   дешевле пусками, дороже временем. Две цифры: число несовместимых
   партий · время до рабочей конфигурации.
8. **Прокси-стоимость развёртывания** — КА × платформа + партии ×
   выведение с коэффициентом попутной доступности типа орбиты (ССО —
   массовый ride-share, наклонные — реже и дороже за кг); параметрики
   О-20 заменят прокси тем же полем.

### В. Живучесть и эксплуатация

9. **Деградация при потере одного КА** — Δ max gap худшей зоны:
   изящность деградации, различает построения с равной номинальной
   службой.
10. **Поддержание и увод** — Δv на срок жизни и соответствие нормативу
    увода (НОО-полка Б1 уже требует).

### Г. Инженерные следствия орбиты (прокси-модели, вычислимы сейчас)

11. **Энергорежим платформы**: худшая по году доля тени на витке и
    диапазон β-угла — по подгруппам. Терминаторная ССО живёт почти без
    затмений с постоянным β; наклонная 52° — затмения до ~трети витка и
    гуляющий β → масса СЭП, ресурс АКБ по циклам, поворот панелей. Для
    платформы ≤ 100 кг это метрика первого ранга.
12. **Радиационная среда**: класс дозы по высоте и наклонению
    (таблица-прокси: ЮАА, полярные рога) → требования стойкости из
    типовых (Б1) и ресурс электроники.
13. **Наземный сегмент под латентность**: минимальное число станций (из
    каталога площадок РФ), достигающее латентности п. 5, — стоимость сети
    станций как следствие наклонений; высокоширотные станции кормят ССО
    каждый виток, наклонные — нет.
14. **Окно связи терминала**: медианная длительность сеанса и доплер
    (высота → скорость) — энергоцена сеанса для батарейных классов
    потребителей; короткое окно с большим доплером бьёт по C′-терминалам.

Ядро сравнения — А+Б (всегда); Г — прокси-моделями простой астрономии и
таблиц, уточняются волнами, в таблице сравнения присутствуют с пометкой
«прокси».

## Свёртка — вторым шагом, тремя механизмами по порядку

1. **Пороги из требований** — фильтр: не проходит порог показателя
   (латентность, покрытие класса A′) — вне сравнения, без взвешиваний.
2. **Парето-фронт** по 2–3 осям (запас ёмкости · max gap · стоимость):
   недоминируемые подсвечены, компромисс виден, не спрятан.
3. **Веса владельца** — явный сохранённый профиль весов, если нужна одна
   цифра; зашитых весов в коде не бывает.

## Задача Code

- Метрики 1–6 и 9 считаются из того же интеграла видимости §5 (гэпы по
  ячейкам дают всё); 7–8 — из построения; 10 — из платформы и норматива.
- **Экран сравнения**: строки — построения, колонки — метрики; сортировка
  заголовком; Парето-подсветка; пороги требований — фильтром с перечнем
  отсеянных (кто и почему выбыл — честно, не молча).
- Свёртка весами — после итога прохода, профилем, не константами.
- Группа Г — прокси: тень/β — прямая астрономия по подгруппам; радиация —
  таблица классов; станции — перебор по каталогу; окно/доплер — из
  геометрии. Больших моделей не заводить — пометка «прокси» в таблице.
- Мера: построения из примера владельца (52°-Walker против смеси с ССО)
  различимы таблицей без единого балла: смесь выигрывает полярную
  ёмкость, латентность «севера» и энергорежим ССО-подгруппы
  (терминаторная — без затмений), проигрывает пусковыми партиями;
  наклонная подгруппа несёт худший энергорежим — и это видно колонкой Г.

(10.2514/1.A36518); сравнение IoT-созвездий по покрытию и ревизиту против
