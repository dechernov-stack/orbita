# ПМИ-2. Сквозной проход MVP: пустой проект → KDP-B

Преемница `docs/tz/manual-run/ПМИ.md` — путь тот же, интерфейс переделан.
Проверяется **продукт целиком**: инженер проходит Формулирование штатным
интерфейсом, без скриптов и подсказок. Правила спринта — `МВП-ПРОГОН.md`:
блокер — сообщением сразу; остальное — строкой в `замечания.md`, идём
дальше.

**Условия.** Живой стенд (база не сбрасывается) — проход новым проектом;
шаг 0 «первая установка» на живом стенде не воспроизводится, проверен
ранее. Материал: записка миссии (файл) и пакеты `packets/` — по ходу.
До старта Code снимает резервную копию (тег в журнал).

**Форма записи:** № · сделал · ожидал · вышло (заполняется по ходу; пустая
графа «вышло» = совпало).

## А. Старт проекта

| № | Действие | Где | Ожидаемо |
|---|---|---|---|
| А1 | Создать проект: имя, Pre-Phase A; дату внутреннего обзора задать, MCR — календарём от опоры | Портфель → Создать | лента точек по фазе; обратный порядок дат — отказ с именами точек |
| А2 | Ш1: класс миссии «НОО · связь и IoT», ограничения — типовые + одно своё | Начало проекта | ограничения правятся; сохраняется само |
| А3 | Ш2: взять «Типовые требования», «Комплект Д1–Д9», «Каркас PBS+WBS» | Начало → Библиотека | строка меняется на «Взято ✓ создано N · отменить»; счётчик шага растёт |
| А4 | Ш2: отменить взятие каркаса, взять снова | там же | отмена гасит созданное; повтор не плодит дублей |
| А5 | Ш2: загрузить записку миссии, заполнить карточку (тип чипами) | там же | карточка обязательна; файл в списке с чекбоксом участия |
| А6 | Ш3: открыть промпт целиком | Начало → ИИ | запреты Ш1 — строками; документы поимённо «N из M» |
| А7 | Запустить генерацию целей и нужд | там же | предложения ушли на акцепт; в модель ничего не записано |

## Б. Постановка

| № | Действие | Где | Ожидаемо |
|---|---|---|---|
| Б1 | Акцептовать цели и нужды (часть отклонить) | Предложения ИИ | отклонённое не в модели; происхождение у принятого |
| Б2 | Разбор записки → профили стейкхолдеров; акцепт | Исходные документы → Разобрать | акцепт лёг на полку А2 (область LIB) |
| Б3 | Запустить генерацию требований профилем AP-0201 | Инструменты → Профили | доля акцепта в реестре профилей обновится после Б4 |
| Б4 | Акцепт требований; одно предложение с числом без источника найти | Предложения ИИ | числа без основания фильтр не пропустил вовсе |

## В. Требования

| № | Действие | Где | Ожидаемо |
|---|---|---|---|
| В1 | Реестр: группировка «по носителю», схлопнуть группу; вид сохранить | Требования | группы схлопываются; вид переживает перезаход |
| В2 | Чип «Нужда не покрыта» → покрыть одну нужду новым требованием | Требования → Постановка | счётчик уменьшился |
| В3 | Декомпозировать требование | карточка | родитель подставлен, уровень унаследован |
| В4 | Базировать выделенное массово | реестр | подтверждение числом; статусы сменились |
| В5 | Изменить базированное без основания, затем с основанием | карточка | без основания — отказ; с основанием — Baseline + помета |
| В6 | Перебазировать изменённое | реестр/цикл | помета погасла (якорь — последнее утверждение) |

## Г. Состав и модели

| № | Действие | Где | Ожидаемо |
|---|---|---|---|
| Г1 | Создать корень системы (кнопкой с карточки проектного требования) | карточка → Распределение | сводная запись журнала «Распределено на корень: N»; статусы не упали |
| Г2 | Дерево: вхождения ×N (3 КА × 2 БЦВМ), свёртка массы | Концепция | множитель честный; бюджет сходится |
| Г3 | Распределить системные требования на элементы | реестр «по носителю» | «Без носителя (системные)» → 0 |
| Г4 | Входы моделирования пачкой; расчёт покрытия | Модели | результат привязан к показателям; **баги — сюда, приоритет** |
| Г5 | Изменить вход модели → пересчёт | Модели | показатель обновился; конфликт с базированным — виден, не молчит |
