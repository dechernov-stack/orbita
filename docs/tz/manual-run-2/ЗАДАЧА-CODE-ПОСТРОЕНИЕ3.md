# Задача Code (моделирование): составное орбитальное построение

Сейчас построение — один Walker с одним наклонением. Нужно: **построение =
набор подгрупп**, пример владельца: 4 плоскости 52° + 3 плоскости ССО.

## 1. Модель данных

Вход моделирования «построение»: список подгрупп, у каждой:

- имя; тип: `walker_delta` / `walker_star` / `sso`;
- плоскости × КА в плоскости; высота;
- **walker**: наклонение, фазовый параметр F;
- **sso**: LTAN (местное время узла); **наклонение вычисляется из высоты**
  и показывается серым с подсказкой «вычислено: ССО для h=…» — не вводится;
- итог построения: сумма КА — вычисляется, не вводится.

Существующий одиночный Walker мигрирует в построение с одной подгруппой —
паттерн миграции ×1, без фантазии.

## 2. Расчёты

- Покрытие (`/coverage`) — по **объединению** подгрупп; показатели
  требований — от полного построения.
- Свёртки числа КА, бюджеты × кратность, стоимость — суммой по подгруппам.
- Разрез «по подгруппе» в покрытии — не сейчас (горизонт).

## 3. UI (по паттернам, эталона не ждёт — форма данных)

Таблица подгрупп: строка = подгруппа, поля по типу (ССО скрывает
наклонение, показывает LTAN и вычисленное серым); добавление строкой;
свёртка «итого КА: 84 = 4×2×… + 3×…» под таблицей; сортировка заголовком
и тултипы — по общим механикам.

## 4. Приёмка

- [ ] построение из примера владельца заводится и считается: покрытие
      объединением, итог КА суммой, бюджеты × кратность честные;
- [ ] ССО: наклонение вычислено верно для заданной высоты (сверка с
      справочным значением в тесте), руками не вводится;
- [ ] прежние проекты с одиночным Walker живут без правок (миграция ×1);
- [ ] изменение подгруппы → пересчёт → конфликт с базированным показателем
      виден, не молчит (существующая механика).

## 5. Тепловая карта: равномерно зелёное — так не бывает

Физика: плотность проходов зависит от широты — Walker 52° почти не видит
выше ~57°, пик обслуживания у широт ±i; ССО со сходящимися у полюсов
трассами обслуживает полярные ячейки в разы–десятки раз плотнее экватора.
Равномерный цвет = дефект (владелец видит его на всех типах построений).
Проверить три гипотезы по порядку:

1. **Заглушка**: значение в ячейках — константа/среднее, интеграла по
   трассам нет вовсе (витрина, не расчёт). Признак: все ячейки численно
   равны.
2. **Потерянная широта**: расчёт «мгновенная зона × среднее время» без
   интеграла видимости по орбитам — широтная зависимость съедена
   усреднением.
3. **Сломанная шкала**: значения различаются, но нормировка (min=max,
   кламп) красит всё одним; легенда без чисел это скрывает.

Требуемое: ёмкость ячейки = интеграл по построению (проходы × время в
зоне × ёмкость канала) на сетке спроса; шкала с числовой легендой; тултип
ячейки — число, не только цвет (общая механика подсказок).

**Меры (в тест и отчёт):**
- [ ] Walker 52°: ячейки выше широты видимости — ноль, честно серые
      «вне зоны», не зелёные;
- [ ] ССО: отношение полюс/экватор по проходо-минутам ≥ 5× (число в
      отчёт, сверка руками по одной ячейке);
- [ ] сумма по карте сходится с агрегатной ёмкостью построения (баланс);
- [ ] min ≠ max на любой реальной группировке; легенда с числами;
- [ ] какая из трёх гипотез подтвердилась — в отчёте явно; если №1 —
      это находка ранга «perfCheck»: расчёт был витриной.

## 6. Визуализация: плоская карта с зумом — Leaflet

Cesium отменён решением владельца — слишком сложно; нужна плоская карта с
масштабированием.

1. **Библиотека: Leaflet 1.9 + react-leaflet 5** (проверено по npm) —
   лёгкая, BSD, канвас-слои; в наш npm-контур ставится штатно. Запасной
   вариант при упоре в производительность — MapLibre GL; не начинать с
   него.
2. **Подложка — офлайн**: контуры стран GeoJSON (Natural Earth) серым,
   без тайл-сервера и интернета — стенду ничего внешнего не нужно, данные
   на карте главнее подложки. Тайлы не подключать.
3. **Зум/пан свободные; стартовый вид — Россия в кадре, север вверху**
   (центр ~[62°, 95°], зум по стране; поворота карты нет как класса);
   кнопка «домой» возвращает стартовый вид. Слои независимыми
   переключателями: **спрос** (сетка по классам A′/B′/C′ — та самая
   карта спроса, тем же вьюером); ёмкость (ячейки канвас-слоем, цвет по
   шкале с числовой легендой); **запас** (обслуживаемо/спрос — метрика 6
   тем же слоем-семейством); географические маски зон; наземные станции
   точками; **наземные трассы подгрупп** — каждая своим цветом
   (визуальная сверка «4×52° + 3 ССО» глазами).
3а. **Вьюер один на систему.** Карта спроса, карта ёмкости, маски —
   одна подоснова, один компонент `MapView`; отдельных карт со своими
   подосновами не заводить. Спрос и обслуживание на одной подоснове —
   это и есть сравнение глазами.
4. Ячейка: тултип с числом (§5), клик — закрепить подпись.
5. Границы захода: без глобуса, без анимации времени, без лучей.
   Производительность: полная сетка ~100 км — плавный зум без тормозов
   (канвас, не тысячи DOM-элементов).

**Мера §6:** владелец приближает полярную ячейку ССО-подгруппы и читает
число; выключает слой ёмкости и видит трассы двух подгрупп разными
цветами; карта живёт без доступа в интернет.

## 7. Дефект владельца: Walker разносится не на полный круг — единицы углов

Симптом (виден трассами): плоскости не растянуты на 360° — почти
наверняка смешение градусов и радиан (разнос 2π/P, прочитанный как
градусы, кладёт P плоскостей в сектор ~6°; обратное смешение даёт
хаотичную намотку).

1. **Найти и починить место** — RAAN-раскладка Walker (delta: полный
   круг 360°/P; star: полукруг 180°/P — проверить оба), фазирование F,
   аргумент широты.
2. **Закрыть класс, не случай** — правило как с единицами показателей:
   **внутри расчётов только радианы; градусы — только на границах
   ввода и отображения**, конверсия в одном месте. Типизировать
   (`AngleRad`/`AngleDeg` или именование `*_rad`) — смешение перестаёт
   компилироваться/проходить ревью.
3. **Инварианты в тест**: разброс RAAN delta-подгруппы ≈ 2π·(P−1)/P;
   соседние плоскости равноотстоят; ССО-наклонение для h=550 км ≈ 97,6°
   (сверка со справочным — уже в §4); трассы P плоскостей пересекают
   экватор в P равноотстоящих долготных узлах (геометрическая мера,
   видимая и глазами на карте §6).
4. **Перепрогнать меры §5 после фикса**: слипшиеся плоскости искажали
   и карту ёмкости — диагнозы связаны; отчёт должен назвать, изменилась
   ли карта.
