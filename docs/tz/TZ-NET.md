# 60. Адаптер сетевого протокола

Статус: Draft. Источник: Концепция v0.3, разд. 5.5.
Схемы: `contracts/protocol-adapter`.
Первая реализация — LoRaWAN; вероятный целевой вариант спутникового канала — LR-FHSS.

---

### TZ-NET-001. Интерфейс адаптера

```
REQ:        Протокол подключается к ИС через адаптер, реализующий интерфейс:
            параметры физического уровня (режимы, скорости, требуемое Eb/N0,
            время эфира), параметры MAC (доступ, оверхед, поддержка ACK
            и нисходящего канала), модель коллизий и ёмкости.
            Модули баллистики, КА и потоков обращаются только к интерфейсу.
RATIONALE:  Заменяемость протокола — требование первой версии; при лёгкой
            модульности заменяемость обеспечивается контрактом, не плагинами.
TRACE-UP:   КОНЦ-5.5; TZ-COM-007
TRACE-DOWN: TZ-KA-007; TZ-NET-006
VERIFY:     INSPECTION + TEST
ACCEPTANCE:
  - [ ] ни один модуль не содержит констант, специфичных для LoRaWAN
  - [ ] требуемое Eb/N0 и оверхед поступают только из адаптера
  - [ ] адаптер валиден по схеме protocol-adapter
STATUS:     Draft
OWNER:      ведущий системный инженер
```

### TZ-NET-002. Реализация LoRaWAN / LR-FHSS

```
REQ:        Первая реализация адаптера описывает LoRa-подобный физический
            уровень (набор режимов SF со скоростями и порогами) и LR-FHSS
            как вариант спутникового канала, а также MAC с поддержкой
            подтверждений и нисходящего канала.
RATIONALE:  Нисходящий канал обязателен: без него невозможны маяк эфемерид
            (Р5) и подтверждения класса B' (Р6).
TRACE-UP:   ADR-005; ADR-006
TRACE-DOWN: TZ-NET-003
VERIFY:     TEST
ACCEPTANCE:
  - [ ] адаптер с downlink_supported=false отклоняется как несовместимый с Р5/Р6
  - [ ] набор режимов покрывает применяемые в сценариях скорости
  - [ ] время эфира вычисляется по размеру пакета с учётом оверхеда
STATUS:     Draft
OWNER:      ведущий системный инженер
```

### TZ-NET-003. Модель коллизий и ёмкости

```
REQ:        Адаптер предоставляет быструю аналитическую модель коллизий
            (в т.ч. эффект захвата и квазиортогональность режимов) и оценку
            ёмкости линии в сообщениях в секунду при заданном числе
            одновременных демодуляций.
RATIONALE:  Дискретно-событийная симуляция несовместима с бюджетом времени
            Монте-Карло (TZ-COM-004).
TRACE-UP:   КОНЦ-5.5; TZ-COM-004; TZ-NET-002
TRACE-DOWN: TZ-FLW-001; TZ-FLW-004
VERIFY:     TEST
ACCEPTANCE:
  - [ ] расчёт вероятности коллизии не использует пошаговую симуляцию событий
  - [ ] ёмкость линии передаётся в модуль потоков как параметр, а не пересчитывается там
  - [ ] эффект захвата включается и отключается настройкой
STATUS:     Draft
OWNER:      ведущий системный инженер
```

### TZ-NET-004. Калибровка по референсным симуляторам

```
REQ:        Модель коллизий калибруется по эталонным наборам, полученным
            из открытых симуляторов (ns-3 lorawan, FLoRa, ELoRa) или
            измерений. Код указанных симуляторов не заимствуется.
            Расхождение сверх заданного порога останавливает сборку.
RATIONALE:  Референсные симуляторы распространяются под GPL и работают
            слишком медленно для Монте-Карло: они пригодны как источник
            эталонных чисел, но не как встраиваемый компонент.
TRACE-UP:   КОНЦ-5.10; CLAUDE.md §2
TRACE-DOWN: —
MOP:        расхождение с эталоном ≤ заданного max_deviation_pct
VERIFY:     TEST
ACCEPTANCE:
  - [ ] эталонные наборы лежат в tests/reference/ с указанием источника
  - [ ] сверка выполняется в CI
  - [ ] в зависимостях проекта отсутствует GPL-код симуляторов
STATUS:     Draft
OWNER:      ведущий системный инженер
```

### TZ-NET-005. Регуляторные ограничения канала

```
REQ:        Адаптер учитывает ограничения регуляторного региона:
            предел мощности, ограничение занятости канала (duty cycle),
            частотный план. Ограничения применяются к терминалам
            и к нисходящим передачам КА.
RATIONALE:  Duty cycle прямо ограничивает интенсивность передач и период
            маяка эфемерид.
TRACE-UP:   Потребители-2.0; TZ-KA-006
TRACE-DOWN: TZ-FLW-004
VERIFY:     TEST
ACCEPTANCE:
  - [ ] превышение duty cycle популяцией выявляется при сборке сценария
  - [ ] период маяка проверяется на соответствие ограничениям нисходящего канала
  - [ ] регион терминала считается неизменным на протяжении трека (Р7)
STATUS:     Draft
OWNER:      ведущий системный инженер
```

### TZ-NET-006. Замена адаптера

```
REQ:        Замена протокола выполняется подключением другой реализации
            адаптера и пересборкой. Горячее переключение и загрузка
            реализаций во время работы не предусматриваются.
RATIONALE:  Принятое решение о лёгкой модульности (Концепция, разд. 7 п. 1).
TRACE-UP:   КОНЦ-7 п.1; TZ-NET-001
TRACE-DOWN: —
VERIFY:     DEMONSTRATION
ACCEPTANCE:
  - [ ] замена адаптера не требует изменений в модулях баллистики, КА и потоков
  - [ ] сценарий фиксирует использованный адаптер и его версию
  - [ ] отсутствуют механизмы динамической загрузки реализаций
STATUS:     Draft
OWNER:      ведущий системный инженер
```
