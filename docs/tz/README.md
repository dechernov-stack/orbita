# ТЗ на ИС поддержки разработки космической системы

Формат: requirements-as-code. Один источник, два представления —
инженер читает требование с трассировкой и методом верификации,
Claude Code читает его как задачу с исполняемым критерием готовности.

## Состав

Имя файла = префикс идентификаторов внутри него. Требование `TZ-KA-005` — в `TZ-KA.md`.
Порядок чтения — сверху вниз.

## Формат блока требования

```
### TZ-<МОДУЛЬ>-NNN. Краткое название

REQ:        Что система должна делать (одно требование — одна мысль)
RATIONALE:  Зачем; на чём основано
TRACE-UP:   Источники: раздел концепции / модельного документа / ADR
TRACE-DOWN: Требования, которые из него следуют
MOP:        Измеримый показатель (если применимо)
VERIFY:     TEST / ANALYSIS / INSPECTION / DEMONSTRATION
ACCEPTANCE: Чек-лист исполняемых критериев готовности
STATUS:     Draft / Preliminary / Approved / Baseline / Cancelled
OWNER:      Владелец требования
```

`REQ / RATIONALE / TRACE / VERIFY / STATUS` — атрибуты по Прил. 2 регламента БП-PA
(спецификация для инженера и обзорной комиссии).
`ACCEPTANCE` — исполняемый чек-лист: сначала тесты по пунктам, потом код.

## Правила трассировки

`TRACE-UP` — единственный источник истины. `TRACE-DOWN` генерируется скриптом
`tools/regen_trace.py` как строгий обратный индекс; править его вручную не нужно.
Валидатор `tools/validate_trace.py` проверяет разрешимость ссылок и симметрию графа
и запускается в CI.

## Правила

- Идентификаторы стабильны, не перенумеровываются. Отменённое требование получает `STATUS: Cancelled` и остаётся в файле.
- Ограничения проекта (решения Р1–Р9) — в `CLAUDE.md` и `docs/adr/`.
- Контракты между модулями — JSON-схемы в `schemas/`.
- Эталонные наборы — `spec/reference/`; фикстуры — `spec/fixtures/`.

## Проверки в CI

| Скрипт | Что проверяет |
| --- | --- |
| `tools/validate_schemas.py` | схемы валидны по JSON Schema 2020-12, `$ref` разрешаются |
| `tools/validate_trace.py` | ссылки трассировки разрешаются; граф симметричен |
| `tools/regen_trace.py` | регенерация `TRACE-DOWN` из `TRACE-UP` |

Итого: **75 требований, 245 исполняемых критериев приёмки, 17 схем, 9 ADR.**

## Миграция в StrictDoc

При необходимости матриц трассировки и ReqIF-экспорта блоки конвертируются
скриптом в SDoc-формат StrictDoc (Apache 2.0, реестр переиспользования Концепции 5.10).
Структура блока подобрана так, чтобы конвертация была механической.
