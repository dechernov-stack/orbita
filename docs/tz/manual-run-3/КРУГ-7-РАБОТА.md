# Круг 7 «Работы»: 1.1/1.2/1.3 строками, вехи — в конце своих интервалов

## 1. Шаги — полноправные строки, развёрнуто по умолчанию

Требование владельца (повторное — исполнить дословно):

1. Полотно показывает **иерархию строк**: `1 · Развёртывание фазы и
   SEMP` → `1.1 · Орг-структура и план работ` · `1.2 · SEMP по
   шаблону` · `1.3 · Базировать SEMP до SRR`. Нумерация сквозная
   `‹задача›.‹шаг›`, видна в имени строки.
2. **Развёрнуто по умолчанию**, свернуть — шевроном (состояние
   запоминается на сессию). Из попапа больше ничего раскрывать не надо.
3. Строка задачи — **сводная полоса** (от старта первого шага до конца
   последнего, класс «сводная», без drag) — как в любом Ганте; drag
   плана — на шагах и на задачах без шагов.
4. Связи шагов (`SS`/`FS` из полки) рисуются между строками 1.1–1.3 —
   параллельность видна глазами, а не в попапе.
5. Клик строки шага — рамка ведения на нём.

## 2. Вехи — в конце интервалов, которые они закрывают

Дефект: ромб SRR стоит в начале полотна — потому что дата вехи задана
наугад раньше окончания задач, которые к ней зреют.

1. **Веха — конец своего интервала по построению**: задачи, зреющие к
   точке (`зреет к: SRR`), не могут иметь план или расчётное окно,
   заканчивающееся позже даты точки — расхождение = **конфликт**
   («задача 3 заканчивается после SRR»), подсветка обеих, решение —
   человек (сдвинуть план или дату точки).
2. **Порядок полотна — от точек**: интервалы фазы строятся как
   `начало фазы → SRR → SDR/MDR → KDP-B`; расчётные окна задач без
   плана размечаются **внутри своего интервала** (доли ярусов — как
   сейчас), а не от «сегодня». Ромб оказывается в конце интервала
   всегда — по построению, а не по удаче с датой.
3. Если дата точки в прошлом или раньше начала своего интервала —
   «конфликт вех» уже реализован; добавить подсказку «перенести точку»
   ссылкой в жизненный цикл.
4. Первая дата полотна = начало фазы (KDP предыдущей или дата старта
   проекта), не «сегодня»; «сегодня» — линия внутри.

## Приёмка

- [ ] полотно Phase A: 11 задач + 30 шагов строками `N.M`, развёрнуто;
      сводные полосы задач не тянутся, шаги тянутся;
- [ ] 1.1 и 1.2 стоят в одном ярусе (SS), 1.3 — после обоих (FS) —
      видно стрелками;
- [ ] SRR — в конце первого интервала, SDR — второго, KDP-B —
      последнего; задача, чьё окно уходит за свою точку, подсвечена
      конфликтом;
- [ ] полотно начинается началом фазы, «сегодня» — вертикалью внутри;
- [ ] свёртка задачи прячет её шаги; состояние держится в сессии.

## Ловушки

1. Не «раскрытие из попапа» — строки на полотне по умолчанию.
2. Сводную полосу не тянуть (двигаются шаги). 3. Планы шагам —
по-прежнему нет: drag шага задаёт план шага только если у задачи нет
собственного (иначе — правка задачи); проще: **план у шага разрешён,
у сводной задачи вычисляется из шагов** — принять этот вариант.
