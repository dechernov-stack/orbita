# Шаблон SEMP v2 — на полку шаблонов (DT-9002, редакция 2)

Структура: Прил. 1 БП-PA, дополненная по NASA SEH Appendix J. У каждого
раздела три атрибута: **источник данных** (вставка из модели) · **режим
текста** (как рождается печатаемое) · подсказка инженеру.

Режимы текста:
- **[Т]** таблица данных — печатается как таблица, связный текст не нужен;
- **[С]** связный текст — черновик пишет служба из данных вставки
  (вид `section_prose`), инженер правит и принимает; в печать идёт текст;
- **[Р]** рука — свободный текст инженера с заготовкой.

| № | Раздел | Источник данных | Режим |
|---|---|---|---|
| 1 | Назначение и область применения | паспорт (проект, фаза, FA) | [С] короткий |
| 2 | Применимые документы | полка применённых нормативов: обозначение · редакция · как применён | [Т] |
| 3 | Техническое резюме | замысел (4 поля) · класс · цели с горизонтами | [С] — главный связный раздел |
| 4 | Границы технического усилия | заготовка из замысла («не ШПД, не реестр…») | [Р] — что внутри/вне контроля команды |
| 5 | Организация и подрядчики | роли и права (В3); стейкхолдеры-поставщики ↔ узлы состава | [С] абзац + [Т] таблица ролей |
| 6 | Технические процессы (17, NPR 7123.1) | таблица процесс → механизм «Орбиты» → место; для процессов реализации — пометка tailoring «вне области Формулирования, к Phase C/D» | [Т] + [С] вводный абзац |
| 7 | Технические обзоры | лента вех + группы готовности точек | [С] абзац + [Т] вехи (имя · дата · статус словами) |
| 8 | Технические показатели (TPM) | свёртки бюджетов: запас массы, запас мощности; тренды закрытия замечаний точек | [Т] — числа из модели, минимум по SE-62/63/64 |
| 9 | Отклонения (tailoring) | записи неприменимости со следом (кто · когда · обоснование) + пометки §6 | [Т] + [С] абзац |
| 10 | Инструменты и среда | описание среды (правленое: свои расчёты; без обещаний) | [С] короткий |
| 11 | Согласование и актуализация | фиксации переходов документа | [Т] автоматически |

Соответствие-матрица канона (App. J §9) отдельно не ведётся — её роль
играют §6 + §9; сказано в подсказке §9.

## Механика связного текста (решение владельца)

1. На разделе с режимом [С] — действие **«Написать связно»**: промпт
   собирается из данных вставок раздела (и только их), вид пакета
   `section_prose`. Внешний контур годится; живой вызов не обязателен.
2. **Правила вида** (в реестр): не привносить фактов сверх данных;
   каждое число — из данных, с единицей показа; расхождение текста с
   данными — брак; тон — инженерная проза без канцелярита; служебных
   ключей и латиницы полей в тексте не существует.
3. Черновик **не пишется в документ сам** — правка инженера, затем
   принятие (общий контур доверия).
4. Данные изменились → на разделе «текст устарел» (существующая
   механика) + диф: какие поля данных разошлись с текстом.
5. **Печать берёт только принятый текст и [Т]-таблицы.** Сырых пар
   «key: value» в PDF не существует как класса — сторож печати: ни
   одного служебного ключа латиницей.
6. Режим раздела — свойство шаблона (данными), не кода: другой документ
   (ConOps, Project Plan) расставит свои [Т]/[С]/[Р] в своём шаблоне —
   механика одна.
7. История: текст версионируется как всё; происхождение черновика —
   «служба, из данных вставки v…».
8. **Выпуск ложится в Библиотеку → «Результаты»** (правка владельца):
   карточка выпуска — документ · версия · снимок печати (pdf/docx) ·
   **авторство**: авторы текста из истории правок разделов +
   выпустивший + дата; служба — происхождением черновиков, автором не
   бывает никогда (закон ServiceAuthors). Результаты — третий отдел
   библиотеки рядом с Материалами и Полками: вход → работа → результат,
   и результат прошлого проекта — кандидат на «обобщить в образец».

## Мини-задача Code

1. DT-9002 ред. 2 сидом (таблица выше); режимы разделов — поле шаблона.
2. Вид пакета `section_prose` с правилами п. 2 — в реестр видов.
3. Действие «Написать связно» на разделе → промпт из данных вставок;
   приём черновика правкой; «текст устарел» + диф полей.
4. Печать: принятый текст + [Т]-таблицы человеческим форматом (вехи
   словами, узлы именами); сторож «латинский служебный ключ в печати» —
   валит выпуск.
5. Полка описания среды — выправить (Orekit — резерв, не факт).
6. Раздел «Результаты» в Библиотеке: карточки выпусков с авторством по
   п. 8; существующие выпуски (ConOps и др.) — туда же миграцией.

Мера: SEMP проекта ПМИ-3 — §3 связным текстом из замысла (принят
правкой), §2 — таблица НПА с редакциями, §8 — запасы массы и мощности
числами из свёрток, печать без единого служебного ключа; правка даты
SRR подсвечивает §7 «текст устарел» с дифом; выпуск виден в
Библиотеке → Результаты с авторами текста и выпустившим.
