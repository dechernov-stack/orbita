# Сверка SEMP с каноном (NASA SEH, Appendix J) — правки шаблона DT-9002

## Итог сверки

Наши 8 разделов ≈ J.1/J.3/J.4.1/J.5/J.3.4/(tailoring)/J.4.3/подписи —
скелет канона держим. Четыре содержательных пробела, все закрываются
вставками из существующих данных. Плюс два дефекта печати.

## Правки шаблона (в пачку Code)

1. **Новый раздел «Применимые документы»** (J.2): вставка из полки
   применённых нормативов и стандартов проекта — обозначение, редакция,
   чем применён (автоприменение класса / рука). Данные уже есть; писать
   руками нечего.
2. **§4 довести до 17 процессов NPR 7123.1** (J.5): сейчас 8 строк.
   Добавить: ожидания стейкхолдеров (механизм: матрица покрытия нужд),
   определение техтребований, логическая декомпозиция (дерево состава),
   проектное решение (варианты + сравнение), анализ решений (Парето и
   протоколы trade studies), оценка хода (готовность + лента «Работы»),
   планирование (сама «Работа фазы»). Процессы реализации (изготовление,
   интеграция, переход) — строками с честной пометкой tailoring:
   «вне области Формулирования, механизм — к Phase C/D» — это и есть
   требуемый канон: отклонение названо, не умолчано.
3. **Подраздел «Технические показатели (TPM)»** (J.7.4): канон требует
   минимум — запасы массы, запасы мощности, тренды закрытия замечаний
   обзоров. Вставка из свёрток бюджетов (масса/энергия с резервами) и
   RFA-механики точек. Числа уже считаются — им осталось попасть в SEMP.
4. **Подсказки двух рубрик в существующие разделы**: границы
   технического усилия (что внутри/вне контроля команды — §2, рука
   инженера; заготовка «не ШПД, не новый реестр» из замысла уже есть) и
   интеграция подрядчиков (§3: стейкхолдеры-поставщики со связями на
   узлы — источник готов).

Соответствие-матрицу (J.9, compliance) не заводим отдельно: её роль
играют таблица §4 + tailoring-записи §6 — решение зафиксировать в
подсказке раздела.

## Дефекты печати (замечание Code, чинится до правок шаблона)

1. **Вставки рендерятся сырыми парами** «kind: mission_intent;
   for_whom: …», «gate: SRR; due: …; held: false», «CM-0048 — name: …» —
   служебные ключи на латинице в продуктовом документе. Вставка обязана
   печататься человеческим текстом: поля по-русски, вехи «SRR —
   02.09.2026, не проведён», узлы именами без id-префиксов (id — в
   подсказке экрана, не в печати).
2. **Самоописание врёт про инструменты**: «баллистика на Orekit» — на
   стенде свои расчёты покрытия/ёмкости, Orekit в резерве. Полку
   описания среды поправить: самоописание системы не имеет права на
   рекламу будущего.

Мера: печать SEMP проекта ПМИ-3 — ни одного служебного ключа латиницей;
§ «Применимые документы» перечисляет применённые НПА с редакциями; §4 —
17 строк, из них реализация помечена tailoring; TPM — числа из свёрток.
