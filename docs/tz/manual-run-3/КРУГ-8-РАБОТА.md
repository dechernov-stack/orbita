## 2. Таблица слева — имена, ответственный, длительность

Имена на полотне не лепим: слева — **фиксированная таблица строк**,
справа — полотно библиотеки.

| Колонка | Содержание |
|---|---|
| № · Задача / шаг | `1`, `1.1` с отступом; шеврон свёртки |
| Ответственный | учётка (аватар + фамилия), у шага — своя либо наследуется |
| Длительность | **вычисляется из плана** (конец − старт, рабочих дней); без плана — серым из расчётного окна с пометой «план не задан» |
| Статус | текстом (не только цветом — NFR цвета) |

Реализация: таблица-сосед, выровненная по `bar_height`/`padding`/
`header_height` библиотеки — это не графика поверх канвы, сторож
`validate_gantt_library.py` не нарушается. Прокрутка вертикальная —
общая, горизонтальная — только у полотна.

Ввод длительности числом допустим как **эквивалент правки плана**
(конец = старт + N) — это не оценка-статус, а тот же план другими
руками. Запрет прежний: планы не влияют на вычисленные статусы.

## 3. Ответственный — поле задачи фазы в проекте

- назначает руководитель проекта (право); шаг наследует ответственного
  задачи, может иметь своего;
- «Моя работа» фильтрует по ответственному **и** по заданиям;
- ответственный задачи — адресат разрывов этой задачи по умолчанию
  (кнопка «назначить…» подставляет его).

## 4. Прогресс — вычисляемый, движется сам

Прежний запрет снимается **только для вычисленного** прогресса:

- задача со шагами: `progress` = доля закрытых шагов (1 из 3 → 33%);
- задача без шагов: 0 / 100 по вычисленному статусу;
- рисует библиотека штатной заливкой внутри полосы;
- **перетаскивание прогресса руками отключить** (`readonly_progress`
  или перехват, проверить в API 1.2.2) — ручного процента не
  существует по-прежнему;
- в попапе — расшифровка «шаг 2 из 3 закрыт», чтобы процент не был
  голым числом.
