# ПМИ-4. Приёмка с нуля: действие → результат → хранимый артефакт

**Токены.** Живых вызовов — **ноль**. Все ИИ-шаги — вставкой пакетов из
`docs/tz/manual-run-4/пакеты/` (реестр пакетов — раздел Р в конце).
Внешний контур — этот чат: промпт присылается, пакет возвращается.

**Артефакты.** У каждого шага назван артефакт, который сохраняется в
`docs/tz/manual-run-4/артефакты/` под именем шага (`Б2.png`,
`И5-conops.pdf`, `Д1-пакет.json`) и присылается на просмотр. Типы:
**снимок** · **файл** (pdf/docx/json/html) · **пакет** (вставленный JSON
с отметкой принято/отклонено) · **журнал** (строка прогона).

**Предусловия (Code).** Шипы 0–3 задачи «Три пакета» выкачены; тег
`пми4-старт`; резервная копия; журнал `прогон-пми4.md`; пакеты Р01–Р09
по разделу Р (Code готовит сам — промпт там же).

**Пользователи — включены, без паролей.** Режим стенда
`auth_mode=stand`: три учётки заведены, переключение — селектором в
шапке (имя · роль), пароль не спрашивается. Это режим только для
приёмочного стенда — флагом, не правкой прода. Учётки:

| Учётка | Роль | Зачем в прогоне |
|---|---|---|
| Чернов Д. | руководитель проекта · DA | планы Ганта, назначения, фиксация точек |
| Иванов И. | ведущий СИ | базирование, ведение справочников, обобщение на полку |
| Петрова М. | инженер | задания, отказы по праву, «Моя работа» |

Каждый шаг ПМИ исполняется под названной учёткой (по умолчанию — РП);
где роль важна — она названа в действии.

### Промпт подготовки пакетов (Code исполняет как внешний контур)

Ты готовишь пакеты предложений для прохода ПМИ-4 — как внешний контур
службы «Орбиты». Правила, нарушение любого — брак пакета:

1. **Строго по виду**: схема и правила промпта из реестра видов
   (`prompt-package-kinds.json`) — те же, что для живого вызова: правила
   1–12 разбора, П13–П20 для требований. Поля вне схемы не добавляй.
2. **Источник — стенд, не память**: канон записки с его якорями (Д1),
   принятые объекты проекта ПМИ-4 в момент подготовки, полки. Для
   Р05 якоря — из канона стенда, поабзацные; секционные допустимы
   только там, где абзацный якорь не выделяется.
3. **Не выдумывать**: каждая сущность несёт якорь-основание; числа —
   парой `{value, unit}` по справочнику, деньги — плюс `canonical` в
   млн ₽; реквизиты НПА — только из текста, иначе `need_ref: true`;
   метки [И]/[В]/[П] — в `source_mark`.
4. **Порченое — нарочно и помечено**: Р04 несёт ровно две строки-ловушки
   (число без источника; «при необходимости») с комментарием в реестре,
   чтобы приёмка знала, что отсев ожидаем.
5. **Проверка до сдачи**: каждый пакет вставлен на одноразовом стенде
   из копии прода — схема проходит, счётчики `summary` совпадают,
   отказов по форме нет (отсев по содержанию допустим и записан).
   Итог проверки — строкой в реестре пакетов.
