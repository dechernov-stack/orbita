# Сид: правила требований (урожай NASA SEH App. C) — три адреса

## А. Дополнение правил вида `requirements_generation` (в реестр видов)

П13. Формулировка — активным залогом от носителя: «‹Изделие/сторона›
должен ‹глагол› …». Пассив («должно быть обеспечено») — брак.
П14. Одна мысль — одно требование: одно подлежащее, одно сказуемое;
союз «и» между глаголами — признак двух требований, раздели.
П15. Обоснование — полем rationale, в формулировке его нет.
П16. Запрещённые слова формулировки: «по возможности», «при
необходимости», «и т. д.», «и/или», «в том числе, но не только»,
«соответствующий», «адекватный», «этот/эти» без явного референта.
П17. Утвердительная форма: «должен», не «не должен», где выразимо
позитивно.
П18. Модальность строго: «должен» = требование; «будет» = факт
контекста (не требование); «желательно/следует» = цель — целям не
место среди требований, выноси отдельным классом.
П19. Вместо пустого TBD — лучшая оценка с пометой TBR и обоснованием.
П20. Каждое требование верифицируемо: заявлен предполагаемый метод
(испытание/анализ/демонстрация/инспекция) — хотя бы TBD-методом.

## Б. Линт-пометки реестра (мягкие, не блокирующие; id → условие → текст)

- L-C1 · два сказуемых или «и» между глаголами → «возможно, два
  требования в одном — рассмотрите разделение»;
- L-C2 · слово из списка П16 → «неопределённое слово ‹…› — уточните»;
- L-C3 · формулировка начинается не с носителя → «пассив или безлично —
  перепишите от изделия/стороны»;
- L-C4 · «не должен» → «негативная форма — выразима ли позитивно?»;
- L-C5 · TBD-значение без владельца или срока → «канон TBR: что
  сделать · кто · к какому сроку» (поле срока — добавить к помете);
- L-C6 · «желательно/следует» в формулировке → «цель, не требование».

Список слов П16/L-C2 — данными (правится с экрана справочников).

## В. Чек внутреннего обзора (полка чек-листов; задача 11 / О13)

1. Необходимость: «что худшее случится, если требование убрать?» —
   у каждого требования есть ответ (rationale).
2. Трассировка двунаправленная: вверх к нужде/цели/ConOps, вниз к
   носителю — матрицей, дыр нет.
3. Полнота: TBD/TBR перечислены единым списком с владельцами и сроками.
4. Осуществимость: у рискованных — анализ или прецедент в rationale.
5. Проверяемость: метод верификации назначен каждому.
6. Однозначность: выборочное чтение вслух двумя инженерами — одно
   понимание (практика инспекции).
