# Шаг 1. Модель данных, хранилище, валидация схем

Рабочее задание для Claude Code. Основание: архитектура разд. 9 п. 1.
Область: `TZ-MOD-001…007`, `TZ-COM-001, 003, 005, 006, 007`.
Вне области: расчётные модули, ИИ-контур, клиент — не начинать.

## Что уже готово (не переписывать)

| Артефакт | Роль |
| --- | --- |
| `schemas/**` (17 схем) | Нормативная структура данных. Изменение структуры = изменение схемы |
| `db/migrations/V001__init.sql` | DDL PostgreSQL: объекты, связи, параметры, зависимости, результаты, триггер Baseline |
| `db/queries.sql` | Ключевые запросы: обходы трассировки, разрывы, срез на дату, каскад stale, циклы |

`spec/storage_semantics.py` — не пример, а спецификация поведения. Kotlin-тесты должны воспроизводить те же случаи один в один; расхождение трактуется как дефект реализации, а не эталона.

## Порядок работы

### 1.1. Каркас проекта
Kotlin/JVM (ADR-010), Gradle. Слои: `api` (HTTP + валидация), `model` (типы из схем), `store` (PostgreSQL), `schema` (загрузка и валидация JSON Schema 2020-12).
Никаких расчётных зависимостей на этом шаге; Orekit не подключать.

### 1.2. Типы модели из схем
Сгенерировать или написать типы, соответствующие `schemas/core/*` и `schemas/common/*`.
Обязательно: `Quantity` — значение + единица + `Provenance`; конструктор без единицы или происхождения недоступен (TZ-MOD-004).
Углы хранить в радианах (CLAUDE.md §3).

### 1.3. Валидация на границе
Загрузка всех схем при старте с разрешением `$ref`. Каждый вход API валидируется по схеме целевого типа.
Ошибка содержит путь до поля и нарушенное правило (TZ-MOD-002); при нарушении Р1–Р9 — идентификатор ADR (TZ-MOD-003).

### 1.4. Хранилище
Применить `db/migrations/V001__init.sql` миграцией. Реализовать операции: создание объекта, чтение текущей версии, чтение среза на дату, процедура изменения Baseline-объекта (закрытие интервала + новая версия + основание), связи, параметры с зависимостями, результаты со stale.

### 1.5. Обходы трассировки
Реализовать запросы 1–4 из `db/queries.sql`. Направление связи хранить один раз; обратный обход вычислять (ADR-011).

### 1.6. Тесты
Перенести все 19 случаев из `spec/storage_semantics.py` в тесты на PostgreSQL (Testcontainers либо локальная БД).
Добавить негативные наборы из `spec/fixtures/example-violations.json`.
Подключить в CI: `tools/validate_schemas.py`, `tools/validate_trace.py`, тесты хранилища.

## Известные ловушки

1. **Обратные связи не дублировать.** Соблазн хранить оба направления «для скорости» — источник расхождений. На нашем ТЗ ручное дублирование дало 64 рассогласования; итог — обратный индекс генерируется.
2. **Единица — не строка в описании.** Тип `Quantity` должен делать невозможным создание величины без единицы, а не проверять её постфактум.
3. **Baseline не «флаг только для чтения».** Это интервал: старая версия закрывается, новая создаётся. Триггер в DDL страхует от обхода через прямой UPDATE.
4. **Направление цикла в зависимостях.** Проверка «добавление (A) зависит от (B)» ищет, достижим ли A из B, а не наоборот (эталон, разд. TZ-MOD-005).
5. **`stale` — не кэш.** Флаг ставится по графу зависимостей входов, а не по времени.
