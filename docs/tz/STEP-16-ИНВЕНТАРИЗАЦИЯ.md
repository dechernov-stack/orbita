# Шаг 16 §2.1. Инвентаризация неподключённого

Список получен `ci/wiring.py --init` (не руками) и лежит в `ci/unwired.txt`:
**28 маршрутов и 21 функция**. По каждому элементу — исход «подключить» или
«удалить», третьего задание не даёт. Ниже обоснование по каждому.

Проверено по коду, а не по названиям: для маршрута — есть ли потребитель хоть
где-нибудь в `web/src` (не только в `web/src/api/*.ts`), для функции — есть ли
вызывающий вне `src/test`. Совпадения по смыслу (два входа в одно и то же)
сверялись чтением обработчиков.

## 3. Что требует решения владельца

1. **Удаление четырёх функций затрагивает эталон.** `Exchange.kt` и `VizData.kt`
   покрыты `spec/presentation_semantics.py`: удаление `fromExchange`,
   `exchangeFromJson`, `kpiRose`, `kpiRoseJson` требует правки эталона — по
   правилу 4 `CLAUDE.md` отдельным коммитом, не вместе с кодом. Эталон правится
   вслед за решением, а не «чтобы прошло».
2. **Пять маршрутов удаляются вместе с их тестами**, если такие есть.
   Функциональность при этом не теряется: у каждого назван действующий вход.
3. **Номера ADR из §5 задания заняты**: ADR-025 — атмосферные потери,
   ADR-026 — полный масштаб TZ-COM-004. По правилу «номера стабильны и не
   перенумеровываются» новые решения получают **ADR-027** (связи из документа)
   и **ADR-028** (пустой стенд по умолчанию).
4. **Область обхода §1.1 расширена одним файлом**: `coverageByTarget` назван в
   задании поимённо, но лежит в `core/bal/Coverage.kt`, вне «`core/out` +
   `VizData.kt`». Без расширения строку было бы нечем вычеркнуть.

Итог: **40 подключить, 9 удалить**. Ни одной строки «оставить на будущее».
