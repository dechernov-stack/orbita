# 30. Баллистический модуль

Статус: Draft. Источник: Концепция v0.3, разд. 5.2.
Схемы: `contracts/visibility`, `contracts/service-zone`, `contracts/kpi-vector`, `core/scenario`.
Ядро расчётов — Orekit (Apache 2.0). Собственные пропагаторы не разрабатываются.

---

```
            пропагаторов, моделей тени и геометрии видимости не создаются.

  - [ ] версия Orekit и модель гравитационного поля фиксируются в сценарии
  - [ ] результаты воспроизводимы при том же наборе версий (TZ-COM-006)
```

### TZ-BAL-002. Предрасчёт событий видимости

```
VERIFY:     TEST

  - [ ] расписание событий валидно по схеме visibility
  - [ ] пролёт помечается in_service_zone на основании зоны обслуживания, а не только геометрии
```


### TZ-BAL-004. Энергетика витка: худший и лучший сезон

```
REQ:        Модуль рассчитывает энергию, собираемую за виток, и долю
            теневых участков для худшего и лучшего сезона (северное
            полушарие, опорные эпохи — солнцестояния). Допустимый duty cycle
            полезной нагрузки вычисляется как производная величина
            и не задаётся пользователем.
RATIONALE:  Энергетика витка — ключевой критерий (КОНЦ-5.2.Г); для ССО
            терминаторные орбиты дают почти бестеневой режим, что должно
            быть видно явно.
TRACE-UP:   КОНЦ-5.2-Г; TZ-BAL-001; TZ-MOD-004
TRACE-DOWN: TZ-BAL-006; TZ-KA-004; TZ-USR-005
MOP:        Вт·ч/виток (worst/best), доля витка в тени
VERIFY:     TEST + ANALYSIS
ACCEPTANCE:
  - [ ] результат содержит пару значений worst/best с указанием эпох
  - [ ] duty cycle ПН помечен как computed (не manual)
  - [ ] для ССО с LTAN у терминатора доля тени близка к нулю (проверка на эталоне)
  - [ ] глубина разряда АБ не превышает заданного предела либо расчёт помечает нарушение
STATUS:     Draft
OWNER:      проектант-баллистик
```

### TZ-BAL-005. Спрос-взвешенная оценка качества

```
REQ:        Качество варианта построения вычисляется как интеграл по ячейкам
            карты спроса с весами спроса, по зонам обслуживания линий
            (не по геометрическому footprint), раздельно по классам
            потребителей.
RATIONALE:  Р8/ADR-008 и ADR по зонам: покрытие незаселённых областей
            не должно давать паразитного преимущества; зона приёма A'
            шире зоны контура C'.
TRACE-UP:   ADR-008; TZ-FLW-008; TZ-KA-005; TZ-MOD-006; TZ-USR-004; TZ-USR-007
TRACE-DOWN: TZ-BAL-006; TZ-BAL-007
MOP:        доля спроса, обслуженного с требуемым качеством
VERIFY:     TEST
ACCEPTANCE:
  - [ ] ячейка с нулевым спросом не влияет на интегральный показатель
  - [ ] расчёт использует service-zone, а не min_elevation
  - [ ] результат разложен по классам A'/B'/C'
  - [ ] контрольный случай: ССО-построение при населённой карте спроса не доминирует наклонное построение только за счёт полярных областей
STATUS:     Draft
OWNER:      проектант-баллистик
```

### TZ-BAL-006. Вектор KPI и Парето-фронт

```
REQ:        Для каждого варианта формируется вектор KPI по схеме kpi-vector
            (качество, экономика, надёжность, энергетика, среда). ИС
            определяет недоминируемые варианты в пространстве
            «экономика × качество» и помечает доминируемые.
RATIONALE:  Ранжирование вариантов без назначения весов; веса — предмет
            отдельного решения (открытый вопрос концепции).
TRACE-UP:   КОНЦ-5.2; КОНЦ-8 п.1; TZ-BAL-003; TZ-BAL-004; TZ-BAL-005
TRACE-DOWN: TZ-BAL-007
VERIFY:     TEST
ACCEPTANCE:
  - [ ] вектор KPI валиден по схеме
  - [ ] Парето-фронт вычисляется автоматически, доминирующие варианты указаны
  - [ ] срок развёртывания до целевого качества входит в экономику отдельным показателем
  - [ ] кривая деградации при отказе N аппаратов заполнена
  - [ ] свёртка в единый индекс, если применяется, выполняется с явно заданными весами и не подменяет фронт
STATUS:     Draft
OWNER:      проектант-баллистик
```

### TZ-BAL-007. Визуализация

```
REQ:        Модуль обеспечивает: лепестковую диаграмму («роза») нормированных
            KPI с наложением до пяти вариантов; широтный профиль качества
            с наложенной кривой спроса; тепловые карты доступности сервисов
            (мгновенная, среднесуточная, за период); карты разрывов покрытия;
            3D/2D отображение движения аппаратов, трасс и наземных станций;
            временные диаграммы сеансов и энергобаланса витка.
RATIONALE:  Роза — главный экран сравнения; широтный профиль — диагностика
            эффекта ССО.
TRACE-UP:   КОНЦ-5.2 (визуализация); TZ-BAL-005; TZ-BAL-006
TRACE-DOWN: TZ-OUT-002
VERIFY:     DEMONSTRATION + TEST
ACCEPTANCE:
  - [ ] роза строится по нормированным KPI из kpi-vector без ручного ввода
  - [ ] широтный профиль показывает качество и вес спроса на одной оси абсцисс
  - [ ] тепловая карта поддерживает три горизонта усреднения
  - [ ] 3D-сцена строится из результатов Orekit (CZML/CesiumJS), без отдельной модели движения
STATUS:     Draft
OWNER:      проектант-баллистик
```

```
RATIONALE:  Собственные расчёты требуют внешнего подтверждения;

VERIFY:     TEST
ACCEPTANCE:

  - [ ] сверка выполняется в CI
  - [ ] превышение порога останавливает сборку с указанием метрики

OWNER:      проектант-баллистик
```
