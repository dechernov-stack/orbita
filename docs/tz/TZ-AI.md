# 80. ИИ-контур

Статус: Draft. Источник: Концепция v0.3, разд. 5.8.
Два канала: промпт-пакеты (человек в контуре, без затрат API на генерацию) и прямой API для структурных операций малого объёма.
Принцип: ИИ предлагает — инженер утверждает; ручное перебивание данных исключается.

---

### TZ-AI-001. Генерация промпт-пакета

```
REQ:        ИС формирует промпт-пакет: выгрузку контекста из модели, задание
            и жёсткую схему ответа с идентификатором пакета. Пакет
            копируется пользователем во внешний интерфейс LLM.
RATIONALE:  Канал 1: генерация вне API снижает стоимость; один пакет
            пригоден для нескольких LLM.
TRACE-UP:   КОНЦ-5.8
TRACE-DOWN: TZ-AI-002
VERIFY:     TEST
ACCEPTANCE:
  - [ ] пакет содержит идентификатор, контекст, задание и схему ответа
  - [ ] схема ответа соответствует целевому объекту модели
  - [ ] перечень типов пакетов расширяется без изменения кода
STATUS:     Draft
OWNER:      ведущий системный инженер
```

### TZ-AI-002. Разбор ответа по схеме

```
REQ:        Ответ LLM разбирается локально по схеме пакета. Несоответствие
            схеме сообщается пользователю с указанием поля; частично
            корректный ответ принимается в части валидных объектов.
RATIONALE:  Разбор без обращения к API; корректность гарантируется схемой,
            а не доверием к модели.
TRACE-UP:   TZ-AI-001; TZ-MOD-002; TZ-REQ-004
TRACE-DOWN: TZ-AI-004
VERIFY:     TEST
ACCEPTANCE:
  - [ ] разбор выполняется без обращения к внешним сервисам
  - [ ] ошибки схемы перечисляются с путём до поля
  - [ ] объекты, не прошедшие валидацию, не попадают в предложение
STATUS:     Draft
OWNER:      ведущий системный инженер
```

### TZ-AI-003. Арбитраж расхождений между LLM

```
REQ:        При загрузке ответов нескольких LLM на один пакет ИС сопоставляет
            их и выделяет расхождения. Разрешение расхождений выполняется
            одним вызовом API с передачей только спорных фрагментов.
RATIONALE:  Стоимость арбитража на порядок ниже стоимости генерации;
            сопоставление нескольких мнений повышает качество предложений.
TRACE-UP:   КОНЦ-5.8
TRACE-DOWN: TZ-AI-004
VERIFY:     TEST
ACCEPTANCE:
  - [ ] совпадающие фрагменты не передаются в API
  - [ ] расхождения предъявляются пользователю с вариантами
  - [ ] источник каждого варианта (какая LLM) сохраняется
STATUS:     Draft
OWNER:      ведущий системный инженер
```

### TZ-AI-004. Акцепт предложений и происхождение

```
REQ:        Предложение ИИ применяется к модели только после явного акцепта
            инженером. До акцепта предложение не участвует в расчётах
            и отчётах. Применённое значение сохраняет признак происхождения:
            идентификатор пакета, источник, факт редактирования, автор акцепта.
RATIONALE:  TZ-COM-005: прослеживаемость обоснований на обзорах; ИИ —
            ассистент, а не автор.
TRACE-UP:   TZ-AI-002; TZ-AI-003; TZ-AI-005; TZ-COM-005
TRACE-DOWN: TZ-OUT-002
VERIFY:     TEST
ACCEPTANCE:
  - [ ] неакцептованное предложение не влияет на результаты сценариев
  - [ ] отчёт «объекты с неакцептованными предложениями» доступен
  - [ ] отредактированное перед акцептом предложение помечается признаком edited
  - [ ] массовый акцепт без просмотра не предусматривается интерфейсом
STATUS:     Draft
OWNER:      ведущий системный инженер
```

### TZ-AI-005. Прямой API-канал

```
REQ:        Для структурных операций малого объёма (декомпозиция системы
            на компоненты, проверка согласованности бюджетов, предложение
            метода верификации) используется прямой вызов API по схеме
            «предложение — редакция — применение».
RATIONALE:  Канал 2: малый объём и строгая структура оправдывают стоимость
            вызова.
TRACE-UP:   КОНЦ-5.8
TRACE-DOWN: TZ-AI-004
VERIFY:     TEST
ACCEPTANCE:
  - [ ] результат вызова валидируется по схеме целевого объекта
  - [ ] отказ или ошибка API не нарушают состояние модели
  - [ ] перечень операций канала конфигурируем
STATUS:     Draft
OWNER:      ведущий системный инженер
```

### TZ-AI-006. Исключение ручного перебивания

```
REQ:        Применение предложения выполняется как diff к модели с
            возможностью правки отдельных полей. Ручной повторный ввод
            принятых значений не требуется ни на одном шаге.
RATIONALE:  Требование постановки: «предложение — редактирование —
            автоматическая загрузка в систему».
TRACE-UP:   КОНЦ-5.8
TRACE-DOWN: —
VERIFY:     DEMONSTRATION
ACCEPTANCE:
  - [ ] предложение отображается как построчный diff к текущему состоянию
  - [ ] правка выполняется в интерфейсе применения, без копирования значений
  - [ ] после акцепта данные попадают в модель без дополнительных действий
STATUS:     Draft
OWNER:      ведущий системный инженер
```
