# Шаг 14. Импорт внешних данных

Рабочее задание. Применять после шага 11 (§11.2 использует ту же службу обмена).
Основание: ADR-023, ADR-024.

## Эталоны

| Эталон | Проверок | Что фиксирует |
| --- | --- | --- |
| `spec/reqif_semantics.py` | 26 | Отображение модели в ReqIF: типы, составные поля, устойчивость идентификаторов, круговой обмен |
| `spec/import_semantics.py` | 29 | Правовой режим источника, происхождение, тот же фильтр, повторный импорт |

## 1. Служба обмена (§11.2 и шаг 14)

По ADR-023: библиотека `reqif` от strictdoc-project, отдельным контейнером
в compose-стеке, в обе стороны. Ядро обращается к службе, Python в JVM-образ
не попадает.

**Ключевое в отображении: составное поле не сворачивается в строку.** Условие
требования раскладывается на три атрибута с правильными типами — перечисление,
число, строка. Сериализованный JSON в одном строковом атрибуте формально валиден,
но принимающий инструмент не сможет ни отфильтровать по оператору, ни отсортировать
по значению: обмен состоится, смысл потеряется.

**Идентификаторы устойчивы:** одна сущность между выгрузками получает то же
значение. Иначе принимающий инструмент видит новый объект вместо изменённого
и теряет историю.

Проверка выхода против XSD OMG и круговой обмен — в CI.

## 2. Импорт как третий канал

### 2.1. Тот же фильтр
Импортированная запись проходит те же функции правил, что рукописная и
предложенная ИИ. Отдельная «облегчённая» проверка для импорта — дефект,
а не оптимизация.

### 2.2. Правовой режим до загрузчика
Перечень источников с условиями использования ведётся в конфигурации.
Источник без описанного режима — запрещён к импорту.

Для репозитория устройств LoRaWAN режим известен: sui generis право по Директиве
96/9/EC, отдельные записи — можно, каталог целиком — нельзя. **Массовой
синхронизации не делать.**

### 2.3. Происхождение
Блок `provenance.import`: источник, версия, дата, идентификатор записи, условия
использования, признак допустимости массовой выгрузки, версия отображения.
Обязателен при `source=imported`.

### 2.4. Повторный импорт
Обновление записи, не дубликат. **Ручная правка поверх импортированного
не затирается.**

## 3. Первые каналы

| Канал | Источник | Что даёт |
| --- | --- | --- |
| Требования | ReqIF от заказчика или партнёра | наполнение реестра без ручного ввода |
| Профили терминалов | каталог устройств LoRaWAN, по одной записи | реальные радиопараметры вместо оценок |

Остальные источники (орбитальные данные CCSDS OMM, диаграммы направленности,
датащиты компонентов) — по мере надобности, каждый со своим правовым режимом
и своим отображением.

## Готовность

- [ ] 26 проверок `reqif_semantics` и 29 проверок `import_semantics` в тестах
- [ ] служба обмена в compose; JVM-образ без Python
- [ ] выход проходит сверку против XSD OMG
- [ ] круговой обмен сохраняет атрибуты, связи и незнакомые поля
- [ ] идентификатор сущности между выгрузками не меняется
- [ ] составные поля разложены на атрибуты; сериализованных структур нет
- [ ] импорт проходит те же функции правил, что рукописный ввод (обход кода)
- [ ] источник без описанного правового режима отклоняется

- [ ] `provenance.import` обязателен и полон
- [ ] повторный импорт обновляет; ручная правка сохраняется
- [ ] CI зелёный

## Ловушки

1. **Сериализованная структура в строковом атрибуте.** Файл валиден, обмен
   бесполезен.
2. **Плавающие идентификаторы.** Обмен превращается в перезалив, история теряется.
3. **Массовая выгрузка «для удобства».** Правовое ограничение, отыграть дорого.
4. **Послабления для импорта.** «Данные от вендора» — не основание пропускать
   запись без единиц измерения.
5. **Подстановка наугад при непонятом значении.** Неизвестный регион, класс
   или единица — повод отбраковать запись, а не угадать.
6. **Затирание ручных правок при обновлении.** Инженер правил осознанно.
