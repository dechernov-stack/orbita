# 90. Отчёты и экспорт

Статус: Draft. Источник: Концепция v0.3, разд. 5.9, 6.
Документы регламентов формируются как представления модели.

---

### TZ-OUT-001. Генерация документов из модели

```
REQ:        ИС формирует документы по структурам приложений регламентов:
            спецификацию требований (Прил. 2 БП-PA), ConOps-заготовку
            (Прил. 3), описание архитектуры системы (Прил. 4), матрицы
            трассировки и верификации. Содержание берётся из модели;
            ручное дополнение текста документа после генерации не сохраняется.
RATIONALE:  TZ-COM-001: документ — представление модели, а не источник.
TRACE-UP:   БП-PA Прил. 2–4; TZ-COM-001
TRACE-DOWN: TZ-OUT-005
VERIFY:     TEST
ACCEPTANCE:
  - [ ] повторная генерация из неизменённой модели даёт идентичный документ
  - [ ] структура разделов соответствует приложениям регламента
  - [ ] генерация не изменяет модель
STATUS:     Draft
OWNER:      руководитель проекта
```

### TZ-OUT-002. Аналитические отчёты состояния

```

            объекты с неакцептованными предложениями ИИ; TPM с выходом
            за пределы резервов; узкие места по результатам моделирования;
            разрывы трассировки.
RATIONALE:  Управление состоянием пакета между обзорами.
TRACE-UP:   TZ-AI-004; TZ-BAL-007; TZ-FLW-007; TZ-KA-010; TZ-MOD-005
TRACE-DOWN: TZ-OUT-003
VERIFY:     TEST
ACCEPTANCE:
  - [ ] каждый отчёт формируется по текущему состоянию без ручной сборки
  - [ ] отчёт содержит ссылки на объекты для перехода
  - [ ] пустой отчёт отличается от неисполненного (явное указание)
STATUS:     Draft
OWNER:      руководитель проекта
```

### TZ-OUT-004. Матрицы трассировки и верификации

```
REQ:        Матрица трассировки отражает цепочку «цель миссии ↔ требование ↔
            элемент архитектуры ↔ метод верификации». Матрица верификации
            содержит метод и этап для каждого требования и ссылку
            на свидетельство.
RATIONALE:  Прил. 2 БП-PA, разделы 4–5; предъявляются на SRR.
TRACE-UP:   TZ-REQ-003; TZ-REQ-005; TZ-REQ-007
TRACE-DOWN: TZ-OUT-005
VERIFY:     TEST
ACCEPTANCE:
  - [ ] матрицы формируются без ручного заполнения ячеек
  - [ ] пустые ячейки трактуются как разрывы и перечисляются отдельно
  - [ ] свидетельство со статусом stale отмечается в матрице
STATUS:     Draft
OWNER:      ведущий системный инженер
```
