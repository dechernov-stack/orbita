# Решение (ранга ADR): архитектура проекта — одно дерево

## Диагноз (по репозиторию, `origin/main`)

Два несвязанных состава:
- `spacecraft` — тип «Модель аппарата»: параметры платформы и ПН;
  на него ссылаются входы моделирования (`ScenarioInputs.spacecraft_ref`);
- `component` + `component_usage` — PBS: определение/вхождение ×N,
  сегмент, `parameters`, `interfaces`, `wbs_refs`; на его узлы
  распределяются требования (`allocated_to`).

Аппарат, собранный в модели, не узел PBS; требования цепляются к узлам,
у которых нет характеристик аппарата. Трассировке не по чему идти.
Записка «Требования как граф» отложила семантику графа за KDP-B —
но дерево носителей она и задумывала опорой; владелец прав: без него
трассировка пуста, дерево — сейчас.

## Решение: одно дерево носителей = PBS = состав

1. **`spacecraft` растворяется в PBS.** «КА» — определение компонента с
   поддеревом: платформа · полезная нагрузка · подсистемы (БЦВМ, СЭП,
   АФУ…). Характеристики аппарата — `parameters` узлов по **анкетам
   Ф-06** (анкета платформы = параметры узла «Платформа»; три пути
   заполнения работают на узле). Экран «Модель аппарата» становится
   **видом узла КА** в том же дереве, не отдельной сущностью.
2. **Моделирование читает узел.** Входы сценариев и построений берут
   массу, мощность, чувствительность из параметров поддерева КА;
   **подгруппа построения = вхождение «КА» ×N** с параметрами орбиты —
   `quantity` вхождения и есть число аппаратов подгруппы.
3. **Уровни дерева** (Прил. 4 §3): система (корень) → сегмент
   (космический · наземный · пользовательский — из ConOps §2) → элемент
   → подсистема → компонент; вхождения ×N на любом уровне; свёртки по
   дереву. Проектные требования — на корень (есть), системные —
   на сегменты/элементы, ниже — flow down. «Без носителя» — разрыв.
4. **Каркас библиотеки разворачивается в это же дерево** при взятии
   (сегменты и элементы класса миссии) — не рядом с ним.
5. **Функции — новый слой** (Прил. 4 §2): вид `function` (из ConOps и
   нужд), **распределение функции на узлы**; матрица «функции ×
   узлы» — четвёртая матрица workbench появляется естественно.
6. **Интерфейсы — рёбра между узлами** с двумя сторонами (тип есть;
   интерфейсное требование распределяется на интерфейс — уже закон).
7. **WBS — параллельное дерево работ** с привязкой элемент ↔ пакет
   работ (`wbs_refs`/`component_refs` есть) — второй вид того же
   экрана.
8. **Внешние элементы** (`model_element`, Capella) — узлы-ссылки в том
   же дереве (прошлое решение); трассировка и impact их не различают.

## Трассировка «как надо»

Граф по этому дереву (`@xyflow/react`): нужда → требование → узел →
функция → интерфейс → событие верификации → документ. Узлы — контрольные
точки движения: фокус, глубина 1–4, кратчайший путь, битые ссылки
группой. Матрицы: требования × узлы; функции × узлы; требования ×
события верификации; покрытие нужд — все по одному дереву.

## Миграция

- существующие `spacecraft` → определение «КА» + вхождение в узел
  «Космический сегмент» проекта; параметры → `parameters` поддерева;
  ссылки моделирования переключаются на вхождение; `-- legacy:` в
  миграции с объяснением;
- построения: подгруппа → вхождение КА ×N (число КА сохраняется);
- ничего не теряется: старый тип остаётся читаемым в истории.

## Что откладывается (по записке «граф»)

Замыкание декомпозиции, свёртка верификации снизу вверх, эмерджентные
требования — после прогона: они меняют семантику ядра. Здесь — только
опора, на которой это потом сядет.

## Приёмка

- [ ] один экран состава показывает КА с платформой и ПН как поддерево;
      «Модель аппарата» открывается как узел КА, параметры по анкете;
- [ ] построение 4×52° + 3×ССО = два вхождения КА (×4, ×3) — свёртка
      массы группировки честна;
- [ ] требование «масса КА ≤ 100 кг» распределено на узел КА; матрица
      «требования × узлы» его показывает; «Без носителя» → 0 после
      распределения;
- [ ] функция «сбор телеметрии» распределена на ПН и станцию —
      матрица функции × узлы;
- [ ] граф: от нужды до события верификации путь строится по узлам;
- [ ] каркас библиотеки лёг в то же дерево (сегменты — узлы корня);
- [ ] грепом: `spacecraft_ref` в живом коде — 0 (только миграция).
