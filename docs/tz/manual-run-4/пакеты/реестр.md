### Что означают ненулевые числа

**Р04 · отсев 4.** Одна ловушка поставки сработала как задумано: `RQ-P-13`
«число без источника» — величина без происхождения не принимается. Остальные
три (`RQ-P-07`, `RQ-P-08`, `RQ-P-10`, раздел §9 записки) отсеяны за пустую
трассировку: их источник — ограничения и нормативы записки, которые становятся
объектами модели только после акцепта урожая Р05. Это честный порядок шагов, а
не дефект пакета: в живом прогоне Г2 идёт раньше Е1.

**Р04 · доработка 4.** Вторая ловушка поставки: `RQ-P-14` «при необходимости» —
по форме цело, свод качества шлёт в доработку с причиной «неизмеримое
определение»; принимается решением инженера, после чего реестр показывает
помету L-C2. Ещё три требования — с качественным показателем без числа.

**Р08 · доработка 3.** `RQ-S-03`: формулировка говорит «не менее» (угол
места), а оператор меры — «не хуже» по чувствительности; правило видит
расхождение слова и оператора — уточняет инженер. `RQ-S-13` и `RQ-S-13a`:
разделены по П14, но подлежащее осталось составным («полезная нагрузка и
терминалы должны…») — словарь качества признаёт модальное «должна/должен/
должно» и шлёт составное подлежащее на разделение: один носитель — одно
требование. Решение за владельцем: разделить по носителям либо добавить
«должны» в словарь с экрана справочников.

**Р08 · помета TBR.** Пять значений (`RQ-S-03/05/11/12/14`) ждут расчётов
М1/М2а/М3б/М12/М13: мера несёт `tbr`, владельца «вед. СИ», точку SRR и
действие из обоснования; заглушка величины называет своим происхождением
поставку с пометой TBR, в расчёты не идёт.

**Р09 · доработка 14.** У каждого риска высокой критичности правило требует
СРОК реагирования, а поставка сроков не даёт — их назначает владелец риска на
шаге М5. Формулировки собраны из «условие — событие — последствие», шкалы 1–5
по NPR 8000.4, владелец записан ролью.

## Правила раскладки (исполнены)

1. `kind` сопоставлен с реестром видов ИС: `goals_needs_from_docs` разложен на
   два вида (`mission_to_goals`, `mission_to_needs`), `services_from_needs` →
   `needs_to_services`, `requirements_generation` → `services_to_requirements`,
   `requirements_derivation` → `requirement_decomposition`, `risks_from_scenarios`
   → `risk_register`. Своих видов не заведено.
2. Поля вне схемы не потеряны: ушли в `note`, `rationale`, `constraints`,
   `actions` человеческими строками (метки источника, коды поставки, категория
   риска поставки, приоритет покрытия географии).
3. Ссылки `@КОД` (узлы каркаса, стыки, цепочки) остались кодами: канал пакетов
   разрешает их в идентификаторы проекта перед проверкой формы, а неизвестный
   код отказывает пакету целиком с именем кода (ADR-053).
4. Ссылки между пакетами — по коду поставки: Р08 → Р04 через `derives_from` и
   метку «выведено из: RQ-P-NN», сервисы Р03 → нужды Р02 по формулировке.
   Чужие ссылки среза (`ND-0101`, `ND-0103`, `ND-0104`, `ND-0106`) оставлены как
   есть — они нарочно без пары, для диалога сопоставления Г-01.
5. Числа не достраивались: величина без названного источника идёт как есть и
   честно отсеивается; срок риска и связь для §9 остаются за владельцем.
