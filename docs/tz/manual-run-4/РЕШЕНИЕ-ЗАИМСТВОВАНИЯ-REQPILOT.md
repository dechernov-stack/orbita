# Решение: заимствования из ReqPilot — обмен, граф, связи

Правило прежнее (Leaflet, frappe-gantt): **берём готовое из opensource,
пишем только данные и правила**. Версии и лицензии проверены по
реестрам 01.09.2026.

## 1. ReqIF — третий канал обмена (импорт и экспорт)

**Библиотека:** `reqif` от strictdoc-project — Python, **Apache-2.0**,
0.1.0, обновлена 11.08.2026 (★58, 29 форков), умеет парсинг *и*
анпарсинг (round-trip). JVM-альтернативы живой нет: поиск даёт только
заброшенные обёртки RMF (последняя активность 2014–2017) — писать
XML руками на Kotlin ради этого не будем.

**Размещение:** отдельный контейнер-сервис `reqif` (как решали ранее),
HTTP-границей рядом с api; JVM-зависимостей не тянет.

- **Экспорт**: наш реестр → SPEC-OBJECTS / SPEC-RELATIONS /
  SPEC-HIERARCHY / SPEC-TYPES. Профиль и раскладка полей — **по образцу
  `reqpilot/src/lib/export/reqif.ts`** (134 строки, проверено: валидный
  XML, 117 идентификаторов, все с `_`).
- **Стабильные идентификаторы — обязательны**: детерминированы из
  внутреннего id (у ReqPilot — hex-кодирование без дат и случайности);
  повторный экспорт неизменённого проекта даёт побайтово тот же файл
  (кроме CREATION-TIME) — **в тест**.
- **Импорт** (чего у пилота нет, а нам нужно): ReqIF от заказчика →
  кандидаты в наш акцепт-контур с происхождением «ReqIF, файл, дата»;
  неизвестные атрибуты — не терять: складывать в `foreign_attributes`
  объекта, чтобы обратный экспорт не обеднял чужой файл.
- Единицы: `mop` наших требований выгружается парой «значение +
  единица» в отдельные атрибуты (не прозой) — при импорте обратная
  канонизация по справочнику.

## 2. Граф — один движок на систему

**`@xyflow/react` 12.11.6, MIT** (★38 тыс., обновлён вчера). Закрывает
сразу два наших места:
- **граф трассировки требований** (у ReqPilot экран на 62 строки —
  столько это и стоит);
- **схему потока фазы** (круг 4) — узлы-задачи, рёбра-артефакты.

Раскладка DAG — **`@dagrejs/dagre` 3.1.1, MIT** (elkjs не берём:
EPL/GPL — наш запрет на GPL). Координаты не храним, раскладка
вычисляется — правило схемы в силе.

## 3. Виды связей: добавить `conflicts_with`

У нас `derives_from` с видами (декомпозиция/деривация/уточнение);
не хватает **противоречия**: «Р5 требует X, СИС-12 требует не-X» —
инженерная сущность, которую сегодня держат в голове до обзора.
Ложится разрывом в готовность («противоречие не разрешено») и строкой
в чек внутреннего обзора.

## 4. Автономный HTML-отчёт

Один файл без CDN и сети (у пилота — 9,6 КБ на демо-проект): сводка,
дерево, таблицы, матрица, дата. Печатается браузером в PDF. Дёшево,
и это ответ на «отдать комплект смежнику», когда docx избыточен.

## 5. Мелочи, которые стоит взять

- **NFR-007** «цвет не единственный носитель статуса» — линтом рядом с
  подсказками (у нас статусная точка уже с текстом — закрепить).
- **`sample-exports/` в репозитории** — эталоны форматов на
  **синтетическом** проекте: приёмка форматов сравнением, без запуска.
  Ровно наш вывод про фикстуры — у пилота это видно в работе.

## Чего не берём

localStorage как хранилище; baseline-снимок без правил изменения (наш
ADR-031 строже); матрицу «требования × тест-кейсы» как единственную
(наши четыре метода верификации шире); требование без показателя с
единицей.

# Задача Code

## Шип 1 · ReqIF-контейнер (экспорт)

`reqif` (Apache-2.0) в отдельном контейнере; HTTP-граница; профиль по
образцу ReqPilot. Меры: выгрузка проекта — валидный XML (парсится
`xml.etree`), SPEC-OBJECTS = числу требований, SPEC-RELATIONS = числу
связей, все IDENTIFIER с `_`; **повторный экспорт даёт тот же файл**
(тест на детерминизм, CREATION-TIME исключён).

## Шип 2 · ReqIF-импорт

Файл → кандидаты в акцепт с происхождением; `foreign_attributes`
сохраняются и возвращаются при обратном экспорте (round-trip тест на
чужом файле: экспорт нашего → импорт → экспорт = совпадение).

## Шип 3 · Граф на `@xyflow/react` + `@dagrejs/dagre`

Экран трассировки требований: узлы по типам, рёбра по видам связей,
zoom/pan/fit, фильтры, легенда, клик → карточка. Тем же движком —
схема потока фазы (круг 4). Сторож: своей графики поверх библиотеки
нет (по образцу `validate_gantt_library.py`); координаты не хранятся.

## Шип 4 · `conflicts_with` и HTML-отчёт

Вид связи + разрыв «противоречие не разрешено» + строка чека обзора.
Автономный HTML-отчёт комплекта: без внешних ресурсов, печать браузером.

## Ловушки

1. Форк библиотек и патчи их ядра — запрещены (сторожа как у Ганта).
2. GPL/EPL-зависимости не тянуть (elkjs — нет). 3. ReqIF-импорт не
пишет в модель сам — только кандидаты в акцепт. 4. Чужие атрибуты не
терять. 5. Координаты графа не хранить.
