# Задача Code: полный проект-пример «НОО-IoT · золотой путь»

## Цель

Скрипт `tools/build_example_project.py` создаёт проект **«Пример ·
Национальная IoT-платформа (полный)»** со всеми сущностями системы,
включая структуры Capella, — так, как его собрала бы команда за фазу:
через каналы (полки, пакеты, акцепт, фиксации), учётками стенда, с
журналом. Назначение: обзор документов и дизайна владельцем,
регрессионная фикстура, замена ручного PJ-0002. Группа портфеля —
«Примеры», в паспорте — «пример, воспроизводим скриптом, тег ‹…›».

## Правила честности (нарушение — брак)

1. **Только каналы**: ни одной прямой записи в базу; всё — теми же
   ручками, что у пользователя (взятие полок, вставка пакетов, акцепт,
   анкеты, планы, фиксации).
2. **Учётки и роли**: действия от Чернова (РП/DA), Иванова (ведущий
   СИ), Петровой (инженер) по смыслу — фиксации только DA, базирование —
   ведущий СИ, задания — инженеру; история показывает людей.
3. **Демо-значения — с источником «пример (build_example_project)»**;
   там, где значение по-честному неизвестно, — TBR с владельцем и
   точкой, не выдуманное число.
4. **Модели считаются**: М1, М3, М6, М12 и новый М2а — реальными
   расчётами по введённым параметрам; прокси — с пометкой; ничего не
   «нарисовано».
5. **Фаза — только фиксацией**: проект создаётся в Pre-A, MCR и KDP-A
   фиксирует DA с датами в прошлом (сентябрь 2026 — по календарю
   примера), затем Phase A; SRR — не пройден (готовность с честными
   разрывами).
6. **Воспроизводимость**: повторный запуск на существующем примере —
   ноль изменений; удаление и пересборка — тот же результат с точностью
   до дат и идентификаторов.

## Выход для обзора владельца (артефакты в `docs/tz/пример/`)

1. **Печать всех документов**: ConOps, SEMP, ICD, MCReport, пакет
   MCR — pdf + docx.
2. **Снимки всех экранов** проекта под учёткой РП: портфель, работа
   (лента · схема · рамка задачи 2 шаг 2.2), постановка + матрица,
   требования (дерево × 2, карточка вниз, impact), архитектура (пять
   вкладок), дерево состава с анкетой СЭП, стык с ICD, модели (карта,
   сравнение, М2а), библиотека (полки, справочники, результаты),
   готовность SRR, журнал ИИ.
3. **`.sdoc` + ReqIF + выгрузка знаний**.
4. **Карта хранения** `ГДЕ-ЧТО-ХРАНИТСЯ.md`: сущность → таблица/файл →
   экран → печать; чтобы вопрос «где это лежит» имел ответ без
   раскопок.
5. Журнал сборки: сколько объектов, каких видов, кем создано, сколько
   разрывов осталось — честные числа.

## Приёмка

- [ ] повторный запуск — 0 изменений; пересборка — идентична;
- [ ] в истории любого объекта — учётка, канал, дата; прямых записей
      нет (сторож: все объекты имеют `provenance`);
- [ ] «Без носителя» — 0; цепочки без сценарного требования — 0;
      способности без привязки — 0; функции без узла — 0; SRR —
      честные разрывы (анкеты стыков, TBR, модели не построены);
- [ ] М1/М2а/М3а/М6/М10/М12 дали числа; в сравнении построений — Парето
      с отсеянным вариантом по порогу латентности;
- [ ] печать без служебных ключей; ICD собран из стыка; Результаты с
      авторами;
- [ ] `.sdoc` валиден; ReqIF парсится; снимок базирования лежит.

## Ловушки

1. Подделать расчёт числом — брак (сторож «выход модели имеет
   расчёт-источник»). 2. SQL мимо каналов — брак. 3. Пройти SRR «для
   красоты» — нет: пример показывает и незакрытое. 4. Ловушки Р04 в
   пример не класть. 5. Пример не трогает рабочие проекты и прогон
   владельца.
