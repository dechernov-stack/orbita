# Замечания ПМИ-4, разделы В–Г (04.09, 14:18) — два блокера

## БЛОКЕР З-01 · Задания не рождаются, «Мои задания» ведёт в никуда

«Открытые разрывы группы → назначить группу → все на себя» — ничего не
происходит, ни подтверждения, ни ошибки; фраза «Чернов увидит в „Мои
задания"» — мёртвая ссылка; в разделе «Работа» разреза «Мои задания»
нет. Три дефекта одним узлом:
1. **Назначение молчит**: либо задания не создаются (право? роль в
   `auth_mode=stand` не доезжает до канала?), либо создаются без
   отклика. Мера: после подтверждения — тост «назначено 8 → Чернов Д.»
   и счётчик в шапке; ошибка — с именем причины. Молчание запрещено
   как класс.
2. **Ссылка «Мои задания» без маршрута** — сторож мёртвых ссылок обязан
   был поймать; проверить, почему не поймал (ссылка собрана строкой?).
3. **Разрез «Мои задания» в «Работе»** — по концепции три разреза
   (Работа фазы · Мои задания · Готовность); второго нет. Это не новый
   экран, а вид `/views/my-tasks`, который отчитан сделанным, — вывести
   в рейку «Работы» вкладкой/пунктом.
Мера сквозная (В8→Г8 ПМИ): назначил разрыв инженеру → тост → у него в
«Моих» строка с целью и сроком → закрыл разрыв → задание погасло.

## БЛОКЕР В-01 · Гант работает как картинка

Ни клик, ни перетаскивание, ни строки таблицы не отвечают; «непонятно,
что делать дальше». Гипотезы Code проверить по порядку:
1. библиотека в `readonly`, потому что роль РП не определяется под
   `auth_mode=stand` (права на drag ушли, но и клик не должен был
   умереть);
2. обработчики `on_click`/`on_date_change` не привязаны после
   переделки таблицы слева (события перехватывает слой таблицы?);
3. строки таблицы — не цели клика.
Мера: клик по полосе или строке → рамка задачи; hover — курсор и
попап с действиями («открыть · назначить · план»); drag у РП пишет
план, у инженера — отказ по праву с текстом. Под каждой учёткой
проверено.

## П-01 · Промпт для внешнего контура — нечем забрать

Нет «Скопировать промпт» и «Скачать .md». Добавить обе кнопки в шапку
предпросмотра промпта; в md — шапка с видом пакета, отпечатком знаний
и схемой ответа, чтобы ответ вставлялся без правок. Копирование 44 тыс.
знаков выделением — не путь.

## П-02 · После вставки замысла действие неочевидно

Вставили внешний ответ — поля заполнились, а что дальше, не видно.
После вставки: поля в режиме правки с акцентом изменённого, единственная
первичная кнопка **«Принять замысел»** (акцент-цвет), рядом вторичная
«Отменить вставку». Правило общее для всех вставок пакетов: после
вставки первичное действие — акцепт, и оно одно.

## П-03 · Назначение исполнителя — текстовое поле

Имя вводится строкой. Это тот же класс, что «текстовый ID умер»: поле
исполнителя — `RefPicker` по справочнику учёток (поиск, роль рядом с
именем, аватар); несуществующее имя ввести невозможно. Везде, где
назначают: разрывы, задачи, шаги, риски (владелец).

## Мелкое с того же снимка

- «назначить группу · 8…» — обрезок в правой колонке (клятва Т-1: 0);
- «выход не создан (conops)», «(requirement)» — служебные имена видов
  в тексте UI; писать вид по-русски из глоссария («ConOps»,
  «требование») — сторож латинских служебных имён в UI, как в печати;
- «Дальше →» серая без причины — правило disabled: подсказка «шаг 2 не
  закрыт: план работ фазы не задан → к ленте».
