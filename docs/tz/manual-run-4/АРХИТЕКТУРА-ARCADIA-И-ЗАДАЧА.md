# Архитектура по Arcadia в «Орбите»: три полки, одна правда

Три загружаемых файла образуют архитектурный контур проекта:

| Полка | Файл | Что это в Arcadia | Что это у нас |
|---|---|---|---|
| Каркас PBS | `ПОЛКА-PBS.json` — 135 узлов, 130 параметров | **PA**: физические компоненты | дерево носителей = состав = PBS |
| Интерфейсы | `ПОЛКА-ИНТЕРФЕЙСЫ.json` — 26 интерфейсов 8 типов, 71 параметр | **PA**: физические связи; **SA**: обмены идут по ним | рёбра между узлами; носители интерфейсных требований; анкеты интерфейсов; разделы ICD |
| Архитектура | `ПОЛКА-АРХИТЕКТУРА-ARCADIA.json` — 9 акторов, 6 способностей, 25 функций, 10 обменов, 6 цепочек, 9 логических компонентов | **OA · SA · LA** | стейкхолдеры · цели/сервисы · функции · цепочки · распределение на узлы |

Принцип неизменен: Орбита управляет требованиями; архитектура
объясняет, как система их выполнит. PA здесь не дублируется — PBS и
интерфейсы и есть физическая правда, архитектурный файл ссылается на
их коды.

## Как это «звучит» по-Arcadia

- **OA** — зачем: акторы (перевозчик ОГ, оператор ЦУП, регулятор,
  учреждаемый центр…) и операционные способности (OC-01…06), каждая
  трассируется к нашим целям, нуждам, ConOps.
- **SA** — что делает система: 25 функций от «принять сообщение
  терминала» до «увести КА с орбиты», обмены между ними (сообщение,
  подтверждение, команда, ТМ, эфемериды) — и каждый обмен **идёт по
  именованному интерфейсу** второй полки.
- **Функциональные цепочки** — сценарии ConOps как последовательности
  функций: FC-01 «Доставка тревоги ОГ» (терминал → приём →
  приоритизация → сброс → маршрутизация → доставка + подтверждение
  обратно) — это носитель **сценарных требований**: сквозная латентность,
  вероятность доставки. FC-06 «Транзит через ISL» — цепочка, которая
  отвечает на дыру №1 оценки ТЗ (север без РСС).
- **LA** — кто это делает логически: девять логических компонентов
  группируют функции и **разворачиваются** (`deployed_to`) на узлы PBS.
- **PA** — физика: узлы и интерфейсы. Распределение функций на узлы
  (`allocated_to`) — это матрица «функции × узлы», которая на стенде
  сейчас пуста и оживёт от этой полки.
- **Диаграммы к обзорам**: OAB к MCR, SAB и FCD к SRR, LAB и PAB к SDR —
  `illustrated_by`, не покрытие.

## Куда вешаются требования

| Класс требования | Носитель | Отношение | Покрытие |
|---|---|---|---|
| функциональное | функция (SA/LA) | satisfied_by | да |
| характеристика / физическое | узел PBS | allocated_to | да |
| **интерфейсное** | **интерфейс** (ребро) | allocated_to | да — «Без носителя» для интерфейсных смотрит на интерфейсы |
| сценарное / операционное | функциональная цепочка | realized_by | да |
| среда / стойкость | интерфейс `IF-SC-ENV` (КА ↔ среда) | allocated_to | да |
| регуляторное / договорное | организационные интерфейсы (`IF-REG`, `IF-LAUNCH-ORG`) | allocated_to | да |
| иллюстрация | диаграмма | illustrated_by | нет |

# Задача Code: три полки и Arcadia-вид

1. **Сид трёх полок**: `pbs_template`, `interface_template`,
   `architecture_template`; сторож адресов — коды узлов/интерфейсов в
   архитектурном файле обязаны существовать в двух других (по образцу
   `PhaseTaskSeedsTest`). Единицы из `units_to_add` — в справочник.
2. **Взятие в проект**: PBS разворачивается деревом (уровни 0–3 всегда,
   4–5 по классу, `optional` — по подтверждению); интерфейсы — рёбрами с
   анкетами; функции — с распределением на узлы (матрица оживает),
   цепочки — упорядоченными наборами; акторы — предложением в
   стейкхолдеры, способности — `traced_to` к целям/сервисам.
3. **Интерфейс — носитель**: `allocated_to` принимает интерфейс;
   «Без носителя» для интерфейсных требований считает интерфейсы;
   анкета интерфейса из его `params` с зрелостью; **документ ICD** —
   шаблон полки, собирается из параметров и требований интерфейса
   (режимы [Т]/[С]).
4. **Экран «Архитектура»**: вкладки OA · SA · LA · PA — акторы и
   способности; функции с обменами; логические компоненты с
   развёртыванием; PBS с интерфейсами. Цепочки — отдельной вкладкой
   с шагами и требованиями на них. Готовность: функция без узла,
   цепочка без сценарного требования (и наоборот) — разрывы к SDR.
5. **Экспорт в Capella**: требования — ReqIF (StrictDoc), архитектура —
   не экспортируется (Capella строит свою; наши коды — соответствие по
   UUID при появлении модели через `model_element`).

Меры: после взятия трёх полок в новый проект — 135 узлов, 26
интерфейсов с анкетами, 25 функций все с узлами, 6 цепочек; матрица
«функции × узлы» непуста; требование «задержка НСП–РСС ≤ 100 мс»
распределяется на `IF-S-USER` и в «Без носителя» не висит; сценарное
«доставка тревоги ≤ N мин» — на FC-01; сторож адресов валит сид с
несуществующим кодом узла.
