# Замечание Б3-01 · Опциональные узлы блокируют зависимые полки

## Что случилось

Каркас PBS взят, но узлы с `optional: true` (PL-ISL, PL-PNT, PL-P,
MCC-SIM, SC-EXP, USR-APP) создаются только по подтверждению — и не
созданы. Полки интерфейсов, архитектуры и WBS ссылаются на них и
отказывают целиком; архитектура вдобавок отказывает по стыкам
`IF-S-USER…`, которых нет лишь потому, что полка стыков не взялась —
каскад. Текст отказа «возьмите раньше полку, которая их заводит»
здесь врёт: полка взята, узлы не подтверждены.

## Обход для прогона (сейчас)

Перевзять «Каркас PBS» с подтверждением всех опциональных узлов (ISL,
PNT, P-диапазон, Э-ОГ, симулятор — для тестового проекта уместны все),
затем стыки → архитектура → WBS. Счётчики Б3 после этого сойдутся.

## Правило (Code) — зависимость от опционального не блокирует

1. Разрешение `@КОД`: код отсутствует **и** узел/стык помечен
   опциональным в исходной полке (или запись несёт `optional_on`) →
   запись **пропускается** с пометой «пропущено: не подтверждён
   ‹узел›», полка берётся; счётчик пропущенных — в итоге взятия.
   Отсутствует и не опционален → отказ до записи, как сейчас.
2. Текст отказа/итога различает две причины: «полка не взята»
   (порядок) и «узлы не подтверждены» (опциональность) — с кнопками
   «подтвердить узлы →» и «взять без них (пропустить N)».
3. **Добор**: подтверждение опционального узла позже (решение об ISL на
   ЭТП) предлагает «добрать зависимое из взятых полок» — повторное
   взятие создаёт только теперь разрешимые записи, идемпотентно.
4. Каскад: непринятый опциональный стык делает опциональными обмены и
   цепочки на нём — по `optional_on`, не по догадке.

## Данные (поставка обновлена)

- `USR-APP` — больше не опциональный (стык «ЦОД ↔ потребители»
  без него бессмыслен);
- WBS: пять пакетов на опциональных узлах — `optional_on`;
- стыки: `IF-ISL`, `IF-PNT-USER` — `optional_on`;
- архитектура: функции F-22/F-23, обмены EX-ISL/EX-NAV, LC-ISL, FC-06 —
  `optional_on`; сторож сида проверяет, что каждая ссылка на
  опциональный узел несёт `optional_on`.

## Мера

Новый проект: взять PBS **без** подтверждения опциональных → стыки
берутся (24 из 26, «пропущено 2: не подтверждены PL-ISL, PL-PNT»),
архитектура берётся с пропусками, WBS — с пятью пропусками; подтвердить
PL-ISL в дереве → «добрать» создаёт IF-ISL, F-22, EX-ISL, LC-ISL, FC-06,
пакет WBS; повторный добор — 0 новых.
