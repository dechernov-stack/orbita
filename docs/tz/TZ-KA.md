# 40. Моделирование космического аппарата

Статус: Draft. Источник: «Моделирование КА» v0.2; Концепция v0.3, разд. 5.3.
Схемы: `contracts/spacecraft`, `contracts/radio-link`, `contracts/service-zone`.
Уровень детализации — Phase A: бюджеты и огибающие, не схемотехника.

---

### TZ-KA-001. Ввод модели КА с контролем ограничений

```
REQ:        ИС принимает модель КА (платформа + полезная нагрузка) по схеме
            spacecraft. Конфигурации, нарушающие Р1 (bent-pipe), Р2 (масса вне
            12–100 кг), Р3 (оптический ISL), отклоняются со ссылкой на ADR.
RATIONALE:  TZ-MOD-003: ограничения выражены типами; недопустимые конфигурации
            искажают trade studies.
TRACE-UP:   ADR-001; ADR-002; ADR-003; TZ-COM-008; TZ-MOD-002; TZ-MOD-003
TRACE-DOWN: TZ-KA-002
VERIFY:     TEST
ACCEPTANCE:
  - [ ] негативные наборы из tests/reference отклоняются с указанием ADR
  - [ ] корректная модель проходит валидацию без предупреждений
STATUS:     Draft
OWNER:      проектант КА
```

### TZ-KA-004. Энергетическая модель

```
REQ:        Модель включает СБ (площадь, КПД, деградация, схема установки),
            АБ (ёмкость, допустимая глубина разряда) и циклограмму режимов
            с потреблением. Энергобаланс витка рассчитывается совместно
            с баллистическим модулем.
RATIONALE:  Энергетика витка — ключевой критерий оценки построений.
TRACE-UP:   КА-4.2; TZ-BAL-004; TZ-KA-006; TZ-KA-009; TZ-MOD-005
TRACE-DOWN: TZ-KA-009; TZ-KA-010
VERIFY:     TEST
ACCEPTANCE:
  - [ ] генерация СБ учитывает косинусные потери схемы установки и деградацию на срок
  - [ ] расчёт даёт энергобаланс для худшего и лучшего сезона
  - [ ] отрицательный баланс худшего витка помечает конфигурацию как несостоятельную
  - [ ] потребление маяка эфемерид входит в циклограмму (TZ-KA-006)
STATUS:     Draft
OWNER:      проектант КА
```

### TZ-KA-005. Расчёт зон обслуживания

```
REQ:        Для каждой линии и каждого профиля терминала рассчитывается зона
            обслуживания: подмножество footprint, где бюджет линии замыкается
            с требуемым запасом, ДН антенны обеспечивает усиление и есть
            свободная ёмкость. Указывается ограничивающий фактор.
RATIONALE:  TZ-MOD-006: зона обслуживания ≠ зона видимости; смешение
            завышает оценку покрытия.
TRACE-UP:   КА-3.3; TZ-KA-007; TZ-MOD-006
TRACE-DOWN: TZ-BAL-005
VERIFY:     TEST
ACCEPTANCE:
  - [ ] зоны для профилей A' и C' на одной конфигурации различаются
  - [ ] для каждой границы указан limiting_factor
  - [ ] зона рассчитывается по бюджету на краю (худшая геометрия)
  - [ ] service_elevation_deg ≥ min_elevation_deg во всех случаях
STATUS:     Draft
OWNER:      проектант КА
```

### TZ-KA-006. Маяк эфемерид

```
REQ:        Полезная нагрузка ведёт широковещательный маяк эфемерид
            по абонентской нисходящей линии. ИС рассчитывает его нагрузку
            на линию и энергопотребление, а также обеспечивает приём маяка
            худшим терминалом на краю зоны обслуживания.
RATIONALE:  Р5/ADR-005: работа терминалов по расписанию пролётов невозможна
            без маяка; маяк передаётся везде, где есть датчики, включая
            ячейки без спроса на данные.
TRACE-UP:   ADR-005
TRACE-DOWN: TZ-KA-004; TZ-NET-005; TZ-USR-002
MOP:        запас линии маяка на краю зоны ≥ требуемого
VERIFY:     TEST + ANALYSIS
ACCEPTANCE:
  - [ ] формат маяка выбирается из pass_schedule / full_almanac / orbit_model
  - [ ] энергия маяка входит в энергобаланс витка
  - [ ] бюджет линии маяка считается по худшему терминалу на краю зоны
  - [ ] период маяка согласован с max_almanac_age_s профилей терминалов
STATUS:     Draft
OWNER:      проектант КА
```

### TZ-KA-007. Бюджет радиолинии

```
REQ:        Для каждой линии рассчитывается бюджет: ЭИИМ, потери свободного
            пространства, атмосферные, поляризационные, потери наведения, G/T,
            C/N0, требуемое Eb/N0 из адаптера протокола, итоговый запас.
            Бюджеты участков «терминал→КА» и «КА→НС» считаются раздельно.
RATIONALE:  Раздельные бюджеты — следствие regenerative (Р1/ADR-001).
            Параметры терминала берутся из модуля потребителей.
TRACE-UP:   ADR-001; КА-3.4; TZ-NET-001
TRACE-DOWN: TZ-KA-005
VERIFY:     TEST + ANALYSIS
ACCEPTANCE:
  - [ ] сквозной бюджет «терминал→КА→НС» не вычисляется (архитектура regenerative)
  - [ ] требуемое Eb/N0 берётся из адаптера протокола, не задаётся вручную
  - [ ] доплеровский сдвиг и его скорость сравниваются с полосой захвата приёмника
  - [ ] отрицательный запас помечает линию как незамкнутую
STATUS:     Draft
OWNER:      проектант КА
```

### TZ-KA-008. Бортовой буфер и приоритеты

```
REQ:        Модель бортового буфера store-and-forward учитывает объём,
            приоритеты (C' > B' > A'), политику вытеснения при переполнении
            и политику сброса на наземную станцию. Потери от переполнения
            передаются в результаты моделирования.
RATIONALE:  Переполнение буфера — источник потерь, который обязан быть
            виден в Монте-Карло наряду с потерями канала.
TRACE-UP:   КА-3.7
TRACE-DOWN: TZ-FLW-007
VERIFY:     TEST
ACCEPTANCE:
  - [ ] потери от переполнения учитываются отдельно от канальных потерь
  - [ ] приоритет C' соблюдается при вытеснении
  - [ ] требуемый объём буфера сопоставляется с худшим интервалом до сброса
STATUS:     Draft
OWNER:      проектант КА
```

### TZ-KA-009. Режимы и географические маски

```
REQ:        Расписание режимов КА формируется статическими географическими
            масками, генерируемыми из карты спроса и зон наземных станций.
            Интерфейс динамического планировщика предусматривается как
            заглушка и в первой очереди не реализуется.
RATIONALE:  Р4/ADR-004; модель и Монте-Карло не должны зависеть от способа
            формирования расписания.
TRACE-UP:   ADR-004; TZ-KA-004
TRACE-DOWN: TZ-KA-004
VERIFY:     TEST
ACCEPTANCE:
  - [ ] маски перегенерируются при изменении карты спроса
  - [ ] вызов заглушки планировщика возвращает явную ошибку NotImplemented
  - [ ] замена источника расписания не требует изменений в модуле потоков
STATUS:     Draft
OWNER:      проектант КА
```
