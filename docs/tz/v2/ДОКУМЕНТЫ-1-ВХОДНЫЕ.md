# Документы проекта · часть 1 — входные

Входной документ — то, что пришло **извне** проекта и чего мы не пишем:
читаем, разбираем, ссылаемся. Три правила: оригинал неприкосновенен;
истина текста — канон (MD с якорями), истина смысла — урожай, принятый
человеком; входной документ имеет **свою** версию (заказчика,
регулятора, поставщика), и её смена подсвечивает всё, что на него
ссылается.

## 1. Типология входных документов

| Тип | Источник | Что извлекается (классы урожая) | Куда идёт (сцена) | Разбор Д2 | «В промпт» по умолчанию | Срок жизни |
|---|---|---|---|---|---|---|
| **Записка миссии** (по нашему шаблону) | заказчик / инициатор | замысел · стейкхолдеры · нужды · цели · сервисы · ограничения · география · этапы · бюджет · риски · НПА-ссылки | 2–6, 11, 12 | полный | да, все разделы | версия заказчика |
| **Техническое задание** (чужой формат) | заказчик | требования (с уровнем) · состав (узлы) · стыки · этапы · ограничения · нормативы · стейкхолдеры | 3, 5, 7, 8 — и **оценка против нужд** | полный | да | версия ТЗ + изменения (ИИ) |
| **Директива / FAD / протокол решения** | дирекция, DA | цели · ограничения · сроки · ресурсы · назначения ролей | 1, 5, 14 | реестр (без прозы) | разделы «постановка» | до следующего решения |
| **Нормативный документ** (НПА, ГОСТ, стандарт) | регулятор / орган стандартизации | обозначение · редакция · дата · пункты-обязательства | полка Б1 → нормативное основание требований | пункты + реквизиты | нет (по требованию) | **редакция** — смена подсвечивает зависимые |
| **Даташит / спецификация изделия** | поставщик | параметры узла с единицами (по анкете) · стыки · условия среды · масса/мощность | анкеты узлов (7, A5+) | параметрический (в поля анкеты) | нет | ревизия поставщика |

| **ICD внешней системы** (носитель, ГАИС, AIS) | внешняя сторона | параметры стыка · протокол · нагрузки · среды | стыки внешние (7, A5) | параметрический | нет | версия ICD |
| **Внешняя модель** (Capella `.aird`, ReqIF партнёра, `.sdoc`) | партнёр / смежник | элементы модели (UUID) · требования-кандидаты · связи-кандидаты | A4, A5 — только кандидатами | структурный (без LLM) | нет | версия модели |
| **Аналитика / исследование** (рынок, студенческий анализ, обзор) | внешние авторы | сервисы-кандидаты · оценки · критерии · рынки | 6, 7 | полный + derived | выбранные разделы | дата актуальности |

| **Справка / письмо / прочее** | любой | — (контекст) | — | нет | нет (по выбору) | — |

## 2. Карточка входного документа — обязательные поля

| Поле | Обяз. | Смысл |
|---|---|---|
| `type` | ✓ | тип из таблицы (бриф из глоссария) |
| `title` · `file{name, hash, size, format}` | ✓ | оригинал, неизменяем |
| `origin` | ✓ | кто выпустил (организация / стейкхолдер) |
| `doc_version` · `doc_date` | ✓ | версия и дата **самого документа**, не загрузки |
| `valid_until` | для НПА, КП, решений | срок действия / редакции |
| `classification` | ✓ | открытый · ДСП · коммерческая тайна · гостайна (последнее — не загружается, только ссылка) |
| `source_marks` | ✓ для записки/ТЗ | признак наличия меток [И]/[В]/[П] |
| `language` | ✓ | для разбора |
| `canon` · `map` | автоматически | Д1 |
| `harvest` | по типу | предложение Д2 с акцептом |
| `supersedes` | при новой версии | ссылка на предыдущую версию входного |
| `notes` | — | служебное |

## 3. Конвейер входного документа

1. **Загрузка** → карточка обязательна (тип, источник, версия, гриф).
2. **Д1 канон + карта** — всегда (кроме гостайны и бинарных моделей).
3. **Д2 разбор — по типу**: полный (записка, ТЗ, аналитика,
   наследие) · реестр (директива, КП, регуляторные) · параметрический
   (даташит, ICD — прямо в поля анкет и стыков) · структурный без LLM
   (внешние модели: UUID, ReqIF) · нет (справка).
4. **Урожай → акцепт по адресам**; каждая сущность несёт `source{doc,
   anchor}` — это трассировка вверх.
5. **Оценка** (только ТЗ): матрица «нужды × требования ТЗ» — покрыто ·
   не покрыто · требование без нужды; замечания заказчику как RFA.
6. **Устаревание**: новая версия входного (`supersedes`) → диф канонов
   → все сущности с `source` в изменённых блоках получают помету
   «источник обновлён» (как «текст устарел», в обратную сторону);
   норматив с новой редакцией → подсветка нормативных оснований.
7. **Промпт**: разделы «в промпт» по умолчанию типа; блоки — выбором.

## 4. Версии входных против версий наших сущностей

Версия входного документа — свойство документа (заказчика, регулятора),
не наша битемпоральная версия записи: у карточки материала своя
`doc_version`, у записи карточки — своя `version`. Сущность, выведенная
из входного, помнит **и** документ, **и** его версию, **и** якорь; диф
двух версий входного — по канону, блоками.

## 5. Грифы и доступ

`classification` определяет: хранение (открытые и ДСП — в файловом
хранилище стенда; коммерческая тайна — с ограничением ролей; гостайна —
**не загружается**, карточка-ссылка с местом хранения), показ (блоки
ДСП не уходят в выгрузку знаний и во внешний контур без явного
разрешения), печать (гриф на титуле выпуска, если вложено).

## 6. Шаблоны и ожидания к входным, которые мы задаём сами

- **Записка миссии** — наш шаблон (есть): максимальный урожай.
- **Требования к входному ТЗ** — чек-лист ожиданий заказчику: уровни
  требований, показатели с единицами, носители, метод верификации,
  реквизиты НПА, метки источников; по нему же — оценка ТЗ.
- **Запрос данных поставщику** — анкета узла как документ: «дайте
  такие параметры в таких единицах к такой дате» (экспорт анкеты
  формой, импорт ответа — параметрический разбор).
- **Запрос ICD внешней системе** — параметры стыка из полки как
  вопросник.

## 7. Чего среди входных нет

Наши промежуточные (ConOps, реестры, модели) и выходные (пакет точки)
— часть 2 и 3. Служебные заметки без источника — не документы, а
`notes`. Файлы «на всякий случай» без карточки — не загружаются.
