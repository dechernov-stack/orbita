# Поле знаний проекта — онтология фактов, допущений и рамок

На входе и в любой момент проект накапливает **поле знаний**: факты из
источников, допущения команды, рамки от заказчика и регулятора. Не всё
из этого становится проектом: часть *принимается* (становится
параметром, требованием, ограничением), часть *учитывается* (влияет на
суждение, объектов не порождает), часть *отклоняется* или *устаревает*.
Онтология должна различать это явно — иначе поле превратится в свалку
цитат.

## 1. Единица — факт (утверждение с источником)

`fact` = **о чём** (субъект) · **что** (предикат) · **значение** (величина
с единицей или текст) · **откуда** (источник и якорь) · **какого рода**
(вид факта) · **насколько верно** (сила свидетельства, уверенность, дата
актуальности) · **что с ним решено** (диспозиция).

Факт неизменяем как утверждение источника; меняются только его
диспозиция (решением человека, с историей) и статус актуальности
(новая версия источника → `superseded`).

## 2. Виды фактов — что утверждение собой представляет

| Вид | Смысл | Во что может стать при принятии |
|---|---|---|
| `quantity` | величина изделия/среды/рынка | параметр узла · показатель · метрика |
| `capability` | что умеет изделие/организация | функция · технология (TRL) |
| `obligation` | норма, требование внешней стороны | ограничение Р · нормативное основание · требование |
| `framing` | рамка заказчика/программы (сроки, бюджет, запреты) | ограничение Р · веха · оценка |
| `event` | срок, дата, решение внешней стороны | веха · срок действия |
| `relation` | кто с кем: поставщик, оператор, интеграция | стейкхолдер · стык · связь |
| `assessment` | оценка, мнение, прогноз | риск · метрика сравнения · только «учтён» |
| `assumption` | допущение (наше или источника, [П]) | реестр допущений (§4) |

## 3. Диспозиция — что проект сделал с фактом

| Диспозиция | Смысл | Порождает объекты | Влияние на ворота |
|---|---|---|---|
| `free` | известен, решения нет | — | помета «не рассмотрен» к точке, если тема — в текущей сцене |
| `noted` | **учтён**: влияет на суждение, в промпт входит, объектов не создаёт | — | нет |
| `assumed` | принят как допущение до подтверждения | запись в реестре допущений с владельцем и точкой подтверждения | **разрыв**, если не подтверждён к своей точке |
| `adopted` | принят в проектирование | параметр / требование / ограничение / веха / риск со связью `derived_from_fact` | зависимые объекты наследуют актуальность факта |
| `rejected` | отклонён с причиной | — (остаётся в поле, виден) | нет |
| `contested` | противоречит другому факту | — | **блокирующий**, если хотя бы один из них `adopted` |
| `superseded` | заменён новой версией источника | зависимые — помета «источник обновлён» | по зависимым |

Смена диспозиции — решение: кто, когда, почему, к какой точке; история
хранится. `adopted` без объекта-результата невозможен (сторож);
`assumed` без владельца и точки — невозможен.

## 4. Допущения — реестр, а не заметки на полях

Допущение = факт вида `assumption` (или любой факт с диспозицией
`assumed`) + `owner` + `confirm_by` (точка) + `validation` (чем
подтвердится: расчёт М-N, ответ поставщика, испытание, решение
регулятора) + `impact_if_wrong`. Реестр допущений печатается в
MCReport §10/§11 и SEMP; к своей точке допущение обязано стать
`adopted` (подтверждено фактом) или `rejected` (снято — с impact по
`derived_from_fact`). TBR — частный случай допущения о величине.

## 5. Темы — о чём факты, пока сущности ещё нет

Субъект факта — либо ссылка на сущность проекта/полки (узел, стейкхолдер,
норматив), либо **тема** (`topic`): «Платформа Спутникс», «ПП №2216»,
«рынок трекинга контейнеров» — ярлык, под которым факты копятся до
того, как решено, что с ними делать. При принятии тема **разрешается**
в сущность (создаётся или сопоставляется), все её факты получают
`subject.ref`. Тема без разрешения к точке, если по ней есть `adopted`
факты, — невозможна (сторож).

## 6. Сила свидетельства и актуальность

- `evidence`: `claimed` (заявлено источником) · `corroborated`
  (подтверждено вторым независимым) · `measured` (измерено/испытано) ·
  `assumed` (наше допущение).
- `confidence` 0–1 — оценка ИИ/человека; `as_of` — дата снимка
  источника; `valid_until` — для норм, КП, решений.
- Метка [И]/[В]/[П] — происхождение по природе; сила свидетельства —
  по подтверждению; это две оси, не одна.
- Принятый факт с `evidence = claimed` и `confidence < порога` —
  помета «слабое основание» у зависимого объекта; к PDR принятые
  величины должны быть ≥ `corroborated`.

## 7. Связи поля знаний

| Связь | Откуда → куда | Смысл |
|---|---|---|
| `about` | факт → сущность \| тема | предмет факта |
| `derived_from_fact` | параметр · требование · ограничение · веха · риск → факт | происхождение принятого |
| `supports` | факт → решение · допущение · вариант | основание решения (AoA, базовая концепция) |
| `contradicts` | факт ↔ факт | конфликт источников; диспозиция `contested` |
| `supersedes` | факт → факт | новая версия источника |
| `confirms` | факт → допущение | подтверждение |

## 8. Где поле живёт и как читается

- **Проектное поле** (L2): факты проекта; экран «Поле знаний»: по темам,
  по диспозиции, по источникам; фильтры «не рассмотрены в текущей
  сцене», «допущения к ближайшей точке», «противоречия»; у каждой
  сущности — вкладка «Основания» (её факты и допущения).
- **Библиотечное поле** (L0): факты класса миссии, обобщённые с
  очисткой проектной специфики («доплер на 550 км ломает LR-FHSS без
  компенсации») — через «обобщить», с источниками; входят в промпты
  класса (Ф-09 «факты, не имена»).
- **Промпт**: источник «фактология» отдаёт факты с диспозицией
  `adopted` · `assumed` · `noted` (не `rejected`), со ссылками; ИИ
  цитирует факты, а не документы.
- **Документы**: MCReport §2 (AoA) собирает `supports`; §10/§11 —
  допущения и открытые вопросы (`contested`, `free` по темам сцен);
  SEMP — реестр допущений.

## 9. Инварианты

1. Факт без источника и якоря не существует; величина без единицы —
   не факт. 2. `adopted` ⇒ есть объект с `derived_from_fact`; `assumed`
   ⇒ владелец, точка, способ подтверждения. 3. Противоречие с принятым
   фактом блокирует точку до решения. 4. Тема с принятыми фактами
   обязана разрешиться в сущность. 5. Диспозицию меняет человек;
   ИИ предлагает. 6. Новая версия источника не меняет диспозиций молча
   — только `superseded` + пометы зависимым. 7. Отклонённое не
   удаляется. 8. Гриф источника наследуется.

## 10. Пример из загрузки Спутникс

«масса КА 80–200 кг» — `quantity`, [В], `claimed`, тема «Платформа
Спутникс» → диспозиция `contested` против рамки Р2 (`framing`,
`adopted`) — блок до решения РП: сузить конфигурацию (факт остаётся
`noted`, параметр не принимается) или пересмотреть Р2 (решение с
основанием, факт → `adopted`). «санкционный список с 23.02.2024» —
`event`, [В], `claimed` → `adopted` в риск. «6–12 Вт на ПН (Perseus)» —
`quantity` по другой платформе → `noted` (учтён для сравнения, узел
не порождает).
