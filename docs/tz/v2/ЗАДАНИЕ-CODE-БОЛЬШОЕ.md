## Шип E · Знания 2: типы входных и умный вход (≈3 дня)

1. **ТЗ** (тип `tor`): полный разбор + **оценка против нужд** —
   матрица «нужды × требования ТЗ» (покрыта · не покрыта · требование
   без нужды); замечания заказчику как RFA. Проверка — на `тз.docx`
   (МКУСС ПД) и пакете `ПАКЕТ-РАЗБОР-ТЗ`.
2. **Даташит** — параметрический разбор прямо в поля анкет узлов с
   якорями; проверка — на PDF характеристик платформы (задание
   «рассмотрим как базовую» → конфликт с Р2 до создания узла; риск).
3. **Нормативы с текстом**: пункты — фактами `obligation`; новая
   редакция → `superseded` + пометы «источник обновлён».
4. **Снимок URL** — контейнер `snapshot` на Chromium из образа
   DocPilot; страница без рендера — честный отказ с предложением PDF.
5. Реестр допущений к ближайшей точке; темы → разрешение в сущность;
   противоречия фактов — блок точки.
Мера: три типа входных дают факты своим режимом; ТЗ оценено матрицей;
даташит заполнил анкету; допущение без подтверждения к точке — разрыв.

## Сквозные правила

Красный CI — стоп; сторожа UI (мёртвые ссылки, disabled без причины,
`undefined`, служебные имена, обрезки, тест действия); библиотеки
версией, без форков и GPL; миграции с `-- legacy:`; живые вызовы —
разбор входных и рендеринг документов, остальное пакетами; демо и
примеры — только спутниковый IoT; отчёт без пересказа процесса.
