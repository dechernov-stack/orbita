# Шаблон: минимальный набор моделей системы (полка «Модели системы»)

Модель — не файл, а ответ на инженерный вопрос: входы из параметров
узлов PBS (анкеты), выходы — в бюджеты, метрики и показатели
требований. У каждой — точка, к которой она обязана дать первый
честный ответ; до неё — приглашение, после — разрыв «модель не
построена». Инструмент сегодня — честно: свой расчёт · прокси
(помечен) · внешний.

## Связи моделей (кто кого кормит)

М1 → М2а–г, М3, М4, М8, М10, М12 · М2а → М3а (окна и энергоцена сеанса) · М2б → М3в · М2в → М3г · М2г → М3д · М3а–М3е → сквозная латентность (М3е) · М2г ↔ М12 (ISL против числа станций) · М2а, М3а → М13 (энергоцена и сеансы терминала) · М13 → М3а (классы терминалов) · М1, М3г, М3е, М12 → М14 (планирование, ТМ, доставка) · М14 → М3е (латентность наземного плеча) · М3 → М12, М11 · М6 → М1, М7, М11 ·
М4 ↔ М5 (β-режимы) · все → показатели требований (mop) через
«пересчитан после базирования».

## Правила полки

1. Взятие набора создаёт **записи моделей проекта** со статусом «не
   построена»; готовность к точке проверяет «модель дала ответ» (есть
   выход с датой расчёта) — не наличие файла.
2. Прокси всегда помечен на выходе; замена прокси расчётом — версией
   модели, история сохраняется.
3. Входы модели — только параметры узлов PBS: параметр не задан →
   разрыв «вход модели не задан» ведёт к анкете узла.
3а. Поток М3x и линк М2x привязаны к **интерфейсу PBS** (ребро между
   двумя узлами): интерфейсные требования распределяются на интерфейс,
   модели читают параметры обоих его концов; сквозная латентность —
   сумма плеч с указанием узкого места.
4. Выход модели, ставший значением показателя требования, несёт
   происхождение «М4 v3, дата».
5. Класс миссии выбирает обязательный поднабор: для НОО-IoT — М1–М4,
   М6, М8, М10, М12, **М13, М14** к SRR; М5, М7, М9 — к SDR; М11 — по
   регламенту.
