# Интеллектуальная загрузка: источник + задание → факты → действия

Вы правы: документ редко «одного типа», и раскладывать его по типу на
входе — ошибка. Правильно другое: **тип — вывод, факт — атом, задание —
намерение.** ИИ на входе читает документ целиком, атомизирует его в
факты с якорями, а из задания пользователя («рассмотрим как базовую»,
«разбери и положи на полку») строит план действий — и предъявляет его
на акцепт целиком. Контекст проекта (класс, ограничения, анкеты, полки)
ему известен, поэтому он не ошибётся там, где ошибся бы чистый разбор.

## 1. Вход

`источник` (файл · URL · вставленный текст) + `задание` (свободная
фраза, одна-две) + контекст (проект, текущая сцена, класс миссии,
ограничения Р, полки, анкеты). Задание не обязательно — тогда
умолчание «разбери по сущностям».

## 2. Конвейер

| Шаг | Что делает | Кто |
|---|---|---|
| **Снимок источника** | файл — как есть; URL — рендер headless-браузером в PDF+MD с датой снимка (страницы на JS без рендера пусты — как страница Спутникс); повторная загрузка того же URL — диф снимков | детерминированно |
| **Д1 канон + карта** | якоря блоков, таблицы, числа канонизированы по справочнику | детерминированно |
| **Д2а классификация** | какие типы содержимого внутри и в каких блоках (постановка 40 % · параметры изделия 30 % · нормативы 10 % · маркетинг 20 %) | ИИ |
| **Д2б атомизация** | список **фактов**: субъект · предикат · значение `{value, unit}` или текст · якорь · метка [И]/[В]/[П] · уверенность · дата актуальности | ИИ |
| **Д2в план действий** | из задания + фактов + контекста — действия по каналам системы с предпросмотром: «создать типовой компонент на полку (12 параметров)», «завести поставщика», «сравнить с Р2», «запросить у поставщика 5 недостающих параметров» | ИИ + правила |
| **Акцепт плана** | пользователь правит и принимает **пакет действий**, не факты поштучно; каждое действие показывает, что создаст/изменит | человек |
| **Выполнение** | действия идут штатными каналами с происхождением «загрузка ‹id›, факт ‹n›»; факты сохраняются как **фактология** проекта и переиспользуются | система |

Факт — сущность (`fact`): он живёт после загрузки, на него ссылаются
параметры, требования, риски; повторная загрузка новой версии
источника пересчитывает факты и помечает зависимое «источник обновлён».

## 3. Каталог заданий (intent) — семантика, не свобода

| Задание | Что означает | Типичные действия |
|---|---|---|
| разбери по сущностям | полный урожай по классам | кандидаты во все разделы |
| положи на полку как типовой ‹компонент/риск/профиль› | обобщение в библиотеку | `typical_*` с параметрами и источником |
| **рассмотрим как базовую ‹платформу/ПН/…›** | кандидат базового решения в проекте | типовой компонент → экземпляр узла с `template_ref`; запись решения «кандидат»; сравнение с ограничениями и требованиями; запрос недостающих параметров |
| сравни с нашим ‹узлом/требованием› | диф фактов против текущих значений | таблица расхождений; пометы |
| обнови параметры ‹узла› | параметрический импорт | новые версии `parameter` с origin datasheet |
| это норматив — заведи | норматив с редакцией и пунктами | `normative_document` + кандидаты оснований |
| это ТЗ — оцени против нужд | разбор + оценка | матрица покрытия; RFA заказчику |
| просто в контекст | без действий | блоки в промпт, фактов не создаём |

Задание вне каталога — ИИ предлагает ближайшее и **спрашивает**, не
гадает.

## 4. Пример — ссылка на платформу Спутникс + «рассмотрим как базовую»

1. Снимок: страница на JS — рендер; в снимок попадает и PDF линейки
   платформ с сайта (ИИ предлагает: «страница пуста без рендера, есть
   PDF с характеристиками — взять его как источник?»). Дата снимка —
   05.09.2026, источник внешний → метка [В].
2. Факты (примеры): «платформа микро-класса, масса КА 80–200 кг» [В] ·
   «линейка CubeSat: доступная средневитковая мощность ПН ≥ 8 Вт на
   орбите МКС» [В] · «Perseus 6U: 6–12 Вт на ПН, 3 ДМ + 3 МИО» [В] ·
   «компания в санкционном списке США с 23.02.2024» [В].
3. План действий (предпросмотр):
   - создать **типовой компонент** «Платформа Спутникс микро 80–200 кг»
     на полку: параметры — масса, мощность на ПН, СОС (3 ДМ + 3 МИО),
     `maturity_class = off_the_shelf`, источник — снимок с датой;
   - создать **стейкхолдера-поставщика** «Спутникс»;
   - в проекте: узел `SC-PLT` ← `template_ref` на типовой, запись
     **решения** «кандидат базовой платформы» (не выбор — кандидат);
   - **конфликт с ограничением Р2** «платформы 12U…100 кг»: масса
     80–200 кг выходит за рамку — пометить, предложить сузить до
     конфигурации ≤ 100 кг или пересмотреть Р2 с основанием;
   - **запрос данных поставщику** по анкете платформы: не хватает
     напряжения шины, ёмкости АКБ, точности ориентации, Δv, стыков ПН —
     форма-запрос;
   - **риск** «санкционные ограничения поставщика» — регуляторный/
     поставочный, владелец РП.
4. Акцепт: пользователь снимает «стейкхолдер» (уже есть), принимает
   остальное; система выполняет каналами; факты остаются в фактологии.

Что показал пример: без контекста ИИ создал бы «платформу 80–200 кг»
и ошибся бы; с контекстом Р2 и анкеты он не ошибается — он сталкивает
факт с рамкой и спрашивает.

## 5. Пример — записка + «разбери по сущностям и положи на полку»

Задание — двойное: полный урожай в проект **и** обобщение на полки
(профили стейкхолдеров, типовые риски, нормативы с редакциями).
План: 101 кандидат в проект + 13 обобщений на полки с очисткой
специфики; акцепт двумя группами.

## 6. Правила честности

1. Факт без якоря не существует; величина без единицы справочника —
   не факт.
2. Метка и дата: внешние источники — [В] с датой снимка; допущения —
   [П]; внутренние — [И].
3. Конфликт фактов между источниками (масса 80 кг у одного, 120 у
   другого) — показать оба с источниками; ИИ не выбирает.
4. Ни одно действие не выполняется без акцепта плана; план показывает
   последствия («изменит 3 параметра узла СЭП»).
5. Задание неоднозначно → вопрос, не догадка; действие вне каталога →
   предложение с подтверждением.
6. Гриф источника наследуется фактами и действиями.

## 7. Сущности (дополнение реестра)

| Вид | Обязательные поля |
|---|---|
| `intake_task` | источник{file|url|text} · снимок{path, date, hash} · задание · контекст{проект, сцена} · план[действия] · статус (планируется · на акцепте · выполнено) · автор |
| `fact` | субъект · предикат · значение{measure|text} · источник{material, anchor} · метка · уверенность · дата актуальности · статус (свободен · использован · отклонён) |
| `action` (в плане) | вид (create_typical · create_entity · update_params · compare · request_data · flag_conflict · attach_context) · цель · предпросмотр · происхождение фактов[] · решение акцепта |

Связи: сущность → `derived_from_fact`; факт → `material` (якорь).
