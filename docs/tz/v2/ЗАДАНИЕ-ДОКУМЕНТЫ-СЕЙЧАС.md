# Задание Code: документы — сейчас, минимум (перенос порядка волн)

Решение владельца: без документов проверять нечего — выходы сцен висят
в воздухе. Документная механика поднимается **перед фронтом волны 4**
как минимум, который делает проход возможным: **каждая сцена
заканчивается разделом документа, который можно прочитать и
напечатать.**

## 1. Принцип: документ — снимок сцен

Mission Concept Report (Прил. 3 БП-PPA, 11 разделов) живёт с первой
сцены как **живой документ**: раздел = запрос к выходам сцены (элемент
`query`), плюс тезисы; выполненная сцена — заполненный раздел; пустой
раздел говорит, какой сцены ждёт. То же — Draft ConOps (Прил. 5) с
сцены 9. Проход владельца идёт **по документу**: прочитал §1–§3 —
проверил сцены 2–7.

| Раздел MCReport | Сцены-источники | Элементы по умолчанию |
|---|---|---|
| §1 Цели, задачи, стейкхолдеры | 2, 3, 4 | замысел · стейкхолдеры с нуждами · цели с показателями |
| §2 Анализ альтернатив | 7 | варианты · метрики · пороги · Парето · отклонённые с причинами |
| §3 Базовая концепция и сервисы | 6, 7 | сервисы с классами · базовый вариант · обоснование · состав до L2 |
| §4 Требования уровня проекта | 8 | реестр (6 колонок) · покрытие целей |
| §5 Технологии | 10 | TRL · планы созревания |
| §6 Риски | 11 | реестр 1–5 · владельцы · сроки |
| §7 Оценка засорения | 11 | ODA базового варианта |
| §8 Стоимость и сроки | 12 | ROM диапазоном · допущения |
| §9 Descopes | 7 | из базовой концепции |
| §10 Допущения | 2–12 | реестр допущений (поле знаний) |
| §11 Открытые вопросы | 2–12 | темы без разрешения · contested-факты |

## 2. Что переносится из DocPilot (код есть — перенести, не переписать)

- модель: `document` · `section` · `element` (query · entity_ref ·
  fact_ref · statement · table · figure) · `baseline` (тег в git) ·
  `rendering` · `release`;
- полнота по `expects` шаблона на ступень;
- рендеринг: **stub сразу** (таблицы и списки из элементов — читаемо
  для прохода) и **LLM-рендер тем же портом** — день живого ИИ
  проводим здесь, на нашем ConOps, не на насосе;
- сторож чисел с исключениями; квалификаторы — списком данными;
  рецензия патчами;
- печать: HTML2PDF и Typst (титул, авторы из элементов, тег
  базирования); docx — позже.

## 3. Минимальный интерфейс (по `ДИЗАЙН-ПРИНЦИПЫ-V2`)

- **В мероприятии** — одна строка внизу: «в документ: MCReport §3 ·
  4 элемента · <a>посмотреть</a>»; клик — раздел в том виде, как он
  напечатается.
- **Экран «Документы»** — список документов проекта с полнотой к
  ступени («MCReport · 4 из 11 разделов полны к MCR»); открытие —
  документ целиком, разделы с их элементами и рендерингом; кнопки:
  «Базировать» (СИ), «Написать связно» (по разделу), «Печать».
- Тезис (statement) добавляется в разделе — единственный свободный
  текст; число без опоры — помета.
- Ничего лишнего: без панели истории, без схемы; контекст — в шапке.

## 4. Порядок

1. Перенос кода DocPilot в `documents` (модуль, порт уже есть) —
   модель, полнота, stub-рендер, печать HTML2PDF.
2. Шаблон MCReport с картой «раздел → сцены → элементы по умолчанию»
   (таблица выше) — данными полки; шаблон Draft ConOps (Прил. 5).
3. Автонаполнение: выполнение сцены создаёт/обновляет элементы её
   разделов (`query` с фиксированными параметрами); удаление сцены —
   элементы устаревают, не исчезают.
4. Строка «в документ» в мероприятии; экран «Документы».
5. LLM-рендер за портом + день живого ИИ на ConOps IoT (ответы:
   читаемость, ложные срабатывания сторожа, квалификаторы).
6. Typst-печать с титулом.

## Приёмка (проход владельца — по документу)

- [ ] после сцен 1–4: MCReport §1 читается и печатается в PDF —
      замысел, три стейкхолдера с нуждами, цели с показателями и
      годами; §2–§11 показывают, каких сцен ждут;
- [ ] после сцены 7: §2 — таблица сравнения с Парето и отсеянным по
      порогу; §3 — базовый вариант с обоснованием; §9 — descopes;
- [ ] после сцены 8: §4 — реестр 6 колонок; полнота к MCR — «N из 11»;
- [ ] тезис с числом без опоры — помета; рендер stub без «kind:» и
      служебных имён; печать без ключей;
- [ ] базирование «внутренний обзор» — тег в git, диф после правки
      одного тезиса — один узел;
- [ ] день живого ИИ: §1 и §3 связным текстом настоящей моделью,
      сторож на живой прозе — отчёт с числом ложных срабатываний.

Фронт волны 4 (модели, технологии, риски, стоимость) идёт после этого
и сразу пишет в §5–§8 — тогда и он проверяется документом.
