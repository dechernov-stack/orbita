# ТЗ «Орбита v2» — головной документ для Code

06.09.2026 · единственный вход в пакет. Всё остальное — приложения,
на которые это ТЗ ссылается. Ни один документ пакета не отменяет
другой; при противоречии — приоритет у этого ТЗ, затем у
`СХЕМЫ-ПОЛЕЙ-V2.yaml`, затем у профильных решений.

## 1. Что строим и почему заново

Продукт, который **ведёт** команду по фазам Формулирования (Pre-A,
Phase A) и выпускает пакет передачи в Phase B. Прежний продукт умел
многое и не вёл ничего: данные писались в произвольные места, ворота не
держали, интерфейс был складом возможностей. v2: процесс — данные и
движок; сущности знают сцену рождения; ворота отказывают на сервере;
документ — структура с порождаемой прозой; экран — сцена.

Движок переделывается на треть (модель данных, полки, каналы, Гант,
граф, StrictDoc — остаются), интерфейс — с нуля поверх тех же данных.

## 3. Backend — коротко (полностью — `ТЗ-BACKEND-V2`)

14 модулей с явным `api`, своей схемой БД и зависимостями только вниз
(Konsist в CI); ядро сущности (`born_in`, версия атомарной сущности,
классы полей, провенанс); реестр связей с обоснованием; Flowable
встроенный, модель фазы порождается из `phase_template` (многостандартный:
NASA / РК-11КТ, экспертизы с контрольными вопросами, `stage_output_dataset`,
дорожки, `instantiate_per`); `GateEvaluator` = готовность; схемы из
YAML генерацией; strangler за флагами; `documents` — порт, реализация
переносится из DocPilot в волне 5.

## 4. Frontend — ТЗ

### 4.1 Принципы (сторожа)

1. **Экран = сцена.** Вход один — «Работа»: лента сцен и точек фазы.
   Сцена открывает рамку: степпер, нить потока, панель условий выхода
   (✓/☐ с причинами и переходами), встроенный фрагмент экрана — только
   тот, что нужен шагу, без чужих первичных действий.
2. **Видимость по сцене**: виды, чьи сцены не наступили, в интерфейсе
   не существуют; эксперт-режим — явный переключатель в шапке,
   выключен по умолчанию, показывает библиотеку, обмен, Arcadia, журналы.
3. **Карточка раскрывается вниз** под строкой, не сбоку.
4. **Статус — текстом и цветом**; панели — с заголовком и счётчиком;
   пустое состояние — текстом с причиной и переходом.
5. **Запрещено как класс**: `disabled` без причины и перехода; мёртвая
   ссылка (все ссылки — через маршрутизатор, сторож e2e «к месту →
   URL/фрагмент изменился»); `undefined`/`null`/`NaN` в DOM; служебные
   имена видов в тексте (только глоссарий); обрезки и переносы статусов;
   цвет как единственный носитель; ввод ссылок строкой (только пикеры,
   включая учётки).
6. **Ни одного экрана без брифа и эталона**; отклонение от эталона —
   с обоснованием в отчёте волны.
7. **Библиотеки, не самострой**: frappe-gantt, `@xyflow/react` +
   `@dagrejs/dagre`, Leaflet; сторожа «своя графика поверх библиотеки —
   отказ» — в силе; GPL/EPL — нет.
8. Дизайн-токены: одна гарнитура, 14 px, фокус-кольцо, три сущности
   на экране (навигация · список · карточка) — не больше.

## 6. Правила работы Code

1. Шипами с тегами; полный прогон на каждом; отчёт без пересказа
   процесса.
2. **Не гадать**: неясность → честный минимум + вопрос владельцу в
   отчёте; адреса, проверки, условия — не выдумывать (сторожа адресов
   и связей).
3. Контент и полки — из поставок внешнего контура генератором; правка
   пакетов руками — отказ сторожа.
4. Токены: живые вызовы службы — только там, где проверяется живой
   контур; остальное — пакеты и внешний контур.
5. Витрин нет: fixture помечен, прокси подписан, расчёт — расчётом.
6. Библиотеки версией; форк и патчи ядра — нет; GPL/EPL — нет.
7. Миграции с `-- legacy:`; данные стенда не теряются; резервная копия
   до каждой волны.
8. Пилоты (FlowPilot, DocPilot) — источник кода для модулей, не
   соседние сервисы.
