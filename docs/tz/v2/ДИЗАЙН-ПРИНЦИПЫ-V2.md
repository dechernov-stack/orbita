# Дизайн v2 — принципы против перегрузки

Диагноз владельца: экран показывает всё, что система знает, а инженеру
нужно то, с чем он работает сейчас. Ниже — правила, по которым
перестраиваются все экраны v2; эталоны переделываются по ним.

## 1. Тест действия — главное правило

Каждый элемент на экране обязан пройти один из трёх вопросов:
**с ним работают** (ввод, выбор, принятие) · **он объясняет, почему
нельзя дальше** (условие, разрыв — с переходом) · **он нужен для
следующего клика** (вход, ссылка). Всё остальное — не на экране:
свёрнуто, за кликом или в другом режиме. Счётчики вместо списков,
одна строка вместо панели.

## 2. Три плотности по роли

| Роль | Что видит по умолчанию | Что за кликом |
|---|---|---|
| **Инженер** (Петрова) | одно мероприятие: заголовок в одну строку, рабочая поверхность во всю ширину, внизу одна строка выходов-счётчиков и «что не даёт завершить» | входы, история, схема сцены, условия точки |
| **Ведущий СИ** (Иванов) | схема мероприятий сцены (компактно, сверху) + поверхность выбранного | карта фазы, дорожка моделирования, история |
| **РП / DA** (Чернов) | карта фазы с дорожками и точками, блокирующие, назначения, планы | поверхности мероприятий |

Плотность — не настройка, а следствие роли учётки; переключить можно,
но умолчание — своё у каждой.

## 3. Иерархия информации — три яруса

1. **Первичное** — то, что делаю: поверхность мероприятия.
2. **Вторичное** — что не даёт завершить и что это откроет: одна строка
   или боковая рейка иконками со счётчиками (условия 2/3 · входы 2 ·
   откроет 3), раскрывается по клику.
3. **Третичное** — история, схема, точки, нить потока — отдельные
   раскрытия, по умолчанию скрыты; шапка уже несёт проект · сцену ·
   точку — в рамке это не повторяется.

## 4. Конкретные запреты

- Дублирование контекста: сцена в шапке **и** в рамке; входы в нити
  потока **и** в карточке мероприятия — один раз.
- Списки «что откроет», «история», «условия точки» развёрнутыми по
  умолчанию у инженера.
- Плейсхолдеры, похожие на содержимое; подсказки длиннее одной строки.
- Панели с заголовком ради панели; пустые состояния с абзацем — только
  строка с причиной и действием.
- Три колонки на экране инженера; максимум — поверхность + узкая рейка.

## 5. Типографика и сетка (уточнение токенов)

Три размера: 15 заголовок мероприятия · 14 текст · 12 служебное;
один цвет акцента; статус — текстом и точкой; отступы 8/12/16; ширина
поверхности — вся, рейка справа 48 px в свёрнутом виде, 280 в
развёрнутом; строка выходов внизу — фиксирована.

## 6. Как это ляжет на сделанное

Схема фазы (`PhaseMap`) — экран РП и режим «карта» для остальных, не
стартовый экран инженера; схема мероприятий сцены — сверху у СИ,
свёрнута у инженера в одну строку «0.1 → 0.2 · вы здесь»; условия и
история — в рейку; поверхность мероприятия — во всю ширину. Ничего из
построенного не выбрасывается — меняются умолчания видимости по роли.

## Приёмка дизайна

- [ ] под учёткой инженера в мероприятии 0.1 на экране: одна строка
      контекста, таблица работы, строка выходов, рейка со счётчиками —
      и больше ничего;
- [ ] под учёткой СИ — плюс компактная схема мероприятий сцены;
- [ ] под учёткой РП — карта фазы стартовым экраном;
- [ ] ни одного элемента, не прошедшего тест действия (обход экрана
      втроём: владелец, внешний контур, Code — каждый элемент
      называется по вопросу);
- [ ] контекст не дублируется; плейсхолдеров-как-содержимого нет.
