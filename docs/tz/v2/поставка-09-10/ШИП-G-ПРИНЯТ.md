# Шип G — принят (10.09). Ответ на 3 из 4, содержание условий Phase A

`v2-phase-a`: шаблон Phase A генератором, **сцена A4 экземпляром на
каждый элемент** (EL-GS · EL-SC · EL-UT), точки SRR · SDR · KDP-B,
SEMP §6 — 17 строк из каталога процессов, ICD из стыка, деривация
системных с основанием, внешняя модель только чтение, «выступить от
имени роли» для владельца. Две находки — логин `tg:<id>` и движок,
державший шаблон Pre-A после KDP-A, — из класса «тесты не видят, стенд
показывает»; обе с тестами.

## ToR: 3 из 4 — и это дефект атомизации, не оценки

PNT не названа, потому что требование ТЗ о LEO-PNT не выделено фактом.
Оценка «требование без нужды» может назвать только то, что разбор
вынул. Правило режима `tor`: **каждое требование, функция и сервис ТЗ —
отдельный факт** (в `ПАКЕТ-РАЗБОР-ТЗ` PNT есть как сервис и как
requirement); сверка живого разбора с пакетом — по классам, 42
сущности; мера — 4 из 4.

## Содержание условий A5–A10 — поставлено

`УСЛОВИЯ-СЦЕН-PHASE-A.json`: двенадцать сцен, 44 условия выхода —
каждое читает реестр (`kind · min · where`), привязано к мероприятиям
Романова стадии 2 и к ступени лестницы; у A4 — по узлу экземпляра. Ключевые:
A5 — «без носителя (системные)» = 0, функций без узла = 0, у каждой
цепочки сценарное требование, бюджеты с двумя резервами; A6 — четыре
обязательных модели дали ответ и верифицированы, базовый с
отклонёнными; A7 — у каждого разрыва TRL пакет и веха с датой; A9 —
ОСЗ оба случая; A10 — пакеты созревания в оценке, свёртка сроков
против точек; A12 — функциональная базовая линия к SRR, allocated к
SDR, матрица зрелости без дыр. Генератору — как ожидания сцен; каждому
условию — тест на отказ.
