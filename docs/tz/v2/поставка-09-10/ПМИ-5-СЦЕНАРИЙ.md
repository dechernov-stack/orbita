# ПМИ-5 — полный прогон системы по сценарию (Pre-A → Phase A → пакет)

10.09.2026. Проход владельца по сценам; артефакты по именам шагов;
замечания — в журнал (форма в конце), пачками по темам после каждой
части. Ничего не делать руками там, где предложение есть из знаний.

**Стенд.** Локальный (режим stand, три учётки) или 216 («выступить от
имени роли»). Предусловия Code: диск ≥ 15 ГБ; ключ модели; полки
загружены (PBS · стыки · Arcadia · WBS · шаблоны компонентов · модели ·
процессы Романова · нормативы · FAD/FA · SEMP · ConOps · ICD · SMA ·
Project Plan); разбор — фоновой задачей; маршруты функций/обменов/
цепочек (A4/A5) — есть или названы отсутствующими; позиции EXP-2A —
помета, точку не держат; тег `пми5-старт`; копия базы.

**Токены.** Живые вызовы разрешены только: разбор записки, разбор ТЗ,
разбор даташита (по одному на версию), рендер ConOps §1 и MCReport
§3, SEMP §3. Счёт — в журнале ИИ, итог в конце.

## Часть 3 · Дизайн-обход (тест действия, три роли)

По пять экранов на роль: инженер — мероприятие 0.1, требования,
компонент, поле знаний, документ; СИ — сцена 7, архитектура, модели,
точка; РП — карта фазы, план, WBS, портфель. Каждый элемент экрана
называется по вопросу: работаю · объясняет блокер · нужен для клика ·
**лишний**. Лишние — списком с экраном и ролью.

## Журнал замечаний — форма

`З-NN · часть.шаг · экран · роль · тип (блокер · неудобно · непонятно ·
некрасиво · дефект данных) · суть одной фразой · предложение (если есть)
· снимок`. Пачки: после части 1, после части 2, после обхода. Внешний
контур разбирает пачку в день получения и отдаёт Code с приоритетами;
блокеры — сразу.
