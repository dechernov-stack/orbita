## Режим работы этого шипа

* **Стенд владельца не трогать. Выката нет** до его слова — утром он идёт
  по маршруту 10 минут, решает три точки за DA и запускает ПМИ-8 на
  текущей сборке; ваш выкат ему всё сломает. Разумный момент выката —
  после ПМИ-8, по его слову.
* **Истину не трогать.** Шип клиентский; если экрану нужно поле, которого
  DTO не отдаёт, — добавляется DTO чтения, а не поле истины. Понадобилось
  поле истины — строка в NEXT.md «вопрос владельцу», а экран живёт без него.
* **Сервер — только чтение и DTO.** Новых маршрутов записи в шипе нет;
  нужен — вопрос в NEXT.md.
* **Владелец смотрит картинки, не localhost.** Поэтому поставка каждого
  параграфа — **снимки «после» рядом со снимками «до»** и лист-контакт
  (§0); он читает их на GitHub утром. Коммит без снимков параграфа —
  параграф не сделан.
* Каждый параграф — свой коммит с тестами; CI зелёный; `walkthrough on`
  на стенде не трогать (локальный маркер снимать только на прогон, как
  делали 25.09).

## §1 · Четыре компонента и пиктограммы — до экранов (1–2 дня)

Все четыре — по эталону `reference-tabs-bands-card.html`, токены ship 2
(бумага · поверхность · графит · чернила · кобальт · зелёный · янтарь ·
красный, Golos Text, табличные цифры, радиус 6 только у ввода и чипов).

### 1.1 Вкладки (`Вкладки`, `v2-tabs`) — единственное второе меню

Строка под заголовком раздела: подчёркивание у текущей, слово чёрным,
число приглушённым (`Стороны 18`), слева от слова — **маркер здоровья**
(кружок: пустой — всё в порядке, полузаливка янтарём — есть долг,
заливка красным — держит точку; слово в подсказке: «3 стороны без
нужд»). Не больше семи вкладок; восьмая и дальше — в эксперт-режим.
Выбор помнится на раздел. Клавиатура ← →. `role="tablist"`.

Заменяет **все** самодельные ряды кнопок-ссылок (`v2-form--row` с
`v2-link`): Постановка, Поле знаний, Требования (виды), Документы,
Словарь, Концепция, Точки, Библиотека. После §1 самодельного ряда в
коде нет — сторож 8(a).

### 1.2 Полоса группы (`Полоса`, `v2-band`) — группировка вне таблицы

Группа таблицы — **своя полоса над своей таблицей**, а не строка с
`colSpan` внутри `<tbody>`. Полоса: раскрыватель ▸/▾, предмет группы
жирно, счётчики словами приглушённо («фактов 12 · нерешённых 3 ·
противоречий 1»), справа действия группы пиктограммами (раскрыть,
принять решённые, к месту). Колонки внутри группы **не повторяют
предмет** — он один раз в полосе. «Раскрыть все / свернуть все» —
над первой полосой. Единственная группа раскрыта сразу.

Где применяется: факты по предмету (§3.2), требования по носителю и
уровню (§4), риски по владельцу, предложения по вердикту (§3.3),
кандидаты словаря по источнику (§7).

### 1.3 Карточка объекта (`Карточка`, `v2-object`) — одна на все виды

Одна форма для требования, стороны, нужды, цели, сервиса, ограничения,
узла состава, стыка, бюджета, риска, термина, документа, проекта
(паспорт). Открывается **вниз от строки** (как у требований — владелец
это принял), закрывается той же строкой и Esc.

Строение — из истины, руками ничего не размечать:

* **Шапка**: код моноширинно · заголовок · маркер состояния и слово ·
  «версия N · кто · когда» приглушённо · действия карточки
  пиктограммами (история, к месту, снять с обоснованием).
* **Грани** — поля вида по `label`; контрол — по `field_rules.widgets`
  (enum → селект русскими метками из `enum_labels`; ref → пикер с
  поиском по коду и имени; measure → одна строка «оператор · число ·
  единица справочника»; str длинный → textarea, растущая по тексту;
  вложенный массив → малая таблица со своей полосой добавления;
  ts/date → ввод даты по `reference-date-input`).
* **Подсказка поля** — `note` истины приглушённо под полем, не в
  плейсхолдере. Плейсхолдер — только образец формата («≤ 180 мин»).
* **Строка долга** под гранями: «к базированию: Категория · Приоритет ·
  Носитель», «к SRR: Метод верификации» — из `required_at`; поле, которое
  истина не требует, долгом не выглядит (уже так у требований — теперь
  у всех).
* **Плотность**: одна колонка граней у инженера; две — у СИ и РП;
  «просторно» — три. Порядок граней — порядок полей истины; первые семь
  видны, остальные — «ещё N полей» раскрытием (эксперт-режим — все
  сразу).
* **Правка на месте**: поле правится по клику, сохранение — «сохранено,
  версия N» или «ничего не изменилось» словами (шип 1); ошибка 422 —
  словами сервера у поля.

Сторож «один label — один контрол» и `oneControlPerLabel` — на карточку
целиком.

### 1.4 Массовый приём (`Массово`, хук + панель) — из экрана 12 в общее

Вынести из приёма предложений: колонка отметок, диапазон Shift-кликом,
клавиатура (↑ ↓ Space Enter A R L с подсказкой строкой), «умные
наборы» (все решённые · все без замечаний · по группе), нижняя
липкая панель «выбрано N — действия». Применить к требованиям (§4),
фактам (§3.2), кандидатам словаря (§7), рискам (§7), предложениям (§3.3).
Мера: **сто строк — не больше пяти действий, без мыши проходится.**

### 1.5 Пиктограммы вместо слов — правило и набор

`icons.tsx` дополнить стандартными действиями строки: добавить · снять ·
карточка · связать · принять · отклонить · отложить · вернуть · к месту ·
править · история · скачать · печать · загрузить · прочитать · сформировать.
16 px, 1,5 px, один цвет чернил; действие — кобальт при наведении.

Правило: **в таблице действие строки — пиктограмма** с `title` и
`aria-label` словом; **в панели действий — пиктограмма + слово**;
при плотности «просторно» слово появляется и в таблице. Пиктограмма
без слова где бы то ни было — отказ сторожа 8(c). Заголовки, состояния,
условия — словами всегда: пиктограмма заменяет глагол, не существительное.

### 1.6 Рейка — три яруса тонкими разделителями

Порядок не менять; между «Моя работа | Работа», «Точки | Поле знаний»,
«Словарь | Паспорт», «Паспорт | Библиотека» — разделители (без
подписей ярусов). Эксперт-разделы серым до переключения — как есть.

## §2 · Постановка — первая ночь (регрессия КТ2)

Владелец: «верхнее меню невнятное; стало только хуже». Причина — четыре
кнопки-ссылки в ряд, две из которых не разделы, а отбор («Без нужд»)
и состояние («Покрытие k из n»).

Постановка = **вкладки по понятиям постановки**, порядок как в
онтологии: **Стороны · Нужды · Цели · Сервисы · Ограничения · Допущения ·
Применимость**. Каждая вкладка — реестр одного вида: таблица + карточка
объекта (§1.3) + массовый приём (§1.4) + чипы отбора значениями из данных.

| Вкладка | Колонки | Отбор чипами | Маркер здоровья |
|---|---|---|---|
| Стороны | код · сторона · роль · влияние · сила (кликом по баллу) · нужд | без нужд · сила не задана · по роли | без нужд > 0 → долг |
| Нужды | код · нужда · носители · класс · ждёт (`coverage_expected` словом) · закрыта чем (цели · сервисы чипами) · состояние | не покрыты · без цели · без носителя · TBR | не покрыты > 0 → долг; сцена 4 держится → красный |
| Цели | дерево-таблица цель → задачи, показатели (MOE) · нужд закрывает · источник | без нужд · без показателя | без нужд > 0 |
| Сервисы | сервис · класс QoS · целевой показатель · нужды | без нужды · без показателя | |
| Ограничения | код · формулировка · тип · откуда · типовое/своё · отменено (с историей) | по типу · отменённые | |
| Допущения | реестр §10 по диспозиции (правило 23.09-b): допущение · откуда · диспозиция · срок-точка | по диспозиции | нерешённых > 0 |
| Применимость | как сейчас (§5 шипа 4) | по вердикту | needs_work > 0 |

«Без нужд» — чип отбора на «Сторонах» и маркер её вкладки, не раздел.
«Покрытие k из n» — число вкладки «Нужды» и колонка «состояние», не
раздел. Сетка «влияние × сила» — переключатель «сетка» справа от чипов на
«Сторонах»: при ширине ≥ 1280 панель правее таблицы, иначе под ней;
у инженера не показывается (третьей колонки нет).

**Одна поверхность — один компонент.** Реестры вкладок — файлы
`web/src/v2/registry/{stakeholders,needs,goals,services,constraints,assumptions}.tsx`;
сцены 3–6 показывают **те же** компоненты в теле сцены (со строкой
выходов и «не даёт завершить» от сцены). Второй копии таблицы сторон в
`scenes.tsx` после §2 нет.

Снимки «после» Постановки под тремя ролями — в лист до утра.

## §11 · Умолчания вместо вопросов — решено, не ждать

1. Карточка объекта открывается вниз от строки; боковой панели нет.
2. Порядок вкладок Постановки — как в §2; «Без нужд» и «Покрытие» —
   не вкладки.
3. Поле знаний — три вкладки и эксперт-вкладки; чтение документа —
   действие строки документа.
4. Полоса группы — вне таблицы; предмет в колонках не повторяется.
5. Пиктограммы — свой набор 16 px; в таблице без слова, в панели со
   словом; на «просторно» — со словом везде.
6. Формулировка требования — полным текстом у СИ и РП.
7. Сетка «влияние × сила» — панель справа при ≥ 1280, иначе под таблицей;
   инженеру не показывается.
8. Реестры вкладок — общие компоненты для Постановки и сцен; копий нет.
9. Файл экрана — не длиннее 800 строк, новый — 600.
10. Выкат — не раньше слова владельца после ПМИ-8.
