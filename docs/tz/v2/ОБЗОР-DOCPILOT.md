# Разбор DocPilot (dechernov-stack/docpilot) — 06.09.2026

## Что есть

FastAPI + SQLite, StrictDoc 0.29, GitPython, diff-match-patch, Typst
0.15.1 и Chromium в образе; React-фронт одним компонентом. Backend
2,4 тыс. строк (из них `service.py` — 1,6 тыс.), фронт 0,8 тыс.,
шаблоны 0,26 тыс. 17 тестов, AC-01…AC-11 покрыты именованно плюс
шесть сверх ТЗ; e2e есть. README отвечает на пять вопросов §12 честно.

## Что доказано — и это больше, чем я ожидал

1. **Ось «структура → `.sdoc` → git → диф → рендер → рецензия → выпуск»
   существует и держится тестами.** Базирование = запись + коммит +
   аннотированный тег; диф по MID — свой, полевой, без шума от
   технических полей; ручная правка любого `.sdoc` ловится SHA-сторожем
   и при следующем экспорте отказывает (AC-11).
2. **Сторож чисел работает разумнее, чем в ТЗ**: исключены ISO-даты,
   номера разделов и числа в идентификаторах; сравнение по
   нормализованному числу с единицей в сообщении. Отказ атомарный.
3. **Рецензия защищает суть глубже ТЗ**: отклоняются не только числа,
   но и смысловые квалификаторы — «не», «не менее», «только»,
   «кроме», «запрещ…», «обязат…» — и удаление ссылок. Правки изложения
   хранятся патчами с автором.
4. **Печать честная**: в контейнере строгий нативный режим — выпуск
   считается успешным только при реальном выполнении Typst и HTML2PDF,
   сбой не маскируется запасным PDF; движок каждого файла возвращается
   с файлом.
5. Авторы выпуска — из элементов базирования; ошибки — единым
   форматом; роли соблюдены (базирует СИ, изложение правит рецензент).

## Где противоречие — и оно настоящее

1. **Рендеринг — stub, а вопрос был про ИИ.** Stub склеивает по
   предложению на элемент: «Для насосной станции принято: поток
   120 м³/ч. [MID]». Это не документ, это список. Вся защита (сторож,
   патчи, трассировка) проверена на тексте, который заведомо не
   нарушает правил, а **главная гипотеза ТЗ — «ИИ делает читаемый
   документ из элементов» — не проверена вовсе.** README это признаёт
   («реальный LLM adapter — следующая итерация»), но ощущение
   противоречия — отсюда: харнес построен, содержимого нет.
2. **StrictDoc как формат структуры — с компромиссами.** Каждому узлу
   пришлось добавить обязательное содержательное поле `STATEMENT`
   «для совместимости», многозначные ссылки хранятся строками, диф
   — не штатный, а свой. Значит `.sdoc` здесь — **сериализация, а не
   модель**: грамматика выражает узлы, но не граф ссылок. Для
   требований (ReqIF, экспорт) StrictDoc — правильный канон; для
   документа-структуры его вклад сжимается до «формат и парсер».
3. **`strictdoc check` не существует в 0.29** — моя ошибка ТЗ;
   заменён на parse + JSON export. Принято, но урок мне: не
   утверждать CLI, не проверив.
4. **Монолит внутри прототипа**: `service.py` 1 623 строки из 2 400,
   `DocPilotApp.tsx` 534 строки одним компонентом. Для пилота
   допустимо; в продукт — нет (мы только что написали ТЗ против
   монолитов).
5. **`output/` с PDF закоммичен** — артефакты сборки в репозитории;
   Typst-шаблон — 36 строк, титул и подписи без таблиц и рисунков (в
   README сказано честно).

## Решения

1. **Берём в Орбиту** (в модуль `documents` и `exchange`): базирование
   как «запись + git-тег»; полевой диф по MID; сторож чисел с
   исключениями и единицами; квалификаторы рецензии — **списком
   данными**, не regex в коде; рецензия патчами с атомарным отказом;
   авторы из элементов; строгая нативная печать с именем движка;
   SHA-сторож порождённых файлов.
2. **StrictDoc — канон требований и формат обмена**; для документов —
   экспортный формат, не модель: истина — элементы в базе, `.sdoc`
   порождается минимальной грамматикой, граф ссылок в него не
   тащим. Свой диф по MID остаётся.
3. **До интеграции — день с настоящим ИИ**: четыре раздела ConOps
   через реальную модель, три вопроса: читается ли как документ;
   сколько ложных срабатываний сторожа на живой прозе («три станции»
   прописью, «в течение двух суток», проценты, диапазоны); держится ли
   рецензия квалификаторов на реальном тексте. Без этого пилот не
   отвечает на свой вопрос.
4. Гигиена: `output/` из репозитория, `service.py` разнести по
   границам (домен · sdoc · git · рендер · печать) — как в структуре
   ТЗ §13, которая там была, но не соблюдена.

## Итог

Механика документов работает и берётся в продукт. Ценность — «ИИ пишет
документ, а человек отвечает за суть» — пока обещание. Следующий шаг
короткий и решающий: живой рендеринг четырёх разделов и честная
оценка текста и сторожа.
