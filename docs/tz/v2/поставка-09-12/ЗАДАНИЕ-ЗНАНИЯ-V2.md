## 2. Ранг доверия вместо типа (ПОЛЕ-ЗНАНИЙ-V2-СИНТЕЗ §1)

`material.type` → `material.authority` (mandatory · expert ·
reference · doubtful), профиль содержимого вычисляется разбором;
режим атомизации — по профилю блока. Миграция: записка/ТЗ/директива/
регуляторика → mandatory; аналитика/наследие/даташит/КП → reference;
справка → reference; неизвестное → doubtful (с пометой).

## 3. Корпусные темы и связи фактов (§2 стадия А)

Темы — общие для всех документов, слияние по `same_as` с
подтверждением; связи фактов `supports · contradicts · refines ·
same_as` — в том числе между документами; `authority` у факта от
документа; `evidence` поднимается сверкой до `corroborated`.

## 4. Синтез и сверка по онтологии (§2 стадии Б–В; ОНТОЛОГИЯ)

Служба `synthesis`: вид `formation` (поле → понятия по
`ОНТОЛОГИЯ-ФОРМИРОВАНИЯ`: from_facts · fields · must_link ·
conflict_on · identity) и `reconcile` (новое · дополнить ·
противоречие с рангами · подтверждение). Запуск по команде и по
событиям поля (новый материал, новые факты, ручная правка) с
задержкой-накоплением; один вызов на срез ≤ 50 фактов и сущностей,
кэш по отпечатку; `derived_from_fact` — n:m с рангами; принятое не
меняется молча. Экран поля знаний — вкладка «Постановка из поля» с
дифом и индикатором «поле изменилось: N».

## 5. Сверка ручного ввода (СВЕРКА-РУЧНОГО-ВВОДА)

Ручной ввод → кандидат-факт `expert` (автор, роль, дата) → та же
сверка: дубль (ключ `identity` без токенов, затем семантика по срезу
понятия — с указанием отличия) · противоречие (`conflict_on` после
нормализации единиц и горизонтов) · соединение (`supports/refines`,
`must_link`) · нехватка. Под строкой ввода до сохранения — одно
действие на находку; ИИ не сливает, не переписывает, не выбирает
победителя; несколько вводов — один вызов с задержкой.

## 6. Исследование полноты и верификация документов (ВНЕШНЕЕ-ИССЛЕДОВАНИЕ)
