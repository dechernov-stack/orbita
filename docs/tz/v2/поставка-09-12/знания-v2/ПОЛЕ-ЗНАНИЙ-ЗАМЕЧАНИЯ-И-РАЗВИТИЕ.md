# Поле знаний — замечания прохода 08.09 и развитие

## Замечания и решения — в шип C фронтом

1. **Обоснование при принятии факта — мешает.** Требовалось объяснение
   на каждую диспозицию, поле на десяток символов, фразу придумать
   нечего. Решение: обоснование **обязательно только там, где оно
   несёт смысл** — `rejected` (почему не берём), разрешение
   `contested` (какой факт победил и почему), смена уже принятой
   диспозиции. `adopted` и `noted` — одним кликом, без текста;
   поле — нормальное, многострочное, появляется только когда нужно.
   Обоснование не должно быть налогом на согласие.
2. **Загрузка прямо во вкладке.** Поле знаний — естественный дом для
   входа: кнопка «Загрузить источник» здесь же: файл или ссылка +
   задание → разбор → факты и темы ложатся в поле на глазах, план
   действий — тут же на акцепт. Экран «Материалы» остаётся списком
   источников, вход — в поле.
3. **Ручные темы и факты — да.** Инженер заводит тему («Опыт ЛИ
   Гонец-Д1М») и факт руками: метка [И], `provenance = manual`,
   источник — «инженер, дата» (или ссылка на материал, если есть).
   Ручной факт — полноправный: диспозиции, связи, промпт. Доля знаний
   из источников при этом считается честно — ручные видны отдельно.

## Развитие роли — о чём подумать вместе

**Классификация по применимости.** Факт получает грань «где
пригодится»: сцены и фазы (Pre-A 3 · Phase A A5 · Phase B), узлы
состава, стыки, документы. Первое приближение ставит ИИ при разборе
(по виду факта и предмету), инженер правит. Тогда поле фильтруется
«что пригодится в Phase A» и «что ещё не использовано в текущей
сцене»; знания, доехавшие до Phase B, показывают, что из них уже
принято, а что ждёт.

**Нормативы — глубже.** Три шага: пункты норматива — фактами
`obligation` с якорями (уже решено); **матрица применимости** «норматив
× узел / стык / сцена» — какой пункт к чему относится, с состоянием
«учтён / принят требованием / не применим с обоснованием»; **надзор за
редакциями** — новая редакция помечает зависимые основания.
Нормативное основание требования — только из этой матрицы.

**Подбор стандартов.** Каталог стандартов (ECSS, ГОСТ, CCSDS, ITU-R,
NASA-STD) на полке с областями применения; ИИ предлагает для класса
миссии, узла или стыка «применимые стандарты с обоснованием» —
предложением на акцепт, как урожай; принятые — карточками нормативов с
пометой «требует текста» до загрузки. Для ПО управления — ECSS-E-ST-40C,
для линка — ITU-R P.525, для мусора — NASA-STD-8719.14: подсказка
приходит раньше, чем инженер вспомнит.

**Роль в онтологии.** Поле знаний — слой между источниками и моделью:
всё, что модель знает о мире, проходит через факт с диспозицией.
Библиотечное поле (класс миссии) наполняется обобщением проектных
фактов с очисткой специфики — знания следующего проекта начинаются не с
нуля. Две вещи, чтобы это не превратилось в свалку: диспозиция у
каждого факта (без `free` дольше сцены) и применимость как обязательная
грань принятого.

## Что Code делает сейчас (шип C, фронт)

Обоснование только по смыслу · загрузка во вкладке · ручные темы и
факты · грань «где пригодится» с предложением ИИ · матрица
применимости нормативов (первая версия: норматив × сцена/узел,
состояние). Каталог стандартов и подбор — отдельной поставкой полки
после шипа C.
