# Сверка ручного ввода — эксперт вносит цель, нужду, сторону, что угодно

## Принцип

Ручной ввод — **источник**, равный документу по механике и отличный по
рангу: у него нет якоря, но есть автор и роль. Введённое не попадает в
модель напрямую: оно становится **кандидатом-фактом** (`authority =
expert`, метка [И], источник «‹учётка›, ‹роль›, дата», текст как
есть) и проходит **сверку** — ту же, что предложения синтеза; решает
человек, ИИ только показывает.

Ранги: `mandatory` › `expert` › `reference` › `doubtful`. Эксперт выше
справки и ниже документа заказчика: если ведущий СИ пишет «к 2030»,
а обязательная записка говорит «к 2032», — противоречие с подсказкой
рангов, не победа эксперта и не победа записки.

## Что сверка обязана найти — четыре вопроса

| Вопрос | Как ищется | Что предлагает |
|---|---|---|
| **Дубль?** | 1) детерминированно — ключ идентичности понятия из онтологии (нужда: сторона + ядро формулировки; цель: ядро + ключ показателя; сторона: нормализованное имя/синонимы); 2) семантически — ИИ по срезу поля того же понятия и тем: «то же самое, сказано иначе» с уверенностью и **указанием, чем отличается** (поле, число, охват) | «слить с N2 (совпадает сторона и смысл; отличие: у N2 нет класса QoS)» · «это уточнение G4 — сделать `refines`» · «новое» |
| **Противоречит?** | по `conflict_on` понятия: сравнение значений после нормализации единиц и горизонтов; текстовые — ИИ по паре «введённое ↔ принятое/факт» с формулировкой сути противоречия | `contested` с обоими значениями и рангами: «год 2030 (эксперт) против 2032 (записка, обязательный)» |
| **Соединяется?** | факты поля по теме/субъекту, которые **поддерживают** введённое (`supports`) или которые оно **уточняет/обобщает** (`refines`); существующие понятия, которые нужно связать (нужда → сторона, цель → нужды) | «основание: 3 факта [В] из ТЗ и записки — привязать»; «цель без нужды: покрывает N1 и N4?» |
| **Не хватает?** | обязательные поля/связи по онтологии (`must_link`) | «у нужды нет стороны — выбрать»; «у цели нет показателя — TBR с владельцем?» |

Порядок: сначала детерминированные ключи (дёшево, без токенов), потом
ИИ только по кандидатам одного понятия и смежных тем (срез ≤ 50
фактов и сущностей) — один вызов, отпечаток среза кэшируется.

## Что ИИ имеет право предлагать — и чего нет

Предлагает: слить · уточнить · связать · пометить противоречие ·
принять новым · поднять `evidence` (если введённое совпало с фактом из
независимого источника — `corroborated` для обоих). **Не имеет
права**: сливать сам, менять принятое, выбирать победителя в
противоречии, придумывать основание. Каждое предложение — с
уверенностью и с указанием сравниваемых полей: «похоже» без «чем
именно» — брак.

## Трудные случаи — как ведём

- **Одна нужда покрывает две существующие** (эксперт написал шире):
  предложение «обобщить N2 и N5 в новую, оставить их как уточнения
  (`refines`)», не слияние.
- **Та же мысль, другие слова** («автономность 3 года» ↔ «батарея на
  весь срок без обслуживания»): дубль по смыслу, отличие — количество;
  предложение «слить, взять число из эксперта как TBR к SRR, факт
  записки — основание».
- **Разные единицы и горизонты** (P95 180 мин ↔ 3 часа; «к 2030» ↔
  «этап 1, 1,5–3 года от старта 2027»): нормализация через справочник
  и план — сравнение по канону; несравнимое — «не сравнимо: причина».
- **Противоречие с принятой сущностью, а не с фактом**: сущность
  остаётся, введённое — `contested`, у сущности помета «оспорено
  экспертом ‹дата›»; снимается решением с обоснованием.
- **Эксперт вносит сторону, которой нет в документах** (например,
  «субъекты КИИ»): новое, ранг expert, без основания — законно;
  помета «без документального основания» до появления факта.
- **Много ручных вводов подряд**: сверка копится и запускается одним
  срезом с задержкой, чтобы не платить за каждую строку.

## Что видит эксперт — сразу в строке ввода

Под введённым, до сохранения: «похоже на N2 — слить · уточнить · это
новое», «противоречит G4: год (2030 ↔ 2032, записка обязательный) —
оспорить · исправить», «основания: 3 факта — привязать», «нет стороны
— выбрать». Одно действие на каждую строку, ничего не происходит без
клика. После сохранения — сущность с провенансом `expert` и связями,
факт-основание в поле, диспозиция `adopted`.

## Данные

- `authority` += `expert`; ручной факт: `source {account, role, at}`,
  якоря нет.
- Онтология: у каждого понятия `identity` — ключ дубля (поля +
  нормализация) и порог семантики; `conflict_on` — как есть.
- `reconcile` принимает и ручной кандидат, и предложения синтеза одним
  входом — механизм один.

## Мера

- дубль по смыслу (та же нужда иными словами) найден с указанием
  отличия; дубль по ключу — без вызова ИИ;
- «к 2030» против «к 2032» — противоречие с рангами, ничего не
  переписано;
- нужда без стороны не сохраняется, пока не выбрана; цель получила
  основания из фактов автоматически (по подтверждению);
- десять ручных вводов подряд — один вызов сверки;
- ни одного слияния без клика.
