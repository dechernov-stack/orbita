# Поле знаний v2 — корпус, ранг доверия, синтез по онтологии, сверка

## 1. Тип документа → ранг доверия

Типизация (записка · справка · регуляторика) была нужна режиму
разбора и умолчаниям промпта — и всё. Она сужает: документ с «разными
взглядами на цели» не укладывается в тип. Заменяем:

- **`authority` — ранг доверия**: `обязательный` (заказчик,
  регулятор, директива — его факты имеют вес нормы) · `справочный`
  (аналитика, наследие, даташит — вес свидетельства) · `сомнительный`
  (непроверенный источник, черновик, чужая оценка — принимается только
  явно). Ранг наследуют факты; при конфликте предложение по умолчанию
  — за старшим рангом, решает человек.
- **Профиль содержимого** — не вводится, а **выводится** разбором
  (Д2а): доли «постановка · параметры · нормы · оценки» по блокам;
  режим атомизации выбирается по профилю блока, не по типу файла.
- Даты и версии — как были (карточка входного).

## 2. Алгоритм — три стадии вместо одной

| Стадия | Когда | Что делает | Выход |
|---|---|---|---|
| **А · Атомизация** | при загрузке каждого документа | канон → факты с якорями · темы · связи между фактами (`supports` · `contradicts` · `refines` · `same_as` — в том числе **между документами**) | поле фактов корпуса; темы общие для всех документов |
| **Б · Синтез (формирование)** | по команде «Сформировать постановку из поля» и **автоматически при изменении поля** (новый документ · новые факты · ручная правка цели/нужды) | по **онтологии формирования** (§3): из фактов поля — предложения понятий: стороны · нужды · цели · сервисы · ограничения · допущения · вехи; **не по одному документу, а по всему полю**, с весами рангов | план предложений с происхождением n:m (понятие ← несколько фактов из разных документов) |
| **В · Сверка (reconciliation)** | вместе с Б, всегда | против уже принятого: **новое** · **дополнение** (факт уточняет принятую сущность — предложение «дополнить», не заменить) · **противоречие** (два факта или факт против принятой сущности — `contested`, оба показаны, ранг подсказывает) · **подтверждение** (второй независимый источник → `evidence = corroborated`) | диф «поле → постановка»; принятое **не меняется молча** |

Ручная правка цели или нужды — тоже событие поля: сверка проверяет, не
противоречит ли правка принятым фактам («год 2030 против факта [И]
2032 из обязательного документа»), и предлагает либо факт-основание
для правки (ручной, [И]), либо помету.

## 3. Онтология формирования — что и из чего рождается

Файл `ОНТОЛОГИЯ-ФОРМИРОВАНИЯ.yaml`: для каждого понятия постановки —
из каких видов и предикатов фактов оно рождается, какие поля обязаны
быть заполнены из фактов, какие связи с другими понятиями обязательны
(нужда → сторона; цель → нужда; сервис → нужда + класс; ограничение →
норма или директива), какие противоречия считать конфликтом (одно
понятие, разные значения ключевого поля), какой ранг документа даёт
право «обязательного» статуса. Синтез читает онтологию, промпт
собирается из неё (правила, а не свободный текст), сторожа — из неё
же. Это та же онтология Pre-A, доведённая до **правил образования** —
и Phase A получит свои правила тем же файлом.

## 4. Что меняется в системе

- `material.type` → `material.authority` (+ `profile` вычисляемый);
  режим разбора — по профилю блока.
- `fact`: связи `same_as`, `refines` (были `supports` · `contradicts`);
  `authority` наследуется; `evidence` поднимается сверкой.
- `topic` — корпусная сущность: слияние тем по `same_as` с
  подтверждением; тема без документа — законна (ручная).
- Новая служба **`synthesis`**: вид пакета `formation` (поле → понятия
  по онтологии) и `reconcile` (диф против принятого); запуск — по
  команде и по событиям поля; результат — план на акцепт, как сейчас.
- `derived_from_fact` — n:m: у принятого понятия несколько оснований
  из разных документов, с рангами.
- Экран поля знаний: вкладка «Постановка из поля» — диф: новое ·
  дополнить · противоречит · подтверждено; кнопка «Сформировать»;
  индикатор «поле изменилось с последнего синтеза: N фактов».

## 5. Токены

Синтез — один живой вызов на запуск по **срезу поля** (факты
`adopted · noted` по темам, релевантным понятиям онтологии; не весь
корпус), с кэшем по отпечатку среза; автозапуск — не чаще одного на
событие с задержкой (накопить правки), результат применяется при
опросе. Атомизация — по документу, как решено.

## 6. Мера

- три документа разного ранга (записка — обязательный; анализ идей —
  справочный; ТЗ — обязательный с иным взглядом на цели): синтез даёт
  единую постановку с происхождением из всех трёх; **цель с разными
  годами в записке и ТЗ** показана противоречием с рангами, не выбрана
  молча;
- ручная правка года цели без факта → сверка предлагает ручной факт
  или помету; принятая нужда не переписана;
- второй документ, подтверждающий факт первого → `corroborated`;
- у каждой принятой стороны ≥ 1 нужда из синтеза (43 из записки —
  ожидание).
