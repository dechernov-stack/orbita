# Задание Code · Шип 2 — дизайн (с третьего дня шипа 1, ≈2 недели)

Основания: `ДИЗАЙН-НАПРАВЛЕНИЕ` (образ, токены), `ДИЗАЙН-ПРИНЦИПЫ-V2`
(тест действия, плотность по роли, три яруса), `РЕЖИМЫ-РАБОТЫ-ДВУХ-
РОЛЕЙ`, `STITCH-ПРОМПТ-2` (экраны 1–8 словами), эталоны:
`reference-design-direction`, `reference-bridge-and-mywork`,
`reference-activity-engineer`, `reference-process-surface`,
`reference-scenes-5-8-req-arch`, `reference-scenes-10-12-models`,
макет Stitch-2 «Проекты». Ничего из построенного не выбрасывается —
меняются поверхности и умолчания видимости.

## Токены и сторожа — до экранов (1 день)

- Токены данными: бумага `#F4F6F8`, поверхность `#fff`, графит
  `#C9D0D8`, чернила `#182130`, приглушённый `#5C6675`, кобальт
  `#2A4BD7`, зелёный `#1F7A4D`, янтарь `#B7791F`, красный `#C43A2B`;
  **Golos Text** 14/1.45, табличные цифры; радиус 6 только у ввода;
  теней и градиентов нет.
- Три маркера как компоненты: кружок (сцена) · ромб (точка) ·
  скошенный квадрат (мероприятие); заливка — состояние.
- Пиктограммы: один набор 16 px, 1,5 px, всегда с подписью или
  подсказкой; в рейке — пиктограмма + слово полностью (без капслока и
  усечения).
- Сторожа CI (расширить существующие): капслок в подписях; текст
  усечён без подсказки; третья колонка у роли инженера; статус только
  цветом; `disabled` без причины; код поля/перечисления на экране;
  декоративные строки (тест действия не пройден) — список исключений
  пуст.

| 9 | **Требования** | виды: таблица · по иерархии · по документам · матрица; сортируемые заголовки; чипы фильтров; группировка по носителю/уровню; шесть колонок; карточка вниз по эталону; массовые действия по выделенным (носитель, базирование) | v1-удобство возвращено + карточка |

Плотность по роли — умолчания: инженер — 7; СИ — 4 со схемой; РП/DA —
6 (Мостик) и 5 (карта). Реестры открываются из задачи отфильтрованными
(«3 без носителя» → 3 строки), прямой вход — эксперт-режим.

## Что убрать

Панели ради панелей; подписи через «·» там, где можно фразой;
сцена в шапке; иконки без слов; цветные капсулы статусов; форма из
схемы где бы то ни было; плейсхолдеры как содержимое; декоративные
метаданные.

## Приёмка — КТ2, дизайн-обход тремя ролями

Три роли × пять экранов, каждый элемент назван по вопросу теста
действия — лишних ноль; специалист проходит поручение без карты;
ведущий принимает 100 предложений ≤ 5 действий; на экране инженера
нет третьей колонки; ни одного кода вместо слова. Обход — владелец,
внешний контур, Code; отчёт — список лишнего, если найден.
