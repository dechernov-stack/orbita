# Задание Code: поле знаний — живое. Проект начинается с документов

Решение владельца: проект основан на знаниях — на записке, нормативах,
аналитике и их разборе ИИ; инженер принимает решения, а не набирает
содержание. Сейчас поле знаний не сформировано: модуль есть, разбор
не подключён, сцены живут ручным вводом. Это задание закрывает
разрыв между `ИНТЕЛЛЕКТУАЛЬНАЯ-ЗАГРУЗКА`, `ПОЛЕ-ЗНАНИЙ-ОНТОЛОГИЯ`,
`ДОКУМЕНТЫ-1-ВХОДНЫЕ` и стендом.

## 0. Токены — решение

Разбор входного документа — **живой вызов, разрешён**: один на версию
документа, результат кэшируется отпечатком (повтор той же версии —
без вызова). Всё остальное по-прежнему пакетами. Для регрессии — мои
пакеты `Р05` (урожай записки, 101 сущность) и `Р02/Р03` как ожидаемое
покрытие живого разбора.

## 1. Конвейер, который должен работать на стенде

| Шаг | Вход | Выход | Кто |
|---|---|---|---|
| Загрузка | файл + тип + задание («разбери по сущностям», «это норматив — заведи», «рассмотрим как базовую») | `material` с карточкой, `intake_task` | инженер |
| Д1 | файл | канон MD с якорями блоков + карта | детерминированно (есть) |
| Д2а | канон | классификация содержимого по блокам | ИИ, вид `intake_classify` |
| **Д2б атомизация** | канон + контекст (класс, ограничения Р, полки, анкеты) | **факты**: субъект/тема · предикат · величина с единицей · якорь · метка [И]/[В]/[П] · уверенность · вид (quantity · capability · obligation · framing · event · relation · assessment · assumption) | ИИ, вид `intake_atomize` — **главный вызов** |
| Д2в план | факты + задание + сцена | действия с предпросмотром: «в сцену 3 — 10 стейкхолдеров, 6 нужд», «в сцену 5 — 13 ограничений», «на полку — 11 нормативов с редакциями», «конфликт с Р2» | ИИ + правила |
| Акцепт | план | диспозиции фактов (`adopted` → сущности с `derived_from_fact`; `noted`; `rejected`), темы | человек |
| Сцены | факты `adopted` | **предложения сцен приходят из поля знаний**, не из пустой формы | система |

## 2. Нормативы — отдельный вход

Норматив загружается как `material` типа `normative` (файл или карточка
с реквизитами, если текста нет): `normative_document` с обозначением,
редакцией, датой, сроком; пункты — фактами вида `obligation` с
якорями; принятые — становятся `constraint` (Р-код) или
`normative_basis` требований. Сид на старт: одиннадцать НПА из записки
§2.2 (ПП №2216, ПП №1701, приказ №237/№224, ПП №504, SOLAS V/19 и
V/19-1, 187-ФЗ, ТР ТС 018/2011, ГОСТ Р 71168-2023, ПНСТ 921-2024,
ПНСТ 996-2024) — карточками с реквизитами и обязательствами из
записки; текст — когда загрузят.

## 3. Сцены читают поле знаний

- **Сцена 2**: замысел предлагается из фактов вида framing/relation
  (4 поля с якорями) — форма с предзаполнением и «Принять».
- **Сцена 3**: пользователи миссии и потребности — предложениями из
  фактов relation/capability с масштабами; ручной ввод остаётся, но
  вторым путём.
- **Сцена 4**: цели — из фактов quantity с горизонтом (§5 записки).
- **Сцена 5**: ограничения — из фактов framing/obligation; нормативные
  — с `normative_basis`.
- **Сцена 6**: сервисы — из фактов capability/assessment (§4).
- **Сцена 8**: у каждого требования `source` — факт с якорем; линт
  «источник не факт» — помета.
- **Поле знаний** (экран): темы · диспозиции · источники; фильтр
  «не рассмотрены в текущей сцене»; допущения к ближайшей точке;
  противоречия. Из мероприятия — рейка «⇣ входы» ведёт в факты его
  темы.

## 4. Промпты

Вид `intake_atomize` — правила из `ИНТЕЛЛЕКТУАЛЬНАЯ-ЗАГРУЗКА` §6 и
`ПРОМПТ-РАЗБОР-Д2` (12 правил): факт без якоря не существует; величина
без единицы справочника — не факт; метки; конфликты — оба факта;
контекст проекта в промпте (ограничения Р, класс, анкеты) — чтобы
«80–200 кг» столкнулось с Р2 на входе. Схема ответа — по YAML
(`fact`, `topic`, `action`). Повтор при 529 — есть.

## 5. Мера — проект из знаний

- [ ] загрузить записку с заданием «разбери по сущностям» → один живой
      вызов → ≥ 80 фактов с якорями, ≥ 10 тем, план действий с
      предпросмотром; повторная загрузка той же версии — без вызова;
- [ ] акцепт плана → сцены 2–6 показывают предложения из фактов; замысел
      принят без набора текста; стейкхолдеры и нужды — из фактов;
- [ ] одиннадцать нормативов на полке с редакциями; ограничения сцены 5
      несут `normative_basis`; факт «ПП №2216 до 01.09.2027» — событие
      со сроком;
- [ ] загрузить ссылку Спутникс (PDF характеристик) с заданием
      «рассмотрим как базовую» → конфликт с Р2 показан до создания
      узла; санкционный факт → риск;
- [ ] **доля сущностей проекта с `derived_from_fact` ≥ 80 %** на
      демо-проекте (остальные — решения людей: диспозиции, обоснования,
      планы);
- [ ] сверка живого разбора с `Р05`: покрытие классов ≥ 90 % (отчёт
      расхождений — что ИИ нашёл сверх, что пропустил);
- [ ] экран поля знаний по `ДИЗАЙН-ПРИНЦИПЫ-V2`: темы и диспозиции, без
      панелей ради панелей.

## Ловушки

1. Факты без якорей или без единиц — брак, не «примерно». 2. Диспозицию
меняет человек. 3. Ручной ввод не запрещён — он второй путь, и у
введённого руками `provenance = manual`, чтобы доля из знаний считалась
честно. 4. Разбор нормативов по реквизитам без текста — карточка, не
факты из воздуха.
