# Задание Code на несколько часов — замкнуть «документ → знания → решения → документ»

Цель этих часов: **загрузка записки заканчивается предложениями в
сценах и разделами MCReport без набора текста.** Порядок — по
убыванию обязательности; остановились — где остановились, отчёт
таблицей «пункт · сделано · тег».

## 1. Загрузить полную записку (10 мин)

`ЗАПИСКА-МИССИИ-IoT.md` (318 строк, 12 разделов) — на стенд типом
«записка миссии», задание «разбери по сущностям», **один живой
вызов**. Записать: фактов · тем · токенов · время. Ожидание ≈ 100
фактов, ≥ 10 тем. Старая докладная остаётся материалом, но не
источником сцен.

## 2. План действий из фактов + акцепт с `derived_from_fact` (обязательно)

- Д2в: из фактов и задания — план: «в сцену 2 — замысел (4 поля,
  якоря)», «в сцену 3 — N стейкхолдеров, M нужд», «в сцену 4 — цели с
  показателями», «в сцену 5 — ограничения (в т.ч. нормативные)», «в
  сцену 6 — сервисы с классами», «на полку — нормативы с реквизитами»,
  «темы без разрешения — K».
- Каждое действие — предпросмотр «что появится» до нажатия; акцепт
  пакетом с возможностью снять действие.
- Выполнение — каналами: сущности с `provenance = knowledge`, связь
  `derived_from_fact` (реестр связей), диспозиция факта → `adopted`;
  снятое — факт остаётся `noted`.
- Мера: после акцепта `GET /v2/knowledge/coverage` → доля сущностей
  проекта с `derived_from_fact` (цель ≥ 80 %); ручное — `manual`.

## 3. Предложения сцен из фактов (обязательно для 2–3, желательно 4–6)

- **Сцена 2**: форма замысла предзаполнена четырьмя полями с якорями,
  одна кнопка «Принять замысел».
- **Сцена 3**: мероприятие 0.1 показывает предложения «из записки: N
  пользователей миссии, M потребностей» одной строкой с «Принять» —
  по эталону `reference-activity-engineer.html`; принятое — в таблицу
  с провенансом.
- **Сцены 4, 5, 6**: то же — цели, ограничения (с `normative_basis`),
  сервисы с классом QoS.
- Ручной ввод — второй путь, не убирать.

## 4. Нормативы карточками (30 мин)

Одиннадцать НПА из §2.2 записки — `normative_document` на полке с
обозначением, редакцией, датой, сроком и обязательством (факт
`obligation` с якорем); ограничение сцены 5, принятое из такого факта,
несёт `normative_basis`. Текст НПА — не нужен сейчас.

## 5. Экран поля знаний — минимум (если время)

Темы · диспозиции · источники; фильтры «не рассмотрены в текущей
сцене», «допущения к ближайшей точке», «противоречия». Без панелей
ради панелей — по `ДИЗАЙН-ПРИНЦИПЫ-V2`.

## 6. Сверка с Р05 (скрипт, 20 мин)

`tools/compare_harvest.py`: факты живого разбора против
`Р05-урожай-записки.json` по классам и якорям → отчёт «найдено
сверх / пропущено / совпало» в `docs/tz/v2/отчёты/`. Это первый
измеритель качества атомизации.

## 7. Если останется время — экран инженера по эталону

`reference-activity-engineer.html`: одна строка контекста, поверхность
во всю ширину, рейка 48 px со счётчиками, строка выходов внизу;
карта фазы — стартовый экран РП, для инженера — за кликом.

## Проход владельца после п. 3

Загрузить записку → принять план → сцены 2–6 предложениями → MCReport
§1–§3 напечатать. Артефакты: план (снимок), сцены 2 и 3 (снимки),
PDF §1–§3, `coverage`.

## Не делать в эти часы

Базирование тегом, день живого ИИ, Capella, модели фронтом, Typst —
всё после того, как цепочка знаний замкнута.
