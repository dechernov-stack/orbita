# Документы проекта · часть 2 — промежуточные (черновики ConOps/OpsCon и остальные)

Решение владельца: в работе документ — **не текст, а структура**:
разделы по шаблону, в разделах — факты, сущности и авторские тезисы с
авторством; полнота считается; версия базируется; **читаемый текст
порождает ИИ из базированной версии**, человек рецензирует — и это
выпуск. Возня с рукописным MD исключена.

## 1. Промежуточный документ — структура

| Уровень | Что это | Версия |
|---|---|---|
| `document` | экземпляр шаблона: код, заголовок, владелец, статус | кортеж версий разделов |
| `section` | раздел шаблона с ожиданиями полноты | растёт при любом изменении элементов |
| **`element`** | единица содержания раздела | атомарно, с автором |

Виды элементов (`element.kind`):

| Вид | Содержание | Автор |
|---|---|---|
| `fact_ref` | ссылка на факт поля знаний (с диспозицией) | кто включил |
| `entity_ref` | ссылка на сущность: требование, сценарий, узел, стык, риск, технология, решение, допущение | кто включил |
| `statement` | **авторский тезис** — единственный свободный текст; 1–3 предложения; `supports` → факты/сущности | автор тезиса |
| `query` | выборка реестра (например, «требования уровня проекта, категория performance») с зафиксированными параметрами | кто задал |
| `figure` | выход модели или карта: `model_run`, вариант, снимок | кто включил |
| `table` | таблица из данных (MEL, матрица) — запрос с колонками | кто задал |

Никакого MD и абзацев в структуре нет. Числа — только через факты и
сущности (единица справочника, происхождение). Тезис, содержащий число
без ссылки на факт, — помета «число без основания».

## 2. Полнота — считается, не оценивается

Шаблон раздела несёт **ожидания по ступеням** (`expects`): какие виды
элементов и сколько минимум к какой точке. Примеры (ConOps, Прил. 5):

| Раздел | К MCR | К SRR |
|---|---|---|
| §1 Назначение и контекст | замысел · ≥3 стейкхолдера · ≥1 внешняя система | + границы системы тезисом |
| §2 Режимы и состояния | ≥3 режима (машина режимов КА) | переходы с условиями |
| §3 Операционные сценарии | ≥1 номинальный сценарий (цепочка) | + ≥2 нештатных, завершение миссии |
| §4 Потоки данных и управление | ≥2 обмена (команда, ТМ) | элементы обмена |
| §5 Среда и ограничения | орбита базового варианта · ограничения Р | линки М2 по стыкам |
| §6 Обеспечение и персонал | состав смен (М14) тезисом | нагрузка операторов числом |

Полнота раздела = выполненные ожидания текущей ступени / все; документ
полон на ступень, если полны все разделы. **Готовность к точке
проверяет «полон на ступень», а не «документ существует».**
Невыполненное ожидание — приглашение к месту (сцена, реестр).

## 3. Авторство

У каждого элемента — автор (человек) и дата; у факта — источник; у
тезиса — автор и опоры. Документ знает, кто внёс каждый элемент;
служба ИИ элементов не создаёт (предлагает — через акцепт).
Авторы выпуска = авторы элементов базированной версии + рецензент +
выпустивший.

## 4. Версионность и базирование

- Элемент — атомарен (версия при изменении; ссылки на факты/сущности
  помнят их версии).
- Раздел — версия растёт при добавлении/удалении/изменении элементов;
  документ — кортеж версий разделов.
- **Базирование документа** = `baseline` с `items[{section, version},
  {element, version}, {fact/entity, version}]` — снимок структуры и её
  опор; неизменяем.
- Изменение факта или сущности после базирования → у документа помета
  «опора изменилась» с дифом (какие элементы), не молчаливое
  устаревание.
- Диф между двумя базированиями — по элементам: добавлено · изменено ·
  удалено, с авторами.

## 5. Генерация читаемого текста

1. Триггер — базирование версии (или «предпросмотр» без базирования).
2. ИИ получает **только** структуру раздела: элементы с их данными,
   шаблон раздела с указаниями стиля, глоссарий; **ничего сверх
   элементов** (правило вида `document_render`).
3. Результат — `rendering`: текст по разделам, ссылки на элементы в
   тексте (каждое число и утверждение → элемент), отпечаток промпта,
   модель.
4. Рецензия человеком: правки **изложения** (стиль, порядок фраз) —
   допускаются и хранятся патчем поверх рендеринга; правки **сути**
   (число, факт, утверждение) — запрещены в тексте: их место в
   элементах, после чего перегенерация раздела. Сторож: текст с
   числом, не привязанным к элементу, — отказ выпуска.
5. Принятый рендеринг → выпуск (`release`): docx/pdf/html, авторы, в
   Результаты.
6. Новое базирование → новый рендеринг; показывается диф текстов и
   диф элементов рядом.

## 6. Какие промежуточные документы такие и их шаблоны

| Документ | Шаблон | Природа разделов |
|---|---|---|
| Draft ConOps (Pre-A, Д4) · ConOps baseline (A) | Прил. 5 / Прил. 3 БП-PA | сущности + тезисы |
| **OpsCon** (детализация для операторов, Phase A) | наш: смены · процедуры · окна сеансов · нештатные регламенты | тезисы + запросы (М14, М3г) |
| Mission Concept Report (Д2) | Прил. 3 БП-PPA, 11 разделов | всё: факты, сущности, запросы, фигуры |
| SEMP (Д2 Phase A) | DT-9002 ред. 2 | запросы конфигурации + тезисы |
| Черновик требований (Д3) | Прил. 4 | **запрос реестра** — документ есть представление |
| План технологий (Д5/Д6) | Прил. 6 / Прил. 5 БП-PA | сущности `technology` + тезисы |
| Реестр рисков (Д6/Д7) | Прил. 7 | запрос реестра |
| Оценки (Д8/Д9) | наш | запросы WBS + допущения |
| Архитектура (Д5 Phase A) | Прил. 4 БП-PA | сущности + фигуры + запросы (матрицы) |
| ICD стыка | DT-9003 | запросы параметров стыка + элементы обмена |
| Project Plan (Д10) · FAD/FA (Д1/Д9) | Прил. 7 / Прил. 1–2 | тезисы + запросы плана |

«Документ-представление» (Д3, риски) — разделы из запросов; полнота =
полнота реестра; рендеринг — таблицы, проза минимальна.

## 7. Что меняется в модели

- `section.mode` [Т]/[С]/[Р] заменяется на **состав элементов и
  ожидания**; проза больше не режим, а рендеринг.
- `prose` умирает как сущность; появляются `element` и `rendering`.
- `insertion` → частный случай `element.query`/`table`/`figure`.
- Шаблон документа несёт `expects` по разделам и ступеням, стиль
  рендеринга, глоссарий раздела.

## 8. Инварианты

1. В структуре нет свободного текста, кроме тезисов; тезис с числом
   без опоры — помета. 2. Полнота считается по ожиданиям; готовность
   читает полноту, не существование. 3. Рендеринг — только из
   элементов; число в тексте без элемента — отказ выпуска. 4. Правка
   сути в тексте запрещена; правка изложения — патч с автором.
5. Базирование документа фиксирует версии опор; изменение опоры —
помета с дифом. 6. Авторы выпуска — из элементов, не из кнопки.
