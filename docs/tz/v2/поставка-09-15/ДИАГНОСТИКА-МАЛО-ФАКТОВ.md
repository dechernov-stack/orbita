# Почему разбор вытащил мало фактов — диагностика по числам

Эталон для сравнения — `РАЗБОР-ПП-2216.md`: 22 факта, якоря по
пунктам, три порога полем, четыре факта из одного абзаца п.3б. Любая
проверка ниже сравнивает с ним по якорю, не «на глаз».

| № | Причина | Как проявляется | Чем мерить | Что делать |
|---|---|---|---|---|
| 1 | **Канон пуст или обрезан** — скан без OCR, PDF с картинками, таблицы потеряны | фактов 0–3, все из первой страницы; в поле знаний канон короче документа | длина канона в знаках против ожидаемой (~9 тыс. для ПП 2216); число блоков; есть ли текст п.3б | OCR в конвейере Д1 обязателен для сканов; сторож «канон короче N % от объёма страниц — предупреждение» |
| 2 | **Документ уходит в модель целиком** — один вызов, лимит выхода, обрыв списка | факты обрываются на середине; последних пунктов нет; число фактов «гуляет» между запусками | сколько вызовов на документ (должно быть = число разделов канона); длина ответа против лимита | атомизация **по разделам канона**, как решено; каждому вызову — свой якорный диапазон |
| 3 | **Промпт просит «факты», а не классы** — модель даёт по одному утверждению на абзац | п.3б стал одним фактом; события (сроки) и рамки (область, исключения) пропущены; классы «веха», «framing» — ноль | распределение по классам против эталона: пусто в классах, где ожидание > 0 | в промпт — по одному образцу каждого класса из онтологии и явное «каждое обязательство, порог, срок, исключение — отдельным фактом» |
| 4 | **Ворота отбрасывают** — факт без якоря, величина без единицы, якорь вне канона → отказ поимённо | модель дала 20, принято 6; журнал отказов полон | число отказов по причинам из журнала разбора | смотреть, что именно отбрасывается: если «величина без единицы» массово — модель не знает справочника единиц (добавить его в промпт); если «якорь вне канона» — якоря в промпте и в каноне не совпадают |
| 5 | **Дедупликация схлопывает** — «факт узнаётся по месту в документе»: четыре факта из одного абзаца считаются одним | у абзацев с несколькими обязательствами остаётся один факт | число слияний в журнале; факты с одинаковым якорем в ответе модели против принятых | ключ идемпотентности — якорь **плюс** предикат/нормализованное утверждение, не только место |
| 6 | **Режим по профилю сузил класс** — «норматив» → только `obligation`, события и рамки не запрашивались | сроки и область отсутствуют при полном тексте | классы в промпте режима | режим определяет умолчания, но не выключает классы; события и рамки извлекаются всегда |

## Порядок проверки — час на стенде

1. Загрузить ПП 2216 (этот PDF) и записать: длина канона, блоков,
   вызовов, фактов у модели, принято, отказов по причинам, слияний.
2. Сравнить принятые факты с эталоном **по якорям**: скрипт
   `tools/v2/compare_facts.py --doc ПП-2216 --expected РАЗБОР-ПП-2216.md`
   → «найдено · пропущено · сверх» по классам и по пунктам; особый
   контроль — п.3б (ожидание 4) и три порога (`limit` полем).
3. Первое число, которое отклоняется от нормы, называет причину:
   канон короткий → 1; вызов один → 2; классы пустые → 3; отказов
   много → 4; слияний много → 5; только obligation → 6.
4. Правка — одна на причину, повтор — те же числа.

## Норма (чтобы было с чем сравнивать)

ПП 2216, 5 страниц: канон ≈ 9 тыс. знаков, 12–14 блоков, 3–5 вызовов
по разделам, у модели 24–30 фактов, принято ≥ 20, отказов ≤ 3 с
причинами, слияний 0–2, классов ≥ 4 (event · framing · obligation ·
relation), порогов полем 3.
