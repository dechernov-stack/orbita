## Правила образования

### stakeholder — сторона (организация или группа, участвующая в проекте)

| | |
|---|---|
| образуется из | факт вида `relation` **или** `capability`, чей **субъект — организация**, а **предикат** один из: является заказчиком · является оператором · регулирует · поставляет · эксплуатирует · потребляет · учреждается |
| поля | `name` = субъект факта; `role` = по предикату (заказчик → customer, регулирует → regulator, является оператором → operator, поставляет → supplier, потребляет → consumer, учреждается → established); `interest` = из фактов `assessment`/`framing` о том же субъекте; `scale` = `quantity` о субъекте; `influence` = заказчик/регулятор → decides, оператор/партнёр → influences, потребитель → informed |
| пример | F-0012 `relation` · субъект «АО ГЛОНАСС» · предикат «является оператором» · объект «интеграционная точка ГАИС» → `{name: "АО «ГЛОНАСС»", role: "operator", influence: "influences"}`, basis [F-0012] |
| **не сторона** | автор или подписант нормативного акта (Президент, Правительство — если у факта нет предиката роли **к проекту**); ведомство, упомянутое как издатель; сама проектируемая система; регион или объект (порт, коридор) |

### need — нужда (чего сторона хочет; без решения)

| | |
|---|---|
| образуется из | факт вида `framing` с предикатом «нуждается в · требует · не хватает · вынужден», **или** факт вида `assessment` о стороне с меткой **[П]** (её интерес) |
| поля | `statement` = предикат + объект факта одной фразой; `stakeholder` = **обязательно** (см. ниже); `qos_class` = из фактов о задержке/гарантии; если таких фактов нет — не заполняй |
| пример | F-0007 `framing` · субъект «перевозчик опасных грузов» · предикат «не хватает» · объект «телеметрии груза вне зоны покрытия» → `{statement: "непрерывная телеметрия груза вне зоны наземного покрытия", stakeholder: {code: "SK-0004"}}`, basis [F-0007] |
| **не нужда** | роль стороны («заказчик макрорегиона», «регулятор») — это поле `role`, а не нужда; описание программы или акта; свойство системы («доставка за 180 мин» — это цель или сервис) |

### goal — цель (измеримый результат к сроку)

образуется из факта `quantity` с горизонтом (год, «к 20NN», «этап N»)
или `framing` с предикатом «достичь · развернуть · к году».
Поля: `statement`, `measure` = {значение, единица} — **обязательно**,
`year` — **обязательно**, `needs` = ссылки на нужды, которые цель
покрывает (≥ 1). Без меры или года — **не предлагай цель**, предложи
`assumption`, если факт это допущение.
**Не цель**: обязательство норматива (это `constraint`), описание
услуги (это `service`).

### service — сервис (что система даёт кому)

образуется из факта `capability`, субъект — **система или её часть**.
Поля: `name`, `needs` ≥ 1 ссылкой, `qos_class` из фактов о классе или
задержке, `target_measure` из `quantity`. Нет нужды, которую сервис
закрывает, — **не предлагай**.

### constraint — рамка-запрет

образуется из факта `obligation` (норма) или `framing` с предикатом
«только · не рассматривается · исключается · не более · не менее».
Поля: `type` (obligation → regulatory; framing → technical ·
programmatic · launch · financial), `bound` = {ключ, оператор,
значение, единица}, если в факте есть число.
**Не рамка**: желание стороны (это нужда), целевой показатель (цель).

### assumption — допущение

факт с меткой **[П]** либо вида `assumption`. Поля: `statement`.
Владельца и точку подтверждения ставит человек — не заполняй.

## Что вернуть

Предложения по понятиям сцены, в порядке: сначала стороны, затем
нужды. Потолок — {N} предложений; если фактов больше, бери самые
обоснованные (ранг обязательный выше справочного, [И] выше [П]).

Вердикт каждого предложения:
- `new` — среди принятых нет понятия с таким смыслом;
- `augment` — узнано, но у него появилось новое поле или связь;
- `contradict` — узнано, но расходится в значении поля;
- `confirm` — то же самое из другого материала (свидетельство).

## Правила

1. `basis` — коды фактов **из среза выше**, не меньше одного.
   Придуманный код делает предложение недействительным.
2. У `augment`, `contradict`, `confirm` обязательно `target` (код
   принятого) и `diff_field` (поле, о котором вердикт). «Похоже» без
   поля — брак.
3. При `contradict` в `basis` идут факты **обеих сторон**; победителя
   не выбираешь.
4. Ссылка на сторону у нужды: `{"code": "SK-0004"}` — если сторона уже
   принята; `{"ref": "p1"}` — если она предложена в этом же ответе
   (по `id` предложения). Нужда без стороны не предлагается.
5. Ничего не обобщай и не додумывай: чего нет в фактах — нет.
6. Принятое не меняешь: ты предлагаешь, решает человек.
7. Метки, ранги и незакрытые связи проставит система — в ответе их нет.

## Перед ответом проверь себя

- каждое предложение имеет `basis` из кодов среза;
- ни одна нужда не создана из роли стороны;
- ни одна сторона не создана из автора или издателя акта;
- у каждой нужды есть `stakeholder` (код или ref);
- у каждой цели есть `measure` и `year`;
- у `augment/contradict/confirm` есть `target` и `diff_field`;
- предложений не больше потолка, виды — только для этой сцены.
Не прошедшее проверку — **удали из ответа**, не «исправляй смыслом».
