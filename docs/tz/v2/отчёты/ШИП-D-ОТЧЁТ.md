## Что нашлось живьём

1. **§10 «Допущения» не наполнялся никогда**: шаблон отбирает
   `source_mark = П` по истине схем, запись факта хранила только `mark`.
   Тот же класс, что «запрос шаблона → несуществующий вид». Сторож
   `validate_template_kinds.py` теперь проверяет поля `where` по YAML;
   факт пишется и по схеме (`source_mark`, `source{material, anchor}`),
   плоские поля остаются до DTO из YAML. Колонки статически не проверяются:
   хранилище расходится со схемой ещё в 11 местах (свёртка §8, варианты
   §2, сервисы §3…) — и это список для следующего шага правила 2.
2. **Пройденные точки жили в памяти api** и исчезали с выкатом — теперь
   `decision`-записи и статус точки в реестре.
3. **Маршруты v2 шли мимо входа**: роли не было ни у одного вызова. Теперь
   запись без сессии — 401, учётка и роли идут в маршруты (`Actor`).
4. Риск со сроком к точке нечем было закрыть — добавлен канал закрытия
   решением словами (сцена 17).
5. Ручному факту нужна помета достоверности (И · В · П): допущение
   инженера — это П, и только так оно попадает в §10.

## Живой проход (PJ-V2-W4, 09.09, выкат `v2-points-kdpa`)

`python3 tools/v2/walk_scenes.py --project PJ-V2-W4 --points` после сцен
1–12:

1. План работ фазы задан (окна сцен 1–12) — без него внутренний обзор
   честно держался «план не задан».
2. Риск RSK-0003 «масса платформы выходит за 100 кг» (срок — MCR) закрыт
   решением словами через `POST /v2/risks/RSK-0003/close`.
   **Помета для владельца:** в данных прогона свёртка массы по-прежнему
   122,784 кг с системным резервом против Р2 = 100 кг — решение по риску
   в репетиции принято словами, состав не пересчитан; в настоящем проходе
   риск закрывает либо пересмотр состава, либо осознанное принятие.
3. §10 «Допущения» — ручной факт с пометой П (после исправления
   `source_mark`), §11 «Открытые вопросы» — тема; MCReport 11 из 11.
4. Сцена 15: замечание FND-0001 («Нет: названы ли все стороны…» → сцена
   3) вернуло прожитую сцену 3 в работу (`open`, условие выхода с текстом
   замечания); закрыто — сцена 3 прожита вновь. Инженеру (Петрова М.)
   на фиксацию — 403 «решение по точке «Внутренний обзор» принимает
   руководитель проекта; ваша роль — инженер». РП зафиксировал.
5. Сцена 16: MCR зафиксирован DA (стенд: РП носит DA) — все 7 критериев
   и 8 держащих позиций EXP-0A выполнены, 6 несопоставленных/° видны
