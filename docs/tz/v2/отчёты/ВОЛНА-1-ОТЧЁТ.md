Стандарт по умолчанию: **NASA-7120** (решение владельца 05.09). Отчёт —
таблицей «сцена · прожита/нет · чем закрыта», без пересказа процесса.

|---|---|---|---|

## Что построено

**Ядро (`kernel`).** Сущность знает сцену рождения, область и происхождение;
правка заводит новую версию, прежняя остаётся историей — это держит
частичный уникальный индекс в базе, а не договорённость. Реестр связей знает
свои типы: связь вне реестра не заводится, а `derives_from`, `satisfied_by`,
`realized_by`, `verified_by` требуют обоснования — связь без причины
неотличима от случайной. Схемы читаются только сгенерированные из YAML.

**Библиотека (`library`).** Шаблон фазы Pre-A по NASA-7120: четыре сцены с
условиями входа и выхода, три точки с alias-именами для РК-11КТ, экспертиза
MCR с контрольными вопросами. Контента в коде нет — это данные полки.

**Движок (`process`).** Модель фазы порождается из шаблона генератором CMMN
(сцена → stage, точка → milestone, ворота → sentry); XML руками не пишется.
Состояние сцен вычисляется: ручного статуса не существует.

**Готовность (`readiness`).** Оценщик переводит условие в вопрос к данным и
возвращает **причину словами**: «стейкхолдеров 2 из 3», «без нужд: Сторона 2»,
«нужд без цели: 3 — …». Условие, которого оценщик не знает, не считается
выполненным: тихо пропустить ворота хуже, чем сказать, что правило не
реализовано.

**Фасад (`api`).** Тонкий роутер `/api/v2/…` — только перевод HTTP в вызовы
портов. Подключён к нынешнему серверу одной строкой; эта нить исчезнет в
волне 6 вместе с `HttpApi`.

**«Мои задания».** Личный разрез того же состояния: задание — это
незакрытое условие сцены, адресованное роли, а не отдельная сущность со
своим статусом. Ручного «сделано» нет по построению: строка ведёт в свою
сцену, где разрыв закрывается работой. Разрывы закрытых сцен показаны
отдельной группой «Ожидают» — срок по ним не идёт, они откроются сами.

**Интерфейс.** Раздел «Работа»: степпер сцен с состоянием, рамка сцены с
вопросом, панель условий выхода и шаги. Закрытая сцена не молчит: она
перечисляет, чем держится. Формы сцен 1–4 встроены в рамку; чужих первичных
действий на экране нет.

## Отклонения и честные остатки

1. **Flowable развёрнут, но состояние сцен считает не он.** `SpineTest`
   доказывает, что движок держит ворота, и генератор CMMN из шаблона
   написан; однако вид фазы собирает `TemplateProcessEngine` — проекция
   по тем же условиям, без обращения к таблицам Flowable. Причина: дела
   Flowable требуют своей схемы БД и рестарт-устойчивости, а это отдельный
   шип. Мера «рестарт api без потерь» держится тем, что состояние сцен
   вычисляется из данных домена, а не хранится: перезапуск ничего не теряет,
   потому что терять нечего. **Перенос состояния в Flowable — первый шип
   волны 2.**
2. **`access` пока пуст.** Учётки и роли остались в старом ядре: стенд
   пускает витринные учётки, роутер v2 подписывает правки автором из тела
   запроса. Настоящий `Rights` — волна 2.
3. **Полки v2 не грузятся на стенд.** Загрузчик и сторож отпечатков готовы
   с волны 0; приёмник (`library` как хранилище) ещё не написан — шаблон
   фазы читается файлом с полки-каталога. Это следующий шип.
4. **Порог «План работ фазы» не задан.** Второй вопрос волны 0 остался без
   ответа; в сценах 1–4 он не встречается, поэтому волна не заблокирована.

## Выкат на стенд — отложен по внешней причине

Код волн 1–2 собран и проверен тестами, но **образы api и web собрать не
удалось**: Docker не достаёт базовые образы из реестра.

Что перепробовано и что показало:

| попытка | результат |
|---|---|
| сборщик `orbita-mtu` (сеть MTU 1380) | `DeadlineExceeded` на загрузке метаданных `eclipse-temurin` и `gradle` |
| обычный сборщик (сеть по умолчанию) | метаданные образов берёт, но Gradle внутри не тянет зависимости — рвётся на `junit-jupiter-api` (ровно то, ради чего заведён MTU-сборщик) |
| новый сборщик на хостовой сети | не смог скачать сам `moby/buildkit` |
| классический сборщик в сети 1380 с локальными образами | висит без вывода, контейнер не поднимается |

С хоста реестр отвечает (401 — это нормальный ответ без токена), интернет
есть; недоступен он именно из сетей Docker. Похоже на состояние VPN или
демона, а не на дефект сборки: те же файлы собирались этим же скриптом
сутки назад.

**Стенд остался на прежней версии** — сборка не подменяла образы наполовину.
Тесты при этом идут: они запускаются в уже загруженном образе `gradle`.

Как только сеть восстановится, выкат — одной командой:

```bash
ops/deploy-local.sh api web
```
