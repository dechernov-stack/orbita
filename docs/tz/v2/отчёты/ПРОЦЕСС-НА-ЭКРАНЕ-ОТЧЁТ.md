# Отчёт: процесс на экране — мероприятие как единица работы

Решение принято и исполнено: поверхность работы — та же схема, которую
исполняет движок; единица работы — мероприятие метода, а не форма.

## Приёмка решения

| Пункт | Состояние | Чем закрыт |

## Что появилось

**Мероприятие как сущность интерфейса.** У блока есть код метода (ROM или
наш), имя, цель, роль, дорожка, входы, выходы и рабочая поверхность.
Выходы — не галочки, а СЧЁТЧИКИ из данных: «пользователи миссии 3/3 ·
потребности 5/3 · цели и задачи → сцена 4».

**Выход, рождающийся в другой сцене, помечается стрелкой, а не пустотой.**
По Романову цели — выход мероприятия 0.1; у нас они рождаются в сцене 4.
Так и написано: «цели и задачи → сцена 4», и завершение 0.1 этим не держится.

**Мероприятие закрывается само.** Ручного «готово» нет: выходы есть —
блок выполнен, следующий стал доступен. Состояний пять: не начато ·
доступно · в работе · выполнено · ждёт входа (с причиной).

**Мероприятие без вида выхода не объявляется выполненным.** Дорожка
моделирования показывает мероприятия метода (0.M1–0.M12), которых наш
продукт ещё не считает: они честно стоят «не начато» и говорят, чего ждут,
вместо зелёного «выполнено» на пустом месте.

**Карта «сцена ↔ мероприятия» — генератором.** `tools/v2/gen_phase_activities.py`
разворачивает полку процессов ЖЦ в шаблон фазы: 15 мероприятий в 11 сценах
плюс дорожки моделирования (12) и управления (1). Сторож в CI.

**CMMN получил human task на каждое мероприятие.** Единица работы метода
стала единицей работы движка; схема и модель дела рождаются из одного
шаблона.

## Честные остатки

1. **Дорожка моделирования не связана с записями моделей.** Мероприятия
   0.M1–0.M12 показаны из полки метода, но не сопоставлены нашим моделям
   М1–М14 (волна 4). Сопоставление — следующий шаг: тогда лента
   моделирования оживёт счётчиками прогонов.
2. **Потоки между дорожками не нарисованы.** В эталоне стрелка «пользователи
   миссии (3 → сцена 3)» идёт из сцены в мероприятие моделирования; сейчас
   дорожки живут параллельно, связь видна только текстом входа.
3. **Стандартная нотация (bpmn-js / cmmn-js) не подключена** — по решению
   владельца это отдельный вопрос из-за водяного знака лицензии.
4. **Рабочие поверхности пока привязаны к сцене, а не к мероприятию.**
   Клик по блоку выбирает мероприятие и показывает его карточку, но фрагмент
   под ней — экран сцены целиком (у сцены 3 это список стейкхолдеров).
   Разводить фрагменты по мероприятиям (`surface` уже лежит в данных) —
   работа следующего шага.
