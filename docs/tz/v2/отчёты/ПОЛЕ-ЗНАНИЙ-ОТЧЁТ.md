# Поле знаний: живой разбор — отчёт первого захода

Вход: `ЗАДАНИЕ-ПОЛЕ-ЗНАНИЙ-ЖИВОЕ.md` (решение владельца 06.09) — проект
основан на знаниях, инженер принимает решения, а не набирает содержание.

## Что заработало

**Живой вызов разрешён и сделан.** Контур `core/v2/ai`: прямой транспорт к
провайдеру (Messages API), три попытки при перегрузке (2 · 4 · 8 с),
журнал вызовов сущностью проекта. **Один вызов на версию документа**: ключ
кэша — отпечаток промпта; повтор возвращает записанный ответ и не звонит.

**Д1 — канон детерминированный.** `Canon`: текст → блоки с якорями
`s<раздел>` и `s<раздел>#<абзац>`, отпечаток версии. Те же якоря при том же
тексте — иначе на факт не сошлёшься.

**Д2б — атомизация.** Промпт несёт правила честности §6 и КОНТЕКСТ ПРОЕКТА
(ограничения Р, паспорт): величина документа сталкивается с рамкой на
входе, а не на приёмке. Ответ — JSON с темами и фактами.

**Ворота — на нашей стороне.** `Intake.putFacts` не принимает: факт без
якоря; якорь, которого нет в каноне; величину вида `quantity` без единицы;
факт без утверждения или значения. Отклонённое называется поимённо.

**Диспозиции — решение человека.** `free → noted | assumed | adopted |
rejected | contested`; без причины диспозиция не ставится. Темы заводятся
разбором и считают свои факты.

**Идемпотентность.** Повторный разбор той же версии не звонит И не
удваивает факты: факт узнаётся по месту в документе (материал · якорь ·
утверждение). Оба свойства — из живого прогона, оба закрыты тестом.

## Живой прогон на стенде (06.09)

Записка Минтранса (3 190 знаков, 15 абзацев) → **один вызов, 51 с,
2 251 токен входа, 6 512 выхода** → **32 факта с якорями, 6 тем, 0
отклонений**. Виды фактов: obligation, capability, quantity, framing,
relation, assessment, assumption. Метки [И]/[В]/[П] проставлены моделью и
приняты воротами. Повтор — 0,1 с, ответ из журнала, новых фактов 0.

## Мера задания — что закрыто и что нет

| Пункт | Состояние |
|---|---|
| один живой вызов на версию; повтор без вызова | ✓ живой прогон и `KnowledgeIntakeTest` |
| факты с якорями, темы, отклонение фактов без якоря и единицы | ✓ 32 факта, 6 тем, ворота проверены |
| ≥ 80 фактов, ≥ 10 тем | частично: на записке в 3 190 знаков вышло 32 и 6 — пропорционально объёму. Полной записки (той, что дала 101 кандидата в Р05) на стенде нет |
| план действий с предпросмотром и акцептом | ✗ план собирается прежним каталогом намерений; действия из фактов не строятся |
| сцены 2–6 показывают предложения из фактов | ✗ не сделано |
| одиннадцать нормативов на полке | ✗ не сделано |
| доля сущностей с `derived_from_fact` ≥ 80 % | ✗ связь не заводится: акцепт плана ещё не создаёт сущности из фактов |
| сверка с Р05: покрытие классов ≥ 90 % | ✗ не сделано |
| экран поля знаний | ✗ не сделано (сервер готов: факты, темы, диспозиции, журнал) |

## Что дальше — по порядку

1. **Д2в план и акцепт**: из фактов строятся действия с предпросмотром
   («в сцену 3 — 10 сторон, 6 нужд»), акцепт создаёт сущности со связью
   `derived_from_fact` и ставит диспозицию `adopted`. Это ключ к доле
   80 %, и без него остальные пункты меры не измеряются.
2. **Сцены читают поле знаний**: предложения вместо пустой формы.
3. **Одиннадцать НПА карточками** (реквизиты названы в задании §2).
4. **Экран поля знаний** по `ДИЗАЙН-ПРИНЦИПЫ-V2`: темы, диспозиции,
   источники; из мероприятия рейка «⇣ входы» ведёт в факты его темы.
5. **Сверка с Р05** отчётом расхождений.

**Вопрос владельцу.** На стенде нет полной записки миссии (той, из которой
собран Р05 со 101 кандидатом): есть служебная записка Минтранса на 3 190
знаков. Пришлите md-версию полной записки — тогда мера «≥ 80 фактов» будет
проверена на том же документе, что и Р05, и сверка покрытия станет честной.
