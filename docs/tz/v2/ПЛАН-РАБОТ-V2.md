# План работ «Орбита v2» — backend, frontend, контент, приёмка

06.09.2026 · для Code (исполнение), Codex (пилоты → модули), внешний
контур (модель, эталоны, контент, разбор), владелец (решения, проход).

## 0. Рамка

**Цель v2.** Продукт ведёт команду по фазам: процесс — данные и движок,
сущности знают сцену рождения, ворота держат на сервере, документы —
структура с порождаемой прозой, интерфейс — русло сцен, а не склад
возможностей. Движок переделывается на треть, интерфейс — с чистого
листа поверх тех же данных.

**Основания** (всё утверждено или на утверждении): `МОДЕЛЬ-ДАННЫХ-V2`,
`РЕЕСТР-СУЩНОСТЕЙ-V2` + `СХЕМЫ-ПОЛЕЙ-V2.yaml` (86 видов),
`МОДЕЛЬ-ТРЕБОВАНИЯ-И-КОМПОНЕНТЫ`, `КОМПОНЕНТ-ГРАНИ`, `ГЛУБИНА…`,
`ПОЛЕ-ЗНАНИЙ`, `ИНТЕЛЛЕКТУАЛЬНАЯ-ЗАГРУЗКА`, `ДОКУМЕНТЫ-1/2`,
`РЕШЕНИЕ-ДВИЖОК`, `РЕШЕНИЕ-МЕХАНИКА-ДОКУМЕНТОВ`, `ТЗ-BACKEND-V2`,
`СЦЕНАРИЙ-PRE-A`, `ОНТОЛОГИЯ-PRE-A`, `РОМАНОВ-СТАДИИ-0-2`,
обзоры пилотов FlowPilot и DocPilot.

**Правила исполнения.** Strangler: новое рядом со старым за флагами.
Модули с Konsist. Приёмка волны — **проходом владельца по сценам**, не
сверкой репозитория и не тестами исполнителя. Токены службы — пакетами
и внешним контуром; живые вызовы — только там, где проверяется живой
контур. Ни одного экрана без брифа и эталона.

## 2. Frontend — принципы и инвентарь

**Принципы.** Экран = сцена; вход один — «Работа» (лента сцен и точек);
всё, чего сцена не требует, не существует (эксперт-режим — явный
переключатель); карточка раскрывается **вниз**; статус — текстом и
цветом; панели с заголовком и счётчиком; пустое состояние — текстом с
причиной и переходом; ни одного `disabled` без причины; ни одной
мёртвой ссылки; служебных имён видов в тексте — ноль; каждый экран —
по брифу и эталону, отклонение — с обоснованием.

## 4. Приёмка

- **Каждая волна** — ворота: проход владельца по сценам волны с
  артефактами по именам шагов; `SpineTest` зелёный; Konsist зелёный;
  сторожа (мёртвые ссылки, disabled, служебные имена, `undefined`,
  обрезки, домен в движке, чтение чужих таблиц, вид вне YAML).
- **Отчёт волны** — таблицей «сцена · прожита/нет · тег · вопросы»,
  без пересказа процесса; открытые вопросы — решениями владельца до
  следующей волны.
- **ПМИ-5** в волне 7 — итоговая: по сценарию, ноль живых вызовов
  кроме одного назначенного, восемь выходов на столе.

## 5. Роли

- **Code** — backend и frontend по ТЗ и эталонам; шипами, за флагами.
- **Codex** — короткие пилоты (FlowPilot 2: генератор CMMN из шаблона,
  рестарт, event listener; день живого ИИ на DocPilot); код пилотов
  переносит Code.
- **Внешний контур** — модель, эталоны, контент, пакеты, разбор
  артефактов прохода; не сверка репозитория.
- **Владелец** — решения (в начале волны), проход (в конце волны),
  легенда, приоритеты.

## 6. Риски и ловушки

1. Переписать всё сразу — нет: strangler, старое живёт до замены.
2. Интерфейс уйдёт от эталона — ворота волны это ловят проходом, не
   отчётом.
3. Домен утечёт в Flowable — Konsist + сторож переменных процесса.
4. Сторож чисел задушит прозу — день живого ИИ до интеграции; список
   исключений данными.
5. Токены — пакеты и внешний контур; живые вызовы по назначению.
6. Разрастание Phase B — только полка шаблонов, без экранов.
7. Пилоты вместо продукта — код пилотов переносится в модули, не
   живёт рядом.
