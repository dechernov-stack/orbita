# Задание Code · Шип 6 — ИИ в Phase A и долги прогона (≈ 1,5–2 недели)

Состояние на `c871702`: обе фазы проходятся скриптом до Phase B, карта фазы
строками, лесенка окон, служебный ключ и песочница (ADR-071/072) на 216.
Владелец ведёт новый рабочий проект через обе фазы руками.

Вопрос владельца, на который шип отвечает: **«где в системе ИИ»**. В Pre-A он
есть (чтение документа, раздачи нужд и целей, связный текст, применимость).
В Phase A — почти нет: деривация требований, функции, стыки, анкеты узлов и
риски заводятся руками по одной записи, а это самая объёмная работа фазы
(17 элементов × лестница к SDR). Шип даёт Phase A помощников — **тем же
механизмом, что раздачи Pre-A**: машина находит, модель формулирует,
человек принимает пакетом.

## Режим

* **Рабочие проекты владельца не трогать** — ни записью, ни живым вызовом.
  Живые вызовы — локальная копия `PJ-ПМИ7` (Phase A) или песочница на 216
  (ADR-072). Документы с грифом в живой вызов не идут.
* **ИИ пишет только предложения.** Ни одной записи сущности мимо приёма.
  Ворота — только машинные (правило «читать смысл», 15.09).
* Истина — диффом владельца; нужно поле — строка в NEXT.md, экран живёт без него.
* Каждый параграф — коммит, тесты, CI; выкат — по слову, одним в конце
  (или §0 отдельно, если владелец попросит раньше).

## §0 · Долги прогона (1–2 дня)

1. **Единицы — одна истина в хранилище v2.** `GET /v2/units` отдаёт 183
   единицы полки LIB, а `Normalize` читает записи вида `unit` хранилища v2,
   которых на стенде нет — поэтому «180 мин» и «3 ч» несравнимы. Засеять вид
   `unit` из полки LIB (размерность, множитель, каноническая) загрузчиком
   полок; `/v2/units`, `Normalize`, пикер величины — читают одно. Тест:
   `≤ 180 мин` против `≤ 2 ч` — противоречие; против `≤ 3 ч` — подтверждение.
2. **Оператор величины у факта.** Истина уже держит `fact.value: measure{op?,…}
   | text` — приём его теряет, это дефект кода, не истины. Писать величину
   факта объектом `measure` с оператором; миграция при старте разбирает
   старые значения с числом и единицей. Правило противоречий начинает
   учитывать оператор (`≤ 180` и `≥ 120` — не спор).
3. **Хозяин словаря — ведущий СИ** (умолчание, владелец не возражал):
   принять · слить · отклонить кандидата — роль `si` проекта или «от имени».
   Инженеру — «предложить термин» (кандидат с его именем).
4. **После KDP-B фаза не «переоткрывает» A1.** Нет шаблона Phase B — карта и
   «Работа» говорят «Phase A завершена · решение KDP-B от …; шаблон Phase B
   не заведён», без мнимых сцен.
5. **Коды зрелости Романова** — ждут легенды владельца; ничего не делать.

## §2 · Пять помощников Phase A — одним механизмом

Общее для всех:
* **Вход — срез картины**, не весь проект: узел и его соседи, родительские
  требования, базовая концепция, ConOps; призма — базовый вариант и границы
  устава (как у чтения).
* **Выход — предложения** в «Поле знаний → Предложения» с отбором по прогону;
  кнопка помощника ведёт туда сама. Приём — массовый (шип 5 §1.4), принятое
  засчитывается условиями сцены.
* **Журнал** — токены, секунды, отпечаток среза; повтор на том же срезе —
  из кэша, без живого вызова.
* **Кнопка — в контексте**, не в разделе «Инструменты»: на карточке узла, в
  строке долга, в шапке реестра сцены.

| # | Помощник | Где кнопка | Машина находит | Модель формулирует | Машинные ворота (тест на отказ у каждого) |
|---|---|---|---|---|---|
| 2.1 | **Деривация требований вниз** | карточка узла (A4), реестр системных (A5): «предложить требования узла» | родительские требования, распределённые на узел или его предка; бюджеты с долей узла | требование узла: формулировка EARS, показатель, обоснование, связь `derives` на родителя | родитель существует и выше уровнем; единица из справочника; **сумма долей бюджета ≤ родителя** (масса, мощность, линия); без родителя — отказ |
| 2.2 | **Функции и обмены из сценариев** | A3/A5: «функции из сценариев» | шаги сценариев ConOps с участником-узлом | функция (глагол + объект), элемент обмена между участниками шагов, размещение на узел | участник — узел состава; функция без узла — не предлагается; дубль по ключу идентичности — augment, не new |
| 2.3 | **Стыки из обменов** | A4/A5: «стыки узла» | обмены, пересекающие границу узла; внешние участники сценариев | стык: стороны, тип и направление словами истины, строка ICD; внешняя система — стороной | обе стороны — узлы состава или внешняя сторона; тип и направление — из перечня; повтор существующего стыка — confirm |
| 2.4 | **Анкета узла из паспорта изделия** | строка долга узла «параметры»: «из документа поставщика» | документ роли `supplier`, связанный с узлом (поставщик полем, 27.09-b) | величины анкеты с цитатой и якорем | цитата в каноне документа; единица из справочника; ключ анкеты существует; число без цитаты — отказ (сторож чисел) |
| 2.5 | **Риски из разрывов** | реестр рисков (A8): «риски из разрывов фазы» | TRL ниже порога точки; грани лестницы, пустые к ближайшей точке; запас бюджета ниже политики; непокрытые требования | риск: условие · событие · последствие, владелец по ответственному сцены, срок-точка | каждый риск ссылается на свой разрыв (код); без разрыва — отказ; дубль открытого риска — augment |

2.5 — **машина находит все разрывы сама**, без модели; модель только пишет
формулировку. Если модели нет — предложение приходит с шаблонной
формулировкой («Если TRL узла X к SDR останется N, то…»). ИИ не на
критическом пути.

## §3 · День живой модели — на копии `PJ-ПМИ7` (Phase A)
