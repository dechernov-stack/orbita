# Code · §2.1 — ворота бюджета переделать; дальше C2-приём, потом D

Уровни (`0b2237f`) и порт мер (`640d594`) приняты. Ворота бюджета
(`75bd250`) считают не то, и это надо поправить до D — иначе живой день
§3 утонет в ложных отказах.

## Что не так

1. **Сумма применяется к любому мерному родителю.** «Покрытие ≥ 0,9»,
   «доступность ≥ 99 %», «P95 ≤ 180 мин» — не бюджеты: доли у них не
   складываются. Сейчас два дочерних «покрытие ≥ 0,9» дадут «1,8 > 0,9» и
   отбой.
2. **Считается только партия.** Сестринские требования того же родителя,
   принятые раньше на других узлах (КА взял 60 кг из 100), не входят в
   сумму — следующий узел с 50 кг пройдёт.
3. **Отбой партии целиком** на стороне предложения выбрасывает ответ модели
   (токены) из-за ограничения, которое реально проявляется только при
   приёме.

## Как надо

**Бюджет — это не любой мерный родитель, а родитель, на которого ссылается
запись `budget` (`budget.requirement`).** Истина это уже держит: у бюджета
есть вид (масса · мощность · энергия · линия · Δv · данные · вычисления),
корень и политика резервов.

* **Родитель-бюджет** (есть `budget` с `requirement = родитель`, вид
  аддитивный — все, кроме `link`, где складываются дБ запасов, тоже ок):
  сумма = **принятые дочерние** (связь `derives` на родителя, любые узлы) +
  **принимаемые** ≤ значение родителя × (1 − резерв). Резерв — число
  процентов, если `reserve_policy` его называет («20 %», «маржа 15 %»); нет
  числа — без резерва, как в умолчании §6.3, и помета «политика резервов
  не задана числом».
* **Родитель не бюджет, но мерный**: суммы нет. Две проверки на каждого
  ребёнка отдельно — **та же размерность** и **не мягче родителя**
  (родитель `≤ 180 мин` → ребёнок `≤` и не больше 180; родитель `≥ 0,9` →
  ребёнок `≥` и не меньше 0,9). Оператор ребёнка противоположный — отказ
  этого предложения, не партии.
* **Где ставится сумма.** При предложении — **не отбой, а помета** на
  долях: «сумма долей 120 кг при бюджете 100 кг (принято 60, предложено
  60)». Отказ — **при приёме**: принять долю сверх бюджета нельзя, отказ
  словами с разбивкой; уменьшить долю — правка на месте в карточке
  предложения. Так бюджет делит человек, а ответ модели не пропадает.

Тесты на отказ: два «≥ 0,9» — отказа нет; принятое 60 + предложенное 50 при
бюджете 100 — помета при предложении, отказ при приёме второго; резерв
«20 %» — потолок 80; родитель `≤ 180`, ребёнок `≥ 10` — отказ одного
предложения, остальные в партии живут.

## Порядок

Ворота бюджета как выше + **C2-приём** (связь `derives` при приёме, там же,
где сумма) — одним абзацем приёма. Затем **D** (маршрут, кнопка на карточке
узла, полоса предложений над реестром с отбором по узлу). Затем 2.2–2.5.
Выката нет.
