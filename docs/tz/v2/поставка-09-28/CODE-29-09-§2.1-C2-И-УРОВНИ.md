# Code · §2.1 — C2 да, плюс уровни требований и место приёма

**C2 через публичный порт `Measures` над `Normalize` — да**, именно так:
одна истина единиц, помощник спрашивает порт, контур противоречий — тот же.

## 1. Уровни требований — диф `СХЕМЫ-ДИФФ-29-09-УРОВНИ-ТРЕБОВАНИЙ.patch` (к `add7266`)

`RequirementDeriver.выше()` сравнивает уровни порядком значений перечня
`[project, scenario, system, subsystem, interface]`. Это ломает §2.1 в двух
местах:
* **У элемента A4 нет уровня** — ни `segment`, ни `element` в перечне нет;
  модель поставит «подсистемное» или «системное», а 17 узлов A4 — это
  ровно элементы.
* **`interface` последним** — значит «ниже подсистемного», и помощник
  разрешит «вывести» интерфейсное из подсистемного; а `scenario` окажется
  «выше системного» случайно.

Диф: `requirement.level += segment, element` (со словами), правило
`formation.requirement_level_rule` — порядок ступеней **project → system →
segment → element → subsystem**; `scenario` — ветвь проектной ступени;
`interface` — не ступень, а род носителя (уровень — старшая ступень узлов
стыка). **Уровень требования с носителем-узлом выводится из вида узла**
(`component.kind` → level), модель его не выбирает — уберите `level` из
схемы ответа деривации и из промпта. `выше()` читает порядок из правила,
не из перечня. `gen_ontology.py` — новый известный раздел, как
`model_basis_rule`. Тест на отказ: элемент → элемент (одна ступень),
подсистемное → интерфейсное, проектное → сценарное через системное.

Старые записи не мигрировать — перечень только расширился; где у
требования носитель-узел вида `element`, а уровень иной, — строкой долга
в карточке («уровень не по носителю»), не автоматом.

## 2. Кнопка ведёт не в «Постановку»

В отчёте: «кнопка ведёт в „Постановку“ с отбором по SR-N». Постановка — это
Pre-A (стороны, нужды, цели). Предложения требований узла принимаются в
двух местах, и оба уже есть:
* **«Поле знаний → Предложения»** с отбором по прогону — общее место
  всех помощников (шип 5 §3.3);
* **полоса «Предложения требований» над реестром** (шип 5 §4) — с отбором
  «носитель = узел», когда кнопку нажали на карточке узла.

Кнопка на карточке узла открывает второе; из шапки прогона — первое.
