# `v2-deadline-and-oda` — принят; истина схем синхронизирована; три правила

Истина схем взята **из репозитория** (`docs/tz/v2/СХЕМЫ-ПОЛЕЙ-V2.yaml`
после слияния Code) — расхождений поставок больше не будет: правлю
поверх слитого, `bound` и поля снимка сохранены.

## Два дефекта одного класса — «проверка, которая молча проходит»

1. Срок хранился идентификатором, шаблон искал по коду — ни один срок не
   находился, **точка объявляла себя готовой, ничего не проверив**.
2. Порог «Б1: увод не более 5 лет» читался как число **1** из
   обозначения норматива — честный увод объявлялся нарушением.

Оба пойманы живьём. Правила, чтобы класс закрылся:
- **У каждого критерия готовности — тест на отказ**: фикстура, при
  которой критерий обязан вернуть «не выполнено» с причиной; критерий
  без отрицательного теста не регистрируется. Пустой результат
  проверки ≠ «выполнено».
- **Пороги — только полями**, не числа из строк: `constraint.bound`,
  `normative_document.clauses[].limit {key, op, value, unit}`,
  `metric.threshold`. «Перед словом „лет"» — всё ещё разбор прозы;
  порог Б1 живёт полем `limit` у пункта нормы, ODA читает его.

## Дата вехи технологии

Верно, что веха без даты — состояние с причиной, не «всё хорошо».
Источник даты — **плановый конец пакета созревания** (WBS): веха
рождается разрывом TRL вместе с пакетом, дату получает от его плана;
ручной `POST` даты — только пока пакета нет, с пометой «дата вручную».

## Принято отдельно

`compliant_*` из тела запроса выбрасываются — вердикт вычисляется;
MCR держится открытым риском массы, чей срок наступил, — тем самым,
что печатает свёртка: впервые ворота и свёртка говорят одно и то же.
