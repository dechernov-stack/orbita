# Картина мира проекта — онтология «Орбиты» целиком

Одна картина: все понятия проекта, их границы и связи — внешние (мир
→ проект) и внутренние (постановка → система → требования →
подтверждение → программа → процесс → документы). Факты наполняют
картину основаниями, не заменяют её. Читать как единое; уровни
«документ → факт → предложение → сущность» и четыре оси достоверности
— из аудита, здесь не повторяются.

## Девять областей и их понятия

### 1 · Мир (внешнее по отношению к проекту)

| Понятие | Что это | Чем не является |
|---|---|---|
| Сторона | организация/группа, участвующая в проекте (заказывает · регулирует · эксплуатирует · потребляет · поставляет · финансирует · создаётся) | не издатель акта, не место, не система |
| Интерес | чего сторона хочет от проекта | не нужда, пока не принято |
| Норма | внешний акт с пунктами-обязательствами и редакцией | не сторона; не ограничение сама по себе |
| Программа / чужая цель | цель или показатель чужой программы, заказчика | не цель проекта |
| Обстановка | рынок, география, объёмы, аналоги, события | факты, не сущности |

### 2 · Постановка

| Понятие | Что это | Чем не является |
|---|---|---|
| Устав | документ-рамка: замысел, границы, призма | не «главный источник фактов» |
| Замысел | для кого · что · где · горизонт | не цель |
| Нужда | чего не хватает; носителей много | не роль, не свойство системы, не норма |
| Цель | измеримый результат к сроку, только по уставу решением | не показатель, не требование, не чужая цель |
| Сервис | что система даёт кому, с классом обслуживания | не нужда, не функция |
| Ограничение | запрет/граница для проекта с Р-кодом и числом | не требование, не норма |
| Класс обслуживания | A′/B′/C′: задержка и гарантия | справочник |
| Применимость | чужая нужда × наша способность → вердикт | не цель, не сервис |
| Допущение | принято на веру до точки | не факт [И], не риск |

### 3 · Система (структура — PBS)

| Понятие | Что это | Чем не является |
|---|---|---|
| Узел (определение) | элемент состава: сегмент · элемент · подсистема · агрегат · блок; род `node` (железо) или `behaviour` (ПО) | не вхождение |
| Вхождение | сколько раз и где узел входит (КА ×36, БЦВМ ×2) | не узел |
| Параметр | величина узла: значение · единица · класс зрелости · происхождение · к какой точке | не свойство «в тексте» — сущность с версией |
| Стык (интерфейс) | физическая/организационная связь двух узлов с типом, параметрами, разделами ICD | не обмен |
| Вариант построения | конфигурация орбит и группировки | не состав |
| Базовая концепция | выбранный вариант + обоснование + отклонённые + descopes | не цель |
| Технология | критическая технология узла с TRL текущим/требуемым | не параметр |
| Внешний элемент модели | элемент Capella по UUID, зеркалящий узел | не источник истины требований |
| Типовой узел / каркас PBS / анкета | библиотечные шаблоны с лестницей зрелости | не проектные данные |

### 4 · Система (поведение — Arcadia)

| Понятие | Что это | Чем не является |
|---|---|---|
| Способность (OC) | что система умеет для сторон | не сервис (сервис — обещание, способность — умение) |
| Функция (SA/LA) | что делает система/компонент | не узел |
| Обмен | поток между функциями, идёт по стыку | не стык |
| Элемент обмена | что именно идёт: команда, ТМ-пакет, сообщение — со структурой и единицами | не обмен |
| Цепочка | последовательность функций = сценарий операций | не требование |
| Логический компонент | группа функций, развёрнутая на узлы | не узел PBS |
| Режим / состояние | машина режимов компонента: состояния, переходы, что активно | не функция |

### 5 · Требования

| Понятие | Что это | Чем не является |
|---|---|---|
| Требование | проверяемое «носитель должен …»; уровни: проектное · сценарное · системное · подсистемное · интерфейсное | не цель, не ограничение, не пожелание |
| Носитель | узел · стык · цепочка — по природе уровня | не «автор» |
| Показатель | пара «оператор · значение · единица», TBR с владельцем и точкой | не текст |
| Источник требования | цель · нужда · ограничение · норма · родительское требование, с якорем | не «документ вообще» |
| Связь (объект) | вид из реестра · обоснование · версия · `suspect` | не поле |
| Типовое требование | библиотечное, с применимостью в проекте | не проектное |
| Базовая линия | именованный снимок набора (объект, версия): функциональная · allocated · product | не флаг у записи |
| Конфликт | два требования, противоречащие друг другу; блокирует точку | не помета |

### 6 · Подтверждение

| Понятие | Что это | Чем не является |
|---|---|---|
| Модель системы | что считаем, из каких параметров, к какой точке; статус: не построена · прокси · расчёт · верифицирована | не документ |
| Прогон модели | выход расчёта с версией и снимком входов | не запись модели |
| Метрика | число для сравнения вариантов с порогом | не показатель требования |
| Бюджет / свёртка | масса · энергия · линк · Δv · compute · data с резервами по классу и по ступени | не параметр |
| Событие верификации | требование × метод × результат × дата | не план |
| Запрос данных | анкета узла на текущую ступень | не параметр |
| Оценка засорения | активный увод + пассивный сход, оба против норм | не риск |

### 7 · Программа

| Понятие | Что это | Чем не является |
|---|---|---|
| Пакет работ (WBS) | работа с парой к узлу или сквозная | не узел |
| Оценка | диапазон стоимости/сроков с допущениями по WBS | не число |
| Пакет созревания | работа по подъёму TRL с вехой | не риск |
| Веха / этап | этап проекта или веха технологии с датой | не срок действия нормы |
| Риск | условие → событие → последствие, владелец, срок-точка | не допущение |
| План | даты точек и окна сцен | не Гант (Гант — вид) |
| Задание | поручение человеку на мероприятие или разрыв | не мероприятие |

### 8 · Процесс

| Понятие | Что это | Чем не является |
|---|---|---|
| Фаза | Pre-A · A · B … с шаблоном сцен и точек | — |
| Сцена | крупная работа фазы с входом, выходом, условиями | не задача |
| Мероприятие | единица работы внутри сцены (Романов), с входами и выходами | не шаг, не задание |
| Точка | контрольная точка с критериями; экспертиза — её содержание | не сцена |
| Критерий | проверка по данным, привязанная к сцене, блокирующая или нет | не пожелание |
| Ступень / зрелость | ступень компонента (концепт · определение · архитектура · проект) и зрелость артефакта к точке | не статус |
| Решение | акт DA/РП с исходом и основанием | не помета |
| Замечание | RFA/RID с возвратом в сцену | не риск |

### 9 · Документы и знание

| Понятие | Что это | Чем не является |
|---|---|---|
| Документ-источник | входной: роль · ранг · версия · резюме · вклад | не документ проекта |
| Факт | утверждение источника с цитатой, якорем, диспозицией | не сущность |
| Тема | предмет фактов до разрешения в сущность | не сущность |
| Предложение | кандидат в сущность из фактов, с вердиктом | не сущность |
| Документ проекта | снимок сцен по шаблону: разделы → элементы | не текст |
| Элемент раздела | ссылка на сущность/факт, тезис, запрос, фигура | не абзац |
| Рендеринг | порождённый текст версии, только из элементов | не источник истины |
| Выпуск | напечатанная версия с авторами и тегом | не документ |

## Сквозные цепочки — то, что делает картину картиной

1. **Трасса требования вниз**: сторона → нужда → цель → требование проектное → системное → носитель (узел · стык · цепочка) → функция → узел → параметр → модель → бюджет → рамка Р.
2. **Трасса требования вправо**: требование → метод → событие верификации → точка → базовая линия.
3. **Трасса денег**: узел → пакет WBS → оценка → план → веха → FA.
4. **Трасса технологии**: технология → узел → разрыв TRL → пакет созревания → веха → условное базирование требований и параметров → PDR.
5. **Трасса процесса**: фаза → сцена → мероприятие → выходы → раздел документа → зрелость → точка → решение → базовая линия → фаза.
6. **Трасса знания**: документ → факт → предложение → сущность (основание) → документ проекта → верификация против поля.
7. **Трасса применимости**: чужая нужда (факт) → применимость → сервис → нужда → сторона.
8. **Трасса поведения**: сценарий (цепочка) → функции → обмены → стыки → элементы обмена → ICD; режимы → активные функции → бюджет compute.

Любая сущность обязана лежать хотя бы на одной цепочке — иначе она
вне картины (сторож: «сущность без трассы»).

## Инварианты картины (сторожа — те же, собранные вместе)

1. Нужда без стороны · цель без нужды · сервис без нужды и класса ·
   требование без носителя и источника — не существуют.
2. Функция без узла к SDR · обмен без элемента обмена к SDR ·
   behaviour без node · цепочка без сценарного требования — разрывы.
3. Параметр без единицы и происхождения — не принимается; `computed`
   без прогона — нет; свёртка печатает оба резерва и сверяет с рамкой
   с системным.
4. Требование, зависящее от технологии с разрывом, базируется только
   условно до её вехи; к PDR условного нет.
5. Точка фиксируется решением, переход фазы — только им; критерий
   только читает; критерий без отрицательного теста не регистрируется.
6. Документ проекта — только снимок сущностей; число в тексте без
   элемента — отказ; базовая линия неизменяема.
7. Факт без цитаты и якоря — не факт; сущность без основания — только
   с провенансом «эксперт»; предложение не меняет принятого.
8. Сущность вне сцены рождения не создаётся; ссылка вперёд по сценам —
   нет; библиотека → проект только «взятием», проект → библиотека
   только «обобщением».

## Как это станет истиной

Этот документ + аудит (уровни, оси достоверности, границы понятий
постановки) = онтология. Схемы полей — её техническая проекция: у
каждого понятия — его поля; правила образования как отдельный файл
исчезают. Полки — контент по этой картине. Промпты и инструменты
модели читают картину срезами; словарь именует её понятия.
