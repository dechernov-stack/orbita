# Модель данных «Орбиты» v2 — процесс и MBSE одной структурой

Проектируется на бумаге, до кода. Две опоры: **процесс** (регламент:
фазы → сцены → артефакты → ворота) и **MBSE** (Arcadia: OA → SA → LA →
PA; требования — у нас, архитектура объясняет их выполнение). Всё,
что построено, — куски; здесь — как они складываются.

## 0. Принципы

1. **Процесс — данные.** Фаза, сцена, ворота, критерий, решение —
   объекты; сцена знает, что рождает, что читает и что скрывает.
2. **Каждая сущность знает сцену рождения.** Ответ на «когда и в
   рамках чего это появилось» хранится, а не восстанавливается.
3. **Одна модель системы.** Постановка (OA), функции (SA/LA), состав и
   стыки (PA) — слои одной модели; документы — её снимки.
4. **Требования управляются здесь; архитектура объясняет.** Capella и
   любой внешний MBSE — только на чтение, связи с обоснованием.
5. **Всё вычисляется**: статусы, покрытие, готовность, матрицы,
   прогресс. Ручной ввод — только факты и решения людей.
6. **Две области**: библиотека (шаблоны, справочники, нормативы) и
   проект (факты); ссылка проект → библиотека законна, обратная — нет.
7. **История битемпоральна, происхождение обязательно**: канал, автор-
   человек, источник с якорем; служба — происхождение, не автор.

## 1. Ядро — что есть у любой сущности

| Атрибут | Смысл |
|---|---|
| `id` · `code` | стабильный внутренний · человеческий, переименуемый без разрыва связей |
| `kind` | вид из реестра видов (схема, статусная модель, слой) |
| `area` | `library` \| `project:‹id›` |
| **`born_in`** | сцена (фаза · сцена · шаг), в которой сущность создана; сущность видна только со своей сцены и позже |
| `status` · `version` | по статусной модели вида; версии битемпоральны; правка наследует статус, на Approved/Baseline — только с основанием |
| `provenance` | канал (рука · пакет · служба · полка · импорт) · автор · источник · якорь · отпечаток |
| `relations[]` | типизированные связи из реестра связей, у каждой — `rationale` |
| `params{}` | величины парой `{op, value, unit}` из справочника; TBR — с владельцем и точкой |
| `notes` · `tags` | рабочее, не печатается |

## 2. Пять слоёв

| Слой | Что в нём | Arcadia | Сцены |
|---|---|---|---|
| **L0 Основания** (библиотека) | справочники (единицы, глоссарий, классы QoS, методы верификации, шкалы TRL и риска), нормативы с редакциями, полки-шаблоны: каркас PBS, стыки, архитектура, WBS, модели, типовые требования/риски/профили, шаблоны документов, **шаблоны фаз (сцены)** | — | до проекта |
| **L1 Процесс** (проект) | проект, фаза, **сцена** (экземпляр шаблона сцены), шаг, **точка/ворота**, критерий, решение, замечание, задание, план (даты), роль/учётка | — | 1 и далее |
| **L2 Постановка** | замысел, материал (канон · карта · урожай), стейкхолдер/актор, нужда, цель · показатель, ограничение, сервис, способность (OC), операционная активность, сценарий операций | **OA** | 2–6, 9 |
| **L3 Система** | требование (уровни: проектное · системное · подсистемное · сценарное · интерфейсное), носитель, функция, обмен, функциональная цепочка, логический компонент, **узел состава** (+ параметры, вхождение ×N), **стык**, внешний элемент модели, вариант построения, базовая концепция, технология/TRL, риск | **SA · LA · PA** | 7–11 (Pre-A), 3–10 (Phase A) |
| **L4 Подтверждение** | модель (запись: входы · выходы · версия · прокси/расчёт), метрика, бюджет/свёртка, событие верификации, матрицы и готовность (вычисляемые), WBS-пакеты, оценка | — | 7, 12, 16+ |
| **L5 Документы и обмен** | документ (шаблон · разделы · режимы [Т]/[С]/[Р]), вставка-снимок, проза, выпуск, результат, ICD; каналы ReqIF/StrictDoc, выгрузка знаний, Capella read-only | — | 9, 13, 14 |

Слой — не таблица, а правило: кто на кого ссылается. **L2 → L3 → L4 →
L5 — только вниз по номеру**; L1 ссылается на всё (как «где и когда»),
L0 — ни на что в проекте.

## 3. Процесс как данные

- **Шаблон фазы** (L0): упорядоченные шаблоны сцен; у сцены — вход
  (виды + условия), выход (артефакт: вид или документ + требуемая
  зрелость), **видимость** (какие виды открываются с этой сцены),
  роль, связь с соседями (`FS`/`SS`/`FF`/`INPUT` с обоснованием), шаги
  с целевыми местами (адреса по маршрутизатору).
- **Сцена проекта** (L1): экземпляр шаблона; статус вычисляется из
  наличия выхода и закрытых условий; план (даты) — от РП; ответственный.
- **Ворота**: точка + критерии; критерий = проверка по данным с
  привязкой к сцене-источнику; блокирующие запрещают фиксацию на
  сервере; решение — запись DA с датой; **переход фазы — только этим**.
- **Правило видимости**: сущность вида K доступна пользователю, если
  `scene_opens(K) ≤ текущая сцена проекта`; иначе вид не существует
  (эксперт-режим — явный флаг сессии).
- **Замечание** обзора → сцена возврата; **задание** = адресованный
  разрыв со сроком-точкой.

## 4. Реестр связей — единый

| Связь | Откуда → куда | Кратн. | Обоснование | Считается покрытием |
|---|---|---|---|---|
| `owns` | стейкхолдер → нужда | 1:n | — | нужда без владельца — нет |
| `covers` | сервис → нужда; цель → нужда | n:m | — | да (покрытие нужд) |
| `derives_from` (вид: декомпозиция · деривация · уточнение) | требование → требование / цель / нужда / ограничение | n:m | **да** | трассировка |
| `allocated_to` | требование → узел \| стык | n:1 | — | да («без носителя» = 0) |
| `satisfied_by` | требование → функция | n:m | **да** | да (функциональные) |
| `realized_by` | требование → цепочка | n:m | **да** | да (сценарные) |
| `allocation` | функция → узел | n:m | — | да (функция без узла — разрыв к SDR) |
| `flows_over` | обмен → стык | n:1 | — | — |
| `illustrated_by` | требование → диаграмма | n:m | — | **нет** |
| `traced_to` | способность → цель/нужда/ConOps; актор → стейкхолдер | n:m | — | привязка |
| `verifies` | событие верификации → требование | n:m | — | да (верификация) |
| `conflicts_with` | требование ↔ требование | n:m | **да** | блокирующий разрыв |
| `snapshot_of` | вставка документа → сущности | 1:n | — | устаревание с дифом |
| `input_of` / `output_of` | сцена ↔ артефакт | — | — | статус сцены |
| `pairs_with` | узел ↔ WBS-пакет | 1:1 | — | свёртки |
| `external_identity` | узел → внешний элемент (UUID) | 1:1 | **да** | носитель наравне |

Связь вида, не входящего в реестр, создать нельзя; связь вперёд по
сценам — нельзя.

## 5. MBSE-каркас (что взято из Capella и где живёт)

| Arcadia | У нас | Правило |
|---|---|---|
| OA: акторы, способности, активности | стейкхолдеры, способности (OC), сценарии операций | акторы ↔ стейкхолдеры `traced_to` |
| SA: системные функции, обмены, цепочки | функции (layer SA), обмены `flows_over` стыки, цепочки — носители сценарных требований | цепочка = сценарий ConOps |
| LA: логические компоненты | группировка функций с `deployed_to` узлами | не обязательна в Pre-A |
| PA: физические компоненты, связи | **узлы состава = PBS**, стыки = физические связи | единственная физическая правда |
| Requirements Viewpoint | наши требования → ReqIF (StrictDoc) → Capella на чтение | Capella не источник требований |
| Диаграммы | `model_element` type Diagram, `illustrated_by` | не покрытие; приложение к обзору |
| Идентичность | UUID — истина, имя — снимок с датой | бэкенд в модель не пишет |

## 6. Уровни требований — явно

| Уровень | Источник | Носитель | Сцена |
|---|---|---|---|
| проектное | цель · нужда · ограничение | корень / сегмент | Pre-A 8 |
| сценарное | сценарий ConOps | цепочка | Pre-A 9 / Phase A |
| системное | проектное (деривация) | сегмент · элемент · **стык** (интерфейсное) | Phase A 4 |
| подсистемное | системное | подсистема · компонент | Phase A 5+ |

## 7. Инварианты модели (сторожа завтрашнего дня)

1. Сущность без `born_in` не существует. 2. Вид не виден раньше своей
сцены. 3. Связь вне реестра невозможна; вперёд по сценам — невозможна.
4. Требование без носителя и источника — не требование; интерфейсное —
только на стык; сценарное — только на цепочку. 5. Функция без узла к
SDR — разрыв. 6. Документ — только снимок; вставка помнит версии
источников. 7. Статус вычисляется; ручного нет. 8. Переход фазы — только
решением ворот. 9. Величина — парой с единицей справочника; без
источника — не принимается. 10. Провенанс у всего; автор — человек.
11. Библиотека → проект — только «взятие» с выбором элементов;
проект → библиотека — только «обобщение» со следом.

## 8. Куски и швы — что из движка остаётся, что меняется

**Остаётся как есть**: битемпоральная модель и версии; одно дерево
носителей и стыки; полки и окно взятия; каналы пакетов и акцепт; канон
и урожай документов; Гант (frappe), граф (xyflow); StrictDoc;
справочники и глоссарий; сторожа.

**Меняется**: (а) `born_in` у всех сущностей — миграцией по истории
(сцена рождения вычисляется из даты и фазы; где нельзя — «до
сценария»); (б) видимость видов по сцене — сервером; (в) ворота
запрещают фиксацию на сервере, а не предупреждают; (г) единый реестр
связей с обоснованием вместо разрозненных; (д) уровни требований —
поле, не догадка; (е) «Работа» — единственный вход, остальные экраны —
фрагменты сцен; (ж) реестр требований — шесть колонок и карточка вниз.

3. Пилот сцен 1–4 на правиле видимости и `born_in`.
4. Миграция существующих проектов — только после пилота.
