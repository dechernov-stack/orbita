# Старт проекта ДЗЗ в Orbita

Класс **ДЗЗ · спутниковая группировка наблюдения Земли** имеет код `MC-EO`. Его можно выбрать для любого числа проектов. Заказчик, район, сроки выдачи, состав группировки и требуемая точность задаются отдельно в каждом проекте.

## Установка на стенд

После выкладки клиента и API этой версии из корня репозитория выполните команду. Она использует штатный вход Orbita и требует роли, которой доступна запись на полки.

```bash
python3 tools/v2/load_shelves.py https://orbita.vitalisrun.com/api --eo-only
```

На новом стенде сначала выполните полную поставку той же командой без `--eo-only`. Она установит и общие шаблоны жизненного цикла, и ДЗЗ. Загрузчик проверяет вид и код каждой записи в ответе API. Класс появляется после загрузки своих зависимостей. Повторный запуск допустим и показывает число созданных, обновлённых и уже совпадающих записей.

## Открытие проекта

1. Откройте **Новый проект**, выберите класс ДЗЗ, задайте название, руководителя и даты.
2. Оставьте включённым **Добавить рекомендованные PBS, WBS и модели при создании**. Orbita создаст физический состав, предложенные по этому составу пакеты работ, семь карточек моделей и девять рамок проекта. Без этой отметки рамки всё равно поступят в паспорт проекта, а инженер сможет взять каркасы позже.
3. В **Библиотеке** откройте **Тематические задачи наблюдения**. Найдите задачу по названию, разделу или исходному номеру и возьмите её в проект. На полке **Типы аппаратов и приборов** можно выбрать несколько кандидатов для сравнения. Эти записи фиксируют альтернативы. Конкретный аппарат и его параметры команда определяет в составе проекта.
4. В сцене сервисов опишите решение заказчика и согласуйте срок и способ проверки результата. Цепочки Arcadia используются в сцене операционных сценариев. Для месторождения, сезонной дороги и промыслового флота заданы повод для заказа, продукт, ответственный за решение и способ приёмки.

## Поддержка комплекта

`profile.json` содержит выбор общих позиций IoT по стабильным кодам и собственные элементы ДЗЗ. `tasks.json` содержит карточки задач. `tools/v2/eo_shelves.py` собирает из них штатные записи библиотеки. При открытии проекта его класс определяет, из каких полок берутся каркасы и модели. Поставка доступна разным командам через общую библиотеку, а взятие создаёт записи в выбранном проекте.

```bash
python3 tools/v2/test_eo_shelves.py
python3 tools/v2/gen_schemas.py --check
```
