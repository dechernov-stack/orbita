# Инженерная сессия (§6.2) — сценарий и бланк

Проверяет то, чего прогон миссии не проверял вовсе: **свободную инженерную
работу вне контрольных точек**. Проект по точкам при этом не движется — и не
должен: инженер заводит модель, считает, сравнивает, ошибается и откатывает.

**Кто проводит:** специалист по космическому аппарату (не участвовавший в
разработке ИС). **Где:** стенд `http://localhost:8080`, проект на выбор —
затравка «Ротор-Л» либо свой новый. **Сколько:** ориентировочно 60–90 минут.

Ведущий сессии не подсказывает. Каждое место, где инженер остановился и
спросил «а как?», — находка, а не помеха: она записывается в журнал.

## Что сделать (по шагам)

1. **Представиться** в шапке (без имени правка не принимается) и выбрать проект.
2. **Завести модель аппарата** — раздел «Модели» → «Модель аппарата»:
   платформа (сухая масса, мощность, ориентация), полезная нагрузка
   (regenerative, линии, буфер), режимы с долями витка. Убедиться, что
   бюджеты считаются и резервы показаны отдельной величиной.
3. **Добавить свой шаблон** — раздел «Модели» → «Входы моделирования»:
   создать свою группировку (Walker с иными параметрами) и свой профиль
   терминала; сценарий, ссылающийся на них.
4. **Прогнать три варианта** — «Сравнение вариантов»: сопоставить свою
   конфигурацию с двумя другими по KPI. Проверить, что видно, какой вариант
   чем лучше, и что устаревшие результаты помечены.
5. **Откатить объект** — открыть любой правленный объект в инспекторе,
   «Отменить действие» (undo), убедиться, что откат сам стал версией
   в истории и виден с автором.
6. **Поправить Preliminary** — перевести объект в Preliminary и продолжить
   его править; убедиться, что правка проходит без выпуска новой версии
   документа и без разрешений.
7. **Попробовать сломать**: правка базированного объекта (должна требовать
   основания), ссылка на несуществующий объект, величина без единицы.
   Записать, понятен ли отказ.

## Бланк (§6.2) — заполняется по ходу

| Мера | Целевое | Факт |
| --- | --- | --- |
| Блокировок работы (система не дала сделать то, что вправе делать инженер) | 0 |  |
| Выпусков версии документа ради обычной правки | 0 |  |
| Запросов разрешения (согласование, чтобы продолжить работу) | 0 |  |
| Мест, где пришлось выйти из интерфейса (консоль, база, файл руками) | 0 |  |
| Мест, где инженер не понял отказ системы | 0 |  |

## Журнал сессии

Форма строки: **шаг · что ожидал · что получил · выходил ли из интерфейса**.

| Шаг | Ожидал | Получил | Выход из интерфейса |
| --- | --- | --- | --- |
|  |  |  |  |

## Что считается провалом сессии

- инженер не смог завести аппарат или сценарий без посторонней помощи;
- система потребовала пройти точку, чтобы продолжить обычную работу;
- правка Preliminary потребовала основания (это правило Baseline, не раньше);
- откат не виден в истории либо потерял автора.
