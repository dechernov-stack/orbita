# ADR-045. Требование — полная структура; реестр — два дерева, карточка вниз

**Статус:** принято (ТЗ-CODE-НОЧЬ 02→03.09.2026, шип 2; источники —
РЕШЕНИЕ-ТРЕБОВАНИЕ-ДЕРЕВО-CAPELLA.md §1–2, РЕШЕНИЕ-STRICTDOC-КАНАЛ.md §3,
РЕШЕНИЕ-ЗАИМСТВОВАНИЯ-REQPILOT.md §3)
**Контекст:** требование несло код, формулировку, категорию, родителя,
обоснование, показатель, метод верификации, статус, версию, владельца и
происхождение пакета. Не было краткого имени для дерева и графа, приоритета
данными, критерия приёмки, документа-основания с якорем блока канона,
норматива с пунктом, тегов, рабочей заметки; связи `derives_from` шли без
обоснования; противоречие между требованиями держали в голове до обзора.
Реестр показывал одну иерархию по связям decompose, а карточка открывалась
отдельным экраном.

## Решение

### 1. Структура требования (схема `core/requirement`)

Новые поля, все необязательные к записи (черновик обязан сохраняться):

| Поле | Смысл | Правило |
|---|---|---|
| `title` | краткое имя | дерево, граф и подсказки показывают его, иначе — формулировку |
| `priority` | high · medium · low | справочник `requirement_priority`; не путать с «должен/желательно» |
| `acceptance_criteria` | наблюдаемый результат | **помета к базированию** «нет критерия приёмки» (ворот не держит) |
| `source {doc, anchor}` | документ-основание (SD/NR/DI) и якорь блока канона Д1 | первоклассное поле; из него строится дерево «по документам» |
| `normative_basis {ref, clause}` | норматив (NR) и пункт | лёгкая форма; полный механизм — пакет «граф» |
| `tags[]` | свободные метки | фильтр реестра и графа |
| `comment` | рабочая заметка | **в печать и выгрузку не попадает** |
| `relations[]` | `{ref, kind, rationale, resolution?}` | **обоснование обязательно** у каждой связи; `kind`: refines · derives · depends_on · conflicts_with |

Печать (`requirementRecord`) и ReqIF (`REQUIREMENT_MAP` + эталон
`spec/reqif_semantics.py`) идут по этой структуре поле в поле: Title,
Priority, AcceptanceCriteria; документ-основание и норматив — строками.

### 2. Связи — с обоснованием; противоречие — разрыв

- `relations.refines` → связь `derive` вида `derived` (в свёртку бюджета не
  входит), `relations.derives` → `derive` вида `allocated` (входит),
  `conflicts_with` → новый вид связи `conflict` (V040), `depends_on` — только
  в документе. Пересчёт связей из документа (ADR-027) кладёт `rationale` в
  таблицу; связи вхождений (uses · hosted_on · evolves) от этого правила
  отделены.
- Приём: связь на отсутствующее требование, на само себя или без
  обоснования — отказ (ModelViolation).
- Готовность к базированию (SRR и далее): «Противоречия разрешены» —
  **блокирующий** разрыв, пока у `conflicts_with` нет `resolution`; «Связи
  декомпозиции с обоснованием» (derives_from без relation) и «Критерий
  приёмки записан» — пометы, ворот не держат. Реестр показывает те же
  разрывы чипами «Без критерия приёмки» и «Противоречие не разрешено».

### 3. Реестр — два дерева, карточка вниз

- Слева (≈220 px) — дерево с переключателем: **по иерархии** (корни →
  derives/refines; узел показывает «N · M без показателя · K TBD», флаги
  считает сервер) и **по документам-основаниям** (документ → якорь блока →
  требования, из `source`). Выбор узла сужает список; выбор снимается
  кнопкой с числом показанных.
- **Карточка раскрывается вниз, под строкой, во всю ширину списка** — тот
  же `CardView`, что и отдельный экран (переход из других экранов остаётся);
  в ней — заголовок, приоритет, критерий приёмки (или помета), источник с
  якорем и переходом «к месту в разборе», норматив, теги, связи с
  обоснованием (противоречие без разрешения помечено), комментарий.
- Схемная форма (`ObjectEditor`) показывает новые поля сама: объекты и
  массивы объектов уже поддержаны.

## Последствия

- Пакеты Р04/Р08 ПМИ-4 могут нести новые поля (схема принимает); старые
  пакеты без них — законны.
- «Дерево по документам» видит только требования с записанным `source`;
  урожай Д2 (`provenance.import.item_ref`) в него не переносится — вопрос
  владельцу: считать ли `item_ref` источником автоматически.
- `title` не обязателен схемой (решение говорило «обязательно»): демо и
  пакеты без заголовков остаются валидными; вопрос владельцу — делать ли
  заголовок разрывом к базированию.
