# ADR-031: правка наследует статус; смена статуса — только переходом

Статус: принято (решение владельца, 2026-08-27, заход Т-1).

## Контекст

Прежний закон ядра: любая правка содержимого создавала новую версию в
статусе Draft («изменённое проходит статусы заново»). Следствия на живом
реестре: автораспределение на корень понижало бы базированные требования
молча; дозаполнение TBD службой ИИ «честно сбрасывало в черновик» и
требовало массового перебазирования; помета «изменено после утверждения»
считалась от первого утверждения и горела на ре-базированном вечно.
Принятая модель изменения (Т-2, состояние 1) другая: «Сохранить как v3»
оставляет Baseline с пометой.

## Решение

1. **Правка содержимого наследует статус**: новая версия (v+1) в том же
   статусе. Смена статуса — только переходом (`transition`).
2. **На Approved/Baseline правка допустима только с основанием**
   (непустое `change_ref`) — во всех каналах (рабочий слой отсылает к
   процедуре); в Draft/Preliminary основание не обязательно.
3. **Механические правки** (служебное происхождение: `auto_root` и
   родственные) статус сохраняют всегда, основание автоматическое
   («по правилу уровня проекта»).
4. **Якорь помет — последнее утверждение**: «изменено после утверждения»
   считается от последней transition-записи в Approved/Baseline
   (переход или подтверждение); **повторное базирование гасит помету**.
   Подтверждение — переход в тот же утверждённый статус — законная
   transition-запись (прежде запрещалась).

## Следствия

- Ревизия утверждённого видна ПОМЕТОЙ (содержательное поле изменено
  против якоря), а не понижением статуса; гасится повторным
  утверждением — оно же прогоняет проверки базирования заново.
- Закрытие TBD (пусто → значение) — штатная работа, помету не поднимает
  (решение «закрытие TBD не помета», тот же заход).
- Дозаполнение службой ИИ больше не понижает статус; поле `demoted`
  из ответа enrich-apply умерло.
- Риск: базированное можно испортить правкой с основанием, не проходя
  ворот, — принято осознанно: след (версия + основание + помета)
  обязателен, гашение пометы — только повторным утверждением.

## Реализация

`ObjectStore.change` (наследование статуса, основание на Approved),
`ObjectStore.transition` (подтверждение того же утверждённого статуса;
основание в закрываемой строке — требование триггера),
`Editing.update` (Approved требует процедуры), `ScreenViews.rowMarks`
(якорь — последняя transition-запись в Approved/Baseline). Меры —
ReqRegistryTest (наследование при автораспределении, отказ без
основания, base → правка → base гасит), StorageSemanticsTest,
EnrichmentTest.
