# ADR-048. Структуры внешней модели (Capella): узел-ссылка, связь с обоснованием, только чтение

**Статус:** принято (ответы владельца 03.09 «Очередь дальше» п. 2 = шип 3
ТЗ-CODE-НОЧЬ; РЕШЕНИЕ-ТРЕБОВАНИЕ-ДЕРЕВО-CAPELLA.md §3, РЕШЕНИЕ-STRICTDOC-КАНАЛ.md §5)
**Контекст:** реальной модели Capella нет, и интеграция без модели стала бы
витриной. Но структуры без модели законны, если fixture помечен явно —
так делает workbench («REAL CAPELLA TEST: NOT EXECUTED»).

## Решение

1. **Вид `model_element` (ME-NNNN)**: `source_tool`, `model_id`, **`uuid` —
   истина идентичности**, `type` (OperationalCapability · SystemFunction ·
   LogicalFunction · LogicalComponent · PhysicalComponent · FunctionalExchange
   · FunctionalChain · Diagram), `layer` (OA/SA/LA/PA), имя — снимок,
   `refreshed_at`, `fixture`. Элемент — узел-ссылка: в дереве состава
   показывается серым списком «Внешние элементы модели», с датой снимка.
2. **Вид `arch_link` (AR-NNNN)**: требование → элемент, `relation`
   (satisfied_by · allocated_to · realized_by · traced_to), **обоснование
   обязательно**, автор. При приёме ложится в таблицу связей распределением
   — матрицы, impact и граф считают внешний элемент носителем наравне с
   внутренними узлами; «Без носителя» закрывается и им. Требование может
   ссылаться на элемент и напрямую (`allocated_to.model_element`).
3. **Адаптер только чтения** — контейнер `capella` (`capellambse` 0.8.0,
   Apache-2.0) под профилем compose и переменной `ORBITA_CAPELLA_MODEL`;
   модель монтируется `:ro`. Ядро зовёт его по `ORBITA_CAPELLA_URL`
   (`POST /library/capella/refresh`): элементы приходят по UUID, имена
   обновляются снимком, дата — `refreshed_at`. Без флага — 409 «адаптер не
   включён», без модели — 503 от адаптера. Сторож
   `tools/validate_capella_readonly.py`: в `.capella`/`.aird` система не пишет.
4. **Fixture с баннером**: пакет `16-capella-fixture.json` (пять элементов
   разных слоёв, `fixture: true`) — экран «Внешняя модель» несёт баннер
   «модель: fixture, не доказательство интеграции», пока есть хоть один
   fixture-элемент или адаптер выключен.
5. Обратный путь требований в Capella (StrictDoc → ReqIF → Requirements
   Viewpoint) — описан, не автоматизируется.

## Последствия

- Живой модели у владельца нет: адаптер проверен только тем, что не пишет и
  честно отказывает; первый прогон с настоящей `.aird` — отдельное событие.
- Внешний элемент в матрице «функции × узлы» не участвует: функции
  распределяются на узлы состава и интерфейсы (ADR-047).
