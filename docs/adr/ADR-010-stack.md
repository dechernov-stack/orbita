# ADR-010. Стек: ядро Kotlin/JVM, клиент TypeScript/React

**Статус:** принято
**Контекст:** ядро баллистики — Orekit (Java). Ядро Монте-Карло должно укладываться в бюджет TZ-COM-004. Клиенту нужен 3D-глобус.

**Решение:** ядро — Kotlin/JVM; клиент — TypeScript/React + CesiumJS; хранилище — PostgreSQL.

**Основание:**
- Orekit используется нативно, без моста между языками (мост на горячем пути расчёта — источник и накладных расходов, и ошибок маршалинга);
- JIT даёт скорость, достаточную для ядра МК на примитивных массивах, без перехода на отдельный нативный язык;
- один язык на всём расчётном пути упрощает профилирование и воспроизводимость;
- Kotlin полностью совместим с Java-экосистемой Orekit.

**Отвергнуто:**
- Python-ядро: скорости чистого Python недостаточно для 4·10⁹ событий; связка с Orekit через JPype добавляет мост; вынос ядра в numpy/Rust даёт три языка вместо одного;
- Rust: выигрыш в скорости не окупает отсутствие Orekit и стоимость переписывания баллистики.

**Следствия:** аналитическая обвязка (разовые исследования, калибровка) может делаться на Python вне продукта; в продукт такой код не переносится.
