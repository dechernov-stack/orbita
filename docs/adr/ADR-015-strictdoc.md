# ADR-015. StrictDoc не используется как бэкенд требований

**Статус:** принято
**Контекст:** StrictDoc рассматривался в реестре переиспользования (Концепция, разд. 5.10) как готовое ядро управления требованиями.

**Решение:** StrictDoc не встраивается как бэкенд. Экспорт ReqIF реализуется отдельной библиотекой (выбор реализации и проверка лицензионной совместимости — при реализации TZ-OUT-005).

**Основание:**
- StrictDoc — документо-ориентированный инструмент с собственным форматом и собственным веб-интерфейсом; наша модель шире требований (параметры, TPM, сценарии, результаты моделирования), и её пришлось бы укладывать в чужую модель данных;
- ядро ИС — параметрическая модель с расчётным конвейером, а не документация; управление требованиями здесь один из модулей, а не система целиком.

**Следствия:**
- формат блока требования в `docs/tz/` сохраняет структуру, пригодную для механической конвертации в SDoc, если понадобится обмен;
- StrictDoc остаётся резервным вариантом для отдельного контура документирования и источником примеров по ReqIF.
