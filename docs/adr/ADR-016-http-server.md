# ADR-016. HTTP-слой ядра: jdk.httpserver, без внешнего фреймворка

**Статус:** принято
**Контекст:** шагу 1 нужен HTTP-слой границы модуля (STEP-1 §1.1) при запрете
расчётных зависимостей и минимуме прочих; клиента `web/` ещё нет, поверхность
API мала: объекты ядра, связи, отчёты, валидация контрактов.

**Решение:** HTTP API ядра строится на `com.sun.net.httpserver` (модуль
jdk.httpserver из состава JDK); внешний веб-фреймворк не подключается.

**Основание:**
- ноль внешних зависимостей: на шаге каркаса каждая зависимость должна быть
  оправдана, а фреймворк тянет экосистему ради маршрутизации, которой хватает
  и ручной;
- граница модуля (TZ-MOD-002) реализуется валидацией схем и не зависит от
  выбора HTTP-библиотеки: замена слоя не затрагивает контракты данных;
- один и тот же JDK обслуживает и ядро, и HTTP — меньше поверхностей отказа
  при воспроизведении сборки.

**Отвергнуто:**
- Ktor / Spring (Boot): вес и магия конфигурации несоразмерны десятку
  маршрутов; усложняют воспроизводимость сборки;
- собственный сервер поверх сокетов: изобретение инфраструктуры, которую JDK
  уже содержит.

**Следствия (осознанные ограничения):**
- нет декларативной маршрутизации — диспетчеризация регулярными выражениями
  в одном обработчике; при росте числа маршрутов читаемость падает;
- нет асинхронности и стриминга ответов — обработка запроса блокирующая,
  тело ответа формируется целиком в памяти;
- ограниченная работа с телом запроса — только полное чтение, без частичной
  обработки больших нагрузок.

**Условие пересмотра:** появление клиента `web/` (постоянный API-трафик, CORS,
аутентификация) либо потребность в стриминге результатов расчётов — тогда
решение пересматривается отдельным ADR со сравнением кандидатов.
