# ADR-011. Хранилище: PostgreSQL, JSONB + таблица связей

**Статус:** принято
**Контекст:** модель — граф цифровой нити с версионностью и валидацией по JSON-схемам. Граф невелик (тысячи узлов), обходы — «предки/потомки объекта».

**Решение:** PostgreSQL. Объекты — JSONB, валидируемый схемами на границе API. Связи — отдельная таблица, направление хранится один раз. Версионность — интервалами `valid_from/valid_to`.

**Основание:**
- JSONB сохраняет структуру, заданную схемами, без дублирования её в DDL: схема остаётся единственным источником структуры (TZ-MOD-001);
- рекурсивные CTE покрывают обходы трассировки на графе такого размера;
- интервальная версионность даёт требование TZ-COM-003 без внешних механизмов.

**Отвергнуто:**
- графовая СУБД (Neo4j и подобные): операционная нагрузка и второе хранилище ради графа в тысячи узлов;
- полностью реляционная схема с колонками под каждое поле: структура дублируется в DDL и расходится со схемами.

**Следствия:** направление связи хранится один раз, обратное направление вычисляется. Этот принцип проверен на самом ТЗ: ручное дублирование направлений дало 64 расхождения, устранённых генерацией обратного индекса.
