# ADR-065. Вход через Telegram тонким клиентом tg-authgw; StrictDoc на серверном стенде

**Статус:** Принято · 2026-09-09
**Контекст:** серверный стенд 216:8030 выкачен (workflow `deploy_orbita_server`),
вход на нём выключен, роли точек достаются всем; владелец: «авторизацию через
телегу по старой схеме» — то есть как у afisha и ir-storyboard: центральный
шлюз `tg-authgw` (один общий бот `JB_story_bot`, группы под продукты, сессия
подписана секретом продукта, проверяется приложением локально). Там же —
поднять службу StrictDoc на сервере.

## Решения

**1. Режим `ORBITA_AUTH_MODE=telegram` — тонкий клиент шлюза, не свой бот.**
`core/com/api/TelegramGate.kt`: `POST /start {product}` и `GET /status?token`
делегируются шлюзу (`AUTHGW_URL`); сессия шлюза проверяется локально —
HMAC-SHA256 секретом продукта (`ORBITA_SESSION_SECRET` = `session_secret`
продукта в `AUTHGW_PRODUCTS` шлюза), продукт в теле, срок 21 день. Формат
тот же, что у `tg_authgw.session` (тест читает сессию, выданную Python-шлюзом).
Шлюз не на горячем пути: после approved человек получает ОБЫЧНУЮ сессию
Орбиты (`orbita_session`), и всё остальное — учётки, роли, провенанс,
401 на запись без сессии — работает как прежде.

**2. Учётка заводится при первом входе.** Логин `tg:<telegram-id>`, имя — из
Telegram; пароль случайный и никому не нужен. Владельцы из
`ORBITA_ADMIN_TIDS` получают роль руководителя во всех живых проектах и
запись `*` — по ней роль видят проекты v2, где роли ещё не заводятся
(единственная роль учётки считается её ролью везде). Остальным роли даёт
руководитель через `/auth/roles`. В режиме telegram, как и на стенде,
руководитель несёт и обзорную роль (`da_review`): учётка «РП · DA» одна.

**3. Маршруты и клиент.** `POST /auth/start` → `{token, deep_link}`;
`GET /auth/status?token` → `{status}`, на approved — cookie сессии и
`{login, display_name}`; `whoami` показывает `mode: telegram` и, если режим
не настроен, чего не хватает (`telegram_missing`). Клиент v1 (ворота входа)
и v2 (шапка): кнопка «Войти через Telegram» открывает бота и опрашивает
статус раз в две секунды до пяти минут; отказ и истечение названы словами.

**4. Что на сервере.** `/opt/orbita/.env`: `ORBITA_AUTHGW_URL=http://172.17.0.1:8091`,
`ORBITA_AUTHGW_PRODUCT=orbita` (с префиксом: воркер оркестратора держит свои
`AUTHGW_*` в окружении, и compose подставлял их вместо `.env`), `ORBITA_SESSION_SECRET`, `ORBITA_ADMIN_TIDS`;
`ORBITA_AUTH_MODE=telegram` включается, когда продукт `orbita` заведён в
`AUTHGW_PRODUCTS` шлюза с группой и тем же секретом (новый продукт = группа +
строка в конфиге шлюза, нового бота не надо). Compose передаёт эти переменные
в `api`; локальный стенд остаётся в режиме `stand` (override).

**5. StrictDoc на сервере.** Образ `orbita-strictdoc` собирается и едет на
216 вместе с остальными (`ops/build-and-ship.sh`), профиль включается
`COMPOSE_PROFILES=strictdoc` в `.env` сервера, `ORBITA_STRICTDOC_URL=http://strictdoc:8093`,
лимит памяти 384 МБ в серверном override. Штатный `compose up -d --no-build`
шага `deploy_project` поднимает службу без отдельных рук.

**6. Стенд наружу — только за входом и только через TLS.** В режиме
telegram вход считается включённым ещё до первой учётки (`authOn()`), иначе
до первого входа владельца стенд был бы открыт любому; закрыто и чтение —
фасад v2 отдаёт 401 на любой запрос без сессии (исключение — `GET /kinds`:
перечень видов схемы без данных проекта, по нему выкат проверяет здоровье).
Cookie сессии за прокси получает `Secure` (`X-Forwarded-Proto: https`).
Оболочка v2 без сессии не трогает реестр — только карточка входа. На 216
web-контейнер слушает `172.17.0.1:8030` (docker0, снаружи не виден), наружу —
Caddy с Let's Encrypt под `orbita.vitalisrun.com` (A-запись — у владельца);
голый HTTP-порт не публикуется: cookie по открытому каналу не ходит.

## Последствия

- Вход без пароля и без своей регистрации: пропуск — членство в группе
  Telegram продукта; `/auth/register` и `/auth/login` остаются для режима
  с паролями.
- Обратный путь: снять `ORBITA_AUTH_MODE` в `.env` сервера — режим исчезает,
  учётки `tg:*` остаются записями.
- На стенде 216 после включения режима первый вход владельца делает его
  руководителем всех проектов; остальным членам группы роли раздаёт он.
