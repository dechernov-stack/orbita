# ADR-028. Стенд по умолчанию поднимается пустым

**Статус:** принято (Шаг 16 §3.4)

## Контекст

`docker compose up` заполнял базу демо-проектом «Орбита-IoT»: служба `seed`
была обязательной, `api` зависел от её завершения. Комментарий объяснял:
«иначе первый экран мастера покажет пустые таблицы и будет выглядеть
поломкой».

Следствие: инженер, начинающий свой проект, первым делом видел чужой.
Демо-данные становились условием старта, а само различение «пусто» и
«сломано» перекладывалось с экрана на заполнитель.

## Решение

- `docker compose up` — **пустая система**;
- `docker compose --profile demo up` — с демо-проектом «Орбита-IoT»;
- зависимость `api` от `seed` снята: заполнение — разовая операция профиля,
  а не условие старта API.

Различать пустое и сломанное — работа экрана: три состояния («ответ не
пришёл», «пусто», «есть данные») на всех экранах; пустое состояние несёт
текст, адресованный инженеру, с шагом мастера, где заводится недостающее.

## Последствия

- Первый экран нового проекта — честно пустой, с подсказкой, а не чужие
  данные.
- Стенд с демо для показов и снимков экранов остаётся одной командой.
- Защита заполнителя прежняя: по базе с рабочим проектом `seed` отказывает.
