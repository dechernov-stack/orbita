# ADR-054. Взятие полки — выбор элементов инженером, зависимости по ссылкам

**Статус:** принято (решение владельца Б3-01 ред. 2 от 03.09; первая редакция
с флагами `optional_on` **отозвана**: она прятала ошибку в данные; заморожено в
`docs/tz/manual-run-4/РЕШЕНИЕ-Б3-01-ВЫБОР-ЭЛЕМЕНТОВ.md`)

**Контекст:** каркас PBS берётся без узлов вне рекомендованного набора класса
(`PL-ISL`, `PL-PNT`, `PL-P`, `MCC-SIM`, `SC-EXP`), а стыки, архитектура и WBS
ссылаются на них кодами. Канал отказывал целиком и врал про порядок. Первая
редакция ответа — флаги `optional_on` в данных полок и пропуск с пометой —
переносила решение инженера в поставку: какая запись «необязательная»,
решал разборщик, а не тот, кто берёт.

## Решение

### 1. Данные полки полны, выбор — у инженера при взятии

Полка не знает, что нужно проекту: она несёт всё, а элемент вне
рекомендованного набора класса помечен `default_take: false` — это подсказка
окна, не свойство объекта (канал снимает поле перед записью). Флагов
зависимости в данных нет; сторож сида (`ArchitectureSeedsTest`) не пускает
`optional`/`optional_on` и сверяет состав «вне рекомендованного» с тем, что
назвал владелец. `USR-APP` — в рекомендованном наборе.

Правило действует для **любой** полки — каркас, стыки, архитектура, WBS,
модели, типовые требования, комплекты: окно взятия одно.

### 2. Окно взятия

`GET /library/fragments/LF/take-window` отдаёт элементы полки с
рекомендованным набором, взятым ранее, «зачем» (формулировка, вопрос, состав
работ) и зависимостями, **вычисленными по ссылкам** — кодами `@…` на другие
полки и идентификаторами внутри пачки (шаг цепочки → функция). У каждой
зависимости видно: есть ли она в проекте, а если нет — на какой полке лежит.
«От него зависит» считается по всем полкам библиотеки: сняв `PL-ISL`, инженер
видит стык, функцию, компонент и пакет работ, которые без него не возьмутся.

Отмечено по умолчанию рекомендованное и взятое; поиск; фильтр уровней для
каркаса; итог перед подтверждением — сколько взять, что довзять с других полок,
сколько элементов других полок станут доступны, сколько снять.

### 3. Взятие выбранным набором, довзятие тем же подтверждением, снятие с историей

`POST /library/fragments/LF/apply` принимает `select` (элементы пачки),
`select_all`, `extras` (полка → коды: довзять из другой полки тем же
подтверждением — узел `PL-ISL` из каркаса вместе со стыком `IF-ISL`),
`unselect` (снять взятое — отмена с историей; тронутое руками — отказ с
перечнем). Без `select` берётся рекомендованный набор.

Записи с невзятыми зависимостями в окне **серые** с кнопкой «взять ‹узел› из
полки ‹…›»; их можно довзять сразу либо оставить невыбранными — полка берётся
выбранным набором. Идемпотентность — **по записям**: взятое узнаётся по коду,
без кода — по виду и имени (стейкхолдер-актор связи «применяет» не несёт),
повторное открытие показывает его отмеченным и дублей не создаёт.

### 4. Отказ — только для настоящей ошибки, до первой записи

- элемент выбран, а его зависимость не взята и лежит на другой полке →
  «‹элемент› требует ‹код›: возьмите его из полки ‹…› тем же подтверждением
  или снимите ‹элемент›» — окно такого выбора не пропускает, сервер называет
  починку;
- зависимость из этой же полки не выбрана → «‹элемент› требует ‹…› из этой
  же полки: выберите его тоже или снимите ‹элемент›»;
- код, которого нет ни в проекте, ни на полках → настоящая ошибка данных.

Ни одного отказа «возьмите раньше полку» при живых зависимостях.

## Последствия

- Мера решения (`SelectionTest`, 7 проверок): каркас рекомендованным набором —
  130 узлов; в окне стыков `IF-ISL` вне набора и требует `PL-ISL` с полки
  каркаса; рекомендованные стыки — 24 без отказа; выбрать `IF-ISL` без узла —
  отказ называет узел и полку, с довзятием — узел и стык одним подтверждением;
  архитектура 51 и WBS 49 без отказов; повторное открытие — `F-22`, `FC-06`,
  `LC-ISL` одним подтверждением (обмен `EX-ISL` по стыку проекта), пакет
  `05.05`; повтор рекомендованного — ноль; снятие отметки — отмена; сломанная
  ссылка — отказ «нет ни в проекте, ни на полках».
- Снято: пропуск с пометой, `confirm`/`topup`, блок «неподтверждённые узлы» в
  дереве состава, флаги `optional`/`optional_on` в схемах стыка, функции,
  обмена, цепочки, логического компонента и пакета работ.
- Маршруты взятия живут в `routeLibraryTake`: общий `when` у предела метода JVM.
