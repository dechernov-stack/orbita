# ADR-054. Зависимость от необязательного узла не блокирует полку

**Статус:** принято (замечание владельца Б3-01 от 03.09, поставка полок с
`optional_on`; заморожено в `docs/tz/manual-run-4/ЗАМЕЧАНИЕ-Б3-01.md`)

**Контекст:** каркас PBS берётся без опциональных узлов (`PL-ISL`, `PL-PNT`,
`PL-P`, `MCC-SIM`, `SC-EXP` — по подтверждению), а полки стыков, архитектуры
и WBS ссылаются на них кодами. Канал (ADR-052 §2) отказывал целиком, потому
что кода в проекте нет, — и текст отказа «возьмите раньше полку, которая их
заводит» врал: полка взята, узлы не подтверждены. Каскад: архитектура
отказывала ещё и по стыкам `IF-S-USER…`, которых не было лишь оттого, что
полка стыков не взялась. Обход прогона — перевзять каркас со всеми
опциональными — прячет решение, которое инженер вправе отложить до ЭТП.

## Решение

### 1. Опциональность — данные полок, не догадка канала

Запись полки, зависящая от необязательного узла, несёт `optional_on: [коды]`
— поставка называет их сама: стыки `IF-ISL`, `IF-PNT-USER`; функции `F-22`,
`F-23`, их обмены `EX-ISL`, `EX-NAV`; цепочка `FC-06`; логический компонент
`LC-ISL`; пять пакетов WBS. Сторож сида (`ArchitectureSeedsTest`) проверяет,
что **каждая** ссылка на опциональный узел или стык несёт `optional_on`, —
без этого пропуск был бы догадкой. `USR-APP` стал обязательным: стык
«ЦОД ↔ потребители» без него бессмыслен.

### 2. Пропуск с пометой вместо отказа

При взятии код отсутствует **и** запись ждёт опционального (свой
`optional_on`, узел помечен опциональным на любой полке библиотеки, либо
запись зависит от уже пропущенной) → запись **пропускается** с пометой
«пропущено: не подтверждён ‹узел›», полка берётся; пропущенное — в итоге
взятия (`skipped`, `skipped_on`). Каскад идёт по данным: пропущенный стык
делает опциональными обмены на нём, пропущенная функция — цепочку, чей шаг
на неё ведёт (ссылки пачки — и кодами, и идентификаторами). Всё решается
**до первой записи**: полка не ложится наполовину.

Собственный флаг `optional` гасит только узел каркаса (у него нет
`optional_on`); стык или пакет с `optional_on` живут резолвом узлов, а не
своим флагом — иначе они пропускались бы и при подтверждённых узлах.

Отсутствует **и не опционален** → отказ, как прежде, но с **причиной**:
«полка не взята: «…» — возьмите её раньше» (порядок) либо «узлов с этими
кодами в проекте нет и на полках они не помечены необязательными» (состав).

### 3. Подтверждение и добор

**Подтвердить узел** — `POST /library/fragments/LF/confirm {codes}`: узел с
потомками заводится из уже взятого каркаса, родители разрешаются в узлы
проекта по коду. Дерево состава называет, что подтверждать
(`pending_optional`): опциональные узлы взятых каркасов, которых в проекте
нет.

**Добор** — `POST /library/topup`: повторное взятие всех применённых к проекту
полок создаёт только теперь разрешимые записи. Идемпотентность стала
**по записям**, а не по полке целиком: взятое узнаётся по коду (без кода —
по виду и имени, потому что стейкхолдер-актор связи «применяет» не несёт) и
не создаётся заново; повтор без новых — ноль.

## Последствия

- Мера замечания: новый проект, каркас без подтверждения → стыки 24 из 26
  («пропущено 2: не подтверждены PL-ISL, PL-PNT»), архитектура 51 из 55
  (`F-22`, `F-23`, `FC-06`, `LC-ISL`), WBS 49 из 54; подтвердить `PL-ISL` →
  добор создаёт `IF-ISL`, `F-22` (с обменом `EX-ISL` по стыку проекта),
  `FC-06`, `LC-ISL`, пакет `05.05` — пять записей; повторный добор — ноль.
  Закреплено `OptionalNodesTest`.
- Экран «Начало пути» показывает «пропущено: не подтверждены …» с переходом
  «подтвердить узлы →»; экран дерева состава — список неподтверждённых с
  кнопкой «подтвердить» и после него «добрать зависимое из взятых полок →».
- Маршруты взятия вынесены в `routeLibraryTake`: общий `when` снова упёрся в
  предел метода JVM.
