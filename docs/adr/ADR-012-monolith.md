# ADR-012. Модульный монолит

**Статус:** принято
**Контекст:** принято решение о лёгкой модульности (Концепция, разд. 7 п. 1): без шин сообщений и горячего переключения.

**Решение:** все модули собираются в один процесс. Границы модулей обеспечиваются контрактами `schemas/contracts/` и валидацией на границе, а не сетевыми вызовами. Отдельные воркеры допускаются только для пакетных trade studies.

**Основание:**
- расчётный конвейер передаёт между этапами большие массивы (расписания видимости, карты спроса) — сетевая сериализация на этом пути стала бы основной статьёй расходов времени при бюджете TZ-COM-004;
- изоляция, ради которой обычно берут микросервисы, здесь достигается контрактами;
- команда и объём задачи не оправдывают распределённую эксплуатацию.

**Следствия:** масштабирование — вертикальное плюс горизонтальное по независимым сценариям (воркеры). Разделение на сервисы возможно позже по границам существующих контрактов без изменения модели.
