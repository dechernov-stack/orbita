# ADR-041. Шаги — строками полотна; точка закрывает свой интервал

**Статус:** принято (круг 7 «Работы»)
**Контекст:** после круга 6 шаги жили подзадачами, но раскрывались из попапа,
а ромб SRR стоял в начале полотна — дата вехи оказалась раньше окончания
задач, которые к ней зреют. Владелец (повторно): полотно обязано показывать
иерархию строк `1 · … / 1.1 · … / 1.2 · …` развёрнутой, а точка обязана
стоять в конце того интервала, который она закрывает.

## Решение

### 1. Шаги — полноправные строки, развёрнутые по умолчанию

Строки идут иерархией: `1 · Развёртывание фазы и SEMP`, под ней
`1.1 · Орг-структура и план работ`, `1.2 · SEMP по шаблону`,
`1.3 · Базировать SEMP до SRR`. Нумерация сквозная `‹задача›.‹шаг›` и стоит в
имени строки — левой колонки у библиотеки нет, а имя есть.

Свернуть — щелчком по сводной полосе задачи; шеврон `▾`/`▸` стоит в её имени.
Состояние держится на СЕССИЮ (`sessionStorage`): вкладка помнит, вечность —
нет. Из попапа раскрывать больше нечего.

Связи шагов (`SS`/`FS` с полки) рисуются между строками — параллельность
видна глазами, а не в попапе.

### 2. План — у шага; полоса задачи сводная

Владелец принял этот вариант прямо: «план у шага разрешён, у сводной задачи
вычисляется из шагов». Поэтому:

* `work_plan` принимает адрес шага (`PW-0101#2`) наравне с задачей;
* полоса задачи с шагами — **сводная**: от старта первого шага до конца
  последнего, класс `pw-summary`, ручек нет, перетаскивание отклоняется
  словами «план ставится шагам»;
* план задачи остаётся только у задач без шагов (в нынешней полке таких нет:
  схема требует хотя бы один шаг);
* окно шага без плана — доля окна задачи по его ярусу: порядок, а не срок.

### 3. Точка закрывает свой интервал

Фаза делится точками на интервалы: `начало фазы → SRR → SDR/MDR → KDP-B`.
Начало фазы — последняя ПРОЙДЕННАЯ точка перед первой точкой фазы, иначе день
создания проекта; «сегодня» началом фазы не бывает — полотно показывает фазу,
а не то, когда на него посмотрели.

Задача без плана размечается **внутри интервала своей точки** (доли ярусов —
как раньше), поэтому ромб оказывается в конце интервала ПО ПОСТРОЕНИЮ, а не
по удаче с датой.

Расхождения теперь называются:

* окно задачи (план или расчёт) уходит за дату её точки — конфликт: «задача 3
  заканчивается 07.09 — после точки SRR (02.09)»; подсвечены обе стороны,
  двигает человек (план либо дату точки);
* дата точки не позже начала своего интервала — «конфликт вех» с подсказкой
  перенести точку; из попапа точки ведёт переход на жизненный цикл.

## Последствия

* «когда» читается сверху вниз как в обычном Ганте: сводная задача, под ней
  её работы, справа — ромб, закрывающий интервал;
* планирование стало мельче зерном: РП двигает работы, а не задачу целиком, и
  сводная полоса складывается сама;
* прежняя приёмка круга 5 «РП тянет полосу задачи» заменена: тянут шаг —
  так решил владелец, и полоса задачи теперь принципиально не тянется.
