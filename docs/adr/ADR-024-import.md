# ADR-024. Импорт внешних данных: третий канал в модель

**Статус:** принято
**Контекст:** источники инженерных данных существуют и структурированы: требования
в ReqIF, профили абонентских устройств в каталогах сетей LoRaWAN, орбитальные данные
в CCSDS OMM, диаграммы направленности в отраслевых форматах. Вводить это руками —
потеря времени и источник опечаток.

**Решение.** Импорт — третий канал поступления данных в модель, наряду с ручным
вводом и предложениями ИИ. Для него действуют три правила.

## 1. Тот же фильтр

Импортированная запись проходит **те же функции правил**, что рукописная
и предложенная ИИ. Никаких послаблений вида «данные от вендора, значит корректные»:
иначе импорт становится мягким подбрюшьем — то, что нельзя ввести руками, заходит
через загрузку.

Это прямое продолжение решения шага 5: отдельная «облегчённая» проверка для
предложений ИИ была признана дефектом. Для импорта — то же самое.

## 2. Правовой режим источника фиксируется до написания загрузчика

Часть источников допускает извлечение **отдельных записей** и запрещает выгрузку
каталога целиком. Пример: репозиторий устройств LoRaWAN (The Things Network) —
база, защищённая авторским правом и **sui generis** правом по Директиве 96/9/EC;
извлечение и переиспользование репозитория целиком либо существенной его части
запрещено, извлечение сведений об отдельном устройстве разрешено.

Практическое следствие: **импорт по одной записи, по действию инженера — да;
синхронизация каталога — нет.** Различие не в удобстве, а в праве, и отыграть его
после написания массового загрузчика дорого.

Источник, правовой режим которого не описан, считается **запрещённым к импорту**,
а не разрешённым по умолчанию.

## 3. Происхождение обязательно и содержательно

Значение `imported` существовало в перечне происхождения с первого шага, но
структуры под ним не было. Добавлен блок `provenance.import`: источник, его версия,
дата получения, идентификатор записи в источнике, **условия использования**,
признак допустимости массовой выгрузки, версия отображения полей.

Без этого через полгода нельзя сказать, откуда взята чувствительность приёмника
и можно ли показывать её заказчику.

## Отображение и повторный импорт

- Версия отображения фиксируется: изменение правил перевода полей источника
  в модель обязано быть отличимо.
- Неизвестные поля источника **сохраняются**, а не отбрасываются.
- Неизвестное значение перечисления (например, регион, которого нет в нашем
  перечне) не подставляется наугад: запись отбраковывается фильтром.
- Повторный импорт **обновляет** запись, а не создаёт дубликат.
- **Ручная правка поверх импортированного не затирается** обновлением: инженер
  правил осознанно. То же правило, что для предложенного размещения станций.

## Следствия

- эталон `spec/import_semantics.py` (29 проверок);
- перечень источников с правовым режимом ведётся в конфигурации, не в коде;
- первые каналы: ReqIF (ADR-023) и профили абонентских устройств;
- остальные источники — по мере надобности, каждый со своим правовым режимом.
