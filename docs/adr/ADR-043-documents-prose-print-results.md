# ADR-043. Документы: режим раздела данными, связный текст из вставок, печать по-человечески

**Статус:** принято (задача «три пакета», шипы 0–2; источники ШАБЛОН-SEMP.md v2,
SEMP-СВЕРКА-NASA.md, ЗАМЕЧАНИЯ-ПМИ3-Г.md)
**Контекст:** печать docx/PDF выводила вставки сырыми парами «kind:
mission_intent; held: false» — служебные ключи латиницей в продуктовом
документе; SEMP держал 8 разделов против канона NASA SEH App. J; связного
текста у разделов не было вовсе — только данные; «текст устарел» говорил
«что-то ушло», не называя что.

## Решение

### 1. Печать — человеческим текстом, сторож в два слоя

Запись вставки печатается предложением: веха «SRR — 02.09.2026, не
проведена», узел именем без id-префикса (id остаётся подсказке экрана), нужда
«Минтранс России (заказчик): …», поля по-русски (`PrintHumanizer.LABELS`),
перечисления — общим справочником `EnumLabels`, единицы — `UnitLabels`;
второй таблицы подписей печать не заводит. Обозначение в первой колонке
остаётся только у записей, где id и есть обозначение документа (требование,
нужда, риск, решение).

Сторож: выпуск отказывает документу, в печатном тексте которого остался
латинский служебный ключ (тот же текст, что уходит в docx и PDF);
`tools/validate_print_keys.py` сверяет словарь подписей с ключами, которые
кладёт генератор, и не пускает сырое сшивание обратно.

### 2. Режим раздела — свойство шаблона

`sections[].mode` в `document_template`: `table` [Т] — таблица данных;
`prose` [С] — связный текст, черновик пишет служба из данных вставок, инженер
правит и принимает; `prose_table` — абзац и таблица; `manual` [Р] — рука с
заготовкой. Другой документ (ConOps, Project Plan) расставит свои режимы в
своём шаблоне — механика одна, кода на документ нет.

Печать берёт принятый текст и [Т]-таблицы: у связного раздела с принятым
текстом данные в печать не идут (они пересказаны прозой); без текста печатаются
данные, а рядом стоит разрыв «связного текста нет» — документ не остаётся с
дырой и не выдаёт таблицу за прозу.

### 3. «Написать связно» — у раздела, не у шага задачи

Действие живёт на [С]-разделе экрана документов и открывает службу видом
`section_prose` с адресом раздела. Вход собирает СЕРВЕР
(`DocumentModel.proseInput`): подсказка раздела и данные его вставок — теми же
человеческими строками, что идут в печать, и ничего сверх них. Правила вида
(реестр): не привносить фактов, каждое число из данных с единицей показа,
расхождение с данными — брак, без канцелярита, без служебных ключей. Черновик
в документ сам не пишется: правка и явное принятие на экране документов; шаг
2.2 задачи SEMP открывает то же действие из рамки ведения. `semp_draft`
остаётся частным случаем (тот же контур).

### 4. Устаревание с дифом

Принятый текст хранит снимок данных вставок строками (`inserts_lines`). Когда
данные уходят, раздел получает `text_stale` и `text_diff`: «было: …» — строки,
которых больше нет, «стало: …» — появившиеся. Молчаливой перезаписи текста не
существует: помета и рука.

### 5. SEMP ред. 2 — 11 разделов по NASA SEH App. J

Применимые документы (J.2) — из паспорта; 17 процессов NPR 7123.1 (J.5) —
конфигурацией `semp-configuration.json`, процессы реализации (5, 6, 9) — с
пометкой tailoring «вне области Формулирования, к Phase C/D»: отклонение
названо, не умолчано; TPM (J.7.4) — запас массы и мощности из свёрток бюджетов
и тренды закрытия замечаний точек; организация — роли проекта и стейкхолдеры с
узлами; обзоры — вехи словами и группы готовности; согласование — выпуски
историей. Модель для документов собирается ОДНОЙ функцией
(`DocumentModel.model`) вместо восьми копий по маршрутам. Приложение 1 БП-PA
обновлено до ред. 2 отдельным коммитом — регламент остаётся источником
структуры, и тест сверяет копию с ним.

Самоописание среды выправлено: расчёты — свои, Orekit — в резерве.

## Последствия

* печать перестала быть «черновым оформлением»: PDF читается людьми вне
  «Орбиты», а ключ латиницей — брак сборки, а не косметика;
* связный текст появляется у любого документа полки, где шаблон так решил;
* устаревший текст называет, что именно разошлось, — перечитать можно
  прицельно;
* Библиотека → «Результаты» (шип 2.3): третий отдел рядом с Материалами и
  Полками — карточки выпусков: документ · версия · снимок печати (docx/PDF) ·
  авторы текста из ИСТОРИИ правок разделов + выпустивший + дата; служба
  автором не бывает (её версии в авторы не попадают — сторож ServiceAuthors,
  тест). Существующие выпуски — без миграции: карточка есть проекция объекта
  выпуска. «Обобщить в образец» с карточки открывает службу видом
  `template_extraction` с печатным текстом выпуска на входе. Слепок документа
  больше не включает раздел истории выпусков: иначе сам выпуск дописывал в
  него строку, и документ «уезжал» от собственного слепка в момент выпуска.
* Г-01 (шип 2.4): ссылка пакета на чужой проект — диалог сопоставления и на
  загрузке пачкой (одна таблица `LinkMappingTable` на службу и пачку),
  подтверждённая карта применяется при импорте тем же `LinkMapping.применить`;
  нарезка срезов для другого проекта — `tools/slice_packet.py` перемапливает
  ссылки по совпадению формулировки через тот же расчёт сервера. Изоляция не
  ослабляется: записывается только ссылка на объект этого проекта.
* Один шаблон на код: сид первой загрузки и редакция владельца могут лежать
  на полке вместе — побеждает старшая редакция.
