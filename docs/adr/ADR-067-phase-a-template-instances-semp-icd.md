# ADR-067. Phase A: шаблон фазы с экземплярами сцен на узлы, SEMP/OpsCon/ICD живыми документами, деривация системных требований, внешняя модель

**Статус:** Принято · 2026-09-10 (шип G)
**Контекст:** `ЗАДАНИЕ-CODE-БОЛЬШОЕ` §Шип G; `КОНТЕНТ-ЗАДАЧИ-PHASE-A.md`
(БП-PA, О1–О17); `РОМАНОВ-СТАДИИ-0-2.md` §1 п. 5 (аванпроект рекурсивен:
экземпляр сцены на узел), §3 (`process_catalog` с колонкой Романова);
`ДОКУМЕНТЫ-2-ПРОМЕЖУТОЧНЫЕ` §6 (OpsCon, SEMP DT-9002, ICD DT-9003); ADR-048
(Capella только чтение); ADR-062 (точки как экспертизы).

## Решения

**1. Шаблон Phase A (`PHT-9002`) — порождённый, не рукописный.**
`tools/v2/gen_phase_a_template.py` собирает `ШАБЛОН-ФАЗЫ-PHASE-A-NASA.json`:
сцены A1–A10 — задачи 1–10 БП-PA (шаги «заголовок — подсказка — место»,
условия входа/выхода словарём готовности), мероприятия — блоки стадии 2
Романова (2.x · 2.E* · 2.M* · 2.ME* · 2.P · 2.PE) с их входами и выходами;
точки — задача 11 строгой цепочкой: внутренний обзор → SRR (EXP-2A) →
SDR/MDR (EXP-2B, 44 позиции, 7 сопоставлены нашим артефактам) → KDP-B
(матрица Д1–Д10). Сторож в CI: шаблон совпадает с генератором.

**2. Переход фазы — данными проекта.** Точка `KDP-A` Pre-A несёт
`opens_template: PHT-9002`; решение «approve» пишет проекту `phase` и
`phase_template` и заводит записи точек новой фазы (`GateRecords.ensureGates`)
— иначе решению по SRR некуда лечь. Движок берёт шаблон: открытый явно →
записанный в проекте → Pre-A.

**3. Аванпроект рекурсивен: `instantiate_per: element`.** Движок
разворачивает сцену A4 в экземпляр на каждый узел состава вида `element`
(ключ `A4:<код>`, заголовок «Аванпроект элемента <имя>»), условия выхода
параметризованы `{node}` (`node_requirements_min:{node}:1`,
`node_interfaces_min:{node}:1`). Узлов нет — сцена одна и держится словами,
где их завести. Сцена шаблона прожита, когда прожиты все экземпляры (так
SDR ждёт `scene_done:A4`), начата — когда начат хотя бы один.

**4. Связи сцен названы: FS · SS · FF · INPUT с обоснованием** (`depends`
в шаблоне, `links` в виде сцены). SS обслуживается новым условием
`scene_started:<key>`: ConOps и требования растут вместе, а не по очереди.

**5. Системное требование — только из проектного, с основанием.**
`Requirements.derive(parent, statement, rationale, carrier, subtype)`:
уровень `system`, источник — родитель, связь `derives_from` с видом
уточнения (decomposition · derivation · refinement) и обоснованием — без
«почему» отказ. Условия `system_requirements_min`,
`each_system_requirement_derived`, `node_requirements_min`,
`node_interfaces_min` — в контурах требований и архитектуры. Маршрут
`POST /v2/requirements/derive`.

**6. SEMP, OpsCon, ICD — живые документы** (`tools/v2/gen_phase_a_documents.py`):
SEMP 11 разделов по БП-PA Прил. 1, §2 читает полку нормативов, §6 —
**полку процессов СИ** (`PRC-9001`, 17 процессов NPR 7123.1 → механизм
«Орбиты» → место, ISO 15288 и мероприятия Романова; порождена из
конфигурации SEMP первой версии, `tools/v2/gen_process_catalog.py`), §8 —
свёртки бюджетов, §9 — отклонения. OpsCon: режимы · сценарии · окна
сеансов · нештатные регламенты из рисков. ICD: реестр стыков, параметры на
стыках, требования с носителем-стыком, элементы обмена. Запросы документов
умеют область полки (`area: library`) и природу носителя/цели
(`carrier_kind`, `target_kind`).

**7. Внешняя модель — только чтение.** `ArchitectureFactory.externalModel`:
адаптер Capella по `ORBITA_CAPELLA_URL` либо учебная fixture из ресурса
модуля (28 элементов OA/SA/LA/PA в форме адаптера) с баннером «не
доказательство интеграции»; соответствие узлам состава — по
`external_identity`. Экран «Внешняя модель» в эксперт-режиме v2.

## Последствия

- Проекты v2, прошедшие KDP-A до этого решения, шаблона Phase A не
  получили (переход записывал только `phase`): движок берёт шаблон с полки
  по имени фазы (`phase_template.phase == project.phase`), записывает его
  проекту и заводит точки — один раз, при первом чтении ленты.
- Стенд за входом через Telegram (216): инструменты (`walk_scenes`,
  `load_shelves`, `check_tor_mode`, `check_exchange`) входят через бота
  одной учёткой владельца (`tools/v2/stand_session.py`: ссылка в консоль,
  подтверждение в Telegram, сессия в `~/.config/orbita/session-<хост>`),
  а «учётки» chernov · ivanov · petrova становятся ролью «от имени»
  (ADR-066). Фиктивных учёток на 216 нет.
- Логин `tg:<id>` не проходил проверку логина В3 (только латиница и цифры):
  первый вход через Telegram упал бы на INSERT — миграция V047 допускает
  второй вид логина явно. Нашёл `ActingRoleTest` при прогоне `ci/checks.sh`.
- Полки на стенде: `PHT-9002`, `PRC-9001`, `semp`, `opscon`, `icd` —
  `tools/v2/load_shelves.py`.
- Мера шипа: переход KDP-A → Phase A на проекте прогона; лента Phase A с
  экземплярами «аванпроект элемента»; SEMP §6 — 17 строк; ICD `IF-S-USER`
  из стыка — проверяется прогоном на стенде.
