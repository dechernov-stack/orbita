# ADR-046. Граф трассировки и impact — библиотекой, без хранимых координат

**Статус:** принято (ТЗ-CODE-НОЧЬ 02→03.09.2026, шип 4; источники —
РЕШЕНИЕ-ЗАИМСТВОВАНИЯ-REQPILOT.md §2, РЕШЕНИЕ-STRICTDOC-КАНАЛ.md §2,
РЕШЕНИЕ-АРХИТЕКТУРА-ОДНО-ДЕРЕВО.md «Трассировка как надо»)
**Контекст:** трассировка жила матрицами и группировкой реестра; «кого
заденет изменение» узнавали после правки. С одним деревом носителей
(ADR-044) и полной структурой требования (ADR-045) появилось, по чему идти:
нужда → требование → узел состава → интерфейс → событие верификации →
документ со вставкой.

## Решение

1. **Граф — проекция модели.** `GET /views/trace-graph?focus=&depth=&to=`
   отдаёт узлы (`need · service · goal · conops · requirement · node ·
   interface · event · evidence · document · missing`) и рёбра (`trace ·
   derive · allocation · conflict · side · verifies · evidence · inserted_in
   · source · depends_on`) — из объектов, таблицы связей, сторон интерфейсов,
   событий верификации внутри требований и разделов документов, отрендеренных
   по шаблонам полки. **Координат в ответе нет**; хранить раскладку негде.
2. **Рисует библиотека.** `@xyflow/react` 12.11.6 (MIT) + `@dagrejs/dagre`
   3.1.1 (MIT); elkjs (EPL) не берём. Раскладка считается при показе
   (dagre, слева направо), узлы не перетаскиваются. Сторож
   `tools/validate_graph_library.py`: своей графики и памяти раскладки в
   экране нет, сервер координат не отдаёт, маршрута записи нет, форка нет.
3. **Impact — группами по природе** (образец `reqpilot/services/impact.py`):
   для фокуса — нужды-источники, родители, дети, зависимые, противоречия,
   события верификации, носители-узлы, интерфейсы, документы со вставкой,
   **битые ссылки отдельной группой** (ссылка на отсутствующий объект —
   узел `missing`). Глубина окрестности 1–4; кратчайший путь до второго
   объекта — обходом в ширину, циклы не зацикливают.
4. **Из карточки требования — «что заденет →»**: граф с фокусом на
   требовании до изменения, а не помета после. Клик по узлу — фокус; «к
   месту» ведёт в штатный экран объекта.
5. Слой функций (шип 1b) не заведён — граф говорит об этом словами
   (`functions_note`), пустой колонки «как будто так и надо» нет.

## Последствия

- Схема потока фазы (круг 4) остаётся на серверном SVG: перенос на тот же
  движок означал бы переписать сторож `validate_flow_computed.py` и
  раскладку колоннами по вехам — не дёшево ночью; вопрос владельцу.
- Документы в графе — по рендеру шаблонов при каждом запросе (документов
  мало); выпуски (`document_issue`) не хранят снимок разделов на стенде,
  поэтому ребро идёт к шаблону, а не к выпуску.
- Матрицы «требования × узлы» и «функции × узлы» отдельными экранами не
  делались — горизонт (записка «граф» §6).
