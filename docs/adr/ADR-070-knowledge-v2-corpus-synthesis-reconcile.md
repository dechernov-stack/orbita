# ADR-070. Знания v2: ранг доверия вместо типа, корпус фактов, синтез и сверка по онтологии, исследование и верификация

**Статус:** Принято · 2026-09-12 (пакет «Знания v2», предусловие ПМИ-6)
**Контекст:** поставка владельца 12.09 — `ЗАДАНИЕ-ЗНАНИЯ-V2` (головной), `ПОЛЕ-ЗНАНИЙ-V2-СИНТЕЗ`,
`ОНТОЛОГИЯ-ФОРМИРОВАНИЯ.yaml`, `СВЕРКА-РУЧНОГО-ВВОДА`, `ВНЕШНЕЕ-ИССЛЕДОВАНИЕ-И-ВЕРИФИКАЦИЯ`,
`ЗАМЕЧАНИЯ-ПМИ5-СЦЕНА-3`; сценарий прогона `ПМИ-6-СЦЕНАРИЙ`. Прежнее поле знаний
(ADR-063, ADR-069) разбирало документ по одному и типом файла выбирало режим; постановка
рождалась из одного разбора, а принятое правилось только заново.

## Решения

**1. Ранг доверия вместо типа документа.** `material.authority` — `mandatory` (заказчик,
регулятор, директива) · `expert` (ручной ввод: учётка, роль, дата) · `reference` (аналитика,
наследие, даташит) · `doubtful` (непроверенный). Ранг наследуют факты (`fact.authority`),
в противоречии он **подсказывает, а не выбирает победителя**. Прежний `material.type`
остался необязательным: им по-прежнему выбирается режим разбора (`tor` · `datasheet` ·
`normative`), но это не поле доверия. Профиль содержимого (`material.profile` — доли
«постановка · параметры · нормы · оценки») **вычисляется разбором**, не вводится.

**2. Факт получил источник союзом и связи.** `fact.source` — либо `{material, anchor}`
(документ с якорем), либо `{account, role, at}` (эксперт без якоря). Ворота честности не
ослаблены, а **разветвлены**: документальный факт без якоря не существует, экспертный без
учётки, роли и даты — тоже. Связи фактов — реестром (`supports` · `contradicts` · `refines` ·
`same_as`), в том числе **между документами**; конфликт перестал быть полем и стал связью.
Темы корпусные: `topic.merged_into`, слияние по `same_as` — предложением, сливает клик.

**3. Онтология формирования — вторая истина, генератором.** `docs/tz/v2/ОНТОЛОГИЯ-ФОРМИРОВАНИЯ.yaml`
→ `GeneratedOntology` (`tools/v2/gen_ontology.py`, сторож в CI): для каждого понятия —
`from_facts` · `fields` · `must_link` · `conflict_on` · `identity{key, semantic, threshold}`.
Правила образования живут в данных, а не в коде; второй копии порогов и ключей нет.
Парсера YAML в изделии нет — только генерация.

**4. Сверка двумя ступенями, первая — бесплатная.** Ступень 1 детерминированная
(`IdentityKeys`, `Normalize`, `Reconciler`): ключ идентичности понятия, нормализация единиц и
горизонтов, `conflict_on`, `must_link` — **без единого вызова модели**. Ступень 2
семантическая (`SemanticReconciler`) — один вызов по срезу того же понятия, только если ключ
не совпал. Четыре вопроса к кандидату: дубль · противоречие · соединение · нехватка.
ИИ **не сливает, не переписывает принятое и не выбирает победителя**; «похоже» без «чем
именно» — брак. Ручной ввод — тот же механизм: кандидат-факт ранга `expert` проходит сверку,
решает человек кликом. Десять вводов подряд — один вызов.

**5. Синтез — из всего поля, предложением.** `Synthesizer` собирает срез (факты `adopted` ·
`noted` с темами и принятые сущности, потолок 50, урезание по рангу и словами), один живой
вызов на срез, кэш по отпечатку среза; диф четырьмя группами: **новое · дополнить ·
противоречие · подтверждено**. Происхождение n:m: у понятия несколько оснований из разных
документов с рангами. Запуск — командой и событием поля с задержкой-накоплением; фон
повторяет ADR-069 (сеть в фоне, база на потоке запросов). Подтверждение вторым независимым
источником поднимает `evidence` до `corroborated`.

**6. Исследование полноты — внешним контуром, без токенов.** `research_task`: вопросы из
рамки и онтологии по пяти классам (сторона · программа · норма · применение · аналог), промпт
собирается системой из среза поля и отдаётся файлом `.md`; исследование выполняется вне
продукта; результат возвращается материалом ранга `doubtful` и до подтверждения источников
человеком **не предлагается сценам**; после подтверждения — `reference`. Гриф наружу не
уходит: `dsp`/`commercial` в промпт не идут и считаются строкой, `state_secret` останавливает
сборку промпта отказом.

**7. Верификация документа против поля.** `verification_report`: после сборки и базирования
документ проверяется элементами — тезис без основания · число против факта · противоречие ·
устарело. **Правок молча не бывает**: отчёт предлагает, переносит находку в замечание, решает
человек.

**8. Флаг `knowledge_v2` — признак ПРОЕКТА, не стенда.** Один стенд держит старый и новый
проект одновременно: поле `project.knowledge_v2`, единственное чтение — `KnowledgeFlag.on`,
умолчание для новых проектов — `ORBITA_KNOWLEDGE_V2_DEFAULT`. На проекте без флага поведение
прежнее до буквы; все прежние тесты остались зелёными без правок.

## Последствия

- Виды выросли с 90 до 93: `synthesis_run`, `research_task`, `verification_report`.
- Поставочный YAML владельца — более старый снимок: скопировать его целиком значило бы
  потерять `fact.entity_class` (режим ТЗ) и `material.type` (режим разбора). Мержили
  аддитивно, по списку.
- Онтология знает два понятия без вида в схемах: `assumption` ложится на факт
  (`disposition=assumed`), `milestone` вида не имеет — предложение остаётся фактом
  `kind=event` с темой. Заводить вид в коде запрещено: решение владельца.
- Реализация шла волнами по разным файлам, сборка централизованная: два прогона gradle
  одновременно ломают друг друга.
