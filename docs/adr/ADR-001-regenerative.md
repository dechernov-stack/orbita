# ADR-001. Полезная нагрузка — только regenerative

**Статус:** принято (рецензирование, решение Р1)
**Контекст:** выбор архитектуры связной ПН: bent-pipe (ретрансляция спектра без демодуляции) или regenerative (демодуляция и обработка пакетов на борту).

**Решение:** только regenerative. Bent-pipe не реализуется и не моделируется.

**Основание:**
- store-and-forward требует хранения данных на борту — bent-pipe хранить не умеет (нужна одновременная видимость терминала и НС одним КА);
- буфер с приоритетами C' > B' > A' требует различения пакетов;
- широковещательный маяк эфемерид (Р5) требует генерации сообщения бортом;
- ACK класса B' и эфемеридный backoff (Р6) требуют разбора пакета на борту;
- энергетика IoT-терминалов: bent-pipe даёт сквозной бюджет «терминал → КА → НС», для сигналов на грани шума не замыкается; regenerative даёт раздельные бюджеты участков.

**Следствия:**
- протокольная нейтральность борта теряется: заменяемость адаптера сохраняется в ИС (моделирование), но для лётного изделия смена протокола = модификация бортового ПО в пределах возможностей SDR-приёмника;
- бюджеты линий считаются раздельно по участкам;
- ПН сложнее и дороже, что учитывается в прокси-стоимости.
