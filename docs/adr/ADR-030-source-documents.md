# ADR-030. Библиотека исходных документов: записка — объект модели

**Статус:** принято
**Контекст:** постановочный материал проекта рождается из внешних документов —
записка Минтранса, аналогичная записка Минсельхоза, письма, протоколы,
стандарты. Сейчас их содержимое попадает в систему копипастом в поле «вход
операции» службы ИИ и нигде не хранится: через месяц нельзя сказать, из какого
документа выросла нужда, и нельзя повторить операцию на той же редакции
документа. Живая сессия (список после MCR, п. 4) назвала это прямо: «нужна
библиотека файлов с версиями — мы записку Минтранса загрузим и из них
сформируем Needs».

## Решение

Исходный документ — управляемый объект ядра `SD-NNNN` (`source_document`),
с той же статусной моделью и версионностью, что у остальных видов. Не файловое
хранилище рядом с моделью, а объект В модели: на него можно сослаться,
его редакция фиксируется версией объекта, его правка оставляет след.

### 1. Содержимое — текст, не бинарь

Хранится **текст** документа (или его значимая выдержка): именно текст нужен
службе ИИ для порождения нужд и целей, и именно текст можно показать рядом
с нуждой как основание. Бинарные форматы (PDF, DOCX) в модель не кладутся:
ИС — не документооборот; реквизиты (наименование, организация, дата, редакция)
хранятся полями, оригинал живёт в системе документооборота организации.
Загрузка `.txt`/`.md` файлом — да (это текст); конвертация PDF — вне ИС.

### 2. Правовой режим обязателен

По ADR-024 источник, правовой режим которого не описан, запрещён к импорту.
Поле `rights` обязательно: «внутренний документ, использование в проекте
согласовано», «публичный стандарт», и т.п. Пустое поле — объект не сохранится.

### 3. Связь с порождённым материалом

Вход службы ИИ можно взять из документа библиотеки: промпт получает текст
документа и его идентификатор с версией. Ссылка на источник входит в промпт —
модель обязана ссылаться на документ в `rationale` порождённых объектов,
а инженер видит в журнале вызовов, на каком документе выполнялась операция.

Автоматическую простановку `provenance.import.dataset = SD-NNNN@версия`
на каждом акцептованном объекте канал ИИ пока не делает: у предложений уже
есть происхождение `ai_proposed` с акцептом (TZ-AI-004), и смешение двух
происхождений требует отдельного решения по схеме provenance. Отмечено
следующим шагом.

## Следствия

- схема `schemas/core/source-document.schema.json`; вид `source_document`
  (`SD-NNNN`) в `CoreType`; миграция `V014` (значение enum + шаблон id);
- реестр «Исходные документы» в разделе «Постановка»; загрузка текста файлом;
- экран «Служба ИИ»: вход операции можно взять из документа библиотеки;
- следующий шаг (не в этом решении): простановка происхождения
  `import.dataset` на материале, порождённом из документа.
