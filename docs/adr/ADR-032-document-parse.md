# ADR-032. Разбор документа при загрузке: канон и карта — два слоя

**Статус:** принято (решение владельца, `docs/tz/manual-run-2/пачка-1/РЕШЕНИЕ-РАЗБОР-ДОКУМЕНТОВ.md`)
**Контекст:** ADR-030 положил в карточку `source_document` плоский текст —
его хватало, чтобы отдать документ службе ИИ целиком. Дальше так нельзя:
на записку Минтранса ссылаются нужды, цели и нормативы, а сослаться не на
что — координат внутри документа нет; каждый новый вид извлечения гонит
через LLM весь файл заново; числа документа («7–9 млрд ₽») лежат строкой,
а не величиной; таблицы теряются в потоке абзацев.

## Решение

У документа **два слоя рядом с файлом**, оба считаются один раз при
загрузке, детерминированно, без LLM:

1. **MD-канон** — 100% текста с якорями: `{#b0}` у титула, `<!-- bN -->`
   перед абзацами, `{#sN}` у разделов, `<!-- tN -->` у таблиц, таблицы —
   MD-таблицами. Текст документа живёт **только здесь**, единственный раз.
2. **JSON-карта** — структура и находки, **текста не хранит**: оглавление
   блоков, таблицы со строками и ключевой колонкой (адрес строки `t1#15`),
   числа с единицами каноном справочника и происхождением, термы глоссария,
   обозначения нормативов кандидатами.

Всё, что потребляет документ дальше — промпты, извлечения, поиск,
цитирование, — читает эти слои. Сырой файл службе не отдаётся повторно.

### Почему рядом с файлом, а не объектом модели

Копия чужого текста в модели раздувает объекты и порождает второй носитель
истины. Разбор — производная файла: он живёт в `ORBITA_FILES_DIR/SD-NNNN/parse/`
и входит в копию О-18 вместе с файлами.

### Версионирование — отпечатком

Имя разбора: `<хеш файла>-v<версия разборщика>`. Новый файл — новый разбор;
новая версия разборщика — новый разбор при следующем обращении; прежние
остаются, пока их не подберут. Повторный вызов на том же отпечатке ничего
не пересчитывает — это и есть «служба не читает docx второй раз».

### Словари — данными, не кодом

Написания единиц в тексте («млрд руб.», «млрд ₽» → `BRUB`) лежат в
справочнике единиц полем `spellings`, термы — в глоссарии. Новая единица
или новый терм — правка полки LIB, не правка разборщика (ADR справочника
единиц, Ф-03).

### Структура — по именам стилей, не по идентификаторам

Уровень заголовка определяется именем стиля из `styles.xml` («Title»,
«heading 2») и `outlineLvl`: идентификаторы у редакторов произвольны
(LibreOffice пишет `Style_3` там, где Word пишет `Heading1`). Заголовок
первой строкой — титул документа. Раздел, состоящий только из таблицы, —
не раздел, а заголовок таблицы: его якорь становится якорем таблицы (так
же в ручном эталоне владельца).

## Смысловой разбор (Д2) — один вызов на документ

Поверх выжимки — **единый смысловой разбор**: вид пакета
`document_semantic_parse`, правила задания (11 правил владельца) живут в
реестре видов полем `rules` — перечень расширяется без правки кода. Промпт
собирает система: правила + карточка документа + выжимка блоками из канона;
сырой файл модели не уходит.

Урожай — **кандидаты, не объекты**: класс + координата блока + поля по
смыслу. Схема ответа — `core/document-harvest`; классы расширяемы (сущность
вне перечня несёт `schema_note` и не выбрасывается). Пакет принимается
маршрутом `POST /sd-parse/SD-NNNN/harvest` (закрытый контур и шаг Б2 ПМИ) и
ложится рядом с разбором.

**Акцепт по адресам** (`POST …/harvest/accept`) раскладывает выбранное:
стейкхолдеры — на полку А2, нормативы — на А1, цели/нужды/сервисы — в
постановку, суммы — оценкой каноном млн ₽, ограничения — в паспорт Р-кодом.
Координата блока уходит в `provenance.import.item_ref`: видно, из какого
места какого документа выросла сущность. Недостающее обязательное поле
(роль стейкхолдера, реквизиты норматива, вид цели) **спрашивается у
инженера**, а не выдумывается службой: норматив без обозначения остаётся
готовым разрывом. География и вехи адресуются, но объектами не становятся —
маску и дату ставит инженер.

### Заготовка с честной пустотой — общий закон акцепта

Ответ владельца на вопрос «раскладывать самим или оставить руками» — ни то,
ни другое: **объект создаётся, значение не выдумывается; пустота законная и
видимая, с приглашением там, где это разрыв**.

- **География**: акцепт создаёт область карты спроса (`geo_mask`) с именем,
  признаком приоритета и происхождением-якорем — **без геометрии**.
  «Геометрия не задана» становится разрывом готовности карты спроса
  (проверка `geo_masks`, место починки — «Затравка спроса»), границу задаёт
  инженер. Автополигон «Арктики» по слову из текста был бы витриной.
- **Веха**: акцепт кладёт в ленту паспорта веху программы с
  примечанием-происхождением («этап 1: длительность 0–2 года; источник
  SD-0003, блоки b4») и **незаданной датой** — тихий дефис. Вычислять дату
  от «сегодня» или из длительности документа система не станет:
  планирование сроками умерло решением О-10 и через документ не воскресает.

### Приёмка — на синтетике

Примеры владельца в репозитории не лежат (репозиторий публичен). Фикстуру
docx порождает сам тест по свойствам, которые обязан держать разборщик:
разделы трёх уровней, абзацы с переносами, таблица N×M с ключевой колонкой,
числа несистемными единицами, обозначения нормативов без реквизитов, девять
классов урожая плюс один вне схемы. Потеря текста 0 проверяется сверкой
полного текста фикстуры с каноном. Реальные документы стенда — живые
испытания вне CI: их разбор смотрит владелец, находки идут фиксами.

## Последствия

- Промпт службы сможет включать документ **блоками**, а не целиком (Д3):
  токены падают кратно, состав точнее.
- Урожай смыслового разбора (Д2) ложится координатами на канон — кандидаты
  показываются «в месте документа», акцепт раскладывает их по адресам.
- Онтология получает готовый слой: канонические числа, термы, нормативы.
- Формат вне списка (xlsx, pptx — Д3) разбора не получает; приём файла это
  не ломает — карточка живёт без разбора, кнопка «переразобрать» ждёт.

## Приёмка

Синтетические фикстуры (`DocumentParseFixtureTest`, `DocumentHarvestTest`):
канон несёт весь текст фикстуры, таблица отдаёт N из N строк с ключевой
колонкой, «7–9 млрд ₽» лежит каноном 7000–9000 MRUB и «30 мин» — 1800 s с
происхождением, обозначения нормативов приходят кандидатами, класс вне
перечня выживает пометкой. Акцепт: «Арктика (приоритет)» даёт область без
геометрии и разрыв готовности; «Этап 1» — веху без даты с происхождением;
ни одного вычисленного значения, которого нет в тексте.
