# Библиотека: полки против факта

Источник: `docs/tz/manual-run-2/СТРУКТУРА-БИБЛИОТЕКИ.md` (при расхождении он
старше). Задача: `ЗАДАЧА-CODE-БИБЛИОТЕКА.md`. Инвентаризация 2026-08-26 —
первый коммит, дальше делается только недостающее.

Форма хранения: **Т** — типизированный объект; **Ф** — фрагмент
(`library_fragment`: пачка П1/П2 + манифест); **Д** — документ-карточка
(source_document с полкой). Область: `LIB` (псевдопроект библиотеки;
ссылки проект → библиотека законны).

## Готовая механика, которая переиспользуется

- Пачка П1/П2: POST /import/objects + GET /export/objects — содержимое фрагментов.
- Провенанс imported с dataset/version/retrieved_at/terms — родословная взятого (уже в канале Ш2).
- Связи выводятся из документа (ADR-027) → «применяет» = поле `applies`
  в документе экземпляра + вид связи `applies` в links.
- Деревья: component.parent / wbs_element.parent — замыкание поддерева.
- Мастер-путь: состояние в паспорте, сборка профиля, Ш2-панель — перестраиваются на полки.

## Расхождения с задачей, зафиксированные инвентаризацией

1. «normative_document (А1, есть — проверить)» — вида НЕТ; заводится.
2. Файлы-вложения (А3/А4/В2 «документ-файл») система не хранит — карточка
   с текстовой выжимкой; blob-хранилище — вопрос владельцу.
3. Б2 в задаче CODE не входит в §5-наполнение — форма готова, наполнение позже.
