# МОДЕЛИРОВАНИЕ КОСМИЧЕСКОГО АППАРАТА

*Детализация модуля 5.3 Концепции ИС (v0.2). Версия 0.1 — проект для обсуждения.*

---

## 1. Назначение и место в ИС

Модуль описывает КА как **параметрический объект** в дереве «Система — Компоненты» и порождает входы для остальных модулей:

| Выход модуля | Потребитель | Использование |
| --- | --- | --- |
| Зоны обслуживания (по линиям) | Баллистический модуль | Расчёт доступности сервиса по карте спроса |
| Энергетическая модель (СБ, АБ, циклограммы) | Баллистический модуль | Энергобаланс витка worst/best сезон |
| Ёмкость каналов, буферы, режимы доставки | Модуль потоков | Монте-Карло задержек и доставки |
| Бюджеты (масса, энергия, ΔV, память) → TPM | Реестр TPM, обзоры SRR/SDR | Тренды и резервы |
| Черновые требования к подсистемам | Flow down (Ш4) | Пакет SDR |

Уровень детализации — Phase A: **бюджеты и огибающие**, не схемотехника. Правило отбора параметров то же, что у потребителей: в модель входит только то, что влияет на связь, энергетику, баллистику или стоимость.

## 2. Структура объекта: платформа + полезная нагрузка

КА = Платформа (шина) + Полезная нагрузка (связной комплекс). Обе части — ветки дерева компонентов со своими параметрами и резервами; ИС поддерживает **библиотеку пресетов** (п. 8) для быстрого старта trade studies.

## 3. Полезная нагрузка (связной комплекс)

### 3.1. Реестр радиолиний

Каждая линия — отдельный объект:

| Линия | Направление | Типовой диапазон |
| --- | --- | --- |
| Абонентская восходящая (user uplink) | Терминал → КА | UHF / L / S (по протоколу) |
| Абонентская нисходящая (user downlink) | КА → терминал (B'-ACK, C'-команды, **широковещательный маяк эфемерид/альманаха** — обязателен для работы A' по расписанию пролётов) | UHF / L / S |
| Фидерная (feeder up/down) | КА ↔ НС | S / X / Ka |
| Межспутниковая (ISL) | КА ↔ КА | РЧ (S/Ka); оптика — вне рамок (решение п. 10) |
| ТМ/ТУ (TT&C) | КА ↔ НС управления | UHF / S |

Атрибуты линии: частотный план и полоса; поляризация; мощность передатчика / ЭИИМ; G/T и чувствительность приёма; модуляция и кодирование (**из адаптера протокола** — для абонентских линий); число одновременных каналов/лучей; требуемый запас (link margin).

### 3.2. Антенны

| Атрибут | Содержание |
| --- | --- |
| Тип | Патч / решётка (в т.ч. фазированная) / рупор / вибратор |
| Модель ДН | Изофлюксная / гауссова по ширине луча / табличная (импорт) |
| Усиление, ширина луча | дБи; градусы по уровню −3 дБ |
| Наведение | Надирное фиксированное / электронное сканирование / механическое |
| Число лучей | Для многолучевых — схема покрытия |
| Точность наведения | Требование к платформе (п. 4.3) |

### 3.3. Зона видимости ≠ зона обслуживания

Принципиальное различие, которое модуль обязан поддерживать:

- **Зона видимости** — геометрический footprint (высота, угол места ≥ мин.);
- **Зона обслуживания** — подмножество footprint, где (а) бюджет линии замыкается с требуемым запасом, (б) ДН антенны обеспечивает усиление, (в) есть свободная ёмкость.

В баллистический модуль передаётся именно зона обслуживания — по каждой линии отдельно (зона приёма A' шире зоны двустороннего контура C'). Расчёт границы — замыкание бюджета линии на краю (худшая геометрия).

### 3.4. Бюджет радиолинии

Стандартная таблица по каждой линии: ЭИИМ → потери свободного пространства (f, дальность по геометрии) → атмосферные/ионосферные потери → поляризационные потери → потери наведения → G/T → C/N0 → сравнение с требуемым Eb/N0 (из адаптера протокола, с учётом кодирования) → **запас**. Дополнительно: доплеровский сдвиг и скорость его изменения (из баллистики) vs полоса захвата приёмника; для LoRaWAN-подобных — устойчивость чирпа к доплеру по SF.

Бюджеты линий считаются с двух сторон: параметры терминала — из модуля потребителей, параметры КА — отсюда. Один расчёт — два владельца входов.

### 3.5. Приёмный тракт и ёмкость

| Атрибут | Содержание |
| --- | --- |
| Число одновременных демодуляций | Каналы × SF (для LoRa-подобных — матрица канал/SF) |
| Модель коллизий | Из адаптера протокола (калиброванного) |
| Ёмкость линии | Сообщений/сек в зоне обслуживания — вход модуля потоков |

### 3.6. Межспутниковая связь и режимы доставки

| Атрибут | Содержание |
| --- | --- |
| Тип ISL | РЧ (S/Ka); скорость; дальность; энергопотребление. Оптика — вне рамок первой очереди (решение п. 10) |
| Топология | В плоскости (постоянная геометрия) / межплоскостная (переменная дальность и наведение) |
| Время установления соединения | Существенно для бюджета T класса C' |
| Ограничения | Углы наведения, исключение засветки, число одновременных линков |

Три режима доставки (переключаются в сценарии): store-and-forward → ISL в плоскости → полная сетка. Модуль отдаёт в баллистику/потоки граф связности группировки в каждом режиме.

### 3.7. Бортовая обработка и память

| Атрибут | Содержание |
| --- | --- |
| Архитектура | **Regenerative** (демодуляция и обработка на борту) — зафиксировано (решение п. 10); bent-pipe не рассматривается |
| Буфер store-and-forward | Объём; политика приоритетов (C' > B' > A'); политика вытеснения при переполнении |
| Политика сброса | Сброс всей очереди на НС / выборочный по приоритету |

Переполнение буфера — источник потерь, который обязан быть виден в Монте-Карло (стыкуется с offered/carried load из модели потребителей).

## 4. Платформа

### 4.1. Массовый бюджет
MEL по подсистемам (конструкция, СЭП, СОиС, ДУ, БКУ, терморегулирование, ПН) с резервами по зрелости: новые элементы — 25–30%, модифицированные — 15–20%, существующие — 5–10%; системный резерв сверху. Сухая/заправленная масса. MEL — прямой вход Д-документов и CADRe.

### 4.2. Энергетика
| Атрибут | Содержание |
| --- | --- |
| СБ | Площадь; КПД; деградация %/год; ориентация (фиксированная на корпусе / поворотные панели); косинусные потери из ориентации |
| АБ | Ёмкость (Вт·ч); допустимая глубина разряда (DoD) по ресурсу циклов; КПД заряда/разряда |
| Циклограмма | Перечень режимов × потребление (п. 5) |

Интеграция с баллистикой: генерация на витке = f(тени, ориентация, сезон) → **энергия за виток worst/best (северное полушарие)**; допустимый duty cycle ПН — производная, а не входной параметр.

### 4.3. Ориентация и стабилизация
Точность наведения (требование от антенн и ISL); скорости программных разворотов; режимы (надир / солнце / инерциальная).

### 4.4. Двигательная установка и ΔV
Наличие ДУ (для кубсатов — возможно отсутствие); бюджет ΔV: довыведение/фазирование, поддержание, уклонения, **увод с орбиты** (стыкуется с ODA по NASA-STD-8719.14); тип ДУ как прокси массы/стоимости.

### 4.5. Срок службы и надёжность
Расчётный срок; радиационная нагрузка на высоте (прокси из баллистики); вероятность безотказной работы на срок → вход **кривой деградации группировки** (KPI 5.2.В концепции).

### 4.6. Терморежим
В Phase A — на уровне ограничения: максимальная длительность непрерывной передачи / скважность по тепловому фактору. Глубокого теплового расчёта в ИС не делаем.

## 5. Режимы и циклограммы

Таблица режимов КА (минимум): дежурный / приём / приём+передача / ISL / сброс на НС / коррекция / safe. Для каждого — потребляемая мощность и условия входа/выхода.

Ключевая связка: **расписание режимов управляется географией** — передатчик и приёмный тракт включаются над ячейками карты спроса, сброс — в зонах НС. Реализация первой очереди — **статические географические маски** (полигоны включения режимов, генерируются из карты спроса при её изменении); в интерфейсе модуля предусмотрена **заглушка планировщика** для будущего динамического управления режимами (по очередям, энергобалансу, приоритетам) — модель и Монте-Карло от способа формирования расписания не зависят. Это замыкает треугольник «карта спроса → циклограмма → энергия витка»: спрос ночью/зимой в северных широтах — худший случай одновременно по трафику и по энергетике, и модель обязана его показывать.

## 6. Интерфейсы модуля

| Направление | Контрагент | Данные |
| --- | --- | --- |
| → | Баллистический модуль | Зоны обслуживания по линиям; энергомодель; граф ISL; ΔV/увод |
| → | Модуль потоков | Ёмкости линий; буферы и приоритеты; время установления ISL |
| → | TPM / отчёты | Бюджеты с резервами и трендами |
| ← | Адаптер протокола | Модуляция/кодирование, Eb/N0, оверхед, матрица SF |
| ← | Модуль потребителей | Радиопараметры терминалов (вторая сторона бюджетов линий) |
| ← | Баллистический модуль | Геометрия (дальности, углы, доплер, тени) |

## 7. TPM аппарата (реестр к обзорам)

| TPM | Цель | Резерв | Источник значения |
| --- | --- | --- | --- |
| Масса КА | ≤ лимита средства выведения | по зрелости MEL | MEL (4.1) |
| Энергобаланс худшего витка | ≥ 0 при целевом duty cycle | ≥ 15–20% | 4.2 + баллистика |
| Запас худшей линии | ≥ 3 дБ (абонентские) | — | 3.4 |
| Ёмкость абонентской линии | ≥ пикового спроса ячейки | — | 3.5 + потоки |
| Буфер S&F | ≥ худшего интервала до сброса | — | 3.7 + баллистика |
| ΔV | ≥ бюджета вкл. увод | ≥ 10% | 4.4 |

## 8. Библиотека пресетов платформ

Диапазон платформ первой очереди зафиксирован: **от кубсата 12U до платформы 100 кг** — ниже и выше не рассматриваем (решение рецензирования). Пресеты: кубсат 12U / 16U; микроплатформа 25–50 кг; микроплатформа 50–100 кг. Пресет = заполненные MEL-огибающие, энергетика, наличие ДУ, типовые антенны. Пресеты не заменяют проектирование — они задают реалистичные стартовые точки и не дают trade study уехать в нефизичные комбинации («12U с оптическим ISL и поворотными панелями»). Конфигурации вне диапазона 12U–100 кг ИС помечает как недопустимые для проекта.

## 9. Контур ИИ

Промпт-пакеты модуля:
- «описание миссии + пресет → черновик MEL и циклограммы» (схема ответа — структура п. 4.1/5);
- «проверка согласованности бюджетов» (масса↔энергия↔ёмкость↔буфер: ИИ ищет противоречия и нефизичности, инженер принимает);
- «требование к подсистеме из бюджета» (flow down: дефицит бюджета линии → черновик требования к антенне/мощности).

## 10. Решения и открытые вопросы

**Решено (рецензирование):**
- ISL — только РЧ; оптические межспутниковые линии не моделируем и не рассматриваем. Согласовано с диапазоном платформ 12U–100 кг (п. 8): оптика в этом классе нереалистична, а из модели уходят точность взаимного наведения и время установления оптического соединения;
- управление режимами по карте спроса (п. 5) — в первой очереди **статические географические маски**; в архитектуре модуля оставляется **заглушка (интерфейс планировщика)** для последующего перехода к динамическому планированию без пересмотра модели;
- архитектура полезной нагрузки — **только regenerative** (демодуляция и обработка на борту); bent-pipe не рассматривается. Основание: store-and-forward, буфер с приоритетами C'>B'>A', маяк эфемерид, ACK и эфемеридный backoff требуют понимания протокола бортом; раздельные бюджеты участков «терминал→КА» и «КА→НС» необходимы для энергетики IoT-терминалов. **Следствие:** протокольная нейтральность борта теряется — заменяемость протокольного адаптера сохраняется в ИС (моделирование), но для лётного изделия смена протокола означает модификацию бортового ПО (в пределах возможностей SDR-приёмника).

Открытые вопросы:

1. Точность модели атмосферных/ионосферных потерь для UHF/L/S на первой фазе (константы vs модель от угла места);
2. Наполнение пресетов п. 8 параметрами кандидатных платформ проекта (диапазон 12U–100 кг зафиксирован).
